# EMBER接手判断：已经学成什么，学习联系断在哪里，下一步怎样收束

2026-10-15，新主讨论`01a13dd9-837d-7f33-b15a-4eb170bcf04b`。
本文是科研判断，不是新架构的实施合同。唯一在执行的科学范围仍是video-effect design§14的有限N16恢复。
Owner要求的接手goal是形成自己的完整认识和解决方向，不把候选设计、审阅或工程完成写成EMBER已经超过MT。

## 1. 我接手的目标

输入是exact language和同task的action-hidden、有序正确视频。系统可以实践、读回实际后果、修订参数，最后留下
一套完整task LoRA，在未参与适应的新初态上独立控制。第一优先是固定LoRA明显超过强MT；视频确实提供操作帮助、
保持已有能力和合理覆盖仍是目标，但不能把全部视频controls或胜过充分语言适应变成取得第一份性能进步的前置门槛。

MT是有用的起点和比较对象，不是被冻结的科学信条。rank8、Reader、Jacobian、关系表示、轮数都不是目标。
同样，不应为了证明实践有用而强迫所有condition多次实践：如果第一次编译已经够好，就应保留这份能力。
新condition中准备动作轨迹再拟合最终LoRA的排除条件保持；训练共享Writer时使用合法non-held动作监督是不同的事。

我不认为现有证据证明了EMBER不可行，也不认为存在一个已经被确定、修掉就必然成功的bug。
目前最有支持的判断是：项目已经获得部分参数编译能力，但教学内容、实际修订方向与新初态控制增益之间的学习联系仍不稳。
近几天的主要方法一端在学习少量任务的专家参数映射，另一端在少量实践状态上优化固定的观测模仿评分；两者取得的局部能力
都还不足以支持要求的迁移。历史中确实有FM、真实经历和共享RL，不能把这个判断简化成“过去没有端到端训练/没有RL”。

## 3. 我怎样理解已经尝试过的学习机制

### 3.1 学出一个任务专家，并不自动学会怎样根据经历改进

旧强G把有序视频、语言和真实H编码为memory，由完整参数decoder输出38处LoRA。每层实际执行仍是
`(W_l + c_l B_l A_l) h_l`，这些残差共同改变原生十步flow的动作。它不是一个与控制无关的空接口。
seen427/576和expert-only成功的实际恢复证明这条联系能学出控制，不能把全部旧方法叫作无效。

但同task四条视频和不同H仍可以指向同一个专家E。监督此时允许网络识别task，再回归E；
把label写成`E-parent`并不会使E依赖H。144个condition仍只有36个独立task目标，不因重复视频或更多更新变成更多任务映射。
H可以帮助推断E，因此不能形式化地断言H无用；问题在于这个目标没有直接区分哪段经历要求哪种有益修订。

去掉直接语言入口也没有消除全部任务识别线索。V/VL后续在34个有定义任务上，换视频均把输出推向供体专家，
说明视频确实影响映射；它不区分动态操作理解与视觉任务识别。训练拟合和seen控制继续提高而held停滞，
降低的是“继续同一映射曝光即可解决迁移”的支持度，不是证明视觉内容无用。

这里必须尊重更早的反例：v5.2/v6已有实际动作功能梯度；T已有共同读写算子；Product已有跨场景同指令的完整功能监督；
经验Compiler已有真实H、递推及回报信用。增加一个接口名称或再说一次“把梯度接通”，没有绕过这些负证据。

### 3.2 最近的实践算法确实学习了，但学习对象还偏局部

当前Phi从真实双相机patch、语言和帧顺序预测手/实体/关节关系。它在28个任务的224条视频上接受物理量与变化监督；
OOI有效216/224，缺失的是task25的8条，不能误读成只有8条有效。新教学的预测经自身实体匹配和DTW形成
`R = 2*success + exp(-distance)`。这使视频实际参与优化目标，同时也把预测误差与示范路径偏好带进了回报。

关系变化可见，不等于变化对成功必要。已有task34个例把非目标红杯权重置于目标白杯之上，预测评分和既存sealed关系
评分对一次失败分支的排序相反；task12也给非目标番茄酱较高权重。这些是实际限制，但坏候选的终局信用可能远大于视频项，
所以不能把全部退步解释成视频奖励压过成功。本轮未重开teacher GT或重算sealed分数。

当前更新每个parent只抽一个decision，用连续动作的一个正负随机方向和两条夹爪序列构成四格真实续跑。
这提供的是对局部扰动分布的信用，不是四个独立连续方向。梯度实际经过完整十步flow写回全部因子；
在因子坐标u上可写为`g_u = mean_e[T_e J_e^T g_e]`，随后执行实际Adam与有限点动作限制。
新状态的动作变化还依赖该状态与这些支撑状态的Jacobian对应，不能由旧状态的评分或动作RMS直接推出。
task12有提案在最大raw RMS仅0.0642时把实践成功3/4降到0/4，被接受规则拒绝；这直接限定了有限点信赖约束的能力。

还有一个真实的执行分布差别：`joint_branches`把raw夹爪输出送进sigmoid，逐步Bernoulli采样；
实际PandaGripper使用输出的sign累加夹爪命令。raw约±1时，探索概率约0.27/0.73，仍会频繁改变开合，
增加raw幅度可以改善探索分布却不改变同状态部署时的符号。这是已登记的近似，不是新发现的合同bug；
它使“分支上有信用”不能直接等同“部署控制获得了正确梯度”，但现有数据没有测出其总体因果贡献。

我另外从纠正后37次更新的148个parent四格重算了终局信用类别：27个parent有非零终局信用，
25个含真实成功/失败对比，只有2个来自四格全失败而parent成功；后一类唯一独占的提案被拒绝。
25个有对比的四格中18个同时随连续方向和夹爪序列变化，6个仅随连续方向变化，1个仅随夹爪序列变化。
no-video对应56个parent，8个非零，其中7个有成功对比，1个全失败对成功parent且提案被拒绝。
因此，不能把当前失败缩成“终局梯度主要是常量baseline造成的夹爪噪声”；这个具体竞争解释没有得到计数支持。
这些是保存分数的代数分类，不是参数梯度归因或额外实验。逐parent来源和分类保存在纠正批
`analysis/main_takeover_20261015/terminal_credit_categories.json`。

N4实践成功增加而新初态没有整体净增，与评分不可靠、局部方向高方差及有限支撑迁移不足都相容。
本批只把Phi学成了关系预测器；它没有通过新初态控制结果反向学习整个评分和修订规则。
这解释了为何不能把1120次Phi更新称为“学习了1120次怎样改好策略”。同样，192次交互额度不等于192次参数学习：
N16的16次bootstrap加每次80请求，在当前上限下最多形成两次更新机会，比N4的最多四次还少。
N16结果能限定这一实际预算安排，不能证明充分学习后的整个交互适应原理无效。

### 3.3 历史负结果必须限定到真正执行过的学习条件

10月10日functional revision已经有真实native VJP/JVP、视频/H和外层FM，不是只连了一个小动作头。
但360更新后最终LoRA相对MT平均变化约1.6e−8，上游Reader变化极弱，正式共享PG没有运行。
它强烈质疑当时的尺度与学习组织，不能替代对有效幅度、真实新初态回报训练过的修订算法的判断。
当前native Adam确实产生了实质修改和实践正例，这只补上“能动起来”，没有补上“稳定向有用方向迁移”。

相反，10月6日去噪回报学习确实正式更新过完整共享Writer，1152个episode、140/288组有非零LOO，
seen ODE109→102、SDE109→109、held154/158对父161；不能再声称“加真实RL就是尚未尝试的基本修复”，
也不能把它仅归结成SDE变好但ODE没继承。旧经验Compiler的真实H覆盖有限、参数Compiler仍主要用独立专家query，
固定G的后段RL只改善决策；这些不同范围不能混为一个已经充分检验的元学习实例。

## 4. 推进为什么让人感觉一直在重来

前任后期已经写出不少正确分析。问题不仅是缺少阅读，而是这些结论没有稳定地约束后继投入。
固定E的限制、内部指标与闭环的区别、局部可控制性不能拼成整链资格，在更早的专家意见和findings中都存在。
后续仍常从某个局部疑问直接跳到一套新方案，等结果失败再重新补完整解释。

三个具体责任不能归给Owner：过早用候选和审阅结束goal；把抑制直接L任务索引扩成删除整个真实H，造成2.37GPUh的中止批；
从有限局部内容移植转向跨场景主方案时，没有先对照最近似Product阴性与实际操作覆盖。
Owner的例子和疑问需要由主讨论消化，不应逐条变成实验指令或让Owner反复充当验收人。

还有两种互相加强的偏差：对小幅正收益要求近乎完整解释才愿意承认进步，对新架构却会用图接通和局部可行性
接受一大段后继投入；停止一个版本后又换名称继续承载同一个弱假设。应对称地保留正负证据，按完整方法的实际增益分配投入。

工程错误确实额外消耗时间：settling、joint schema和中断恢复都有真实原件。但纠正后仍未形成所需收益，
所以工程错误不能承担全部科学解释。25,399行的五份主要记录保存了很多事实，也重复了许多“当前”“唯一active”和旧接收人；
字数本身不是问题，缺少一个简短、明确、会改变选择的当前判断才是问题。本次不因分析任务删除历史原件或展开全库清理。

## 5. 我选择的解决顺序

第一，保住已经出现的性能进步。D175/168和G165是必须面对的历史强点；局部阴性不将它们清零。
也不强迫一项本可一次编译成功的方法增加实践、选择器或新的长期记忆，来满足某种架构形式。

第二，把“完整编译之后在独立初态上是否更好”作为下一项学习组织的中心。
这一点不是再追加一个loss名称：训练数据单位需要明确包含合法教学、真实incoming/H、实际参数修改，
以及修改后在另一些初态的控制结果；得到信用的必须是产生修改的读取/写入规则，不能只有固定候选的选择器。
教师actions可以在non-held共享学习中提供密集功能监督，但不能把新condition的自身成功轨迹准备成最终LoRA的模仿目标。

我更倾向保留强控制起点和已验证的原生完整参数接口，把教学/反馈解释和实际修订效果一起训练，而不是再训练一个
只拟合固定E的更大decoder，或假定固定几何距离天然是好老师。若使用学习准则，其输入应来自真实视频内容及自身后果，
它产生的方向须经过真实policy形成完整LoRA；共享训练再用分离初态上的实际结果或合法功能查询教这个准则。
最终condition只更新自身参数副本，最终eval前冻结，读写辅助退出。共享prior可以在授权训练中与编译接口共同学习，
不能因为当前MT合并方式方便，就把这种可能性永久排除。

这个方向仍有需要面对的历史：functional revision的更新尺度、PPW/LocalField的局部传递、经验Compiler的真实分布覆盖、
共享RL的控制阴性都限制它。新的可执行设计必须说明实质改变了哪项学习条件；仅写出新的外层目标不够。
我目前没有证据保证某个新网络一定超过MT，也不把这一方向包装成已经解决。它是我愿意承担的优先取舍，
不是给Owner再列一份需要逐项决定的架构菜单。

具体要补的是三段有消费者的学习联系：视频的可见运动/对象变化与自身执行后果怎样比较；比较产生的信号怎样改变
完整LoRA在真实执行hidden上的作用；共享训练怎样奖励这种修改在另一些初态上的控制收益。训练记录须能指出
每个监督的输入、来源和真正被更新的模块。只训练关系预测器、只让最终价值头看成功，或只把成功写入H，均不能
代替对生成修改的模块的学习。合法动作/FM可提供密集的功能信用，实际新初态控制负责裁决；若选择直接回报学习，
必须给出真实可计算的估计器及其随机变量，不能对成功标量写一个形式上的链式导数。这是下一设计的明确工作内容，
不是声称本报告已经完成了该设计。

两项仍需保留的竞争解释会实际影响这项选择。其一，只有36个独立task映射可能限制外推；source见过71任务不等于
Writer学过71种编译。旧D71只在180步窗口把支持池12扩至71，156对匹配154，不足以否定充分新任务学习，
却已降低“扩池即可修复”的优先级；不能据任务数少就自动恢复95-task。其二，MT在共享训练task上已经学习过，
在held上没有，真实实践中遇到的学习需求可能不同。已有T从source起步的161是正例，Experience/Parameter/Functional
各自有MT依赖，不能拼成一项匹配起点裁决。我不会由保留强MT控制能力推出必须永久固定MT，也不会仅因source
更弱、错误更多就说它一定更适合学习。下一完整方法要明确自己的训练分布与部署分布为何足够对应；这个未决项
不自动生成一批起点比较或成为等待Owner的新门槛。

第三，使用一个有决策价值的完整循环裁决，而非先做无止境局部探针。
当前继续的是已开始的N16：它同时改变支撑宽度、有效更新机会和预算，只按该完整算法解释。
两视频都在合理保持与覆盖下获益，提高此机制支持度；只练习改善而新初态不改善，停止固定Phi评分加局部native Adam的
继续扩量/调参；只有单视频或单任务改善，保留其局部证据，不由此升级为未知任务成功。
后继不以“所有RL已经失败”作放弃理由，也不以“更新还不够多”自动追加同家族训练。

如果需要更换学习机制，先给出能执行的完整数据、梯度消费者、部署算子、预计wall与停止线；
首次有信息量的控制节点直接和强参照比较。视频机制证据服务于判断为什么涨/不涨，在早期完整循环取得适量公平证据，
不把解释全部做完设为超过MT之前的新门槛。正式模型资格仍依strict single-checkpoint paired400与相邻能力，而非本批内部128。

## 6. 外部研究提供的依据和边界

重新核了原论文而非只按方法名称类比。[MIL](https://proceedings.mlr.press/v78/finn17a/finn17a.pdf)
展示过训练时用专家动作学习一个测试时不需要动作标签的适应损失；这是学习关系的前件，不能证明大VLA固定LoRA会同样学成。
[Watch, Try, Learn](https://arxiv.org/html/1906.03352v2)用demo/trial/reward条件和独立示范动作训练再次尝试，
其运行时条件策略不满足EMBER最后固定LoRA后辅助退出的要求。

[WIZARD](https://arxiv.org/html/2606.07217v1)确实研究语言/视频直接生成VLA LoRA，采用三suite训练、第四suite测试；
其pi0.5 MT对照随suite仅约1%–19%，和当前EMBER的153/400不是同一个问题实例。论文正例支持参数编译的可行性，
不证明其权重重建配方可直接解决本项目已遇到的强参照和迁移缺口。
[RoboTTT](https://research.nvidia.com/labs/gear/robottt/)在训练和执行中持续更新fast weights，
自己的失败与人类纠正有明确不同的上下文/监督角色。它提示应训练实际适应过程，但不能直接把持续运行的记忆层换名为
EMBER部署前完成的一套LoRA。引用这些方法是限定可借鉴的学习关系，没有授权移植、下载模型或追加实验。
