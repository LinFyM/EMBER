# 从教学特征到执行算子：计算审计与下一方法假设

2026-09-26。Owner要求开始推进完整机制分析后的工作产物。本文是**方法假设与实验取舍**，不是已验证根因、
新方法成绩或GPU运行合同。最初形成于S0执行期间；其完成裁决已补入§11，当前仅Reader工程准备激活，
执行状态以[progress](../../progress.md)为准。

## 1. 本轮作出的判断

不能继续把问题概括成“没读到视频”“缺时序模块”或“只差LoRA出口”。当前C0完整400的正确/另一正确/语言
为120/132/121，旧大幅落后语言的现象没有稳定复现；冻结后续内容干预27对20/80又表明存在有限有益作用。
另一方面，几轮保留联合特征、原生续算和功能辅助的学习均没有获得足够能力。这些事实要求解释**知识怎样被学成
执行条件下可用的作用**，而非再次用张量完整、非零梯度或更大结构作充分理由。

本轮优先形成的候选是：**以执行状态查询教学内容的原生功能读出，建立可实测的条件控制函数，再检验它能否被
唯一完整LoRA承接。** 它包含一个必须允许失败的前提：合法视频读出本身要有真实闭环能力和有益教学贡献。
没有这个前提，不开始蒸馏，不把弱动作头重新称为功能教师。

后续独立推导在§10进一步收紧这个理由：当前LoRA已有逐query的特征信用；可精确编译的线性读出与LoRA
连梯度也等价。候选真正改变的是非线性、按执行query读取完整教学memory的参数化，不能把它说成补上缺失梯度。
因此候选成功仍只建立功能教师的前提，不自动定位Compiler，更不保证能传给最终LoRA。

这不是认定“固定LoRA不能按状态选择动作”。它本来可以。所比较的是两种条件作用的参数化与学习接口，
不把单层线性与整网非线性混为一谈，也不以放宽后的读出模型成绩冒充EMBER部署结果。

## 2. 现有代码实际上处理了什么

核对对象是当前`writer/{video_program,procedure,temporal,model,supervised,function_credit}.py`；
原科学模型C0的实现来源为dca1b550，最近S0开关不改变下面完整内容路径的定义。
记语言为L，教学帧为I_t，机器人执行查询为x=(o,s,a_tau,tau)，四个轴t/h/tau/native depth分别解释。

| 接口 | 实际计算 | 可以说什么；不能说什么 |
| --- | --- | --- |
| q_j | exact task token经原生text-only路径、Text Meta及2048→256投影 | 语言位置地址；不是已标注实体 |
| E_tj | 同帧原生图文task token投影，加q_j查询256个真实agentview patch的读出 | 当前C0教学侧单相机；双相机是执行侧，不能混为一个输入合同。E不是纯动态量，同j也不保证是稳定物体轨迹 |
| H_th | 真实图文prefix下，公开固定noise、tau=1的完整50×1024 Action Expert响应 | source动作计算表征；不是teacher正确动作或观察到的未来 |
| P_t | 初始mean_h(H)投影；每层重新读完整H、前后E，随后因果时间attention | 有学习过程关系的输入和算子；没有显式标注的抓取/放置阶段 |
| C_j | 每语言位置跨帧读取E，再沿语言轴处理 | 全视频语义内容；该读取自身对帧集合置换不变 |
| 参数slot | Core读取→Core条件的中心化P读取→AdaLN→slot交互 | 条件化的参数内容；slot/rank不是已知技能或物体 |
| A_l,B_l | 共享家族head从slot生成两侧完整因子，加合法identity模板 | 决定实际policy层的条件作用；参数相近不保证行为相近 |

具体地，FrameRead满足

```text
r_j = W_o sum_t [(1-lambda)/T + lambda alpha_tj] W_v E_tj.
```

在固定E时，这个读出本身不保留顺序；顺序还可经P传递。原件中中心内容选择较小只能描述这个接口，
不能推出内容选择没有功能价值；BF16权重和误差不能计为学习出的选择（findings§155）。

Procedure到slot的Value为

```text
p_r = W_o sum_t beta_rt W_v(P_t - mean_t P_t).
u_r = (1 + gamma(p_r)) * RMS(c_r) + beta(p_r).
```

中心化去掉了Value均值，但P仍进入Key，不能宣称整条函数对P公共平移不变。时间编码、内容相关权重和后续非线性
也使一般已训练模型的“S0广播首帧”不必等同于给P输入常量；fresh零读出初始化存在下文§11的特殊不动子空间。
上述性质没有单独证明某个实际有用特征被丢弃，更不自动支持取消中心化。

部署第l个target上的更新则是

```text
delta y_l(x;V,L) = B_l(V,L) A_l(V,L) h_l(x)
                 = sum_r b_lr(V,L) <a_lr(V,L), h_l(x)>.
```

h_l由机器人自己的当前图像/state、动作latent、flow time及前层适配共同决定。
A定义对当前激活的作用方向，B定义输出方向；整个深层policy仍可形成复杂的状态条件行为。
A/B有基变换不唯一性，因此不能把某个rank坐标直接解释为“拿起”“再放下”。

## 3. 现有监督并未缺少跨episode信用

一个teacher生成同一LoRA，训练query来自同task其它episode。现实现先累积完整LoRA cotangent，再同版本重放Writer：

```text
g_w(V,L) = sum_q omega_q d loss_FM(F_source+w(x_q), y_q) / d w,
g_phi = [d G_phi(V,L)/d phi]^T g_w(V,L).
```

这是链式求导，不是截断掉动作信用；对query求和也不是新增的工程错误。
难点假设是：每个query需要的条件作用，必须经过一个共享参数生成Jacobian，才能给教学特征信用。
公式只给出这个依赖，不证明梯度必然冲突、必须改FM、或某个辅助loss一定更好。

在理想teacher/query条件独立的已知task分布下，同task固定LoRA可以最小化该task期望风险；有限池排除teacher
会有采样依赖，不能把理想独立性无条件套到真实sampler。即使语言唯一标识task，有限模型仍可能借视频学会
未见任务的操作规律。两点应同时保留：**不能用视频差异大小定义教学成功，也不能用训练有静态解证明视频无用。**
完整推导与限制见[信息可识别性分析](video_information_identifiability.md#3-为什么跨episode-fm允许视频无关解却不证明视频无用)。

## 4. 下一假设要改变的具体联系

当前Compiler先将教学内容变成一套A/B，再由未知的执行状态使用。候选功能读出则显式学习：
**对于当前执行特征，教学中哪些内容应改变该层输出。** 对一个可微cross-attention读出，记

```text
q_l(x) = Q_l h_l(x),
k_i = K_l m_i(V,L),  v_i = V_l m_i(V,L),
alpha_i(x,V) = softmax_i(q_l(x)^T k_i / sqrt(d)),
R_l(x,V) = U_l sum_i alpha_i(x,V) v_i.
```

m_i须来自真实q/E/H及有序处理，Value不能由task ID、动作标签或执行query构造。
执行query来自当前policy，且只在这个训练/诊断读出中使用；最终Writer仍只能读取L,V。
语言解释关注对象和目标；时间内容提供观察到的状态与变化；query决定这些内容何时对自己的计算有用。
这是拟学习的角色，不把注意力权重本身当成已理解操作的证据。

若g为下游动作损失对R输出的梯度，局部精确导数为

```text
d loss / d v_i = alpha_i U_l^T g,
d loss / d k_i = alpha_i [g^T U_l(v_i - v_bar)] q_l / sqrt(d).
```

它显示同一真实执行query怎样同时训练“读哪个内容”和“该内容产生什么作用”。与当前路径相比，候选把这段
query—教学内容的交互显式放在原生动作计算里，不先要求所有作用经自由参数生成间接建立。
这提供一个具体学习假设，而不是有用知识必然学成的定理。它不是“第一次给视频query级信用”；见§10的精确等价式。
表示欠缺、有限任务支持或学习预算仍可能使它失败。

为防止再次混淆层次：固定LoRA单target是线性算子，R通常是非线性函数，但整个LoRA policy不是线性的。
不能由此证明rank16不够，不能将读出优胜唯一归因于softmax，更不能将它作为逃避MT-BC下界的借口。

## 5. 最终怎样接回唯一LoRA

这里的R是候选功能教师/诊断参照，不是增加一套部署控制器。只有它在独立episode和合法视频上取得行为证据后，
才值得检验如下完整方法：

```text
L,V → 共享原生图文/Action特征 → 有序教学表示
    → G_phi一次输出全部38-target A/B
    → 冻结source依自身状态执行。

训练监督：跨episode真实LoRA FM继续端到端学习G_phi；
合法训练task上的功能读出R只提供同坐标的附加监督，不进入部署。
```

候选监督对象是**在真实执行特征上的作用**，例如`BA h`对`R(h,V)`，不是任意专家A/B的欧氏坐标。
若用于学习，R须在学生自己的h上取值，不能用另一个运行路径的h冒充同一点；辅助项中的h可stop-gradient，
避免学生仅通过移动查询特征降低局部匹配误差，而主FM仍保留完整反传。
教师标签来源、R是否冻结、权重及学习节点必须在后继合同明确；本分析不隐含批准一个额外蒸馏loss。
准备稿将R作用于第10层q/v两个真实LoRA target，避免hidden输入纠正与投影输出纠正坐标不一致。
最终Writer仍输出全部38-target；只在有对应R输出的target定义局部标签。
即便在学生自己的h上查询R，也不能假设这些h都在教师已学会的分布内；这种传递覆盖仍需实测，不能被同坐标形式消除。

一般平方误差只给出三角界

```text
||S-y||_2 <= ||T-y||_2 + ||S-T||_2,
```

不保证蒸馏优于真实标签，更不是闭环成功界。必须分别观察教师能力、传递误差和学生闭环。
不能把弱教师准确复制称为改进，也不能为降低传递误差保留其错误。

另有一个可以精确定义的局部判别。固定授权训练查询，收集同target的实际输入X及R输出Y，
令`X=U Sigma V^T`为薄SVD、rank(X)=s，考察`min_rank(M)<=r ||Y-MX||_F^2`。
在非零奇异子空间上，最优残差是

```text
||Y(I - VV^T)||_F^2 + sum_(j>r) sigma_j(YV)^2.
```

第一项是该有限查询上单个线性算子不能复现的部分，第二项是指定rank的额外代价。
这比仅检查LoRA参数范数明确，但依然只属于固定局部接口：深层各target共同改变h，训练/部署状态也不同，
因此它不是全模型不可表示性证明，更不能单凭这个数增加rank或认定Compiler已失败。
若一个condition的查询数不超过输入维度且X列满秩，第一项可机械地等于零，不能据此称非线性作用已经可迁移编译。
不同video有不同目标LoRA，不能将其查询混为同一个固定M来制造残差。真正使用此判别时需明确样本量、有效秩和独立查询。
与旧Native Correction不同，Y应来自已具行为证据的合法教学读出；它不是privileged cotangent标签或任意专家参数。

## 7. 实验应裁决什么，而不是默认打开哪些阶段

当前首选待辨解释为H_read：有益操作信息与执行条件的联系难以通过当前参数生成链共同学成；
替代解释H_repr：给定数据与学习预算，原生教学表示本身尚未取得可迁移知识。
二者可能同时成立；读出与Compiler都改变时，不能由总分唯一定位某一个tensor。

第一项值得准备的是**fresh联合学习的原生条件读出比较**，而非立即重训一套带KD的Writer。
最低有解释力的参照应包含同接口的language条件读出，以区分视频收益与单纯新增执行容量；
已有C0/B及S0用于明确预算/输入边界，不能把B当MT-BC。只做固定弱E读头不满足这项比较。
Reader本身执行时使用教学memory，必须标注为训练/诊断模型，不能进EMBER零交互部署成绩表。

| 观察 | 会改变的判断与行动 |
| --- | --- |
| Reader正确闭环与匹配language读出均无优势 | 下调本query—内容接口，不启动蒸馏；不从单个小面板断言所有视频表示不可能 |
| Reader强于当前Writer，却不强于同接口language | 可能改善执行参数化，但未建立视频教学价值；不把它作为视频知识教师继续整条投入 |
| Reader从正确/另一正确视频获得一致额外闭环能力，且能力丢失可接受 | 获得合法功能教师的前提证据；才值得登记同坐标作用传递、真实LoRA主FM及固定部署验收 |
| 教师成立，学生局部作用匹配改善但闭环没有改善 | 编译/分布传递尚未成立，不称修复；不因局部loss漂亮无限续训 |
| 唯一LoRA同时保留教师有益贡献并取得绝对提升 | 再按固定完整400和强MT-BC比较，检验保持与覆盖；screen不选正式模型 |

这些是候选的明确证伪方向，不是所有方法必须经过的普遍审批链。可直接由一项更有依据的结构学习干预替代，
但须解释替代依据。S0完成后只修订相关支持度，不自动把输/赢映射为“删动态/加动态”。

### 10.1 当前LoRA本来就收到执行条件下的选择与作用信用

固定一个target，吸收固定scale，记`delta_y=sum_i b_i (a_i^T h)`、`g=d loss/d delta_y`。
其局部精确导数是

```text
d loss/d b_i = g (a_i^T h),
d loss/d a_i = h (b_i^T g).
```

如果a_i、b_i由视频特征m产生，那么m同时获得“该执行特征是否应触发”和“触发后输出是否有益”的链式信用。
多query累积没有抹掉这种依赖。以上是该target的偏导；完整反传还包含h对较早LoRA/参数的依赖，现有FM保留该路径。
所以“Writer先生成参数，就无法给视频具体执行状态的信用”是错误命题；不能据它设计Reader或更换训练loss。

进一步，给定相同的可学习K(m)、V(m)，无归一化线性读出满足

```text
R_lin(h,m) = V(m) [K(m)^T h] = B(m) A(m) h,
B=V, A=K^T.
```

只要合法rank、初始化、scale、实际计算位置和完整学习图一致，先生成BA与在线按相同K/V读取在实数数学中
前向、对m的梯度、对query的梯度都相同。训练期保留memory与部署前把它编译掉，不会自身产生优化优势。
正常kernel/浮点差异不是本命题的科学变量。若再改变K/V生成器、使用不同优化参数、归一化或损失，
差别应归于这些实际变化，不能归于“现在是读出，所以信用更直接”。

这也排除了一个廉价但无意义的替代实验：把已有A/B重新命名为Key/Value，训练同一个函数，期待它解决视频利用。

### 10.2 准备稿实际改变的是哪些特征运算

现有Compiler在执行h未知时，把C/P读取成固定的层/rank slots，再生成参数。执行时通过A与h的内积激活相应作用。
准备稿则在每次真实flow计算中，用h形成query，重新从完整C/P选择内容，并用`GELU(W_h LN(h))`调制该内容。
不同执行状态因而可以读取不同教学位置；但同一特性增加了编译难度。

| 运算 | 现有完整LoRA | 候选Reader |
| --- | --- | --- |
| 教学内容在哪一步收缩 | 先收缩到固定层/rank slots与A/B | 保存C/P，得到执行h后再读 |
| 单target对给定h的直接作用 | 固定BA对h线性；全策略仍非线性 | softmax选择、LN及GELU乘法造成额外非线性 |
| 谁得到query级信用 | A/B及上游Writer都有 | query/key/value及教学encoder都有 |
| 源模型作用位置 | 全部38 targets | 只第10层q/v两个targets |
| 能否立即作为EMBER部署 | 能 | 不能；还依赖执行时教学memory |

另核对原C0实际run_contract的`model.camera_view`与`observer.camera_view`均为`agentview`，
`video_program.py`按一相机生成256个patch；执行policy才使用双相机。本文初稿将教学侧误写为512/双相机，现更正。
候选须保持同一单相机输入，否则会在读出比较里混入未经登记的相机变量；此前没有按错误文字派发或执行。

两种函数类因此没有已经证明的包含关系：Reader放宽局部计算，却减少适配位置。
正结果不能唯一归因softmax或证明旧C/P已有足够知识，因为encoder也共同重学；负结果也不是“所有合法视频知识不存在”。
但阴性必须降低这套具体联合读出及其后继编译投入的优先级，不能用这些边界保护它反复加层重试。

H_read应准确表述为：**在本预算中，先在真实执行query上学习非线性教学内容选择，比现有提前参数编译更容易
获得可跨video/init使用的有效控制函数。** 这是关于参数化与有限学习的预测，不是缺梯度定理。
其竞争解释包括：教学表示/任务支持没有形成可迁移内容，或原有提前编译已足够而新增在线计算没有实际优势。

### 10.3 “可用教师”与“一套LoRA可承接”是两个可失败命题

softmax读出不能一般地精确写成一个固定单target矩阵。最小反例：标量query h，keys/values均为{-1,+1}，
读出为`R(h)=tanh(h)`。在h={-2,-1,1,2}上不存在一个标量M使`Mh=R(h)`；在±1上完全拟合也会在±2失配。
这反驳自动局部编译的保证，**不反驳深层完整38-target LoRA的表达能力**，也不构成增加rank的依据。

同坐标局部损失也不是充分传递合同。设后续执行图F在某激活附近的Jacobian为J，局部误差e的动作影响为
`F(y+e)-F(y)=J e+O(||e||^2)`；它依赖`e^T J^T J e`而非只依赖`||e||^2`。
大误差可能落在后续函数的零空间，小误差也可能被放大。因此不能仅凭同坐标或局部L2更小选择蒸馏方案。
J还随执行状态、flow time及学生较早层适配而变；这里不授权再开Jacobian/去噪位置探针。

后继若有强教师，传递方案须同时明确：

- 最终完整LoRA在自己的真实执行路径上接受主FM，不能只在教师路径拟合局部hidden。
- 局部教师标签是候选学习偏置，不能硬性钉住其它层如何表示同一有效行为；是否采用须另有机制依据。
- 用最终LoRA闭环验证有益教学能力和保持，不能把Reader成绩、局部误差或参数可压缩性代入最终成绩。

本轮因此不提前选定局部L2/KD为下一训练目标，不把“Teacher→LoRA”画成已经接通的解决方案。
先读出仍是可检验候选，而非所有方法的必要课程；有更充分依据的直接完整LoRA方法可替代它。

### 11.2 精确算术下的双零不动子空间

这是本架构与首帧广播共同产生的特殊性质，不是所有VLA的训练问题。
`ProcedureReadBlock`的H及相邻E读取输出投影均为零初始化；S0初始`I_t=I_0`。
在这些读出仍为零时，每个有效时间位置得到相同输入。时间RoPE只进入Q/K：
即便每行attention权重不同，相同Value的归一化加权和仍相同。
因果mask、逐位置RMS/FFN和残差也保持这一性质，故精确算术下`P_t=p_0`。

Compiler对Procedure Value中心化，随后用无bias的零初始化矩阵W产生调制。记读取结果为r、上游cotangent为g：

```text
P_t = p_0  =>  P_t - mean_t(P) = 0  =>  r = 0,
(gamma,beta) = W RMS(r),                 W_init = 0,
dL/dW = g RMS(r)^T = 0,
dL/dr = J_RMS(r)^T W^T g = 0.
```

主项与额外项都只经同一完整LoRA监督、没有独立Procedure目标时，该分支的读出与Action Meta不能由这条路径启动。
零Adam动量及对零权重的weight decay也不会自行打破它；Core/Text/VL路径仍可正常学习。
完整视频的`I_t`原本可以变化，使r非零；第一次调制更新后，梯度就可能进入Procedure/Action Meta。
“可训练参数总数相同”因而不足以证明首帧与全视频拥有相同的优化可达路径。

实际BF16实现并不是精确算术系统。本批105/210/315/420四个S0 checkpoint中，
modulation、两层H读出、两层E读出及72个Action Meta B张量仍全部为零；525/630都已非零。
这与450步才首次记录Action Meta梯度一致。我们没有识别第450步破坏对称性的具体数值事件，
不据此追逐bitwise一致、扩dtype、改变kernel或展开精度实验。

实际Compiler的合成CPU检验得到：常量P与零W时，W/P梯度均为0，Core梯度非零；
仅令P变化，W梯度非零而P仍为0；更新一次W后，P梯度也非零。
它验证双零接口的代数，不替代真实学习干预，更不证明该机制解释全部闭环差额。

## 12. 接管后的科学判断：可迁移知识与实际执行作用

2026-09-26，新科学主讨论`01a0dd74-4c71-7c82-8629-8333ef74dfdd`。以下是对既有代码、数学和证据的综合，
没有新训练/模型forward/闭环，不是根因或修复声明；本次原始行复算范围见progress。

### 12.1 所需知识必须跨teacher与执行初态起作用

以“目标物入篮”为例，所需的是目标角色、目的关系及操作后状态如何变化，不能把教师某时刻的绝对位置或手臂轨迹
直接当成新初态的动作。这是期望学习的功能，不是声称当前E/P已编码这些语义。实际E由图文task-span与语言查询patch
共同形成，允许任务共同语义；H是在公开noise/tau1下的原生响应，不是教师动作。P重读完整H、相邻E并因果处理时间，
提供学习变化与关系的算子，但没有已被验证的物体绑定、阶段识别或跨初态对应。

主FM要求同一视频生成的LoRA服务同task其它episode的当前观测，使复制单条轨迹不能一般满足所有查询。
但它也允许依赖共同任务语义的有限训练解。二者都不是新发现的缺梯度或视频无用定理；早期普通FM正例限制了后一种外推。
真正要改善的是：教学产生的条件作用在不同执行状态下帮助正确操作，并同时保住已有成功。
同task两视频生成相近作用可以是正确抽象，不能为了更大特征或LoRA差异奖励演示细节。

### 12.2 Reader同时改变了内容选择与状态调制

当前LoRA的`BAh`及其上游已接收query级信用，§10的等价结论保持。候选将教学表示M=(C,P)保留到执行h到来后读取；
教师时间位置只是可查询的地址，不应与机器人当前执行步数逐帧硬对齐。它可能利用当前h选择与自身状态有关的教学关系，
但这个跨初态联系仍须由联合FM学成，不能由attention形式担保。

对设计§2的实际算子，令`s(h)=GELU(W_h LN(h))`、`u(h,M)=W_c c(h,C)+W_p p(h,C,P)`，
则每个target的残差为`R_m(h,M)=W_om [s(h) * u(h,M)]`。固定memory时，其局部精确导数为

```text
partial R_m / partial h
  = W_om [diag(u) J_s + diag(s) J_u].
```

第一项是执行状态对内容作用的调制，即使内容读取不随h变化也可存在；第二项才包含随执行query改变的教学内容选择。
候选同时有这两项，并从原38处适配改为2处。因此涨分只能先支持这套联合参数化，不能唯一证明动态检索或Compiler病因。
R_L的同接口参照有助于区分一般执行参数化收益与视频条件的额外收益，但也不是纯参数量匹配的动态信息消融。
不据这个分解增设gate/attention/层位探针，先沿既有有界候选的整体能力预测裁决。

固定h时，教学memory的局部信用为`J_(R_m,M)=W_om diag(s) J_(u,M)`。
零输出head使初始化时这条上游信用为零；输出head自身的梯度为`g_m [s*u]^T`，非退化输入下可以先学习。
这说明工程应验证后续上游活动，而非要求第一步全非零；非零仍不等于学到了有益操作知识。

### 12.3 方法选择保持两个可失败命题

当前保留Reader作为有限投入候选，理由是上述具体的条件作用学习差别，而非断言原Writer缺状态、缺梯度或只能做静态控制。
其第一命题是合法视频联合读出能获得跨正确视频/初态的实质能力，且不靠大范围丢失旧能力取得净分；
第二命题是这份能力能由最终一次生成的完整LoRA承接。两项均未验证，S0结果没有替其中任何一项背书。

未来Reader若无益，降低这条路线优先级；若仅胜C0而不胜匹配R_L，不建立视频教师；若有益，才具体设计传递。

### 12.4 执行query究竟包含什么，修正如何进入真实动作

接管后进一步只读核对`pi05_processing.py`、`writer/function_credit.py`及当前固定LeRobot实现的
`embed_suffix`、`denoise_step`、原生attention与mask；没有增加模型forward或实验。
执行端8维state按冻结Source统计归一化并离散为`Task: ..., State: ...; Action:`中的token；
图像与这些token形成真实prefix。教学prefix则明确没有state，H仍来自公开noise/tau1。
因此教学H与执行h具有不同输入语义，不能把前者解释为教师真实动作，也不能要求两者逐位置直接对应。
执行中使用机器人自己的state是原policy合法输入，不是向部署Writer泄漏教师state。

真实FM调用`NativeFlowPrediction`：缓存冻结prefix KV，再以随机tau和带噪动作调用原生`denoise_step`。
Reader的层9输入h已消费当前视觉、任务/state token及动作/flow条件；它不是裸图像或只有噪声的query。
本候选在此之前没有执行adapter，因此给定同一个FM输入，进入层9前的h由Source决定。
闭环采样的后续flow步则会间接依赖Reader，因为前一步修正已改变下一步的动作latent。

这给§5中“学生h上查询教师仍可能超出支持”的限制提供了实际执行依据。

原生attention为8个query head共享1个KV head、head width256。q残差经过原生RoPE后改变该动作位置
读取prefix和suffix的权重；v残差修改动作suffix的Value，经GQA重复后可影响其它动作位置。
prefix不能读取action suffix，而50个action位置在同一attention块中可相互读取，不能将其误写成
只看先前action的自回归序列。第10层的残差仍经过原生输出投影、AdaRMS gate、后续层和动作输出头，
再经10步flow、前5个实际动作及环境状态变化形成闭环效果。
因此某个reader输出或某条梯度的非零既不是独立控制通道，也不能直接解释为抓取／放置语义。

这次核对确认的是既定作用链和解释边界：教师时间地址、50个预测动作位置、flow时间与环境执行时间
是不同的轴；“当前状态读取教学”不意味着按教师进度播放轨迹。它不引入新的层位、去噪或梯度探针，
也不改变已冻结的工程接口与后继投资规则。

## 13. 完整链的数学对象：过程特征、执行作用与实际学习必须相容

Owner进一步明确，实质进步是在推进过程中更清楚这三段怎样共同成立，而非仅完成新架构或停止无效投入；
不要求此刻完成一套推导。以下是主讨论结合既有证据与源码形成的初步认识，随实际推进修订，不作实验前置关卡。
其中结构性质与功能条件分别陈述；没有新增模型计算，也没有证明模型已经学会这些条件。

### 13.1 “运动过程特征”应保留什么

设教学条件`z=(L,V)`，中间表示`m=E_psi(z)`，生成器输出完整LoRA `w=C_omega(m)`，实际动作流场为`v_w(x)`。
`x`包含执行者自己的图像/state、语言、动作latent与flow time；不能把它换成教师的绝对位置或视频时间。
有用过程至少涉及：对什么对象/关系操作、在什么当前条件下适用、希望造成什么状态变化、哪些变化为后续操作创造条件。
这些是功能职责，不要求显式阶段标签、手工对象图或某个特定token对应一个动作。

例如“物体入篮”，教师手向右运动不直接给出新初态下机器人向右的指令；需要转移的是对目标物建立抓持、在持物条件下
改变物体相对容器的关系、完成放置等条件作用。当前E的同一语言位置不是已验证的跨帧物体对应，H也不是教师动作。
相邻E读入P使状态变化可参与计算，却没有单独保证目标绑定、接触前提或执行方向已学成。

更精确的功能标准可用合格参数集合表达。对条件z及其合法跨episode查询分布，令
`W_z(epsilon)={w: R_z(w)<=epsilon}`，其中R是明确的监督风险，不能直接称成功率。
若`E(z)=E(z')`，确定性Compiler只能给出同一w；要同时达到这两个风险要求，必须有
`W_z(epsilon) ∩ W_z'(epsilon) != empty`。这是必要条件，不是现有特征违反条件的证据。
执行policy仍读取L和当前状态，因此不同任务完全可能共享一个合格w；不能反向要求每个任务/视频有不同表示或LoRA。

同一操作在不同演示初态下也不要求embedding逐元素相等。真正应保持的是所生成策略在相关执行条件上的功能，
例如`d_mu(w,w')=E_(x~mu)||v_w(x)-v_w'(x)||²`；mu必须写清来源和覆盖，不能用一个小面板冒充全状态空间。
这个标准把“保留过程、忽略轨迹细节”落到可消费的功能上，但没有提供一个现成充分的表示损失。

### 13.2 中间特征必须生成条件作用，不能只生成看起来合理的参数

每个target实际作用是`delta y_l=s_l B_l(m) A_l(m) h_l(x;w)`，s_l为固定LoRA scale。
其中`A_l h_l`给出当前状态下哪些作用被激活，B_l决定向该原生投影输出写什么；两者共同依赖教学。
rank坐标可以可逆变换，`B S^-1 · S A=BA`，所以某一行A或列B不具有唯一“抓取阶段”语义。
过程组织也可分布在多个target和source非线性中，一套固定LoRA不等于一段固定动作轨迹。

在一个明确的参考参数和执行query处，对小参数扰动有

```text
delta v(x) = sum_l D_l(x) s_l delta(B_l A_l) h_l(x) + higher-order terms,
D_l(x) = derivative of final flow velocity with respect to target-l output.
```

D_l包含实际attention、gate、后续层及输出头的续算；多层共同更新带来的交互属于高阶项，有限步必须看真实前向。
因此特征的好坏取决于它能否生成适用于新x的这些作用，不能只看视频重建、特征可分性或A/B距离。
同理，教师Reader的局部作用即使有益，学生还必须在自己的h与D下实现有效作用；§5/§10的传递限制仍在。

### 13.3 现有FactorHead给出的一个具体学习机制

源码`FactorHead`实际为无bias的`Linear(256,216)→GELU→Linear(216,d)`，末层零初始化；
Compiler给每个target的r个slot，B模板为零，A模板为非零合法identity因子。
对共享B-head家族f，令`Xi_(z,l)`为r×216的末层前slot特征，末层权重为`U_f`，则

```text
B_l(z) = U_f Xi_(z,l)^T,
delta y_l(z,x) = U_f phi_(z,l,x),
phi_(z,l,x) = s_l Xi_(z,l)^T A_l(z) h_l(x;w).
```

这不是新增近似：固定当前上游量时，它就是该head的真实局部计算。它揭示中间视频特征最终必须与执行状态形成
一个有用的联合特征phi；“视频里能读出过程”与“phi能把对应作用施加到合适执行状态”不是同一命题。

在identity初点U_f=0，令g_q为真实FM对对应target输出的cotangent，q包含条件、query及共享该head的target，
权重a_q包含实际task和两组query权重。对该head的精确偏导为

```text
grad_U L = sum_q a_q g_q phi_q^T.
```

此时经U向该slot/encoder回传的偏导为零，A分支也因B=0没有这一功能信用；输出head先获得更新，随后上游才可学习。
这不是当前Reader修复了的缺梯度：它的输出也零初始化，只是联合特征改为
`phi_R(z,x)=GELU(W_h LN(h)) * [W_c c(h,C)+W_p p(h,C,P)]`，在同样的`U_m phi_R`之后接受真实FM。

若仅为解释使用一次SGD且冻结此步的上游特征，则
`delta y_i=-eta sum_q a_q g_q <phi_q,phi_i>`。
这表明一条训练query会怎样影响另一状态/教学条件，取决于联合特征联系以及作用方向，而不只取决于“梯度非零”。
它不是实际AdamW轨迹的等式：实际Adam矩统计、裁剪、权重衰减与随后上游更新均须按原训练计算解释。
同一家族还跨层共享head，求和不能漏掉其它层；不能由本式宣布梯度冲突、归一化、head共享或训练时钟是已识别根因。

### 13.4 架构与训练配套的具体责任

跨episode主FM让同一个m/w服务其它初态，给的是“怎样在这些状态下完成操作”的信用，而非复制教师轨迹的信用。
但它并未直接标注物体对应、操作前提或过程语义，也允许有限训练任务上的语言/静态解；§3的识别边界不变。
增加视频敏感性loss、要求每条视频产生不同参数，或者直接拟合privileged纠正，都不能由上述推导自然推出。
旧共享获取反例也禁止把“局部目标存在且可微”当作它能由合法视频学出的保证。

由此，后续方法推导要共同回答三个具体问题，而非分别给三个模块起名字：

1. 合法视频中哪些对象/状态变化能改变所需执行作用，表示怎样保留这种联系并跨演示初态使用？
2. 这些联系经实际Compiler形成什么`A h→B`作用，source的哪些真实计算消费它，哪些功能仍由source提供？
3. 已登记标签产生的梯度怎样训练这个联合特征和作用；哪些替代解也能降低损失，现有训练支持与已有行为证据怎样约束它们？

当前Reader是对联合特征phi的一次有界改变，仍沿用未获语义保证的C/P，并减少到两个target；
它没有单独解决过程表示，也没有解决最终编译。后续结果只能在对应范围更新上述三段联系的证据。
本节的新增认识是实际FactorHead与Reader都在学习“教学×执行状态”的联合作用特征，且初始信用有同样的零head边界；
两者的差别必须落实到联合特征如何形成及怎样被有限学习利用，不能用“直接读出”四字宣称理论优势。
这收紧后续方法解释，不激活新探针、head扫描、蒸馏或替代架构，也不把这份推导当作模型已达到预期功能的实证。
