# 专家第四轮回复：无奖励试做条件下的元编译器候选

> 来源：2026-10-08 旧专家对话的完整回复。以下保留原文；其中无奖励、前向更新、一轮试做等前提已被后续 owner 澄清或重新开放，不是当前执行合同。当前入口见 [README](README.md)。原文中的旧会话引文标记若不可解析，请沿正文 Git/论文链接及历史证据入口核对。

## 我的判断

**我建议撤换 EMBER 当前的核心学习组织：不再以“从教学特征直接预测一套参数”为主问题，而是学习“教学要求什么效果，当前控制器实际造成什么效果，以及怎样根据这两者的差异，生成一个在新初态上更有效的控制器”。**

我最看好的完整方向是：

> **用教学视频形成目标与操作过程的条件；用无奖励自身试做建立动作与后果的对应；在 non-held 上元训练一个前向参数更新器，使这两类证据共同转化为完整 LoRA 的控制修订。最终执行仍只使用冻结 source 加一套固定 LoRA。**

这需要一起重建教学表示、经验解释和参数编译器，也需要改变训练事件与信用分配。它不能简化成给 T 加一条自身轨迹输入。

我同时收回两个容易过强的判断：

1. **跨情境配对现在不应继续作为主要修复方向。** 已完成的实验没有给它所需的支持。
2. **“让模型预测自身未来，再用预测误差适应”不够成为新主线。** 机器人可以准确预测自己会失败。预测准确，既不意味着目标选对，也不意味着下一步控制正确。

我对“应当转向学习适应过程”的推荐有**中等信心**；对下面这套具体方法能在现有数据与冻结 source 下稳定超过充分语言参照，只有**中低信心**。这个区别应体现在首批投入规模和停止条件中。

本轮核查固定在提交 [`8972a879`](https://github.com/LinFyM/EMBER/commit/8972a879e566d7acb656195109a0d1bb40d38793)。我核对了新增结果、相关执行源码与边界变更，没有重新运行模型，也没有重新加载未上传的权重和完整轨迹。

## 一、新结果要求改变什么判断

### 1. Product 的结果足以降低原建议的优先级

这次实验确实检验了我第三轮收窄后的建议：在 T 的计算图、起点和匹配曝光下，改变教学—query 的配对关系。不能将它降格成工程接通。

更有诊断意义的是它的收益结构：

- Product 相对 Within 为 **+5/+3**；
- Product correct 相对原 T 的 **−9，全部来自 task3 的 −2 和 task31 的 −7**；
- 书—caddy 面板中，Product 的 35 个成功全部包含在 Within 的 36 个成功里，没有独有新增；
- 两臂换合法视频仍各有 43 次成败交换；
- task23/39 的基本失败没有改变。

因此，合理更新是：**在现成 T 上，仅重新组织这类跨情境配对，没有显示足以承担总体修复的作用。** 它也进一步削弱了“教学场景依赖过强是当前统一主因”的优先级。它没有实验否定新视频入口、自由 A/B、不同初始化或新的适应学习组织，因为那些组合没有实施。[配对原件及主读回](https://github.com/LinFyM/EMBER/blob/8972a879e566d7acb656195109a0d1bb40d38793/docs/analyses/cross_context_pairing_20261008.json)

### 2. 新教师证明了控制增量，也限定了它的有效范围

当前 source 上的独立教师，末点初态 12/16，T50 接手 9/16。接手救回 6 个原失败，同时丢失 3 个原成功；新增集中在 task32/38，task29 仍为 0/4。

这支持两个不同结论：

- **现有完整 LoRA 家族内，还有能通过学习获得的实际控制能力。**
- **一个从初态较强的函数，不自动成为其他控制器所到状态上的可靠纠正函数。**

所以我不会以“冻结 source 已经没有余地”为理由要求立即解冻前缀，也不会以“独立教师已经较强”为理由恢复一条庞大的教师蒸馏流水线。后续 Writer 蒸馏未实施，不能记作蒸馏失败。[教师结果与逐行比较](https://github.com/LinFyM/EMBER/blob/8972a879e566d7acb656195109a0d1bb40d38793/docs/analyses/aligned_teacher_recovery_20261008.json)

### 3. State credit 分析不能替下一轮学习提供正反成绩

它改变了有限样本上的信用估计，但没有 actor 更新，也没有新闭环。尤其，未裁剪梯度平方量减少，不等于实际裁剪与优化之后的视频方向更有效。

因此，它既没有否定 actor-critic，也没有证明更复杂的状态基线是突破口。**若新方法需要完整结果信用，理由必须来自新的学习问题，不能来自这份分析已经“验证了更好的梯度”。**[完整 Writer 信用分析](https://github.com/LinFyM/EMBER/blob/8972a879e566d7acb656195109a0d1bb40d38793/docs/analyses/state_baseline_full_writer_credit_20261008.json)

这些更新没有推翻旧 v5.2/v6、GOMQ、同视频辅助或 T 的真实视频增益。它们仍然说明条件化学习可以获得能力。现在需要解释和改变的是：**这些能力为什么没有在一个共享、合法、完整的方法中可靠积累。**

## 二、我现在优先怀疑的，是学习对象没有被充分分解和识别

当前真实 FM 已经通过同一生成 LoRA，在机器人自身状态上提供跨 episode 的动作信用。不存在一个普遍的“教学没有接到动作”问题。

但这条信用要求一个共享函数同时完成：

1. 从教学中识别目标、操作过程和有用细节；
2. 区分教学场景特有的轨迹与可迁移关系；
3. 推断机器人在其他状态下应该怎样行动；
4. 把整个反馈函数压成参数；
5. 在持续共享训练中保持其他条件下的能力。

原目标可以简写为：

\[
\min_\phi
\mathbb E_{g,D,Q}
\mathcal L_{\rm FM}
\left(\pi_{\Theta+G_\phi(D,L_g)};Q_g\right).
\]

这里 \(\Theta\) 是冻结 source。这个风险有真实功能信用，却没有把上述推断过程识别出来。一个能在训练任务成功轨迹上表现不错的解，可以仍然没有学会：

> **遇到一种新的教学—自身控制失配时，哪些观察说明应该修改哪一种控制关系。**

这不是说当前模型一定用了场景捷径，也不是说共享生成一定不可学。我的判断是：**长期投入一直主要在改善这个复杂映射的输入、参数化和局部监督，而对“如何从可获得的证据推断控制修订”本身，缺少足够明确的学习事件。**

新增自身试做许可，使这件事第一次有了不同的信息条件。原来 Writer 只能旁观一个成功过程；现在它可以知道：

- 当前可执行控制器在这个任务里实际做了什么；
- 哪些对象随之发生了变化；
- 哪些教学所要求的变化没有发生；
- 同样的动作在不同初态中是否产生相似后果。

这类信息可能减少“从视频直接猜整套修正”的难度。但它仍然不会自动给出正确答案。

### 必须区分两种误差

设实际动作是 \(a\)，实际后果是 \(d\)，模型预测的后果是 \(\hat d\)，教学在当前情境要求的效果是 \(d^\star\)。

\[
\underbrace{d-\hat d}_{\text{动作后果理解误差}}
\qquad\text{与}\qquad
\underbrace{d^\star-d}_{\text{任务要求与实际后果的差异}}
\]

不是一回事。

例如：

- 准确预测退出动作会把抽屉带回去，预测误差可以为零；
- 准确预测杯子将停在微波炉外，预测误差也可以为零；
- 从这些前后图像准确反演出实际动作，仍然只是解释已经发生的行为。

**修复需要第二种差异，以及“什么动作能够改变这种差异”的知识。** 这是我不再推荐纯未来预测适应的原因。

## 三、文献真正改变了我的方法判断

这些论文没有提供一套可直接迁入 EMBER 的架构，但它们帮助分清了三个不同问题：形成可调用功能、学习适应过程、编译已有功能。

| 工作 | 对本次重设计有用的原理 | EMBER 不能直接继承的前提 |
|---|---|---|
| **HOST、XSkill** | 教学过程要在自身状态下被解释，并由经过训练的动作消费者使用。过程识别与执行之间需要明确接口。 | 部署持续读取教学；HOST 训练视频与动作模型本体。XSkill 自己也有未见衔接失败，不能由技能成立推出组合成立。 |
| **Doc-to-LoRA** | 参数编译可以学习一个跨上下文的功能保持问题，而不必回归某组任意专家参数。 | 其底座已经能在文档上下文中回答问题。EMBER 尚没有普遍有效的“带视频上下文的自身控制函数”可直接压缩。 |
| **WAM-TTT** | 适应规则本身可以被外层控制目标训练：不是任意自监督更新都值得做。 | 元训练更新 WAM 本体，并依赖既有视频—动作联合模型。冻结 π0.5 加一个预测头，不具备同样前提。 |
| **ICRT、Zero-WAM** | 应训练模型使用示范解决独立 query，并使任务条件影响实际消费者。 | ICRT 的示范含动作和 proprio；Zero-WAM 有大规模世界—动作训练，ICL 测试关闭语言。都不能直接证明 action-hidden 视频相对完整语言的增量。 |

HOST 的前级目标在训练时还使用了停止梯度的真实 clean tokens；这提醒我们，**“所有中间量必须被最终动作 loss 一路反传”不是普遍定理，真正关键的是实际消费者是否被训练为使用那个接口。** XSkill 的真实衔接反例，则要求新方案同时承担局部执行和阶段连接的风险。:chatgpt-content-reference{index="0"}

Doc-to-LoRA 对我最重要的启发，是不能把“还未建立有用的条件控制函数”直接当成“只剩参数压缩”。WAM-TTT 则支持把适应后的控制效果作为训练对象；它不支持用预测损失下降替代控制改善。:chatgpt-content-reference{index="1"}

ICRT 与 Zero-WAM 的条件和规模差异，也使我不会据此主张“只要重新做上下文训练就应当成功”。:chatgpt-content-reference{index="2"}

版本边界：XSkill 的机制按会议原文核对；Doc-to-LoRA 的机制核对使用作者预印本，未完整取得 PMLR 最终 PDF，不将两版视为已经逐字核验相同。

## 四、首选完整方法：学习“目标效果—自身经验—控制修订”的元编译器

### 4.1 方法依赖的核心假说

我建议用下面这个有条件的分解组织学习：

\[
\text{任务控制}
\approx
\text{在自身状态中确定所需效果}
+
\text{实现该效果的动作知识}
+
\text{将这两者编译为固定反馈函数}.
\]

更具体地：

\[
a\sim I_\eta\bigl(a\mid s,\ d^\star(P_g,s),\ C_g\bigr).
\]

其中：

- \(s\)：机器人自身 RGB 与合法 proprio；
- \(P_g\)：从教学和语言获得的目标、过程及约束；
- \(d^\star(P_g,s)\)：在这个自身状态下需要实现的效果；
- \(C_g\)：自身真实动作—后果经验；
- \(I_\eta\)：经过训练的效果条件动作函数。

**这是待检验的结构假说，不是现有模型已经具备的分解。**

它可能降低学习难度的原因，是一些局部动作—效果关系能够跨目标复用。若当前几何、操作对象、所需变化和保持条件已经给足，实现该变化所需的控制，不应还完全依赖整项任务的名字。

这个近似在接近、抓取、对象运输、关节操作等局部范围有理由成立；在接触模式不明、历史不可见、长程选择或未见操作机制上可能不成立。不能靠把中间量叫作“技能”消除这些限制。

### 4.2 教学表示：保留“起点、终点和变化”，而不把变化本身当作控制值

我会撤下固定 probe 下 native hidden 差分作为主要教学表达的地位。

首版读取：

- 冻结 source 图像编码及原生前缀中保留空间位置的视觉 tokens；
- exact language 的 tokens；
- 教学实际具有的视角、图像位置和时间信息。

在这些特征之上训练独立的时空读取器。原生前缀保持冻结。source 的视觉能力继续作为特征基础，其动作知识另在真实自身输入上使用。

教学中间表示应同时保留：

1. **对象身份与语言角色**：什么被操作，什么是接收对象或操作部件；
2. **几何与外观**：位置、相对方向、可见形状，不能一开始全部做成场景不变量；
3. **状态变化**：移动、开度、接近、分离、对象是否随手运动；
4. **过程中的条件**：哪些关系需要先建立，哪些需要暂时保持，什么时候可以撤销。

效果 token 应描述一对状态：

\[
e_{t,h}
=
E_\eta(z_t,z_{t+h},L),
\]

而非只有 \(z_{t+h}-z_t\)。否则，已经打开并需要保持可用的容器、已经抓住并需要继续保持的对象，很容易在“变化很小”时消失。

在可获得可靠训练标签的部分，可以采用相对几何。例如对象 \(i\) 相对接收体 \(j\) 的位置：

\[
r^{ij}=R_j^\top(x_i-x_j).
\]

在真实位姿已知、坐标变换正确的条件下，它对共同刚体变换具有明确的不变性。**从 RGB 估计这些量是否准确，则是另一个学习问题。** 新任务侧不能读对象真值；也不能把图像平面位移直接称为机器人坐标中的控制方向。

我会保留原始空间 tokens 的内容通路，避免把未被少数关系量表达的抓取面、入口形状和上下文提前删掉。Product 的结果尤其不支持继续把“去掉更多场景差别”当成主要原则。

### 4.3 自身经验：学习“什么动作造成了什么效果”

第一版使用一个固定的强共享控制器作为试做起点，在预先规定的初态与预算下收集：

\[
C_g=\{(s_i,a_i,s_i^+)\}.
\]

这里的 \(a_i\) 必须是实际执行的动作。例如按现有重规划周期使用执行过的前 5 步，不能把尚未执行的完整 50 步预测都登记成真实动作—后果标签。

从前后观测估计：

\[
d_i=E_\eta(s_i,s_i^+).
\]

然后学习效果条件的动作分布：

\[
I_\eta(a_i\mid s_i,d_i,C_{\setminus i}).
\]

这是一种 hindsight 监督：动作标签的含义是“它造成了这个实际效果”。

若试做把抽屉碰关了，这个样本可以教“哪些动作在这种配置下导致关闭”；它不应教“开抽屉任务就执行这些动作”。

这里还有两个容易产生假进步的捷径，需要在定义中排除：

- 不能主要依靠未来 proprio 的差分反演动作，然后宣称学会了对象控制。动作条件必须包含任务相关对象、相对关系或接触后果，而不只是手臂自身位移。
- 对象没有运动时，往往有许多不同动作都能产生相同可见结果。因此应学习条件分布与不确定性，不能把确定性均值当作可靠纠正指令。

**source 的动作知识在这一环节作为先验参与。** 在真实自身 RGB、proprio 和语言上运行 source／共享 LoRA，取得动作分布和 action expert hidden；效果条件函数学习这些先验如何随所需效果及实际经验改变。这里不再用一个虚构 teacher state 或固定高斯 probe 代替真实控制情境。

### 4.4 教学与自身经验的对应：查询所需效果，不能只匹配轨迹外观

给定自身试做状态 \(s_i\)，教学读取器产生一个所需效果分布：

\[
d_i^\star=T_\eta(P_g,s_i,C_g).
\]

计算上，可以让自身状态 tokens 查询教学的有序转移 tokens，再输出对象绑定、所需变化、需要暂时保持的关系和不确定性。

它不能只按教学时钟推进。已经建立的条件若在自身执行中丢失，模型需要允许重新处理它；不同阶段有歧义时，也不能简单平均成一个物理上不存在的目标。

随后，效果条件动作函数被查询的是：

\[
I_\eta(a\mid s_i,d_i^\star,C_g),
\]

而非“在教学某一帧附近通常执行什么动作”。

自身经验可用 Transformer 进行条件读取：query 包含自身状态与所需效果，context 保留每次动作的出发状态、真实动作和实际后果。值的解释由真实动作监督学习，不将某个视觉 embedding 直接规定为动作或参数更新。

这一步依然可能学错。注意力、动作似然或目标读出都不授予它强教师资格。它产生的是**有不确定性的控制修订证据**，最终是否采用，由完整 LoRA 的训练效果决定。

### 4.5 完整参数编译：生成对自身状态起作用的函数

编译器接收三类内容：

- 完整教学的过程与目标表示；
- 自身动作—后果经验；
- 在这些自身状态上，教学所需效果与实际效果的差异，以及候选动作分布相对当前控制器的变化。

它通过一次共享参数的前向计算，输出所有 38 targets 的 A/B：

\[
\lambda^\star
=
U_\phi(P_g,C_g,\lambda_b).
\]

我会采用全局联合的参数槽，让不同 target、rank 槽之间交换信息；每个 target 用自己的输出头生成相应维度的 A/B。以下限制全部撤下：

- 教学读取必须使用执行侧同一个 A；
- 写入值必须来自固定 native 差分；
- 所有条件信息必须经过顺序 delta memory；
- 教学层与目标参数层必须一一对应；
- 公共与条件部分必须承担预先规定的语义分工。

可以从强 MT 的因子构造稳定起点：

\[
A_\ell^\star=A_{\ell,b}+\Delta A_{\ell,\phi},
\qquad
B_\ell^\star=B_{\ell,b}+\Delta B_{\ell,\phi}.
\]

最终实际矩阵只有：

\[
\Delta W_\ell=B_\ell^\star A_\ell^\star.
\]

这仍是一套 LoRA；两边因子都可以改变。MT 初始化的理由是提供已知可执行参照，减少重建设计初期的无效行为。它不是突破原理，也不保证优化保持 MT 能力。

**自由 A/B 本身没有新资格。** 完整 P/Q 已经证明，解除这种限制之后，共享学习仍然会失败。本次主要变化是编译器获得了新任务真实动作后果，并被训练为依据这些证据修改控制功能。

### 4.6 最终部署时，谁根据当前状态选择行为？

必须把这点说清：

> **最终评测没有教学读取器、效果选择器、逆模型或轨迹 memory 在旁边帮助控制。它们必须已经通过编译影响固定 LoRA。**

最终只有：

\[
a_t\sim
\pi_{\Theta+\lambda^\star}(a\mid o_t,p_t,L).
\]

在某个 target 中：

\[
y_\ell=W_\ell h_\ell+B_\ell^\star A_\ell^\star h_\ell.
\]

参数固定，\(h_\ell\) 仍随自身图像、proprio、flow 状态和前面各层的计算变化。不同状态下的行为必须由这个真实消费者学会。

因此，“在自身状态重新实例化所需效果”首先是**训练与编译所要建立的函数关系**，不是可以偷偷保留到部署的外部算子。若新模型只让外部效果函数变好，最终 π0.5＋LoRA 没有获得相应行为，这套方法就没有成立。

## 五、训练要怎样让上述体系成立

### 5.1 改变训练事件，而不只改变损失项

新的基本训练单位应是一次完整的适应事件：

1. 取一个 non-held 任务的合法教学；
2. 用固定起点控制器在一组初态真实试做；
3. 隐去这些试做中的 reward、success、目标真值等条件输入；
4. 前向生成最终完整 LoRA；
5. 在没有参与适应的其他 episode／初态上训练和评价它。

首版固定试做控制器，有一个方法上的好处：可以先检验**解释同一批经验并生成修订**，避免同时学习探索策略，并避免把视频改变试做轨迹的作用混入结果。

我暂不把多轮自身重读或多轮试做设为必要结构。旧 self-read 已经有真实参数回读和共同训练；“多理解一遍”没有独立资格。第一轮如果不能把实际经验变成跨初态收益，不能默认增加轮数会解决。

### 5.2 四类监督承担不同职责

| 监督 | 标签来自哪里 | 实际承担信用的参数 |
|---|---|---|
| 对象、几何、状态变化与可见性 | non-held 允许的训练标签；有可靠来源时使用位姿、关节或接触记录 | 教学与自身经验的视觉读取 |
| 效果条件动作监督 | 真实执行动作及实际达到的效果；包括未完成任务的试做 | 经验条件动作函数、对应特征 |
| 独立 episode 的真实 FM | 现有成功示范中的真实 query 动作 | **最终完整 LoRA 消费者**，再回传到编译器、经验解释和教学读取 |
| 独立初态的完整结果信用 | non-held 上生成策略实际执行所得的完整任务结果 | **适应后的策略及参数更新器** |

前两项让中间量有内容，但不能单独构成成功。后两项决定这些内容是否转成实际能力。

新增主风险可以写为：

\[
\begin{aligned}
\mathcal L_{\rm meta}
={}&
\mathbb E\,
\mathcal L_{\rm FM}
\left(
\pi_{\Theta+U_\phi(P_g,C_g,\lambda_b)};
Q_g^{\rm independent}
\right)\\
&-\beta\,
\mathbb E_{\tau\sim\pi_{\Theta+\lambda^\star}}
R_g(\tau)
+\text{效果与动作接口的训练项}.
\end{aligned}
\]

这里的回报只存在于 non-held 训练侧。新任务适应不读取它。

### 5.3 为什么不能只保留原 FM，再把自身经验接进去？

因为“支持输入进入 learner occupancy”不等于“正确控制监督覆盖了这些状态”。

假如自身试做卡在把手附近，而外层仍只在成功示范占据域计算 FM，一个较大的更新器仍可以学会更准确地认任务，继续忽略失败的具体结构。

因此，我建议改变目前将监督学习与独立共享 RL 分开的默认组织：**完整结果信用要训练“看过这些合法经验之后，生成的控制修订是否有效”这个事件。** 保留真实 FM，防止只依靠稀疏回报从头寻找所有动作；同时让实际新初态闭环对那些成功示范没有覆盖的错误承担信用。

这不是声称 actor-critic 会解决 EMBER。旧共享 RL 和新的 state baseline 分析都不支持这种保证。它只是说明：如果要学习如何从一次失败经验修订控制，训练结果不能始终只来自与那次失败无关的成功轨迹。

环境不需要可微。首版试做由固定控制器产生；编译后的新初态执行，可以使用真实策略梯度，经全部生成因子回到更新器。不能把模型预测的“更接近目标”直接当环境成功，也不能通过只优化一个效果预测头绕开这个代价。

### 5.4 已有数据提供什么，新交互增加什么？

已有数据已经提供：

- 同 task 跨 episode 的真实执行监督；
- 多初态、多对象位置和相当多的自身状态；
- 真实动作与图像变化；
- 一些操作过程、关系及功能标签。

这些不应再被说成缺失。

新增交互应当增加的，是：**当前控制器实际失配附近，动作与后果的变化，以及这种经验对后续修订是否有用。**

同一个状态附近若永远只有一种动作，仍很难识别什么替代动作会更好。训练侧可在现有任务中，通过固定初态、不同策略噪声或有界动作变化取得不同实际后果。这些是新的控制约束，不是新增独立 meta-task。

但动作—后果样本数量不能冒充任务多样性；相似轨迹的重复也不能冒充完整功能 Jacobian。尤其在遮挡、接触和近乎零对象运动时，局部逆问题仍可能不可辨识。

### 5.5 如何保持和组合能力？

我不建议用冻结某些 rank、正交化更新或逐阶段累加参数，代替功能保持。

训练应同时覆盖：

- 正在争取的新行为；
- 已成功的接近、抓取和运输行为；
- 阶段之间的接续；
- 后续操作是否破坏前面仍需保持的条件。

保持条件必须有时效。例如，task39 在杯子进入前需要保持入口可用，进入后又需要关门；不能把“以前打开过”变成永久保持目标。

完整成功与真实多阶段动作监督应承担这些取舍。Owner 允许正常能力交换，因此目标不是所有旧成功一条不丢，而是取得更强、更广泛且相对稳定的完整能力。

## 六、以 task23 为例：新方案应当学到什么

task23 是打开上层抽屉并把碗放进去。已有行为记录表明，它不能统一解释成没学会开抽屉：有些控制器能打开，却长时间停在柜体附近；许多行没有移动碗；C 又确实存在一个完整成功反例。task39 则常已拿起杯子，但未进入腔体。这些是不同的控制缺口。[已有逐行行为与机制核查](https://github.com/LinFyM/EMBER/blob/8972a879e566d7acb656195109a0d1bb40d38793/docs/analyses/feature_to_operator_mechanism_20260926.md)

对 task23，新方法不能只学一个 `Open→Pick→Place` 标签序列。它至少需要从教学中保留：

- 抽屉入口怎样变得可用；
- 手怎样离开把手区域；
- 何时开始操作碗；
- 碗相对入口怎样移动；
- 在碗进入前，哪些动作会破坏入口条件。

自身试做可能提供几种不同证据：

| 观察到的实际情况 | 应当被考虑的修订 | 不能由此直接推出的结论 |
|---|---|---|
| 手停在把手附近，碗未动 | 后续对象调用或退出过程需要改变 | 不等于只缺一个阶段编号 |
| 退出后抽屉关回 | 退出方向、接触状态与暂时保持条件需要联合处理 | 不等于任何更小动作都更好 |
| 碗抬起但停在入口错误一侧 | 自身场景下的运输与入口对应需要改变 | 不等于复制教师坐标 |
| 碗到入口附近但不能进入 | 姿态、接近方向或局部接触控制需要改变 | 不等于更准确识别容器就够了 |

假设模型已经准确预测“这个退出动作会关回抽屉”。纯预测更新没有信号。新方法仍应看到：实际效果与教学后续所需条件不一致；经验条件动作函数给出可能的其他效果实现方式；编译器是否将它变成有效控制，则由 non-held 上相似失配之后的独立执行监督学习。

这里没有免费答案。若训练池和自身试做从未提供“离开把手而不破坏入口条件”的可用控制关系，模型不能仅凭一个完整教学视频推导所有接触细节。

task39 的预期也应具体：教学可提供接近姿态、入口关系和先放入再关门的过程；自身经验可揭示当前策略在哪个几何关系上停滞。但若机器人从未接近到能观察有意义接触后果的状态，几条试做未必能提供足够校准。

**这两项共同失败仍是未来大幅超过 MT 的重要能力来源。** 我不会因 MT 也失败而降低它们的价值。只是新路线必须实际增加这些完整能力，不能把 task3/31 的成功交换减少当成全部目标。

## 七、为什么可能超过强 MT，以及为什么仍可能没有视频增量

这条路线的潜在优势必须拆开核算。

### 一部分收益属于通用控制学习

效果条件动作训练、更好的自身状态覆盖、真实结果信用，都可能提高 MT 或语言生成器。

这些不能归给视频。

### 视频特有的候选收益，是减少新任务“所需效果函数”的学习负担

exact language 通常指定最终目标，但未必以机器人容易直接使用的形式给出：

- 操作部件和接近面的视觉绑定；
- 准备姿态；
- 中间对象关系；
- 暂时需要保持的条件；
- 一个成功过程中的操作顺序和几何细节。

视频能够在与自身效果表示相近的视觉空间中提供这些实例。于是有限学习条件下，模型可能不必只从语言—任务映射中推断全部过程。

这不是信息论必要性。充分的语言模型加自身图像，原则上也可能恢复这些信息。尤其在 LIBERO、同机器人和较强 source 条件下，视频的额外价值可能比在跨 embodiment 任务中小。

因此，我推荐的两项关键差值是：

\[
\Delta_{\rm experience}
=
S(V,L,C)-S(V,L,\varnothing),
\]

\[
\Delta_{\rm video}
=
S(V,L,C)-S(L,C).
\]

第一项问自身经验有没有帮助；第二项问视频是否让同样的经验更有用。最终还必须看相对同数据强 MT 的完整能力。

**若 L＋同预算自身试做取得几乎全部收益，我会将结果归为控制适应进步，并降低它作为 EMBER 视频编译主线的优先级。** 不应靠削弱语言、减少语言模型训练或把无试做 MT 作为唯一对照保住视频叙事。

这也是本方案最关键的未知：在当前任务分布中，视频提供的过程实例，是否足以在有限训练下帮助解释自身失败，并转成充分语言参照之外的控制收益。现有材料还没有回答它。

## 八、与最近似旧路线相比，真正改变了什么

| 历史路线 | 已经做过、不能重新宣称的新东西 | 本次需要兑现的真实差别 |
|---|---|---|
| Horizon、SemanticPath、显式语义与效果监督 | 时序、过程、目标或效果标签已经存在 | 用教学要求与新任务自身实际后果共同推断控制修订，而非只把过程表示送给静态生成器 |
| LocalActionGrounded、NativeCorrection、LocalField | 动作反演、真实纠正以及同一写入消费者的监督都出现过 | 新任务自身动作成为合法条件证据；训练适应后的独立执行，而非只预测教学位置的动作或更新场 |
| 完整 P/Q | 自由完整 A/B、共同训练已经存在 | 编译器输入和训练事件改变；自由输出仅解除假设，不承担主要成功解释 |
| GOMQ、SEOD、learner-state 路线 | 成功占据域、真实自身调用和局部功能信用已经存在 | 不要求新任务有纠正专家；用训练侧功能信用学习如何解释无标签自身经验 |
| self-read | 当前生成参数回到教学读取的计算确实做过 | 新信息来自真实行动后果；重复前向本身没有新增资格 |
| Online Reader、特权 1NN、独立专家蒸馏 | 局部动作和在线条件读取已有正反结果 | 不预设已经存在强在线教师；局部效果动作函数的建议必须由最终 LoRA 的真实行为承担信用 |

我专门回查了 LocalField：其真实高维局部场确实接受监督，并由同一 \(Ur\) 与实际 \(X\) 收缩为 LoRA。因此，“监督对象直接进入最终参数”不能作为本次独有理由。[LocalField 实际因子代码](https://github.com/LinFyM/EMBER/blob/50dafb05/src/ember/writer/factor.py)、[真实纠正监督代码](https://github.com/LinFyM/EMBER/blob/50dafb05/src/ember/writer/correction.py)

**如果实施后，实际内容只是新视觉 Transformer、交叉注意力、完整 A/B 和原 FM，而自身动作后果没有形成新的控制约束、独立执行没有训练修订效果，就应视为重演旧问题。**

## 九、我建议的首项工作，以及它能改变什么判断

首项工作应直接检验：

> **同一批无奖励自身经验，能否借助正确教学视频，被编译成比完整语言参照更有效的新初态控制？**

这是一项有界的完整方法投入，不是表示探针。也不应立即建设一个大世界模型或一批昂贵纠正教师。

### 1. 固定一轮试做，暂不学习探索

用共同强共享起点，在固定的两个适应初态上试做；预算、噪声规则和 reset 与成功无关。L/V 两臂读取同一批自身经验。

这样第一项优先检验经验解释和参数修订，不将探索行为的差异混入结论。

新任务阶段只做共享网络的前向计算。没有新任务 loss 优化、SGD、奖励选择或 checkpoint 选择。

### 2. 保留三个强参照

| 方法 | 信息与能力 |
|---|---|
| 同训练资料继续学习的强 MT | 能使用新增 non-held 控制监督；作为完整共享控制参照 |
| **L＋自身经验** | exact language、完整自身试做；与 V 使用相同的适应结构和训练预算 |
| **V＋L＋自身经验** | 再加入正确教学视频；最终同样只输出单套完整 LoRA |

L 不能是被随意删掉输入后的弱消融。它应是独立训练、能够根据语言和自身场景形成目标条件的完整方法。

零经验输出和合法另一视频可以作为同一模型的额外读数，不必再建立另一族架构。首项不使用 Test，也不使用封存的 shuffled/reversed 结果。

### 3. 先做完整行为的方向检验，再谈正式资格

可以先从现有 non-held 池中预先留出一组适应训练分组，覆盖对象选择、接触操作和阶段衔接，在独立初态运行完整任务。

例如，8 个分组、每组 4 个教学条件、每条件 4 个新初态，得到每臂 128 条完整执行；V 再做对应的另一合法视频。这个规模足以看收益是否只集中在少数条件，也比立即启动多轮正式 400 更适合第一笔投入。

**这只是方法方向检验，不能与 161/400、153/400直接排名。** 留出的是本次适应训练分组，也不能称为 source 从未见过这些任务；旧 source 与相关分支的曝光仍须登记。

### 4. 不同结果对应明确取舍

- **V 同时超过 L 和强 MT，并在新初态取得分散于多项任务的完整新增能力：**提高整条路线优先级。随后才有理由按现行 paired400、另一合法视频、相邻点和独立训练重复建立方法资格。
- **L/V 都改善，但二者近似：**支持自身经验适应，削弱视频作为主要增量来源的判断。不要继续通过给视频端加模块维持方向。
- **效果或动作读出变好，最终 LoRA 的新初态完整能力不变：**否定这一版从经验到参数的训练连接。不能登记为模块通过，也不能默认只是再加一个 decoder。
- **只在适应初态有效，换初态即消失：**主要学到局部状态或轨迹适配，核心跨初态假说未兑现。
- **训练侧都没有建立基本控制功能：**当前实现或预算未学成，不能推出原则不可能；但也不自动延长投入。需要新的实质解释才能继续。

### 5. 成本应按真实方法投入登记

旧 Within/Product 两臂正式训练约 **7.35 GPUh**，整批约 **13.67 GPUh**；四个独立教师整批约 **4.92 GPUh**。新方法增加了视觉／效果接口、经验条件动作函数、完整元训练及实际交互，不能沿用这些数字承诺低成本。[配对资源记录](https://github.com/LinFyM/EMBER/blob/8972a879e566d7acb656195109a0d1bb40d38793/docs/analyses/cross_context_pairing_20261008.json)、[教师资源记录](https://github.com/LinFyM/EMBER/blob/8972a879e566d7acb656195109a0d1bb40d38793/docs/analyses/aligned_teacher_recovery_20261008.json)

我会把首批设为**数个工程日、约 40–100 GPUh 的立项上限量级**，而非成功所需算力预测；用首段真实吞吐修正。训练交互另设明确上限，完整评测与适应试做分别计数。达到上限仍只有内部指标改善，就停止自动追加。

正式 paired400 阶段还要按教学条件计算适应成本。不能只给八个 task 做一次适应，却把 400 条不同教学条件的成绩表述成原协议的一次视频编译结果。

## 十、应保留什么、停止什么，以及仍缺哪些事实

我会保留：

- 冻结 source 和原生前缀保护；
- exact language、合法有序 action-hidden 视频；
- 完整 38-target 单套 LoRA 与最终独立执行；
- 真实跨 episode FM；
- 强 MT、逐任务收益损失、合法换视频和完整行为裁决；
- 旧正例作为能力存在与局部可学的证据。

我会停止把以下内容作为默认主线：

- T 的配对、归一化、写入顺序或局部内容修补；
- 以更准确的关系、动作或未来预测作为继续完整训练的充分理由；
- 将自由 A/B 或再次 native 回读当作突破原则；
- 先大规模制造独立教师，再希望共享 Writer 自动继承；
- 仅因新 critic 改变了梯度统计就启动另一轮 RL。

资料缺口也应分清：

| 类别 | 当前缺口 | 对判断的作用 |
|---|---|---|
| **已有但未完整上传** | 部分权重、完整轨迹、逐状态特征与大张量 | 可进一步核实具体调用、接触或失配；不能补出尚未进行的学习结果 |
| **尚未测量** | 视频相对充分语言在同试做条件下的增量；经验是否改变跨初态控制；最终 LoRA 是否保持了有用的效果条件功能 | 是本路线排序的核心未知 |
| **需要新实验** | 当前控制器失配附近的有辨别力动作—后果经验；适应后的独立完整执行；稳定性和重复 | 决定方法是否成立，不能靠上传文件或更长推导代替 |

我目前不建议放宽冻结 source 或前缀保护。完整独立教师的正例、C 的有限组合成功，都说明还不能把这些边界判为主要障碍。

但有一个应保留的条件性例外：如果最终政策的正常自身输入在两个需要不同动作的状态间存在不可消除的混淆，那么固定参数、无额外历史的控制器可能缺少必要信息。届时可以单独讨论增加短自身历史或改变执行接口，说明代价；现在没有足够证据把它当作统一解释。

**我愿意负责推荐的取舍，是把下一笔主要投入用于学习“从合法教学与真实自身后果推断控制修订”，并让最终固定 LoRA 的独立完整行为承担全部成败。**

这个方向值得尝试的理由，是它新增了过去部署阶段没有的自身动作证据，并将适应效果纳入训练；它最可能失败的地方，是教学要求仍不能被可靠重表达为自身所需效果，或这些效果与动作知识无法被共享编译成跨初态函数。

如果同预算语言方法取得全部收益，或者中间功能变好而完整 LoRA 没有变强，我会降低甚至撤下这条视频主线。届时需要改变的是母假说，而不只是下一版网络的名字。
