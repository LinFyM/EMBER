# EMBER 独立科研审阅

**我的主要判断是：EMBER 已经学到真实的视频条件作用，也多次获得完整闭环能力的增益；但项目长期没有把“某个功能在局部存在”与“合法视频能够让共享模型在新任务的自身状态上可靠调用该功能”区分清楚。** 当前停滞最值得优先怀疑的，是两个尚未分离的问题：

1. **现有学习条件允许多种同样能降低训练损失的解，却没有充分识别出希望迁移的任务—控制关系。**
2. **当前 native 编译算子对教学特征怎样作用于机器人自身状态施加了很强的几何约束，而这些约束没有获得足够的跨任务行为证据。**

此外，最近的教师诊断表明，某些困难还发生在更前面：**我们未必已经拥有能在实际失败状态上完成余下任务的控制功能。** 这时，“只差把知识压进 LoRA”本身就是未经证实的前提。

我不认为证据已经足以选定下一套必胜架构。但它足以支持一个实质取舍：**降低继续给 T/C 增加局部解释器、角色头、校准头和对应约束的优先级；把下一笔主要投入用于辨明并学习“在自身实际状态上有完整行为效力的任务适配”。** 若这一方向成立，我倾向采用约束更少的完整 LoRA 编译器，而不再让 fixed-probe native 寻址、共享 A 和 delta memory 默认支配方法。

以下先重建历史，再解释当前机制、主要问题与建议。

## 二、历史告诉了我们什么

### 1．7月到8月中旬：完整 Writer 已经产生能力，随后要解决的是功能稳定性

7月的原始目标是让 Writer 产生可用适配起点，再利用 RL 改善策略。今天的“首次生成、首次闭环就有效”是更强的目标，不能把7月所有选择按今天的合同判为失败。早期 SmolVLA 到 generic π0.5 的转换，同时涉及 foundation 能力、source 身份和学习目标变化，不能视作一个干净的单变量架构实验。[原始概念，`1226236…`](https://github.com/LinFyM/EMBER/blob/1226236beb342d56c7741164e8da1c4eb8d70725/docs/concept.md)；[π0.5 重置记录，`6bb13dee…`](https://github.com/LinFyM/EMBER/blob/6bb13dee8f971bd4ebcc4e39c9119dbf7f5b38fc/findings.md)

此后的 v5.2 已经是一条完整路线：语言和图像内容进入 Core，视频过程进入 Procedure，经层／秩槽和完整因子头生成 LoRA，再由机器人自己的跨 episode FM 监督整个策略。它并不缺“从教学到自身动作”的训练链。旧协议下，普通 FM 的 v5.2 曾到132/400，v6 到143/400；它们是今天仍须解释的正结果。[v5.2 原设计与实现版本](https://github.com/LinFyM/EMBER/blob/529da6bbe290f7393422937aa7cc278cee732107/docs/action_forecast_writer_v5_2_design.md)；[v6 原设计](https://github.com/LinFyM/EMBER/blob/3a6f801d08facb3e855ab24f84e0b53cb8802e88/docs/action_forecast_writer_v6_design.md)

当时的主要不足逐渐变成：不同教学条件、继续训练和采样组织会引起较大成功交换。针对这一点，项目尝试了更多视频、集合表示、共享 Core、原生 probe、LPCP，以及成功占据域上的功能训练。

这些尝试得到的认识应当精确保留：

- 多视频确实降低了一些表示／参数统计量的方差，但没有自动提高完整成功率。
- LPCP 的完整参数变化极小，仍能产生明显成功交换。因此，参数余弦或更新幅度不能替代功能稳定性。
- GOMQ cycle2/3/4 的正确条件原行可复算为 **151、135、131/400**。151 相对匹配的固定查询参照135，是保留122、新增29、损失13，正效应真实。
- 但 GOMQ 这一轮总共只有极少量优化更新，门控开启后上游实际学习更短；不能称其已经充分收敛，也不能把151视作稳定完成的方法。[GOMQ 原实现，`8553b613…`](https://github.com/LinFyM/EMBER/blob/8553b613de7791df50e0f3ef85678fcaca1cac0c/src/ember/writer/model.py)；[GOMQ 正确条件及训练原件](https://github.com/LinFyM/EMBER/tree/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/review_materials/20260907/records/historical_gomq)

**这一阶段合理的结论是：完整视频 Writer 与普通功能监督能够产生实际控制能力，但功能对训练和条件变化的稳定性没有解决。** 它不支持“普通 FM 从未有效”，也不支持“只需提高视频表示一致性”。

这里还有一个后续反复出现的比较问题：相同任务访问次数或接近的查询数，并不等于相同学习过程。旧 matched-exposure 记录中，v5.2 与 v6 对任务完整批次的反应甚至相反，批次组织、优化步数和学习率同时变化。不能从其中单独推出“大批次”“更多 episode”或某种结构一定更好。[匹配曝光记录](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/review_materials/20261007_research_reassessment/history_records/training/pi05_as_writer_v52_v6_recipe_matched_exposure_seed7_20260801/analysis.json)

### 2．8月中下旬：特权功能、native 和 bank，把研究重点转向了局部可实现性

接下来的推理大致是：

> 既然直接训练的 task expert 有更强功能，而 Writer 没有获得它，就先确认输出空间能否实现这些功能，再让自然视频预测合适坐标。

这个分解有价值，尤其揭示了真正的表示限制。例如，早期固定 span 和 scalar signed-output pooling 确实会丢掉行为必要方向；对 Q、action_in 等不同维度的目标采用同一种原生输出池化，并不天然保留成功更新。分组和更灵活的 native 参数化恢复过部分能力。**因此，“参数化只是实现细节”是不成立的。**[8月24日 native-factor 专家意见](https://github.com/LinFyM/EMBER/blob/fcdb6e43706c5fcedf10eaa5d2d459602b263016/docs/expert_review_20260824_native_factor.md)

问题出在后续推论的跨度。

G1 的114/250主要是**特权解析初始化的局部容量结果**，不是合法视频共享 Writer 学出来的结果。G2 的动态读出改善，也有明确适用范围：原实现主要从视频 Program 和查询进度预测阶段、动作或接触等内容，并不读取机器人当前实际 RGB/state；它证明了某些教学过程可读出，不能证明机器人在偏离状态上知道该执行什么。接回 G3 共享编译后，并没有保住此前的完整控制参照。[当时冻结的完整历史账本](https://github.com/LinFyM/EMBER/blob/fcdb6e43706c5fcedf10eaa5d2d459602b263016/docs/research_history.md)；[G2 NaturalProgram 原实现](https://github.com/LinFyM/EMBER/blob/fcdb6e43706c5fcedf10eaa5d2d459602b263016/src/ember/ecp/natural_program.py)

bank 路线进一步假设：问题在当前 bank 的坐标和逆映射，只要找到正确 chart，就能让自然 Program 取得局部可达功能。这里也有真实数学发现：某些逆坐标确实改善指定 primal 的恢复；同时，完整求逆可能消除 bank 的内容特异性，使“正确 bank 恢复得好”不再证明自然教学携带了决定性内容。接回自然条件后，共享获取仍弱。

这段历史中不能抹掉两个边界：

- content 初始化加真实功能训练有过正改善，不能把全部 bank 实验归为完全无效。
- PNBTT 只完成 E1 的自由查询／共享键等局部阶段，E2 的自然 Program 没有执行，不能把未运行部分登记为失败。[bank 专家原文](https://github.com/LinFyM/EMBER/blob/fcdb6e43706c5fcedf10eaa5d2d459602b263016/docs/expert_review_20260826_bank_conditioned_native_factor.md)；[历史路线与完成边界](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/review_materials/20261007_research_reassessment/HISTORY_MAP.md)

**我的判断：这些工作合理地否定了一些过窄输出空间，但之后研究对“局部几何可解”的投入，超过了它对“合法视频共享学习会成功”的预测力。** 通过 G1、读出或 free-query 正控，不能自动提高下一完整方法的可信度。

### 3．9月初：完整 P/Q 与 clone 差距，已经直接暴露了共享获取问题

完整 P/Q 并不是今天才想到的“更充分特征＋完整输出”。

它保留完整 horizon 和多层原生响应，让过程与策略表示反复交互，并输出完整38-target因子。四任务短窗中，解除原限制确实提高了行为成绩。因此，保留更多信息、释放输出空间，在那个条件下有正效应。[完整 P/Q 原实现，`b2bb03ce…`](https://github.com/LinFyM/EMBER/tree/b2bb03ce9ce92c31e26b795ce9d78a156ab1138c/src/ember/ecp/policy_response_writer)

但更关键的对照是：两个弱任务各自训练完整 Writer clone，合计 **14/20**；共享版本只有 **3或4/20**。共享32、64、96、128步的原行是2、3、4、3，**没有出现先学到 clone 能力、再忘掉的过程**。因此，这一例不能用灾难遗忘解释。它指向共享参数化、优化耦合或条件映射获取，但尚未单独定位哪一项。

width256 分支只有训练结果，没有闭环成绩；不能说扩宽已经完整失败。[clone 行为对照](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/review_materials/20260907/records/pq_single_task/pi05_ecp_prw_complete_single_task_20260906/behavior_comparison.json)；[训练对照](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/review_materials/20260907/records/pq_single_task/pi05_ecp_prw_complete_single_task_20260906/training_comparison.json)

随后 Horizon 试图进一步解决时间、对应和视觉核实：完整50槽、局部对应、相对 horizon 差、两端实际视觉读取、历史汇聚和多轮过程更新，都已经进入实现。

它曾达到110/400，之后下降，同时训练侧能力继续增长。删除 Compiler 额外语言查询在两个初始化下有过改善，但续训后依然回落。**这里的失败形态与前面的共享 P/Q 不同：它更像已经获得一部分训练适配，却没有保住跨任务泛化。** 不能把两者统一命名为“同一个共享冲突”。[Horizon 设计](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/designs/horizon_relation_video_writer_design.md)；[9月11日原始评审与结果](https://github.com/LinFyM/EMBER/tree/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/review_materials/20260911)

### 4．9月中旬：显式语义、动作、纠正和 Pullback，逐步尝试把“信息”变成“有效参数变化”

这一阶段的转向有清楚动机：单靠完整 FM，视频过程可能没有学成预期功能，所以直接提供动作、对象、空间关系、语义阶段或纠正方向。

真实纠正 oracle 是重要正例。它从动作误差构造更新，在小面板上确实改善了自身控制；但收益集中，Object 等方向没有普遍改善。它证明“这个条件下的某种纠正有用”，没有证明合法视频能预测它，更没有证明共享训练能保持它。[真实纠正实现，`f39d594f`](https://github.com/LinFyM/EMBER/blob/f39d594f/scripts/diagnose_native_corrective_transfer.py)；[历史纠正与动作监督审计](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/analyses/v52_evidence_audit_20260917.md)

尤其需要纠正一种容易倒写的叙述：**过去并非总是只有孤立辅助头。**

- NativeCorrection 监督的是实际 \(BA\) 更新与纠正矩阵的差异，不能简单归咎于 LoRA 因子 gauge。
- LocalField 已经有完整双向时间上下文、真实 X 寻址，以及同时受局部监督并进入 \(BA\) 的消费者。
- Pullback 则把视频预测的动作余切，经冻结原生 Jacobian 拉回多层参数空间；它确实将动作意义与执行坐标绑定起来。[LocalField 原实现，`50dafb05`](https://github.com/LinFyM/EMBER/blob/50dafb05/src/ember/writer/factor.py)；[Pullback 原实现，`d6defa69…`](https://github.com/LinFyM/EMBER/blob/d6defa69fa851a5d6c5e1092139e5b008f0a09dd/src/ember/writer/correction.py)

Pullback 的限制也具体存在：多个层的更新被共同的动作余切和固定 pullback 关系耦合；后来的共享左右变换并没有把它变成自由完整因子。有限优化下，free-q 未显示出 free-AB 那样的局部空间，长训练也没有形成强完整方法。**所以今天再提出“通过动作把教学和参数联系起来”，必须说明如何改变这项失败预测。**

source 对齐修正则属于必要的工程与数据纠错。它值得做，但不能承担全部科学解释。核对旧、新 v5.2 源码后，关键 temporal 计算几乎相同；与此同时，source、动作索引、查询规则和视频映射改变，旧、新400行只有极少数使用同一教学视频。于是，旧结果未复现不能单独归因于某个 Compiler 结构改变。对齐后的 A 也经历了 held 上升后回落、训练侧继续改善。[source 对齐证据边界](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/review_materials/20261007_research_reassessment/history_records/analysis/source_alignment_20260915/archival_A_B_comparison_boundary.json)

### 5．9月19—23日：教学自身信用是强正例，覆盖重划后的损失也是真问题

这一段有一个不能淡化的因果对照。

实际方案在原跨 episode 主 FM 之外，将教学自身真实动作的信用送回**同一个生成 LoRA**，并更新整个 Writer／Meta 链。它不是只训练 Procedure 辅助头；当时最初偏向 P-only 的建议后来已被修改。

与把对应查询替换为同 task 另一 episode 的匹配对照相比：

| 节点 | 教学自身信用 | 跨 episode 替代对照 |
|---|---:|---:|
| 900 | 149 | 125 |
| 1200 | **174** | **136** |
| 1500 | 165 | 147 |
| 1800 | 160 | 136 |
| 2100 | 158 | 159 |

每列均为该旧协议的400行。1200点的配对结果是保留117、新增57、损失19，净增38，不能归为噪声式“没有任何帮助”；后期优势消失同样不能忽略。174时仍有三个任务为零，改善也明显集中。[9月19日完整学习报告与原行](https://github.com/LinFyM/EMBER/tree/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/review_materials/20260919)

**正确认识是：教学自身信用能够使视频条件更快获得某些有用功能，但并未建立持续、广泛的跨任务适配。**

覆盖重划以后，不能直接拿174与当前 MT153比较。不过，也不能把下降全归因于 held 变难。在共享的五个 held 任务、相同初始化与教学映射的250行上，旧1200与新1800是 **144→92**。训练混合、任务支持、source 等因素仍有耦合，因此这不是“加任务必然有害”的单因果结论；但它足以证明，原来已经取得的一些能力在新学习设定下没有保住。[共享 held 配对原行](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/review_materials/20260921/coverage_retraining/diagnostics/shared_held_old1200_new1800.csv)

后续梯度读回显示，辅助信用并非普遍消失或被统一压没；短窗方向试验又不足以选定完整修复。这里需要区分“信用存在”与“信用会产生希望的跨任务更新”。[9月22日因果诊断](https://github.com/LinFyM/EMBER/tree/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/review_materials/20260922/writer_causal_diagnostics)

### 6．9月24—28日：关系支持、条件速度与对应数据，分别检验了不同假说

这几天的工作不能压缩成“都证明视频无用”。

首先，四臂条件编译比较使用的是训练集合内部留出，**不是当前官方 Validation400，也不是强 MT153的同一面板**。它说明在该条件下，训练充分的语言条件生成器可以很强，视频或额外局部信用没有稳定超越；不能跨面板把数字直接排序。[条件编译诊断合同](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/designs/conditional_compilation_diagnostics_design.md)

关系支持替换试图通过不同对象—目的地边，教会未见组合。结果中个别交互项为正，但完整组合臂没有可靠高于原臂。新增支持任务本身往往已被 source 较好掌握。它削弱了“把关系边补齐，组合能力就自然出现”的具体假说；它没有证明所有扩任务或关系学习无效。[关系支持原设计与结果](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/designs/relational_support_causality_design.md)

条件速度 V/L 则尝试让教学决定动作输出处的条件反馈方向，并与公共策略共同学习。其早期151/147后来变成102/112；这条路线只给 action_out 条件容量，也不能作为所有完整 LoRA 条件学习的否定。后续还有部分状态映射问题，需要按严格可比子集判断。[条件速度设计](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/designs/conditional_velocity_operator_design.md)

P/I 对应实验尤其接近“补跨初始化控制关系”的新建议。它已经使用真实相对参考轨迹构造查询，并比较匹配教学与独立配对；两臂的查询、视频边际与曝光得到控制。早期 P/I 为124/91，后来108/107：**对应关系曾产生真实早期优势，随后没有保持。**

同时，这个实验没有证明“新增对应数据优于原数据”，因为缺少对应的同数据强 MT 臂；新增参考中，实际连接段的占比有限，大量标签仍是 waypoint 和终态重复。匹配参考时钟也不自动等于从自身观测判断何时执行何种控制。[P/I 数据、实现和结果合同](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/designs/demonstration_transfer_learning_design.md)

### 7．9月底到10月初：T 获得有效视频作用，C 实际检验了进一步联合读写

T 的主要变化是把教学寻址与执行读取使用的 A 绑在一起，并通过视频动态构造完整因子更新。它确实取得当前最高161/400。

但 T/U 的相对顺序随训练变化：450为122/143，900为148/132，1080为147/128。绑定算子的收益需要训练条件解释，不能从单个节点推出普遍优势；U 还增加了独立参数，不是纯粹等参数的输入消融。[T/U 原始证据](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/review_materials/20260930_t_architecture/EVIDENCE.md)

9月30日专家提出的关键修正之一，是共同学习动态解释、条件读取和条件写入。**实际 C 已经完成这条核心计算链**：解释器可传递动态内容，S 改变 A，最终 A 重新形成 M 的地址，A 同时得到直接执行与经 M 的间接信用。

## 四、沿实际计算链解释问题

### 1．教学视频并没有直接变成“动作规则”

当前教学侧实际使用双 RGB、exact language、固定 Gaussian action probe，时间取 \(\tau=1\)，不输入 teacher state。原生视觉语言前缀保持冻结，带公共 LoRA 的 action expert 产生：

- 每帧的 \(H_t\)，包含50个动作 horizon槽；
- 每个目标投影自己的实际输入 \(X_{\ell,t}\)。

这里有四个不同轴：视频时间、动作 horizon、flow时间、网络层。它们不能凭模块命名互相替代。尤其：

- \(H_{t+1}-H_t\) 是固定探针下的策略响应变化，不是已知教师动作；
- action_in的 \(X\) 就是固定噪声探针；
- 某些早期投影输入尚未读入图像；
- 38个 \(X_\ell\) 并非38份相同的末端 H。[实际 native 消费者](https://github.com/LinFyM/EMBER/blob/85919994aef11c17b49b7d0e70a2c110158bff61/src/ember/operator_writer/native.py#L125-L203)

这些特征可能包含有用信息，T的结果证明其中确有可用内容。但“native”不自动意味着它们已经是可在机器人自身状态上检索的控制坐标。

### 2．T 的真正要求，是让教学地址在自身状态上调用正确内容

简化一个target的实际计算：

\[
K_t=\operatorname{normalize}(AX_t),
\]

\[
V_t=O\!\left[
\operatorname{GELU}(PK_t+C\bar H_t)
\odot D(\bar H_{t+1}-\bar H_t)
\right],
\]

\[
M_{t+1}=M_t+(V_t-M_tK_t)K_t^\top/50,
\qquad B_V=B_0+M_N.
\]

最终作用于机器人自身层输入 \(h\) 的条件项是 \(M_NAh\)。令

\[
E_t=I-K_tK_t^\top/50,
\]

可精确展开为：

\[
M_NAh
=
\sum_{t=0}^{N-1}
V_t\,
\frac{K_t^\top E_{t+1}\cdots E_{N-1}Ah}{50}.
\]

**这说明，生成了有意义的 Value 还不够。自身状态 \(h\) 必须通过这些系数激活正确内容，并抑制错误内容。** 这些系数是带后续覆盖效应的、有符号且未归一化的关联，不是已经得到语义保证的注意力概率。[T2340 原实现](https://github.com/LinFyM/EMBER/blob/e2afbfd7c997e3f792921600608efa2fa3c1b25a/src/ember/operator_writer/model.py)

两侧共享 A，确实共享了线性坐标。但教学侧是无state、固定probe、\(\tau=1\)、公共LoRA下的输入；执行侧是自身state、变化的flow latent与时间、上游完整LoRA已经改变的hidden。**共享一个矩阵并不等于已经学会这两个域之间的对应。**

同时，不能倒过来说这条对应根本没有监督：完整 FM 的梯度确实可以隐式教它。问题是这种教学是否足以在有限任务上选中可迁移的对应，而不是仅在训练分布上有效的关联。

### 3．C 已经放开一部分限制，仍保留了主要先验

C的动态解释器在完整视频×horizon网格上传递内容，并用S改变输入侧因子：

\[
A_V=A_0+S_V,\qquad B_V=B_0+M_V.
\]

最终 \(A_V\) 重新参与 key/value 与M的形成，没有被detach。它比“只学Value”前进了一步。

但C仍保留：

- 固定probe原生特征作为关键来源；
- S受教学X张成空间约束；
- M的关联与覆盖形式；
- 教学坐标到自身控制状态的对应假设；
- Value经过共享有限宽度输出映射的限制。

这些限制值得怀疑，**尚不足以单独解释全部失败**。近期直接B局部更新的高比例能量可以投影回既定空间，而且投影后仍保留大部分局部行为收益；更早自由完整P/Q也出现共享失败。这些反例阻止我们把根因简化为“输出空间不够”。

同样，静态LoRA并不等于开环控制。自身hidden随观测和state变化，固定参数可以实现反馈；C在task23的一次完整成功就是应保留的行为反例。真正待检验的是：这套静态参数能否在足够宽的自身状态范围内保持正确反馈。

### 4．训练链确实接通了，但接通不保证跨任务更新有利

当前每次取4个任务，每任务28个来自其他episode的查询。query输入包括自身RGB、state和真实动作；完整FM得到76个因子余切，再以同一参数版本重放native与编译过程，把信用传回公共LoRA、解释器和读写模块。[采样源码](https://github.com/LinFyM/EMBER/blob/85919994aef11c17b49b7d0e70a2c110158bff61/src/ember/operator_writer/data.py#L55-L92)；[信用重放](https://github.com/LinFyM/EMBER/blob/85919994aef11c17b49b7d0e70a2c110158bff61/src/ember/operator_writer/credit.py#L57-L89)

因此，“非零梯度”只证明存在学习通道。它没有证明更新会沿着正确任务关系传播。

把共享生成器在条件 \(i\) 下的输出记作 \(\Theta_i\)，其参数Jacobian记作 \(J_i\)。一阶近似下，共享训练对另一条件的参数作用包含：

\[
\Delta \Theta_i
\approx
-\eta\sum_j J_iP J_j^\top g_j,
\]

其中 \(P\) 表示局部优化预条件，\(g_j\) 是任务 \(j\) 的功能梯度。

真正决定共享效果的是：**不同任务通过 \(J_iP J_j^\top\) 被怎样联系起来，以及这种联系在自身实际访态上是否有利。** 网络可以按操作关系联系任务，也可以按场景、对象外观、语言模板联系任务。更多参数并不自动选择前一种。

这是一种机制解释，不是已经测得的梯度冲突结论。本次缺少足以独立计算这些跨任务功能Jacobian的权重和大张量，不能把该式当成已定位的病因。

## 五、为什么包含常量 MT 解，仍会学得更差

“可退化成常量LoRA”是重要参照，但它只给出函数类的包含关系。

首先，常量LoRA仍然通过π0.5读取语言、图像和自身state；它不是常量动作策略。因此，强MT本来就能处理相当多的任务条件。

其次，若函数类包含MT，只能推出：在**相同训练目标、相同分布、全局最优**条件下，较大函数类的最优风险不会更高。它不保证有限训练：

- 沿MT的优化轨迹前进；
- 自动回到常量子集；
- 在held上保持更低风险；
- 将FM风险的改善转化成完整成功率。

在T的 \(M=0\) 附近，只要视频动态特征与当前误差相关，输出映射O就可以得到梯度，优化会离开常量解的轨迹。之后完整损失监督的是公共与条件作用之和：某项功能被条件分支补上，公共项就不再被单独要求完成它。公共LoRA又改变native特征和寻址，所以它与直接MT不是同一个独立学习过程。

这也解释了为什么 **public-only103不能解读为“模型只学到103份公共知识”**。共享Writer里的映射规则本身也是公共知识。公共loss可以改变功能分配，但不是逻辑必需，也没有被现有实验确认为突破条件。fresh Joint提高公共表现却降低完整表现，已经反对“公共项更强就必然完整更强”的简单推断。[公共项独立审阅](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/review_materials/20260930_t_architecture/PUBLIC_BASE_REVIEW.md)

学习曝光也不能忽略：

| 模型节点 | 查询数 |
|---|---:|
| T/C450 | 50,400 |
| C900 | 100,800 |
| MT300 | 172,800 |
| T2340 | 262,080 |

因此，早期T/C弱于MT并不能全部归于参数化。另一方面，成熟T已经有更多查询，仍只有小幅净优势，“再多训一些”又不能保护整条路线。

## 六、现有数据究竟约束了什么，还缺什么

### 1．原FM已经提供跨episode、自身state与反馈动作监督

这是对“缺反馈监督”最重要的修正。

教学来自一个episode，查询来自同task的另一个episode。实际模型必须根据自己的观测和state输出动作，因此数据已经包含：

- 不同初始化；
- 同一目标下的不同执行阶段；
- 自身状态变化对应不同动作；
- 部分组合任务及阶段连接。

同task更多episode有价值，但它主要增加这种任务内部覆盖，并不等于增加独立任务映射。

在一个理想化的训练分布中，若exact language在有限训练任务上唯一标识task，且教学与query在给定task后独立抽样，则：

\[
\mathbb E[Y\mid q,L,V]
=
\mathbb E[Y\mid q,L].
\]

这里 \(q\) 包括自身观测、state和flow输入。这个推导的含义是：**在已见训练任务上，忽略视频的语言策略也可能达到同样好的总体风险。训练目标本身没有唯一识别“新任务应该怎样从视频取得控制知识”。**

它不证明视频无用。视频仍可能帮助有限数据下的视觉落地、操作参数推断与新任务泛化；T的合法视频收益已经说明这种价值不是空想。但这种价值必须通过跨任务学习偏置和数据变化获得，不能仅由“多了一个输入”推出。

### 2．各种监督不能互相替代

| 监督或数据 | 已经约束的内容 | 仍允许的错误关系 |
|---|---|---|
| 同task跨episode FM | 同一条件LoRA处理另一episode的自身观测与动作 | 通过语言／场景识别已见任务，未必学会新任务适配 |
| 教学自身动作信用 | 教学条件与同一生成LoRA的动作功能相联系 | 复原该教学的路径或局部动作，未必适用于另一状态 |
| 语义、角色、关系、动作读出 | 特征中可获得某类标签 | 标签被实际策略调用的条件仍可能错误 |
| 真实纠正／Pullback | 某些状态下有用的功能方向 | 合法视频预测不了，或固定拉回空间不能保留完整控制 |
| P/I参考对应 | 教学和另一初始化轨迹之间的匹配关系 | 时钟／模板对应代替自身状态反馈 |
| learner-state蒸馏 | 教师被询问学生实际访问的观测 | 教师在该物理状态上未必能完成任务 |
| reward／RL | 实际策略收益方向 | 稀疏信用、局部收益和共享泛化仍可能失败 |

尤其，**learner-state监督不是未尝试的新方向**。8月phase aggregation已经从30条真实projected-policy轨迹提取自身状态，重新查询固定task expert，并进行一轮聚合训练。held5的两组结果从44/44到54/47，存在有限正效应。[原始实现，`966353e3…`](https://github.com/LinFyM/EMBER/blob/966353e309def2ba7b3c71f291a471c3a87fd0c2/src/ember/functional_adaptation/phase_decoder_panels.py)

但它匹配的是教师在相同观测、噪声和时间上的flow输出，**没有验证教师从那个真实接收状态继续运行能完成余下任务**。这是后面建议中一个重要区别，而不是把“DAgger”换一个名字。[完整结果](https://github.com/LinFyM/EMBER/blob/ac233fa0e94b40c525d75746ef2d8fdfb4dc0046/docs/evidence/functional_adaptation_20260819/train24_phase_decoder_state_aggregation_held5_20260821.json)；[监督历史复核](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/analyses/flow_supervision_history_20260926.md)

### 3．动作读出更准，为何反而更不迁移

近期动作校准提供了比“辅助头没接好”更强的负证据。

在记录使用的同一匹配索引和17个fit任务上，P相对F：

\[
\Delta R_{\text{teacher}}=-0.014253,\qquad
\Delta R_{\text{query}}=+0.008147.
\]

也就是，对教师当时动作更准，对匹配到的另一episode动作更差。

这直接削弱了“更准的教学动作读出可以直接作为更好的自身控制条件”的投入理由。它并不否定动作监督；它指出必须学习**动作对状态和任务条件的依赖**，而不能默认教师轨迹中的动作修正能搬到query状态。这里的匹配还不是完全相同物理状态，因此结论严格限于该对齐协议。[机制审计 §108、§140](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/analyses/feature_to_operator_mechanism_20260926.md)

### 4．更多episode、更多task、更多控制关系，解决的是不同问题

- **更多同task episode**：改善状态覆盖、降低偶然噪声，帮助同一任务跨布局与阶段。
- **更多独立meta-task**：增加“任务条件如何改变控制”的实例，可能改善未见任务映射。
- **不同初始化下的控制关系**：约束哪些动作应随自身状态改变，哪些任务意图应该保持。
- **真实偏离状态上的成功续行**：检验并教授已有成功轨迹没有覆盖的接触退出、恢复、阶段衔接等功能。

support36→95只从同一C450继续短窗，新加入任务大约各访问3–4次；154/156的结果不能判定扩任务最终无效。与此同时，增加任务名称不保证增加有价值的适配变化：若新增任务大多已由source很好完成，其训练信号可能主要接近“保持共同策略”。[support扩展合同与读回](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/analyses/conditional_support_diversity_evidence_20261002.json)

也不能按终态谓词名单断言完全缺少某种功能。训练中已有组合任务；global32是**开启炉灶后放moka pot**，不是打开微波炉。source中的close-microwave教学也实际涉及移杯；已有任务包含转腕。它们不等于task39的完整插入控制已经被充分教会，但足以否定“相关过程从未出现”的过强解释。

## 七、两个不利个例揭示的是控制适用域和组合问题

### 1．task23：单独开抽屉成功，不保证进入放碗策略的适用状态

task23是“open the top drawer and put the bowl inside”，正式成功谓词是碗在目标区域内，Open并不是额外终局门槛。

T2340是0/50，C900是1/50。回放记录显示，C比T更经常把抽屉打开，但大量轨迹随后不移动碗，或重新把抽屉推回去；有的轨迹仍剩足够时间。这不是统一的“没来得及”。

相关训练确实存在：

- standalone open-top-drawer任务；
- 抽屉已经打开时，把碗放入的任务42。

但前者示范可以在手仍靠近柜体、尚未为下一操作准备好时结束；后者从自己的标准初态开始。**终态谓词相容，不等于前一个策略的实际终止状态属于后一个策略的成功起始域。**

这正是最近接手结果的意义：四套各自在task42原初态成功的条件，加上task23自身条件，使用两种语言，在9个真实post-open状态形成10臂，全部0/9。其中3个状态剩余步数很短，但另外6个有115–240步，仍全部失败。不能把它写成90个独立起点，也不能用时间不足解释全部。[接手原始读回](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/analyses/cross_task_post_open_transfer_20261007.json)；[实际接手消费者，`8d432bb6`](https://github.com/LinFyM/EMBER/blob/8d432bb6/src/ember/pi05_eval/cross_task_transfer.py)

这个结果不证明“放碗技能不存在”，也没有单独隔离视频表示、场景差异或LoRA编译。它证明的是：

> **原初态成功的donor，尚未取得在这些接收状态上作为续行教师的资格。**

同时保留反例：C900有一次正常初态完整成功，另一个post-open面板中完整C也有成功。因此，不能宣判单套静态LoRA无法完成该组合。

### 2．task39：选对和举起杯子，距离完整插入仍有实质控制缺口

task39的近期诊断中，举杯变得很常见，校准模型甚至50/50出现超过阈值的抬升，完整成功仍为零。抬升既不等于可靠抓持，也不等于掌握进入炉腔的姿态和路径。

仓库回放还记录：杯体长时间停在炉腔前方；去掉门碰撞并不能使原动作完成任务。因此，单纯目标选择、门障碍或“再加强抓取”都不足以解释这组失败。[task39诊断及证据汇总](https://github.com/LinFyM/EMBER/blob/f5fbde8534c2abb99da466a8447f752cc25b4d71/docs/analyses/feature_to_operator_mechanism_20260926.md)

这两个例子共同说明：完整方法需要控制“在什么自身状态下继续哪一动作、如何为下一动作准备、如何避免破坏已经取得的进展”。**给Open、角色、抓取或动作读出增加一个更准标签，只有在它改变这些实际控制关系时才构成修复。**

## 八、研究推进中最需要改变的判断习惯

### 1．不要再把六种不同命题互相担保

过去反复出现如下跳跃：

| 命题 | 可以支持它的证据 | 不能由它自动推出 |
|---|---|---|
| 标签／特权功能有用 | oracle或真实纠正改善 | 合法视频能预测 |
| 输出空间局部可达 | free因子、投影、task-local优化成功 | 共享生成器能学会 |
| 视频含有可读信息 | 动作、阶段、关系读出改善 | 该信息能在自身状态正确调用 |
| 共享训练能获取 | seen完整能力增长 | 跨task迁移 |
| 局部控制有效 | 小面板或接手成功 | 正常初态整任务成功 |
| 完整方法更强 | 同协议完整行为对照 | 换split/source后仍成立 |

这些命题都值得检验，但它们不是一条已经各段通过的流水线。

### 2．累计负证据应降低整个假说的优先级

native坐标、bank逆映射、真实层输入、Pullback、LocalField、同算子T、条件C，彼此并不完全相同。但它们共享一个长期假设：**只要把教学特征更紧地绑定到原生执行几何，共享学习就更容易得到可迁移控制。**

这项假设已有局部正证据，也积累了多次完整或共享阶段的弱结果。现在应当降低其默认优先级。若每次失败都只注销版本名、保留母假说不动，累计实验不会改变研究决策。

### 3．局部通过与短窗阴性都被赋予过高决策权

两种相反错误同时存在：

- 原件中有读出、投影、局部32行通过后迅速进入完整训练，而更便宜的跨episode功能核查已经提示风险。
- 也有短窗未学会后转向新结构；后来更长训练又显示原功能可以获取。

解决办法不是统一“多训”或统一“早停”，而是预先说明这个窗口能排除什么。T/U的顺序反转、G2的学习延迟、support新增任务的低访问量，都不允许用短窗对整个家族下结论；成熟T、Horizon和C的行为曲线，又不允许用“还可以继续训”无限保护它们。

### 4．专家建议应按原假说与停止条件审查

8月专家关于先做容量和读出的建议，本身就没有充分保证后续合法共享学习；责任不能全部归给实现。

9月30日专家正确指出，公共知识不等于public-only分数，也提出了实质性的共同读写。但C核心链路已经执行，并遇到专家自己列出的不利结果。此时应更新方法判断，而不只寻找与建议还差的最后一个结构细节。

### 5．强历史参照应保留，但不能跨协议借分

旧143、151、174都说明真实能力曾经存在。它们应约束“原路线完全无效”的叙述，也值得作为机制参照。它们不授权与当前153直接排名。

相反，source对齐、覆盖重划以后，应该优先建立同身份的完整参照，再解释新模块的贡献。大量局部指标、工程接通与分支排除，只有确实改变后续优先级时才构成科研进展。

## 九、我的首选完整方法原则

### 原则：让教学决定一套在自身状态上有行为效力的任务适配，再把它完整编译进LoRA

这里的“有行为效力”具体指：它能在所声称的自身状态范围内完成原任务或余下任务，而不只是复现一个标签、动作片段或专家输出。

**我建议保留：**

- 当前generic π0.5建立的冻结source；
- 原生视觉语言前缀的权重与图像理解；
- exact language＋action-hidden正确视频的部署输入；
- rollout前一次编译完整38-target单套LoRA；
- 生成LoRA在自身执行图上的直接功能信用；
- 同协议强MT和真实完整行为参照。

**我建议撤下默认核心地位：**

- fixed-probe \(X\) 必须是唯一寻址依据；
- 教学与执行必须共享同一A才能迁移；
- 全部条件权重必须经delta memory形成；
- A、B、公共项与条件项必须预先承担某一种知识分工；
- 某个辅助读出改善即可授权完整训练。

### 一个贯通输入到执行的候选实现

| 环节 | 首选原则 |
|---|---|
| 教学输入 | exact language与完整有序正确视频；离线解释可以使用全部前后文 |
| 特征来源 | 读取冻结前缀的视觉内容、patch与语言表示；native action response可保留为补充，不作为唯一信息出口 |
| 过程解释 | 学习任务相关的对象、相对变化和操作关系；不把固定probe的H差直接规定为动作意义 |
| LoRA编译 | 用容量充足、全宽输出的decoder生成完整A/B，允许跨target交互；不先把可编辑自身方向限制在教学X的关联空间 |
| 实际执行 | 仅保留生成的单套LoRA；自身RGB、state与flow hidden决定实时动作，不带教师memory或特权输入 |
| 主监督 | 原跨episode真实动作监督，加上有实际成功续行依据的自身状态—动作数据 |
| 梯度消费者 | 同一生成LoRA的真实策略FM／动作功能输出；额外标签只服务这条链，不能靠独立头通过来宣布方法有效 |

采用自由完整因子，是**减少未经证明限制的选择**，不是已证优越的新机制。完整P/Q已经说明，自由出口也可能共享失败。原生前缀无需因此解冻；若未来发现关键视觉信息在冻结特征中不可获得，应单独提出边界修改，并明确证据与代价。

我也不把先训MT、加入公共loss或某种课程作为必要前提。它们是可选优化策略，不能替代关于视频如何取得新任务映射的证据。

### 真正新增的学习内容应是什么

重点应从“教师当时做了什么”，推进到：

> **保持任务条件，改变接收状态时，控制怎样改变；保持接收状态，在自然合法的任务变化下，控制又怎样改变。**

这里必须使用实际可成立的任务和物理状态关系。不能为了制造漂亮的对照，给同一语言的两个等价成功视频强行贴互斥动作标签；也不能把不同场景硬说成相同状态。

最有价值的新增监督，是从当前策略真实产生的状态重新求解并**实际完成余下任务**的续行。它应与正常成功轨迹一起训练，使模型同时学会一般执行与阶段连接。监督动作仍通过完整LoRA进入自身策略，不转成一个脱离执行的“阶段分类器”。

这与最近似旧方案的区别必须说清：

| 旧方案 | 已经做过 | 新原则必须改变的预测 |
|---|---|---|
| v5.2／完整P/Q | 完整视频到完整因子，真实FM | 自由输出本身仍不够；需要改变任务函数的学习证据 |
| GOMQ／SEOD | 成功专家占据域、真实flow端点、同功能多视频 | 需要覆盖并认证实际接收状态上的完整续行 |
| phase learner-state | 在真实learner观测上重新查询expert | 被查询的expert必须在该状态有行为效力 |
| LocalField／Pullback／T/C | 真实执行坐标、动作信用、共享读写 | 不再先验要求所需函数服从这一教学—执行几何 |
| P/I | 不同初始化的参考对应 | 对应目标须支持自身反馈与完整成功，而非主要依靠参考时钟 |

**“完整续行认证”是辨识工具，不是一套已经获胜的新架构。** 它的作用是防止再次把无效教师目标蒸馏得更好，再误判为编译失败。

### 为什么它可能提高相对强MT的能力

我期待的收益来源是：在没有训练过完整任务映射时，视频提供目标外观、接触方式、相对操作关系、准备姿态及阶段组织的实例；共享学习器将这些实例转为适合自身状态反馈的参数。

相应行为预测很具体：

- 对抽屉组合，改善应包括退出把手接触、重新接近碗、在放入前保持开口可用，而非仅提高Open出现次数。
- 对微波炉任务，改善应包括进入炉腔所需的姿态、路径和后续关闭，而非仅增加举杯。
- 两条合法视频可以采用不同成功路径，但应重复提供大部分新增完整能力，减少无依据的成功交换。

这些是**待检验假说**。新增续行数据完全可能主要让MT变强。没有一种损失写法能保证视频必须产生额外收益：exact language本来就给出了目标，视频的研究价值在于改善未见任务映射的学习与适配，而不是人为制造语言的信息缺陷。

## 十、最小的判别性检验，以及真正应改变的取舍

我不建议立即建设庞大新教师，也不建议先启动又一套完整900步架构比较。下一步应围绕一个non-held任务族，预先固定状态、预算与判断问题。

### 第一步：确认“已有好功能”是否真的存在于接收状态

选少量来自不同初始化的真实接收状态，同时保留成功轨迹状态作正控。先用**现有且source身份正确的MT、T或训练侧专家**实际接手到原任务结束。

所需新增证据是整任务续行成功，不是更低动作误差、正确角色或短期谓词改善。

- 若现有候选普遍失败，就停止“现有知识只差蒸馏”的推断。
- 若某个当前source上的完整38-target LoRA已经能在这些状态成功，局部输出可达性已被直接回答，不再重复做一遍容量oracle。
- 只有当有效教师采用不同控制形式，或需要把多个教师状态域合并时，才补一个有边界的单套LoRA保留检验。

旧专家绑定旧source，不能把adapter直接挂到当前aligned source后继续沿用其教师身份。也不能因为现有候选失败，就自动升级为一个长期“造全能教师”的工程项目。

### 第二步：检验未训练任务映射上的视频增益

只有上述功能证据成立，才做一组有限、完整的学习比较：

1. **同新增数据的强MT；**
2. **容量合理、充分训练的语言条件生成器；**
3. **首选完整视频Writer。**

这三个参照分别回答：收益是否只是共同控制变强、是否只是更大条件生成器的收益、是否确有教学视频的额外迁移。

必须完整留出任务映射，而不仅留出视频或初始化；对被比较模型的公共LoRA、预热和可训练模块都执行同一信息边界。已经学过该任务的旧MT可以充当训练侧诊断工具，但不能被称为该比较的未见任务参照。

判断应同时覆盖：

- 正常初态出发的完整任务；
- 另一条合法教学；
- 原有能力与新增能力的得失交换；
- 预先固定的末段节点，而不是事后挑一个最高点。

小任务族通过只提高该原则的可信度，不等于完整方法成立。之后仍须在锁定协议的完整开发面板上验证；不能再由局部成功自动跳到“各模块均通过”。

### 不同结果必须对应不同取舍

| 结果 | 应作的取舍 |
|---|---|
| 教师在真实接收状态上失败 | 优先承认控制监督尚不具备效力；停止直接蒸馏路线，不继续给Writer定罪 |
| 有效教师存在，单套完整LoRA保留不了 | 审查执行参数化、标签与优化；增加视频语义头优先级低 |
| 单套LoRA成立，合法Writer连跨视频／跨初态都学不到 | 条件编码和编译映射成为主要嫌疑，有理由重建decoder |
| seen改善、完整任务留出仍弱 | 任务归纳与独立meta-task变化仍不足；更多同task恢复episode未必对症 |
| MT、语言生成器、视频Writer共同上涨，视频无额外优势 | 保留控制数据发现，降低它作为EMBER核心视频方法的价值 |
| 视频优势在未见映射、正常初态、合法换视频及完整保持上重复成立 | 才提高完整方法原则的支持，并投入扩展 |
| 只有特权教学表示有效，合法RGB条件无效 | 转向教学信息获取；不再泛泛扩大LoRA出口 |
| 仅举杯、Open或局部接手改善，完整任务未改善 | 明确判为未解决目标，不用代理指标延长路线 |

## 十一、目前仍缺少哪些材料，限制哪些结论

现有材料足以核对主要研究链和大量行为统计，但还不足以确定唯一根因：

- **缺少对应权重和完整中间张量**，无法独立测量教学X与自身hidden在失败状态上的真实重合、跨任务功能Jacobian，以及梯度更新究竟按什么关系传播。
- **部分连续轨迹、接触与关节状态未完整上传**，因此接触退出、抓持、碰撞与姿态的解释，有些只能依赖已有回放记录；不能把EEF距离或物体抬升当作真实接触／抓取。
- **缺少可靠教师在多类接收状态上的成功域记录**，这是“知识已经有了、只差编译”最关键的事实缺口。
- **缺少同新增对应／续行数据下的强MT和充分语言生成器比较**，因此还不能把潜在的新数据收益归给视频。
- **训练随机性与任务层面不确定性尚不足以支持稳定优势**。大量同一开发面板上的节点，不能替代独立重复；但这也不抹掉已有逐行可见的正效应。

---

**最终取舍是：保留完整视频编译的目标，保留真实功能信用和已经产生的正能力；降低当前native关联算子作为默认研究基础的地位。下一步最有价值的证据，是一项有用的任务适配能否在自身接收状态上成立、被同一完整LoRA保留，并通过合法视频在未训练任务映射上取得超过强MT及语言生成器的完整收益。**

数月没有兑现目标，不能归为一个缺失模块。更具体的原因是：研究多次在不同输入、状态域和优化自由度下取得局部正例，随后把它们用于支持更强的共享迁移主张；而后续负结果没有充分改变母假说的优先级。

我推荐的方向仍可能失败。若有效控制监督不存在，应停止把问题定义成编译；若监督有效但视频没有额外迁移，应降低EMBER在当前数据设定下的视频优势预期；若只有放松部署输入或冻结边界才能成功，则应明确讨论目标的代价。**这些结果都应允许改变研究方向，而不能继续通过给同一弱假说更换模块名称来吸收。**
