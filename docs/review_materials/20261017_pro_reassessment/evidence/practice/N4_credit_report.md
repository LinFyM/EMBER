完整16视频条件共37次更新、21次接受，实践按condition计34/64→45/64；这是32条物理共享bootstrap在两视频条件中各计一次。10个condition实践成功提高，11个condition实际改变最终参数。

仅看实际改参数的11个condition：最终97/176，对同面板MT的92/176，R80/G17/L12，描述性净+5；对无视频参照100/176，R82/G15/L18，净−3。此筛选按实际接受记录形成，不能替代完整方法的事前面板，也不能把共享参照视为两份独立证据。

5个未改参数条件（task13两个、task20/video0、task34两个）为37/80，对MT42/80，R33/G4/L9；净−5不能称参数学习损害。尤其task34两个条件均0次接受，最终仍MT300，各6/16对MT9/16。这些损失不能用于证明“视频更新破坏了白杯任务”。无视频14次更新0接受、最终全MT300，其74对MT67同样不是学习收益。

完整方法仍应报告video0=64/128（R55/G9/L12）、video1=70/128（R58/G12/L9）、MT=67/128、无视频=74/128。两视频合计134与重复计入的MT134相同；这一合计不是256个独立参照。少数正向交换与上述同参数差异共存，不足以确认稳定视频增量。

这里的video-only是本次实际16个分支及其父baseline构成的终局动作信用为0，不表示整个condition只受视频监督，也不表示视频与语言、静态视觉等已完成因果区分。保留原根6项有效条件后，完整16项为15次video-only、22次mixed；分别接受12与9次。

分解严格沿现有score_credit线性算子：先把每格与父baseline的R拆成2×success和S_V，对各部分分别用原u/z/p和executed mask求动作信用，再按T_e/4加权并拼接四父点。没有重算分数。纠正14次mixed中6次两项反向；视频/终局范数比例最小0.00205、中位0.00732、最大0.16918，没有一次视频项范数较大。这是原始动作空间结果，不是经过native雅可比后的参数梯度；更不能由此推断Adam最终更新的分量大小。

接受层也没有用视频小涨换实践成功下降：候选成功减少一律拒绝，视频仅作成功数相同的第二判断。纠正18次接受中8次成功增加，10次成功数不变；task1/video0后两次纯视频信用候选均把实践1/4降到0/4，尽管S_V增加，仍被拒绝。相反，task1/video0首次mixed更新中终局信用范数275.80、视频1.99，实践0→1但最终2/16对MT4/16；这已说明单靠“视频项压过terminal”解释净损失不充分。

局部正例与限制必须同时保留：

- task0/video0一次video-only更新，实践3→4，最终13/16对MT12/16、无视频13/16。终局差分为零时视频确实提供了非零native更新，但跨初态优势并未胜过同参数无视频读出。

最窄、可支持的判断是：视频目标解决了部分“稀疏终局无差分”的信用空白，完整参数更新和实践改进已实际发生；把这些局部反馈编译成可靠新初态能力仍未解决。现有原件没有把感知/匹配目标偏差、动作信用的局部性与方差、native/Adam参数作用以及四初态接受的泛化限制分离开；不能据本分解指定唯一根因，也不能以继续调低视频权重作为已经有证据的主要修复。
