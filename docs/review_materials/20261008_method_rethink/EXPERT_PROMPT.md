# EMBER：结合文献启发与新研究边界，重新思考完整方法

请对 [EMBER 仓库](https://github.com/LinFyM/EMBER)进行一次深入、独立的方法研究。
我们已经在这个问题上停滞很久。此次希望你从完整问题出发，认真判断需要怎样的**实质性方法更新**，
才能让机器人从无动作教学视频中获得可迁移的执行能力，稳定、明显超过强多任务行为克隆（MT-BC）。

本次委托不预置新架构、损失、训练课程、适应轮数或实验配方。请不要替主讨论已有候选补论证，
也不要把下面的文献启发和Owner直觉当作必须同时采用的组件。它们是供你独立思考的材料。
你可以认为某个直觉不成立、现有问题问错了，或需要撤换更基础的假设；请具体解释理由。
我们需要你形成自己的完整解决思路，而不止是一份诊断清单、文献拼接或局部修补建议。

## 一、我们究竟想解决什么

已有一个从generic `lerobot/pi05_base`出发、在经过目标任务去重审计的LIBERO数据上训练得到的冻结source policy。
它具有一定操作能力，但不足以解决许多新任务。我们希望给它新任务的exact language和一条或多条正确教学视频，
由Writer产生一套task-conditioned LoRA，使同一source在不同于教学和适应经历的新初态中可靠完成任务。

这里有几项必须区分的信息：

- **教学输入没有动作和state/proprioception。** 当前是LIBERO仿真中的机器人RGB视频，不能因此把视频当作完整的原生policy输入。
  即使视频来自同类机械臂，通过Action Expert获得的hidden或动作计算响应，也不自动等于教师真实动作或正确动作预测。
- **source是已有的控制先验。** 可以利用其原生视觉、语言与动作计算知识；不能把它的输出当作已经可靠的专家真值。
- **训练与新任务适应不同。** 合法训练任务有动作、state等信息，可以用于训练监督；新任务教学侧仍只能提供视频和语言。
  训练侧标签可用，不代表部署时Writer能读到这些标签。
- **最终产物是完整策略参数。** 最终仍固定一套完整38-target LoRA，由source结合机器人自己的图像和proprioception闭环执行。
  目标包括新初态泛化、有益的教学增量和真实绝对性能；不能用视频敏感、重建更准或内部指标改善替代。

过去要求rollout前一次编译、零交互。Owner现在明确开放了下面的新空间；这是本次讨论相对旧评审的重要变化。

## 二、Owner的新思路与已经澄清的边界

### 1. 编译过程中允许无奖励的真实试做

不再要求“看完视频立刻输出一次LoRA，然后只能评估”。允许source本身或安装阶段性LoRA的policy在环境中实际动作，
Writer可以利用试做产生的**自身RGB、proprioception、实际执行动作及可观察后果**，继续理解教学或修订LoRA。
Owner已明确确认：“符合，允许无奖励的真实试做。”

仍不给环境reward/success/terminal、目标物体真值、教师动作或教师state；也不能通过成功触发的停止或挑选轨迹间接读取成功标签。
source先验是已有资源，实际试做的观察则确实是新环境反馈，应诚实登记互动成本，不把新成绩继续称为零交互成绩。
适应结束后固定最终LoRA，在未参与该condition适应的新初态评估，避免把同一次尝试中的改善当成task-level能力获得。

**请独立判断：这种新资源究竟能消除哪些原有不确定性，不能解决什么？没有奖励和正确动作反馈时，
怎样才可能从自身行为后果获得有用的学习依据？它是否值得成为完整方法的一部分，而非仅仅增加环境调用？**

### 2. 生成可以是阶段性的，当前LoRA可以参与后续理解

Owner的直觉是：能否先理解一部分视频，形成阶段性的适配；再利用已经适配的模型理解后面的内容，继续形成能力，
同时尽量不破坏此前学到的功能？希望最终模型在任务进行到不同状态时，都有明确、合适的控制作用。

去噪、SSM只是Owner用于表达“逐步形成和修订”的类比，不是指定实现；也未规定视频必须硬分段、
每段必须对应独立adapter，或已写入参数必须永远冻结。请保留这个动机，认真判断它在数学与学习上意味着什么。
可以支持、修正或否定其具体直觉。尤其需要区分编译过程的阶段、任务执行的阶段、内部记忆变化与实际控制功能保持。

**这两项开放空间不要求一定组合，也不要求保留主讨论最近提出的任何具体候选。**
请先建立自己的问题解释，再决定采用哪种资源、架构与学习方式。

## 三、现有证据不能绕过，但不应束缚你维护旧架构

截至2026-10-08，相关事实及范围如下。请沿原件核对，不把下面的摘要当成已确认的因果解释。

1. **视频并非完全无效，但没有形成稳定、明显的总体突破。** 当前协议下原T最高161/400，强MT为153/400；
   T的相邻较晚点为147、154、160、154、159。selected T的correct / 同task另一视频 / public-only / cross-suite-wrong为
   161 / 150 / 103 / 65。条件有真实功能作用，也有损伤与换视频交换；这些数字不单独证明已学会可迁移的操作知识。
2. **很多直观方向已经不止做过smoke。** 历史包含阶段表示、native读取、功能蒸馏、真实纠正、动作/效果监督、
   关系支持、教学自身功能信用、公共/条件参数分工、条件A/B、直接视频控制和共享RL。它们有局部正例，也有完整负例。
   不能用“元学习”“阶段化”“真实功能损失”或“让模型自己理解视频”等名称把旧经验清零。
3. **让中间LoRA参与重新读取视频，已经真正训练过。** self-read使用中间适配后的模型重新读取同一教学，
   最终功能梯度贯通两次共享计算；36任务fresh450的单终点116/400，低于同龄单遍Context126和T122。
   这个结果约束纯计算上的多遍自读；当时中间LoRA没有进入环境，没有自身动作后果输入，也未建立中间功能保持的证据。
   不能说新的交互空间已经试过，也不能仅凭多了轮次就预言会突破。
4. **“先有强教师、再把能力编译进去”尚缺可靠前提。** 直接视频控制及若干特权教师没有形成广泛可靠的优势。
   最新四困难训练任务的专用教师从初态有12/16成功，在T访态接手为9/16，仍有任务零恢复及能力损伤；
   它们不够资格被当作普适纠正oracle。这个局部结果也不等于所有教师或功能编译方法已被否定。
5. **最近的局部修正没有解决完整问题。** 同T、同曝光的跨情境配对检验，Within两合法视频臂147/148，
   Product为152/151，未建立超过原T和强MT的总体修复。状态回报预测及完整Writer梯度分析有有限变化，
   但后者没有参数更新或新闭环成绩，不能被当作学习改善或actor-critic已失败的证据。

早期不同协议也有真实较高点和有益干预，不能只保留最近失败的数字；不同split/source/学习预算的分数不能直接排榜。
需要继承的是“当时为何认为会有效—实际改变了什么—结果约束了什么”，而不是守住某个版本或重复所有历史实验。

## 四、综述带来的启发：请审查其原理与适用条件

Owner提供了一篇《EMBER相关文献综述》。其中值得重新思考的内容归纳如下；这是研究线索，不是给你指定的方案。
即使没有随附PDF，也可通过下面的一手入口理解这些线索。综述中的概括请自行核实，不能直接当作事实。

- **教学过程怎样对应机器人自身的控制需要。**
  [HOST](https://arxiv.org/html/2607.20033v4)和[XSkill](https://arxiv.org/html/2307.09955v2)
  提示我们思考教学进程、机器人当前观测、技能或未来目标之间的联系。
  它们的执行方式、监督条件和持续读取教学的能力与EMBER不同；不能直接把阶段定位正确等同于控制已学会。
  请判断真正值得借鉴的学习原理是什么，现有EMBER是否已经部分具备，缺失的又是什么。
- **把上下文编译为参数需要怎样的功能学习条件。**
  [Doc-to-LoRA](https://proceedings.mlr.press/v306/charakorn26a.html)
  展示了上下文到LoRA的功能学习，但有能够读取上下文的基础模型教师及大量独立上下文。
  EMBER已有同task跨episode的真实功能监督，不能只用“增加多query蒸馏”作为新答案。
  请区分参数编译的可表示性、可学习性与知识本身是否已能被正确获取。
- **适应过程本身能否被学出来。**
  [WAM-TTT](https://arxiv.org/html/2607.06988v2)
  提供了从无动作视频形成可用于控制的适应状态这一视角，但元训练可更新其基础模型，适应结果的执行消费者也与标准LoRA不同。
  主配置内层更新为一步，不能将其概括为“多轮迭代已证明更好”；部分记忆更新与既有delta-rule存在实质近邻。
  请找出其有效性的学习条件和真正可迁移的原理，不要只换成fast weights或元学习的名称。
- **模型究竟是在学习任务映射，还是学习如何利用新示范。**
  [ICRT](https://arxiv.org/html/2408.15980v2)和[Zero-WAM](https://arxiv.org/html/2608.26103v2)
  提醒我们审视训练分布和学习压力。更多同task episode不等于更多独立的适应关系；
  但当前不能默认扩数据，也不能通过删弱exact language、制造不公平歧义来强迫视频显得有用。
- **示范与自身尝试能否共同支持新任务适应。**
  补充相关工作[Watch, Try, Learn](https://arxiv.org/html/1906.03352)：它研究示范加试做，但试做含奖励反馈。
  这与新开放的研究空间有关，却没有替EMBER解决无奖励条件下的更新依据，也没有验证最终固定LoRA的出口。

请不要受限于这些论文。可以引用其它真正相关的一手工作，但应解释它解决的具体问题、依赖条件与EMBER的差异。
外部阳性不能替代对我们现有正反证据的解释，文献数量也不能替代方法判断。

## 五、希望你彻底想清楚的核心问题

请连贯回答，而不必机械逐项写成问答。

**主要困难究竟在哪里，为什么值得作大的方法更新？**
请分析当前学习组织方式是否存在基础性限制：视频能提供的知识、source的可调用先验、训练时能获得的正确性信息，
与最后要求的一套可迁移控制参数是否真正接上。哪些是信息不足，哪些是表示、信用、优化或任务泛化问题？
避免用“FM不等于闭环”“共享生成更难”“尚未学会反馈控制”重述现象；也不要预设只能有一个根因。

**Owner的新空间会怎样改变这个判断？**
真实试做究竟提供哪些原来没有的证据，什么时候仍然无法判断正确方向？
让LoRA参与后续理解，怎样可能产生新的有效计算，而不是重复自我确认？
逐步适应如何与不同初态、长任务组合和原有能力保持相容？请明确哪些直觉值得采用、哪些应修正或放弃。

**怎样形成一套可学、可迁移、最终能执行的完整方法？**
请从信息与学习原理推导你主张的方法，说明实际输入和hidden的来源、特征如何被编码/选择/汇聚/调制，
如何形成完整LoRA、怎样作用于机器人自己的执行hidden和动作。
再说明训练期有什么标签、各项损失约束什么、梯度到底教会哪个模块，以及新任务阶段没有这些标签时如何工作。
尤其不能把自身预测当正确动作、把自监督一致性当任务成功，或把有非零梯度当成已经建立可迁移学习依据。

**为什么它应当比最近似的旧完整方法更好？**
请比较实际特征、算子、标签、梯度消费者、学习条件和部署作用，指出真正改变的失败预测。
保留旧正结果及其适用条件；不能因某个短窗负例否定整类方法，也不能靠“从未试过这个组合”论证投入。
请解释预期改善哪些实际控制行为，为什么这种改善有希望扩大到总体能力，而不只是在内部量或少数局部任务上变好。

**怎样防止再走一遍补丁循环或换架构循环？**
请给出明确的优先取舍、最重要的未知，以及能改变完整方法判断的最小证据。
如果结果不符合预期，应降低哪个核心假设的支持度、停止什么投入？
不要给无优先级的大矩阵，也不要让无限局部探针或纸面推导推迟完整方法的检验。

## 六、仍然保留的资源与科学边界

- 使用当前已拥有并经审计的数据规模；不默认增加外部教学视频、独立meta任务或大型预训练数据。
  自身试做是新开放的经验来源，须另计成本，不能变成引入带特权标签的held数据的途径。
- source基础权重冻结，原生图文prefix尽可能保持冻结。Writer具体结构、总参数量、memory、rank、层对应、
  公共/条件分工、读取方式和训练方法均可重新判断，不要求维护当前T/C，也不要求匹配MT的参数预算。
- 训练任务的动作、state、特权监督和reward可以按合法训练合同使用；validation/test的监督信息不得产生训练梯度。
  新任务适应可用上述无奖励自身经历，不能使用教师隐藏标签或环境成功信号。
- 最终一套完整LoRA覆盖全部38个执行目标；不挑视频、不融合checkpoint、不部署并行expert或第二套adapter。
  K=1或多视频及适应成本应如实说明；多视频须保留各自时序，不能靠挑选有利演示冒充泛化。
- 完整能力仍以严格配对、新初态、single-checkpoint的闭环结果判断；保留任务/suite覆盖、能力得失、稳定性与换视频证据。
  试做成本应与结果一起报告，不拿有交互和零交互作隐含等成本比较。
- Test及封存的shuffled/reversed结果不用于本次方法选择。请不要从历史文档中恢复已停止的运行或旧授权。

如果你认为某项边界本身使目标不现实，可以提出需要改变的最小前提、理由和代价；请明确这是建议改变约束，
而不是把尚未授权的条件悄悄放进方案。也不必为了形式上的“改动大”而增加复杂度。
