## Owner 最终决定与解释

以下根据同一讨论中的 Owner 原话和随后明确的接口解释整理；是方法裁决，不是新实验结果。

1. **直接只取末层完整 H。** Owner：“干脆就只取最后输出的horizon，不要保留十八层结构了，就靠最后的compiler生成对应的lora”。
   解释已对齐为实际送入 `action_out_proj` 的最后 50 个 hidden tokens；不读取动作投影后的 50×7/32 数值来替代，
   不先收集 18 层再融合。输入层身份与输出 target 无须一一对应。
2. **逐对核实在窗口聚合之前。** 先形成当前/前序帧软对应，以对应关系发起两端视觉读取，随后才汇总经核实的帧对消息。
   原生 Z 来自同一次冻结图文 prefix，不另建视觉 backbone。采用每轮一次关系紧接一次核实，重复四组。
3. **过去窗口。** Owner：“直接就改成窗口向前……解释成前序帧如何变化成当前帧”。
   已明确为 `max(0,t−4) ≤ u < t` 的过去四个采样位置，不是未来四帧；时间特征使用真实原始帧索引。
4. **区分 H 序列、邻帧 u 序列、完整视频 t 序列。** Owner 强调软对应不够，horizon 的有序变化必须参与图片动态理解。
   最终采用帧对关系形成后的一层完整 H self-attention＋FFN；50 个 query 保留。
   经视觉核实的 `M[t,u,h]` 按历史起点 u 从早到晚用短 GRU 组织；它们是以 t 为共同终点的重叠证据，不是相接动作片段。
5. **局部与长程交替。** 四组独立参数；每组完整 U 上的局部核实后临时 H-read，再做一层长程组织；前三组逐 H 条件化回写，
   最后一组 P 直接进 compiler。不永久丢弃 H 后再复制成 50 份，不保留无用途的第四次回写。
6. **长程最终采用过去单向。** 专家原文推荐双向，主 agent 曾解释其利弊；Owner 最后选择“我觉得还是单程就够了”，
   结合上下文解释为单向，并明确回复采用 `P_t = Temporal(E_0,…,E_t)`。四组都施加 past+self mask，
   回写只作用于同一 t；每组的 U_t 只依赖原视频前缀。**H-query 仍允许完整 H 双向 attention**，两种时间轴不可混同。
   单向/双向长程问题已收口，不因原文或旧概念文档重新恢复双向。
7. **FM 的地位。** Owner 澄清未要求监督与 RL 必须同一步混合，同时表示“如果你觉得可行的话，也可以试试”。
   FM 是训练 action queries 上的 flow-matching 监督；首版选择 FM 辅助 Writer RL、同版本单次联合更新。
   这是可实施训练选择，不是 Owner 要求永远固定两项系数，也不等于 Writer/Meta 联合训练必然要求 loss 联合。
8. **交接。** Owner 于 2026-09-08 要求“后续交给一个新session去推进……把新session启动前的所有工作都做好，然后给我一个启动prompt”。
   本轮完成方法登记、证据、状态和交接准备；实现与训练评测由新 session 承接。本轮不启动科研作业，不创建新 session，
   不向专家发送消息。
   Owner随后进一步要求启动prompt强调：先全面阅读仓库、完整忠实实现最终架构、正式实验并据结果迭代至达标、
   新session设置覆盖全程的goal并遵守约束，遇到难点不能表面解决。未要求token预算。

9. **历史教训、基线与科学自主权。** Owner进一步要求不能重犯反复出现的架构/性能问题；若source与SFT都比不过或只堪堪超过，
   不应继续当成小修小补可以解决的问题。整体架构思想保持，但实际推进中允许有证据的具体方法调整，给予接班者充分自由度。
   当前设计§1.1和长期要求已明确基线、可比性、严重non-pass的判断与自主修订边界；原专家文稿本身不因此改写。
