核心候选可以保留，但需要收紧两处：**辅助读出不能保留上一版那条容易退化为状态动作模型的乘性输出；蒸馏也不能默认是“视频能力传递器”。**它们分别应承担更明确的职责：前者为教学内容建立直接、执行状态条件化的功能信用；后者在这种信用确实产生有用预测之后，帮助完整 LoRA 实现该函数。

另外，你对 J2 的提醒是正确的。它已经让跨 episode 的真实功能损失共同训练 Program 与共享 primal 映射。新方案不能再把“联合功能训练”本身列作创新。下面先解释三段连接，最后用核验过的 J2 实现限定哪些差异是真实的。

# 一、视频表示为什么更可能学到操作变化：必须先处理退化解的竞争

## 1. 上一版的乘性读出确实存在一个过于容易的退化解

上一版写成：

$$
\tilde u(x,V)=u_0(x)+W_o\bigl[W_q q(x)\odot W_r r(x,V)\bigr].
$$

若视频读出变成常量 \(r(x,V)\approx c\)，则

$$
\tilde u(x,V)\approx
u_0(x)+W_o\operatorname{diag}(W_rc)W_q q(x).
$$

新增部分就成了一个主要依赖执行状态的动作修正器。常量视频只是激活它的“开关”。它完全可能降低 FM，却没有学到教学视频中的操作信息。

这不仅是理论上的可能。当前 C 的动作诊断已经显示：相对 source 的共同 FM 改善约为 \(0.040365\)，正确视频相对 static/shuffle 的平均差异却只有约 \(0.000414/0.000410\)。这些不是梯度贡献比例，但说明**共同策略修正拥有很强的可学习信号，过程特异性只是其中很小、未可靠兑现的部分**。给辅助头增加一条强状态旁路，很可能先放大前者。

因此，我建议撤掉这个乘性出口。

## 2. 收紧后的辅助头：执行状态只负责选择，新增动作内容来自时间变化

保留完整共享表示 \(E_{t,i}\)：\(t\) 是视频时间，\(i\) 是准确任务语言的 token 位置。Compiler 可以读取它的完整语义和过程内容。

但辅助头的动作修正读出，使用**逐语义位置的时间中心化 Value**：

$$
c_{t,i}=F_v(E_{t,i}),\qquad
v_{t,i}=c_{t,i}-\sum_u\pi_u c_{u,i},
$$

其中 \(\pi_u\) 是固定、归一的有效时间权重。所有时间 token 仍保留；这里不是把原始视频或完整 H 平均压缩。

执行 query 只进入选择权重：

$$
\alpha_{x,t\mid i}
=
\operatorname{softmax}_t
\bigl(Q(q_x)^\top K(E_{t,i})+\text{routing terms}\bigr),
$$

$$
r_x=\sum_i\beta_{x,i}\sum_t\alpha_{x,t\mid i}v_{t,i},
\qquad
\tilde u_x=u_{0,x}+W_o r_x.
$$

这里 \(W_o\) 是共享、无偏置的动作读出；不再在它后面拼接 \(q_x\)，也不加入 query-only MLP 或乘性状态旁路。每个 action-horizon query 分别读取，最后只监督官方有效动作维度。

**这个参数化能保证的是：若每个语义位置的 Value 在时间上都是常量，辅助动作修正就是零。**执行 query 不能通过与这个常量相乘，偷偷获得一个新的状态动作网络。

但我不会把这个保证扩大为“辅助头必然学习正确动态”，原因有三层。

第一，**时间变化不必来自真实操作变化**。当前 C 对重复首帧仍产生显著的中心化 P4，已经直接证明这一点；后来的无变化参照也证明，消除该性质不自动带来行为修复。

因此，新表示应把视频时间位置放在 Q/K 路由中，而不是直接写进 Value；局部首帧处理也不能人为制造一个与其他时间不同的内容 token。对于逐时间、逐 token 交替处理的图，只要相同画面产生相同内容、时间只影响权重，那么对相同 Value 的归一加权不会凭空制造内容差异。**这是可要求的实现性质，不是已获得的实验结果。**

第二，模型仍可能学到跨视频共有的“接近—移动—释放”模板，甚至从普遍的机械运动中构造一组动态原型，再由 query 选择它们。这比常量乘性旁路难一些，但仍然可能主要依赖执行观测。

第三，时间中心化会舍弃一些有用的静态或均值修正。因此，这个限制只施加于**辅助动作增量**，不施加于完整 Compiler 输入，不要求静态视频生成的整个 LoRA 必须归零。完整 LoRA 的真实 FM 仍负责学习合法的整体任务能力。

换言之，我不是要用结构强迫机器人“只有看到运动才会动”，而是让辅助分支更专注于当前缺失的过程信用。其代价是：辅助头不再是一个追求最高绝对动作拟合能力的自由模型。

## 3. 时间×任务 token 轴保留的，是“变化属于谁”，而不仅是更多位置

以“把橙汁盒放进篮子”为例，视频需要同时表达：

* 哪个物体是橙汁盒，哪个是干扰瓶；
* 橙汁盒与夹爪的关系是否改变；
* 橙汁盒与篮子的关系是否改变；
* 上述变化以什么顺序发生。

若先把所有任务语义混成一个每帧向量，再做时间处理，模型需要在同一有限向量中自行维持这些对应关系。保留 \(E_{t,i}\)，则让与“橙汁”“篮子”“放进”相关的语义位置，在各个时间点保留自己的视觉证据与关系变化，之后再通过同一时刻的语言轴交互组合它们。

这与历史实现的差别不是“以前没有 token”：

* v5.2 的语义 Core 保留语言轴，但其有序 Procedure 是另一条每帧表示；
* v6 曾有 \(D_f[L,d]\) 的逐 token 视觉变化，随后由一个 Action probe query 读成每帧一个向量；
* 当前 Horizon 的 `contextual_language()` 和 H-read 最终仍将有序主干组织为每帧一个过程向量；C 的逐 token 语义分支则对帧集合不敏感。

本候选改变的是：**语义位置不在进入长程过程处理前就被消去，并且执行 query 可以分别对这些位置进行时间读取。**

不过，token 位置不是物体身份标签。一个物体名可能跨多个 subword，同一个词也可能需要上下文消歧。权重必须跨位置共享、按内容工作，不能把“第3个 token”固定解释为目标物体。视觉对应、对象关系、接触状态和跨初始化不变性，仍然都要学习。

因此，这一部分的性质应分为：

| 层次    | 可以主张什么                                                         |
| ----- | -------------------------------------------------------------- |
| 结构保证  | 在规定的压缩点之前保留完整 H；在有序表示中保留时间与任务 token 两个轴；不把执行 query 注入 Value 出口 |
| 归纳偏置  | 同一语言内容跨帧形成可重复查询的位置；先组织局部有向变化，再组织长程关系；辅助动作读出偏向时间变化              |
| 待学习能力 | 正确识别对象、跨帧跟踪其关系、区分关键操作与无关运动，并映射到新初始化中的控制需求                      |

不能用第一行替第三行背书。

## 4. 比现有通路更容易的地方，是信用被赋予的“对象”不同

用一个简化单头读出来看：

$$
r_x=\sum_t\alpha_{x,t}v_t.
$$

当输出层已经开始学习时，attention score 的梯度具有：

$$
\frac{\partial\mathcal L_R}{\partial s_{x,t}}
=
\alpha_{x,t}
\left[
W_o^\top(\tilde u_x-y_x)
\right]^\top(v_t-r_x).
$$

省略了语义位置权重，但核心含义明确：**在这个具体执行状态下，某段教学内容是否有助于修正当前动作误差，直接影响对它的选择。**

例如，机器人尚未抓到橙汁盒时，“盒子与夹爪建立关系”的内容可能有价值；已经拿起盒子时，“盒子进入篮子”的内容可能更有价值。不同执行 query 对同一视频形成不同的内容信用，而不必先让 Compiler 和 native D 学会如何把这些需求全部编码进一套参数，视频编码器才能获得相应信号。

这里必须纠正一种容易误用的说法：**现有按条件汇总 A/B cotangent 并没有数学上丢失逐 query 的梯度信息。**当前 `supervised.py` 的链式重放是真实梯度路径，不能把精确链式法则说成错误的信息聚合。

新路径的优势假说在于：其参数化让“哪个执行状态需要哪段教学内容”首先成为一个直接的选择与动作读出问题；旧路径则必须通过参数生成和完整 policy 的复合 Jacobian 来建立这种对应。**改变的是优化几何与需要同时协调的映射，不是凭空增加监督信息。**

这仍有一个根本边界：若在实际分布上

$$
\mathbb E[y\mid x,V]=\mathbb E[y\mid x],
$$

那么同一平方误差目标的总体最优解不需要视频。当前准确语言与任务划分确实可能提供很强的任务标识。我们的理由只能是：在有限数据、跨任务迁移与有限优化下，视频关系表示可能提供更可复用的控制归纳方式；不能声称损失已识别出唯一的视频依赖解。

# 二、辅助控制为什么可能进入固定 LoRA：它是受约束的函数实现，不是复制检索器

## 1. 实际挂载点确实能够产生状态条件化控制，但自由度有限

固定快照中的 `configs/pi05_lora_v1.json` 明确规定：18层 Action Expert 的 `q_proj/v_proj`，加 `action_in_proj/action_out_proj`，共38个目标，rank16、alpha16。它们不是未指定位置的抽象参数。

| 挂载位置                             | 可改变的功能                         | 不能据此宣称的能力                              |
| -------------------------------- | ------------------------------ | -------------------------------------- |
| Action Expert `q_proj`，1024→2048 | 改变动作 token 根据自身当前激活读取原生上下文的方式  | 不能直接读取已经移除的教学 token，也不能凭空恢复冻结视觉表征丢失的区分 |
| Action Expert `v_proj`，1024→256  | 改变 Action Expert 侧内容在注意力计算中的传递 | 不等于重新训练了冻结图像 prefix 的 Value 编码         |
| `action_in_proj`，32→1024         | 改变噪声动作进入动作网络的表示                | 不是将教师动作或教师状态写进执行输入                     |
| `action_out_proj`，1024→32        | 改变动作隐状态到 flow 输出的读出            | 不能单独承担任意复杂的对象选择与阶段判断                   |

执行 query 的状态来源也很具体：`pi05_processing.py` 将机器人自己的8维状态做 source-only normalization、离散化，并写入 `Task: …, State: …; Action:` 的原生 prompt；图像则来自执行观测。教学读取没有这些 teacher state 输入。

对某一层而言：

$$
\delta q_\ell(x,V)
=
B_{\ell}^{q}(V)A_{\ell}^{q}(V)h_\ell(x).
$$

虽然 \(A,B\) 在 rollout 前固定，\(h_\ell(x)\) 随执行图像、状态、噪声动作与 flow time 改变。因此，同一份 LoRA 可以在不同自身状态下产生不同修正。

例如，视频可以使生成参数倾向于：在目标尚未抓起时加强目标对象相关读取，在已抓起时加强目标容器关系相关读取。它并不需要显式保存一个教师时间指针；这些条件由机器人当前原生激活触发。

但“可以有状态依赖”不等于“可以实现辅助头的一切状态依赖”。辅助头保有 \(T\times L\) 个教学内容位置，能逐 query 重新检索；LoRA 必须将其压缩进固定低秩修改。这是实质性的函数类差距。

**多层 rank16 也不等于整个行为只有16种模式**，因为它作用于多层非线性网络；反过来，也不能用这一点推定任意教学检索函数都可表示。

此外，若需要区分的两个阶段在全部合法执行输入中不可辨认，固定 LoRA不能凭参数产生缺失的在线记忆。使用相同执行 query 的辅助头也不能神奇地解决这种观测混淆。

## 2. 蒸馏额外提供的，不是新标签，而是一个学到的函数目标

设真实FM目标为 \(y\)，完整LoRA预测为 \(S\)，辅助预测为 \(T\)。对于固定、停止梯度的 \(T\)：

$$
\|S-y\|^2+\lambda\|S-T\|^2
$$

等价于

$$
(1+\lambda)
\left\|
S-\frac{y+\lambda T}{1+\lambda}
\right\|^2+\text{与 }S\text{ 无关的项}.
$$

因此，**在同一动作 query 上，蒸馏就是把原始目标与辅助预测混合。**不能把它描述成天然增加了视频因果监督。

为避免蒸馏渐增同时偷偷放大编译路径的总梯度尺度，我更倾向于使用归一的形式：

$$
\mathcal L_{\rm compiled}
=
(1-\rho)\|S-y\|^2
+\rho\|S-\operatorname{sg}(T)\|^2,
\qquad 0\leq\rho<1.
$$

它的潜在收益来自：辅助头可能更容易在多个合法 query 上学到一个较平滑、结构一致的动作函数。学生不只追逐当前随机动作样本及 flow noise 下的误差，也被引导去实现这份已组织好的控制函数。

但它何时有帮助，取决于辅助预测的误差结构。写成：

$$
y=m+\epsilon,\qquad
T=m+b+\eta,
$$

其中 \(m\) 是条件期望目标，\(b\) 是辅助偏差，则混合目标为

$$
m+\rho b+(1-\rho)\epsilon+\rho\eta.
$$

若辅助预测减少了无关方差，而偏差较小，可能有益。若它记住了同一批噪声、与样本误差高度相关，则降方差作用很弱；若它学会错误对象或错误操作偏好，蒸馏会把偏差传给学生。

几个边界应当明确：

**辅助预测等于真实目标时，蒸馏是冗余的；辅助预测主要是共同策略修正时，它提供的也主要是共同修正；辅助头在同一批训练点上拟合得更好，不能证明它在新噪声、新状态或闭环中更可靠。**

真实FM保留了外部动作锚点，但不会自动抵消错误教师。两项损失仍可能在一个有偏的折中点收敛。

## 3. 为什么它可能传递视频行为，为什么又不能保证传递视频差分

辅助目标必须保留到每个合法执行 query 的完整动作函数输出，而不是只蒸馏一个任务平均损失、一个 Program summary 或一种参数 cosine。这样，在“接近目标”和“运输到容器”等不同状态上，学生会接收到不同的功能要求。

如果教师在固定执行状态下，确实因正确教学内容而给出更好的修正，那么这个修正会进入 \(T(x,V)\)，继而进入学生的目标。完整LoRA必须通过自身状态依赖的激活实现它。

不过，普通输出蒸馏只约束训练条件上的函数值，**并不直接约束对视频的导数或对未训练干预的响应**。学生完全可能用语言标识记住这些函数值，而没有继承教师的实际视频读取机制。

这就是为什么“辅助头强、学生动作误差更低”仍然不足以证明视频机制传递。尤其不能人为要求同任务正确视频之间出现大输出差异：它们可能表达等价操作，理想行为本来就应该接近。

我不会为解决这个识别问题，立即引入 wrong-video 退化训练。历史 J3 已经提供了明确警告：counterfactual gap 增大，而 correct 的功能 recovery 未超过 J2，结果主要不是正确能力提升。

## 4. 共享表示、stop-gradient和真实FM，各自只解决一部分问题

**共享 \(E\)** 的好处，是辅助功能梯度直接改善 Compiler 将要读取的表示，避免训练出一套与部署编译无关的漂亮辅助特征。但共享也带来负迁移：有利于在线检索的表示，不一定最容易被固定参数实现。

**目标端 stop-gradient** 防止蒸馏损失通过修改教师来降低自身误差。可是，如果学生和教师共享编码器，仅停止教师输出的梯度还不够：蒸馏仍可以经学生分支修改 \(E\)，从而在下一步改变教师目标。

因此，我建议进一步收紧梯度路由：

$$
\begin{aligned}
\mathcal L_C&=\|S(C(E_\phi(V)))-y\|^2,\\
\mathcal L_R&=\|T_\eta(E_\phi(V),q_0(x))-y\|^2,\\
\mathcal L_D&=
\left\|
S(C(\operatorname{sg}E_\phi(V)))
-\operatorname{sg}T_\eta(E_\phi(V),q_0(x))
\right\|^2.
\end{aligned}
$$

也就是说：

| 损失                         | 更新视频编码器及Action Meta | 更新辅助读出 | 更新Compiler/native D |
| -------------------------- | ------------------: | -----: | ------------------: |
| 真实LoRA FM，\(\mathcal L_C\) |                   是 |      否 |                   是 |
| 辅助真实FM，\(\mathcal L_R\)    |                   是 |      是 |                   否 |
| 蒸馏，\(\mathcal L_D\)        |                   否 |      否 |                   是 |

这不是冻结 Program：编码器仍持续接受两条真实动作监督。只是蒸馏不再直接推动共享表示追逐它自己产生的目标。

执行 query \(q_0(x)\) 也应取自**未安装当前生成LoRA的冻结source**，不让辅助查询坐标随学生适配一起漂移。这样可以少引入一种互相追逐，但不会消除所有共同适应。

# 三、从初始化开始怎样学起来：用橙汁任务走完整条链

以下是预期学习过程，不是对已有模型内部行为的实测描述。

## 1. 一次条件调用的数据流

教学视频中，机器人接近橙汁盒、抓起它、运向篮子、放下；旁边有一个干扰瓶。

视频编码器读取准确语言、真实逐帧 patch 与完整H响应，形成 \(E_{t,i}\)。同一个 \(E\) 用于两个地方：

一方面，Compiler一次生成38-target完整LoRA，这份LoRA对同任务另一episode的整组执行query保持不变。

另一方面，辅助头分别使用那些执行query的冻结source特征，查询 \(E\)。某个query中夹爪尚未接近目标，另一个query中已经拿起目标，第三个query接近篮子。辅助头可以为三者选择不同教学内容。

真实动作只作为这些独立执行query的监督目标；它不进入视频编码器，也不进入Compiler。执行query不能反向成为LoRA生成的条件，否则就改变了“一次编译”的问题。

## 2. 第一步：两个出口先学习，而不是所有模块立即获得有效过程梯度

当前 `native_factor.py` 的实际初始化是：

$$
D_A=0,\quad D_B=0,\quad A=A_0,\quad B=0.
$$

`a_code/b_code` 是非零初始化的映射，\(A_0\) 是合法identity模板。

因此在最初一次真实FM反传中：

* \(D_B\) 可以获得梯度，因为改变B会改变 \(BA_0\)；
* A侧梯度为零，因为B仍为零；
* 经 \(D_B\) 传回codes、Compiler和视频编码器的这条梯度，起点也为零。

辅助头若采用 \(W_o=0\) 维持 source 起点，也有同类启动现象：

$$
\nabla_{W_o}\mathcal L_R
\propto(\tilde u-y)r^\top;
$$

但此时传回attention和视频表示的梯度为零。

**所以辅助头并没有免除所有零初始化等待，也不能用“它第一步就全面学视频”来论证优势。**

它的初始读取必须满足一个重要条件：\(r\) 不能也被初始化成零。若同时使用时间中心化、严格均匀attention和零输出层，那么

$$
r=\sum_t\pi_t(c_t-\bar c)=0,
$$

导致输出层也没有启动梯度；上游又被零输出层挡住，整条辅助分支会陷入停滞。

因此，Q/K和内容投影必须保留非零、非饱和的初始读取，真实变化视频应产生非零读出；不能把所有入口门和出口一起置零。非零初始读取只是启动条件，不是已经正确对齐橙汁和篮子。

## 3. 随后几步：直接动作信用开始塑造“哪些变化值得被读”

在 \(W_o\) 获得非零更新后，辅助误差开始进入视频Value和attention。

假设source在一个query中倾向于接近干扰瓶，而正确动作要求接近橙汁盒。若与橙汁相关的某些教学变化能预测这个修正，输出读出首先对这些特征建立动作方向；随后attention梯度提高该执行状态下对相应内容的选择。

在另一个已经抓起橙汁的query中，同样的接近修正不再合适，运输关系对应的内容会获得不同信用。这个跨执行状态的差异，才有机会使表示从“视频中有一个橙汁盒”走向“目标与夹爪、目标与篮子的关系怎样推进”。

同时，native D的 \(D_B\) 已经开始非零，真实LoRA FM逐步传回Compiler和编码器；A侧也开始参与学习。它向共享表示施加另一种要求：这些教学关系不能只适合被辅助attention读取，还应能被Compiler组织为对实际policy有效的因子。

两条真实监督可能互相帮助，也可能冲突。共享表示不自动产生一致目标。

## 4. 为什么这比增加一条同样困难的长链更有希望

关键差别不只是模块数。

辅助出口最后直接作用在真实动作函数坐标上。它不需要先发现一组有效LoRA方向、学会完整policy对这些方向的响应，再让视频表示理解这种间接含义。给定冻结source query与一个已有可区分性的 \(E\)，其首要问题是内容选择和低维动作读出。

原编译路径则必须协调：

$$
E\rightarrow c_{j,r}\rightarrow A/B
\rightarrow\text{多层policy响应}\rightarrow u.
$$

特别在identity附近，学生可利用的局部更新方向受到 \(A_0\)、当前D和policy Jacobian共同影响。辅助头为编码器提供一条**不必等待这些参数坐标已经学好**的功能约束。

但这条辅助路径仍要学习视觉对应与跨episode映射。若source query本身不能区分关键状态，或者 \(E\) 的有用信息很难被当前attention访问，它也会失败。其失败不能直接证明视频表示没有信息。

相反，新模块确实增加了目标漂移和计算成本。为了让收益大于新增的共同适应负担，我保留以下限制：冻结执行query坐标；辅助出口小且无query旁路；编码器与Compiler从一开始共同训练；蒸馏不更新共享编码器；不增加长期独立预训练、固定Program、再学第二映射的阶段链。

## 5. 预热和蒸馏渐增应当怎样解释

“读出预热”只意味着：在同一条联合训练中，先令蒸馏权重 \(\rho=0\)，保留

$$
\mathcal L_C+\mu\mathcal L_R.
$$

不是让辅助头先独立学到很强，再突然交给学生追赶；也不是在预热期间停止Compiler和D学习。

之后蒸馏可以渐增，但**不能仅因为辅助平均FM下降就自动增强**。如果辅助头首先学到的仍是共同策略修正，其预测可能进一步奖励学生的共同、静态解；真实FM并不能保证阻止这种强化。

这里没有一个仅从总loss计算出来、就能识别“有益视频动态”的可靠自动开关。应把蒸馏的地位降到准确的位置：

> 在辅助预测对独立合法query确实更可靠、且其教学内容贡献已经有支持时，蒸馏帮助实现这种控制函数；若只有共同拟合改善，蒸馏最多是常规训练正则，不能作为视频机制进展，也不应主导学生。

这不是要求新增一串实验，而是限制训练配方的解释与启用条件。当前尚未实现新辅助头，证据不能替我们指定一个必然合适的预热长度或蒸馏上限。

# 四、J2 对上述方案的真正约束

我核对了 J2 的原科学实现 `1d775a445486d84a9743e363360ca7a2863cac46`。

在 `src/ember/ecp/joint_program_primal/train_step.py` 中，`generated_rank16()` 会重新计算 Program，经 `compiler.forward_compact()` 生成残差，再由 `compose_rank12_plus_rank4()` 形成完整rank16。`functional_loss_and_backward()` 对生成LoRA计算真实功能梯度，随后调用 `writer_chain_rule_surrogate(...).backward()`。这的确是通过真实动作功能共同训练，不是冻结Program后的单独映射训练。

`runtime.py` 的 `JointWriterState` 明确注册了 `language_reader`、`scene_reader`、`process_fusion`、`aligner`和`primal_scorer`。正式合同则冻结source、Native Stage0、current-bank operator、carrier、scale、temporal decoder与Action Meta；Program从G2模型权重起步，primal scorer和optimizer fresh。

冻结历史§54记录，J2 step110的 train/held-video **功能recovery**约为0.1708/0.1646，不是闭环成功率；主要Gate未通过。Program/primal近同条件表示、共有更新和任务梯度几何给出了共享学习问题的线索，但这些记录不足以唯一证明某一种捷径是根因。后来的§56还指出，task-local正控有teacher-consensus初始化，首步已获得最终收益的一部分，所以其成功不能证明同函数类从随机方向也容易发现解。

据此，新方案与J2的实质区别是：

| 方面              | J2                                               | 当前保留候选                              |
| --------------- | ------------------------------------------------ | ----------------------------------- |
| 视频表示得到的主要真实动作信用 | 必须经过Program→primal→native operator→完整LoRA→policy | 保留完整LoRA路径，同时增加执行query直接读取视频的动作信用   |
| 执行query参与位置     | 在生成LoRA之后的功能损失端                                  | 还进入训练期视频读取，但绝不进入Compiler            |
| 视频信息组织          | 已有Program及其owner/event结构                         | 保留时间×任务token直至执行条件化读取               |
| 输出实现            | 固定carrier12＋受native operator约束的rank4残差           | 直接生成全部38-target完整A/B，保留当前独立native D |
| 观察侧共同学习         | Native Stage0和Action Meta冻结                      | 允许当前Action Meta与视频表示持续接受真实功能梯度      |
| 新增蒸馏            | 无上述训练读出教师                                        | 条件性帮助Compiler/D实现读出函数，不替代真实FM       |

这里最重要的区别是第一、二行，而不是“我们也做联合训练”。

其他差异也有代价：取消固定bank实现并不保证更易学，完整native D仍可能学共同修正；Action Meta解冻也增加表示漂移。它们不能分别被宣布为绕过J2失败的充分条件。

**J2否定的是：在当时表示、参数化、初始化和预算下，真实功能联合训练本身已经足够。它没有否定所有联合训练，也没有替新辅助读出证明任何能力。**

# 五、现在应保留、修改和悬置的结论

**保留的核心**是：时间×任务token的共享视频表示；训练期用冻结source的真实执行query读取它；完整LoRA从第一步就接受真实FM；部署仍只保留一次生成的38-target标准LoRA，不保留辅助头、视频检索或额外运行时状态。

**需要收紧的设计**是：删除辅助出口的query乘性旁路；将其Value读出偏向逐语义位置的真实时间变化；避免“中心化＋均匀读取＋零出口”的死初始化；蒸馏只更新Compiler/D而不直接改共享编码器；蒸馏权重不因平均FM下降而无条件增强，也不以制造错误条件退化来取得资格。

**仍缺证据的假设**有三项。第一，保留语义轴和直接执行query信用，是否真的更容易学到正确操作内容，而非共有动态模板。第二，辅助头学到的有用函数，是否落在当前完整LoRA能够可靠学习实现的范围内。第三，两条真实功能监督能否共同形成稳定表示，而不是以新的方式共同漂移。

因此，必须撤回上一轮两个过强的诊断推断：辅助头失败，可能是信息不足、读取函数类不足或优化失败；辅助头强而LoRA弱，可能是编译表示、参数化、优化、训练状态覆盖或实际容量不足。**两种现象都不能直接裁决“表示无信息”或“rank16不够”。**

我继续支持这个候选的理由，是它提出了一条比“联合训练会自行协调”更具体的学习路径：**先让同一份教学表示在具体执行状态下获得可解释的动作信用，同时由真实LoRA FM持续限制其可编译性，再谨慎利用动作函数蒸馏帮助参数实现。**这条路径有理由降低原方法的一部分协调难度；它没有保证视频一定胜过静态语义，也没有消除固定参数编译与在线检索之间的差距。其科学价值恰恰取决于这两个尚未被证明的环节能否成立。
