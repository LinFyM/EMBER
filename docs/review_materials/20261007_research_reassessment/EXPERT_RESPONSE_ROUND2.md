# EMBER 第二轮审阅：下一步应改变学习关系，而不是继续寻找一个更像“控制”的中间表示

**我需要修正上一轮的推荐。“更自由的完整 A/B 输出＋经过成功续行认证的自身状态监督”，目前不足以成为 EMBER 的首选完整方法。**前者解除部分表达限制，后者提高动作标签的可信度；但它们都没有解决最关键的问题：为什么一个共享学习器能够从合法教学中推断出未见任务需要的适配，而且这项能力应当超过同数据、同监督下的强 MT 和充分的语言生成器。

新增证据也要求修正另一种解释：**现有策略并非主要缺少“对自身状态发生作用”的能力。**A64 的改变量大部分随 query 改变；修正消费者后的读回确认了实际自身调用；C 确实改变了抽屉接触和开启行为。问题更具体：这些作用没有稳定形成跨任务可复用、在不同接收状态下合适、同时保住已有能力的条件控制。

我目前最可信的判断是：

> **EMBER 已经学会了一些“教学条件如何调制现有控制”的映射，但现有训练关系没有充分约束这些映射应当怎样跨任务延伸；特征和参数化又给这种延伸加入了未经证实的偏置。与此同时，优化所奖励的局部改善，并不充分约束完整行为中的获得与保持。**

这里面有不同层次的问题，不能压成一个“表示不对齐”或“泛化不足”。

**我愿意优先推荐的完整候选，是用真实跨情境的功能监督，学习把教学解释为可复用的任务关系，再一次编译成完整 LoRA。**它的新增原则在训练关系，不在某种 memory、A/B 分工或 decoder 名称。但现有证据只足以支持一次有界、带充分强参照的完整学习检验，尚不足以支持把它登记为下一条长期建设的主线。

如果这次比较显示：相同资料和监督只让 MT 或语言生成器变强，视频没有额外的完整增量，我建议实质降低当前任务条件下视频 LoRA 编译的主线优先级，而不是继续换一个条件算子。

以下判断固定于仓库提交 [`f8a3dc1f112fe4cfe17de82a24feb55c2227351f`](https://github.com/LinFyM/EMBER/commit/f8a3dc1f112fe4cfe17de82a24feb55c2227351f)。我复核了补充原件、相关实际消费者和会影响方法选择的历史实现。下面区分记录事实、基于记录的重算、数学推导和待检验假说；不使用 Test 或 shuffled/reversed 封存结果。

## 一、首先，真正需要解释的是“获得、损失和集中”，不只是 161 与 153

### 1. T 已经获得真实能力，但获得与损失几乎抵消

在当前配对面板上：

| 比较 | 分数变化 | 保留 R | 新增 G | 损失 L |
|---|---:|---:|---:|---:|
| 强 MT → T correct | 153 → 161 | 117 | 44 | 36 |
| T public-only → correct | 103 → 161 | 79 | 82 | 24 |
| T public-only → 同 task 另一视频 | 103 → 150 | 77 | 73 | 26 |
| C450 → C900，seen | 91 → 115/144 | 87 | 28 | 4 |
| C450 → C900，held | 137 → 140/400 | 107 | 33 | 30 |

这些逐行结果支持两个同时成立的判断：

- 视频条件和继续学习确实产生了新能力；
- 新能力没有被稳定汇合成更强的完整策略。

T 相对 MT 是 **44 条获得、36 条损失，80 条成功身份发生变化，净增只有 8 条**。这与“几乎没有任何视频能力”不同，也与“已经突破强 MT”不同。C 的 seen/held 分化则更明确：继续学习主要巩固了训练任务，在 held 上仍是大量交换、很少净增。[逐行结果与汇总](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/review_materials/20261007_research_reassessment/outcome_summary.json)

### 2. 视频增益的任务集中度，比总分更约束解释

T correct 相对 public-only 的净增是 58 条，其中 **54 条来自 task3 和 task11**。两条合法视频共同新增的 64 条中，**53 条也在这两个任务**。

相对 MT，T 的主要净收益同样来自：

- task3：41 → 45；
- task11：36 → 45。

与此同时，task16 是 10 → 5，task26 的 public-only 甚至高于完整 T。换成另一条合法视频，部分成功会交换，整体降到 150。[原始 episode outcomes](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/review_materials/20261007_research_reassessment/episode_outcomes.csv)

因此，现在的证据更接近：

> 教学在部分对象选择、目标绑定和已有搬运控制上提供了可调用的增量；这项增量对任务和条件的依赖仍然较强，其他条件下也会干扰原有控制。

它还不支持“已经学到广泛可迁移的操作规则，只差最后一点闭环优化”。

同样重要的是，**task23 和 task39 在 T 与 MT 上都是零**。它们解释共同的能力上限，却不能直接解释 T 为什么只比 MT 净高 8 条。相对差额主要发生在其他任务的获得和损失中。

所以，下一步如果只投入抽屉、微波炉的纠正教师，可能在解决一个真实问题，却没有直接解决“视频为什么没有稳定超过强 MT”这个首要问题。

### 3. 相邻节点和旧高点应怎样进入判断

T 后续相邻点仍在 147、154、160、154、159 一带，不能把 161 单独当成稳定水平。相邻点也不是独立训练重复。

早期 v5.2/v6、GOMQ、同视频辅助的高点则应保留其证据地位：它们证明某些视频条件和功能监督在相应协议下确实有效。它们同时保留后续回落、条件限制和协议差异，不能被串成一条与当前 153/400 直接比较的统一学习曲线。[历史路线与原件入口](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/review_materials/20261007_research_reassessment/HISTORY_MAP.md)

**对后续方法最有价值的事实是：局部可用的增量已经存在；尚未建立的是怎样让这种增量可迁移、可保持。**

## 二、新证据推翻了哪些过强解释，又把问题推进到了哪里

### 1. A64：应撤回“主要只是共同输出偏移”的解释

A64 的首五步、有效 query 等权分解中，共同项占改变量能量约 **14.14%**，其余主要随 query 变化。这明确削弱“改变基本不随自身输入变化”的判断。

但进一步分解同样不利于另一种乐观解释：

- A 的首五步平均净改善，约 **96.6% 来自 task32 的两个教学条件**；
- 首五步 all7 改善中，约 **83.4% 来自 gripper 通道**；
- full50 的 motion6 风险反而上升；
- J 的部分离线误差更低，也没有形成更强闭环。

这些是对导出分解的重算，不是新的模型实验。[A64 完整逐条件分解](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/review_materials/20261007_research_reassessment/followup_evidence/mechanism/a64_query_function_decomposition.json)

其数学意义很清楚。设对 query \(q\) 的预测改变量为

\[
\delta_q=c+z_q,\qquad \mathbb E_q z_q=0,
\]

父模型误差为 \(r_q\)，则平方风险变化为

\[
\Delta R
=
2\langle \mathbb E r,c\rangle+\|c\|^2
+
2\mathbb E\langle r_q,z_q\rangle
+
\mathbb E\|z_q\|^2.
\]

共同项与变化项都可能有益或有害。**变化项大，不等于变化方向符合物理控制需求。**

而且这里的 query 同时改变 RGB、state、Gaussian 和 flow time。它没有单独测量

\[
\frac{\partial u}{\partial \text{物体相对位置}}
\]

之类的反馈规律。可以确认“函数会随实际 query 改变”；还不能确认“这种变化是跨任务正确的空间反馈”。

### 2. 角色、自身调用和内容居中：正确读取已经不能作为下一步的主要资格证明

修正消费者后的结果确认了实际调用；全部操作单元分解也显示，换位时 key 投影相关项在局部 margin 变化中较大。但这不是完整动作的因果分解，更不是“key 是唯一根因”。

更有决定性的反例是：G 的换位条件可以做到八个案例中都以 butter 为主导对象，原闭环仍为 **0/8**。局部 R 的作用、实体密度、实际 attention mass 之间也不是单调对应关系。[修正消费者后的自身调用](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/review_materials/20261007_research_reassessment/followup_evidence/mechanism/role_self_call_corrected_consumer.json)；[全部操作单元分解](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/review_materials/20261007_research_reassessment/followup_evidence/mechanism/role_swap_all_unit_effects.json)

内容居中实验进一步收紧了判断：

- 完整行为从 **22/55 → 21/55**，保留 16、新增 5、损失 6；
- 首五步 all7 MSE 下降约 **15.3%**；
- 其中 **93.78% 的改善来自 gripper**；
- full50 的 x、y、z 通道均变差；
- 原布局两臂仍为 0/8。

而且这次不是“换了内容，冻结旧出口”的简单失配实验：相关头和映射确实接受了联合学习。[内容居中完整读回](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/review_materials/20261007_research_reassessment/followup_evidence/mechanism/role_centered_content.json)

因此，现在再提出一个更好的区域选择器、角色槽或空间归一化模块，必须说明它怎样改变**真实动作风险中的跨任务约束**。单独证明选得更准、读出更好或平均误差更低，已经不足以改变主线排序。

### 3. 抽屉与微波炉揭示了不同的控制缺口

抽屉中，C 的改变不是虚假的：

- T 曾满足 top Open 的有 9/50；
- C 可解释的原过程里有 23/49；
- C 更经常接触、推动可动 top drawer，而不是长时间顶住固定柜体。

但 T 的 9 条 Open 中有 8 条没有碗体至少 1cm 位移；C 的 23 条中有 20 条如此。这 20 条 C 轨迹首次 Open 后的剩余时间中位数约为 **234.5/300 步**，不能统一解释为“开得太晚，没时间搬碗”。

唯一 C38 原成功应保留，但其逐过程回放未完全匹配，不能拿新回放的接触和关节过程解释原成功。[抽屉逐行与有效性检查](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/review_materials/20261007_research_reassessment/followup_evidence/task23_drawer/verification.json)；[逐行记录](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/review_materials/20261007_research_reassessment/followup_evidence/task23_drawer/per_row.json)

微波炉则不是同一种“根本没操作目标物”的失败。T/C 的全部原轨迹都把杯子明显抬起，但接近炉腔和进入深度不足。去掉门碰撞后固定原命令重放，仍全部没有 In，多数距离更差，也保留变近的反例。

这项干预检验的是

\[
x_{t+1}=F_{\text{collision setting}}(x_t,u_t^{\text{recorded}}),
\]

不是策略在改动物理条件下重新观测、调整动作的闭环。因此它削弱“只要移除门这个机械障碍就能完成”，没有排除全部碰撞相关的控制问题。[微波炉读回合同及全量配对](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/review_materials/20261007_research_reassessment/followup_evidence/task39_door/readback.json)

### 4. 九个接收状态上的十臂全零，否定的是“这些 donor 已经是可用教师”

最新 90 条是真正的独立闭环续行，十臂均 0/9。六个还剩 115–240 步的起点也全部失败，不能主要归因于预算耗尽。

其中 13 条出现了至少 3cm 的抬碗，但都发生在第一次退出 Open 之后；自身 M23 配 L42 也能产生抬升。两张既有 RGB sheet 与这个过程一致：局部动作切换发生了，保持开口、接近、搬运和入内没有组成成功续行。[90 条结果与首计划作用](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/review_materials/20261007_research_reassessment/followup_evidence/post_open_transfer/summary.json)

首计划中换语言的七通道 MSE 差异整体大于换参数，但我不会据此宣称“语言完全主导空间控制”：七通道混合量可能受 gripper 显著影响，需要原通道数组才能分开。

这些证据共同支持：

> “某任务从其正常初态成功”没有赋予该条件“能从另一个任务的当前状态成功续行”的资格。

它们没有证明接收状态不可救，也没有证明所有技能组合不可能。

## 三、我怎样排序竞争原因

我不认为现在能唯一定位根因。比较合理的是以下排序：

| 原因假说 | 当前支持 | 重要反证或限制 | 与其他解释不同的预测 |
|---|---|---|---|
| **跨任务条件使用方式尚未被充分约束** | 训练内功能增加、held 大量交换；收益集中；同 task 多视频仍不能稳定保持 | T、旧 v5.2/v6 等已经学成部分合法视频增量；不能说完全没有迁移 | 直接跨情境功能约束应改善合法视频的一致增量；若充分 L 同样好，视频主张不成立 |
| **优化获得的改善与完整行为中的保持不一致** | A64/居中改善集中于少数条件和 gripper；C held 得失抵消；历史共享更新伤及其他条件 | 没有完整跨任务功能 Jacobian，不能统一归因“梯度冲突” | 更低内部误差可能继续不提高成功；只解决编码仍可能继续交换能力 |
| **控制适用域和阶段连接不足** | NN、donor 接手失败；抽屉已打开却不能接续；微波炉已抬杯却不能进入 | 真实纠正和 task clone 有局部正效应；不是状态普遍不可救 | 合格的接收状态监督可能同时改善 MT、L、V，因此未必产生视频专属收益 |
| **当前 native/因子结构限制了有用适配** | T/C 有明确子空间和地址约束；teacher/query forward 不同 | 完整 P/Q、其他自由出口已有共享失败；局部解限不等于完整收益 | 解限可能改善获取，但若跨任务学习关系不变，仍可能复现“seen 好、held 不稳” |
| **当前任务下视频相对充分语言条件控制的增量本来就有限** | exact language 通常给出目标，自身 RGB 给出场景；充分匹配 L 对照尚缺 | 合法视频真实产生新能力，不能判定视频无用 | 同数据、同成熟程度下 L 追平 V；此时应降低视频专属路线优先级 |

我把第一项排在方法设计的前面，不是因为已经测到了某个“错误语义坐标”，而是因为它指出了**原学习问题中的一个真实自由度**。第四项可以影响这个问题，但不能独自解决它。

## 四、数学与实际算子怎样解释这些现象

### 1. MT 可表示，为什么实际仍会更弱？

如果生成函数包含常量解，

\[
G_\theta(V,L)\equiv W_{\rm MT},
\]

那么在相同训练分布和相同目标下，生成函数类的最优训练风险不会高于这个特定 MT 解的风险。

这只是一条**函数类包含关系**。它不保证：

- 有限优化能到达该解；
- 到达的低 FM 风险解具有更高闭环成功率；
- 在 held 分布上保留这个比较关系；
- 条件分支打开后仍保持 MT 已有成功。

特别是，“能退化为 MT”不意味着训练会自动选择“先完整保留 MT，再增加视频收益”。

当前 public-only=103 也不能当作一个充分训练的 MT。它是移除条件项后的共适应模型。条件分支可能承担了大量对合法教学普遍成立的控制成分；移除它，同时移除了这些共同成分。因而 161−103 不等于“视频提供了强 MT 无法获得的 58 条新知识”。

### 2. 当前教学特征实际处在什么坐标中？

T/C 的教学读取有几个不能略去的事实：

- 双相机 RGB 与 exact language 进入 source 原生前缀；
- teacher prompt 省略 State 段；
- 用固定 seed 的 \(50\times32\) Gaussian probe，在 \(\tau=1\) 运行 action expert；
- \(H_t\) 是末端 norm 后、action_out 前的 hidden；
- \(X_{\ell,t}\) 是 38 个 target 各自真实投影输入；
- 视频时间 \(t\)、50 个预测 horizon 槽、flow time \(\tau\)、网络层 \(\ell\) 是四种不同坐标。

因此，\(\Delta H_t\) 是**冻结基础网络及当时公共 LoRA 在两个图像条件下的内部响应差**。它可能包含物体运动、手臂运动、目标解释、动作先验和外观变化。它不是已知坐标系中的对象位移，更不是观测到的 teacher action 或控制 Jacobian。[实际机制与源码入口](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/review_materials/20261007_research_reassessment/MECHANISM.md)

### 3. T 的“同算子”给了什么，没有给什么？

略去 layer 下标，T 的核心是：

\[
K_t=\operatorname{norm}_{\rm col}(AX_t),
\]

\[
V_t=O\!\left[
\operatorname{GELU}(PK_t+C\bar H_t)
\odot D\Delta\bar H_t
\right],
\]

\[
M_{t+1}=M_t+(V_t-M_tK_t)K_t^\top/50,
\qquad
\Delta y(q)=(B_0+M_{\rm end})Aq.
\]

将递推展开后，视频对自身 \(q\) 的作用由一组依赖 \(K_t\)、后续覆盖矩阵和 \(Aq\) 的系数决定。它们可以有符号，不是“与某个操作阶段匹配的概率”。

这里确有一种合理偏置：教学写入地址和自身读取使用同一 \(A\)。但要让它成为控制关系，还需要：

\[
AX_{\rm teacher}
\quad\text{与}\quad
Aq_{\rm self}
\]

在**功能意义上**相容。

这项相容性不会由共享矩阵自动产生。teacher 缺 state、固定 \(\tau=1\)，自身有 state、不同 flow time、实际动作 latent，而且自身 hidden 已经受到完整生成 LoRA 的上游影响。

此外：

- key 单位化丢弃了投影幅度；
- \(H\) 的归一化及差分改变了静态量与变化量的使用方式；
- \(-MK\) 会按后续地址覆盖已有内容，即使新的 Value 很小也可能覆盖；
- 同样的地址相似，不保证下游动作方向相同。

这些都是实际结构性质。**它们使“原生特征已经天然给出可移植更新”成为一个强假说，而不是源码事实。**

### 4. C 解除了部分限制，但没有解除全部学习问题

C 让

\[
A_V=A_0+S(V),\qquad B_V=B_0+M(V)
\]

共同学习，并用最终 \(A_V\) 对缓存的 \(X/H\) 重新寻址。它不是只加了一个无关辅助头。

但有两类精确约束：

- \(S\) 的行空间来自该视频的 \(X\) 张成空间；
- 条件 B 的写出方向经过共享的宽 256 出口，对某些高维 target 形成跨条件的输出子空间限制。

这些约束应按 target 分别看；例如输出维本来不大的 target，不会受到同样程度的限制。其他层也可能通过非线性传播补偿，不能据此推出整个策略的动作函数只有某个固定低维空间。

另外，C 重新寻址时不按新 \(A_V\) 重跑 native。新的自身计算与教学缓存仍存在结构差别。[C 实际实现，`85919994`](https://github.com/LinFyM/EMBER/blob/85919994/src/ember/operator_writer/conditional_read_write.py)

所以，自由 A/B 是一个合理的表达参照。但完整 P/Q 的历史已经说明：**移除这些约束，不会自动产生跨任务学习能力。**

### 5. FM 已经提供真实功能信用，缺口不是“梯度没有接到控制”

主 FM 使用同一生成 LoRA，在同 task、跨 episode 的真实自身 RGB/state/query 上预测完整 \(50\times7\) velocity；再通过同参数版本重放，把信用回传到编译器和 native 读取。

这条训练链是真实存在的，必须承认。

关键问题在于：它教了哪些联合关系？

设任务由目标 \(g\) 和情境 \(c\) 构成。当前主要风险近似为：

\[
\mathcal L_{\rm within}
=
\mathbb E_{g,c}
\mathbb E_{\substack{V\sim D_{g,c}\\(x,a)\sim D_{g,c}}}
\ell_{\rm FM}
\bigl(\pi_{G(V,L_g)}(x,L_g),a\bigr).
\]

这里 teacher 与 query 跨 episode，却主要处在同一个任务映射中。

在一个简化的总体模型中，如果语言及自身观测已经足以确定训练任务，且独立 episode 的教学与 query 在给定任务后独立，那么：

\[
p(a\mid x,L,V)=p(a\mid x,L).
\]

这是带假设的推导，不是对当前全部数据测得的条件独立结论。它说明：**真实 FM 可以充分奖励正确控制，同时不要求模型把视频理解成跨新任务可复用的操作规则。**

模型可以学到：

- 一个语言条件控制器；
- 一个由教学外观识别训练任务的控制器；
- 一个用视频调制已有任务模板的控制器；
- 一部分可复用关系与一部分场景特例的混合。

在已见任务上，这些解可能都降低风险；在新任务映射上，它们的延伸完全不同。

增加同 task episode 会减少估计误差、扩大自身状态支持，并可能提供真实纠正变化。但它不会自动消除上述解之间的歧义。

### 6. “一条成功视频”也不能识别完整反馈律

这个问题可以用一个局部例子说明。设成功轨迹附近的状态坐标为沿轨迹方向 \(s\) 和偏离方向 \(e\)：

\[
u(s,e)=u_{\rm demo}(s)+K(s)e.
\]

在教学轨迹 \(e=0\) 上，不同 \(K\) 可以产生相同轨迹；离开轨迹后，它们可能给出完全不同、甚至相反的修正。

若其他 episode 提供偏离方向的状态变化，在局部线性、标签可靠等假设下，对 \(K\) 的约束强度与这些变化的协方差有关：

\[
\Delta R
\propto
\operatorname{tr}
\bigl((K-K^\star)\Sigma_e(K-K^\star)^\top\bigr).
\]

这不是对 EMBER 实测了低秩 \(\Sigma_e\)。它指出了需要识别的对象：**教学展示了一个可行实例；共享控制知识和其他真实 query 才能教会偏离这个实例时如何继续。**

现有多 episode、source 训练和 learner-state 查询已经提供其中一部分信息，不能说全部缺失。最新接手结果表明，它们至少还没有覆盖并学成某些关键的接收状态连接。

### 7. 参数共享如何把局部改善变成其他条件的损伤？

对某个当前参数点做局部线性化，普通 SGD 的动作函数变化可写成：

\[
\delta v_i
\approx
-\eta\sum_j J_iJ_j^\top e_j.
\]

这里 \(J_i\) 包含教学解释、完整 LoRA 生成以及自身 action expert 的实际消费者。它不是视频 embedding 的相似度，也不是裸 LoRA 的余弦。

这个式子说明：在条件 \(j\) 上减少误差，是否帮助条件 \(i\)，取决于完整功能更新的相容性。它不证明 EMBER 的所有失败都是梯度冲突；AdamW、有限步幅及非线性也使真实轨迹更复杂。

当前没有完整测量这些跨任务功能关系。现有证据只能确认：**共享更新确实伴随能力交换，平均风险的改善并不足以约束这种交换。**A64 和内容居中的通道、任务集中度，正是具体例子。

## 五、视频究竟可能比语言多提供什么？

我认为值得检验的增量来源，是：

> **视频提供一个已经实例化的目标关系及其实现示例，使模型在有限任务训练下，更容易把语言目标绑定到具体对象、受体、几何关系和必要的操作条件。**

例如，视频可能帮助确定：

- 哪个外观实例承担被操作对象的角色；
- “放进”“放上”“前侧 compartment”在这个装置上对应什么可见关系；
- 一段对象变化与哪个目标有关；
- 哪些准备状态和保持条件对该实例有用。

这些不是全部已经测得的语义。T 的结果支持其中存在有用成分；GT 角色、内容居中和 donor 接手反例表明，不能把其中任何一项单独升级为完整操作知识。

也不能把这说成信息论上“语言必然不够”。exact language 给出了很多目标信息，自身 RGB 也给出了场景。充分学习的 MT 或语言生成器完全可能达到相同能力。

**视频的合理优势主张首先是有限数据下的推断与迁移优势，不是人为制造的输入必需性。**

这意味着一个很实际的要求：新增监督如果也能同样提高 MT，就必须把这部分收益归给共享控制学习。只有 V 在相同条件下继续产生额外完整能力，才支持 EMBER 的视频编译主张。

## 六、数据里已经有一项值得使用、但尚未被这样使用的结构

我复核后需要明确修正：“每个训练 task 都由唯一 exact language 命名”不适用于整个 95-task 支持池。

其中已有一个真实的书—caddy 交叉：

| 情境 | front compartment | left compartment | right compartment |
|---|---:|---:|---:|
| STUDY_SCENE1 | 113 | 114 | 115 |
| STUDY_SCENE2 | 118 | 119 | 120 |
| STUDY_SCENE3 | 121 | 122 | 123 |

同一列的 exact language 逐字相同。规范化 BDDL goal 分别是书进入 caddy 的 front、left、right region。不同 scene 的干扰物和初始区域也确实不同；SCENE3 的书初始在 caddy 附近的区域，不能视为单纯背景换色。

另外，KITCHEN_SCENE3 有真实的：

\[
\{\text{pan},\text{moka}\}
\times
\{\text{place},\text{Turnon}\land\text{place}\}
\]

四格，分别为 58、59、61、32。[95-task manifest](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/configs/operator_read_write_v1/support_diversity_manifest.json)；[规范化 BDDL 审计](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/configs/pi05_source_corpus_v1/overlap_audit.json)

但必须继承三项限制。

**第一，书的九格均已被 source71 训练。**把其中一格从新 Writer 训练中扣掉，只能称 Writer 映射留出，不能称整个策略从未见过该任务。炉灶四格中的 32 未被 source 见过完整任务，但现有 MT/T/C 已用它训练，不能从这些 checkpoint 继续后再称 32 未见。

**第二，BDDL 的合取不是顺序标签。**不能从 `Turnon ∧ On` 自动标注“先开再放”；顺序需由真实教学和必要条件判断。

**第三，每格有 50 条 demonstration 记录，不等于当前 source/MT 在每格有 50 条已认证成功的闭环。**这两种事实不能混用。

更重要的是，历史方法对这些数据的使用方式有实质区别：

- 关系支持替换，改变训练任务池，teacher/query 仍同 task；
- 36→95，改变 task、visit 和权重，teacher/query 仍同 task；
- P/I，改变同 task 内参考与 query 的对应，没有跨 BDDL context 直接承担同一功能风险。

我核对了关系支持的 [`7dc95edb` 实际数据与训练消费者](https://github.com/LinFyM/EMBER/blob/7dc95edbba00cf61439700d77fb321eb8df95c07/src/ember/writer/learning_data.py)，以及当前 [support diversity 实现](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/src/ember/operator_writer/support_diversity.py)。

所以，历史已经检验过“增加关系边之后，隐式共享能否迁移”；尚未直接检验的是：

> **同一教学生成的同一 LoRA，能否在不同真实任务情境的自身 query 上实现同一个目标关系。**

这是一条新增功能约束，不是新增数据量的别名。

## 七、我推荐的完整候选：跨情境的任务关系编译

### 1. 核心原则

保留普通完整任务 FM，同时在经过语义审核的等价任务之间增加：

\[
\mathcal L_{\rm cross}
=
\mathbb E_{g,c\neq c'}
\mathbb E_{\substack{V\sim D_{g,c}\\(x,a)\sim D_{g,c'}}}
\ell_{\rm FM}
\bigl(\pi_{G(V,L_g)}(x,L_g),a\bigr).
\]

例如：

\[
V_{\text{SCENE1, front}}
\longrightarrow
(x,a)_{\text{SCENE2, front}}.
\]

标签来自 SCENE2 的真实自身状态和真实动作，不是把 SCENE1 的动作搬过去。

不要求两个视频生成相同 LoRA，也不要求不同场景的动作相同。要求的是：**教学所表达的关系，在不同自身情境中经完整策略产生合适动作。**

这会直接约束“教学中的哪些内容可以跨情境使用”。它仍允许模型靠语言完成，因而必须保留充分的 L 对照。

### 2. 我撤下首版中的任意 latent 拆拼

若把两个教学表示混成 \(m(z_A,z_B)\)，再用完整 \(L_C\) 和 C 的 query 监督：

\[
\ell\bigl(\pi_{G(m(z_A,z_B),L_C)}(x_C,L_C),a_C\bigr),
\]

合法解 \(G(z,L)=H(L)\) 仍完全满足这个风险。

如果槽没有真正解耦，拆拼还可能让视频变得不可靠，使语言成为更容易使用的输入。因此首版应使用完整真实教学之间的合法功能配对，暂不预设“对象槽×效果槽×顺序槽”已经能安全互换。

### 3. 输入、特征、编译和执行如何接起来

我会采用下面这一条完整实现原则。具体宽度和 rank 只选一档，不把它们当成此次科学问题。

| 环节 | 实际做法 | 承担的职责与边界 |
|---|---|---|
| 教学输入 | 同步双 RGB、有序完整视频、exact language | 不输入 teacher action/state、task ID 或文件身份 |
| 特征来源 | 冻结 source 的原生图文 prefix，保留空间 token，再由可学习的教学编码器读取 | 保护图像理解；不把固定 Gaussian probe 的 \(H/\Delta H\) 当唯一操作地址 |
| 视频解释 | 空间读取与有序时序汇聚共同学习，保留静态内容和过程信息 | 不把 attention、差分或某个 latent 名称直接认定为操作语义 |
| 参数生成 | 生成全部 38 target 的完整 A/B；不要求 A 的条件改变量落在 teacher \(X\) 行空间，也不要求通过同一个窄 O 写出全部条件作用 | 自由输出提供一个较少预设的载体；它本身不是新方法有效性的证据 |
| 部署执行 | 一次编译后仅安装一套完整 LoRA；自身 RGB/state/flow hidden 持续决定动作 | 反馈来自实际自身计算，不依赖在线视频 memory 或外部阶段控制器 |
| 功能监督 | 普通同 task 跨 episode FM＋真实跨情境同关系 FM | 每个动作标签都属于实际 query 所在任务与状态 |
| 梯度消费者 | 完整策略的 FM 通过全部 LoRA 及生成器回传，教学编码器也受同一功能风险训练 | 冻结 source 基础权重；语义标签若使用，只来自 non-held |

这里我会让 source 的动作先验主要承担**自身执行的共享控制基础**，不再要求它在一个固定 teacher probe 下产生的内部坐标天然就是写入地址。

这会失去 T 那种强绑定偏置；换来的是不必预先相信教学 forward 与自身 forward 在那个地址中已经功能对齐。历史自由 P/Q 的失败仍然有效，所以此次成败必须归到完整候选的学习结果，不能归功于“终于输出两侧因子”。

### 4. 如何争取已有能力的保持

首项比较宜让 M、L、V 都从同一个强 MT 函数开始。这样可以降低“条件学习还没有重建公共能力”的混淆。

若采用公共项与条件项，必须在算子层相加：

\[
\Delta W_\ell
=
B_{\ell,s}A_{\ell,s}
+
B_{\ell,V}A_{\ell,V}.
\]

可以在编译时精确拼成：

\[
B_{\ell,\rm final}
=
[B_{\ell,s}\;\;B_{\ell,V}],
\qquad
A_{\ell,\rm final}
=
\begin{bmatrix}
A_{\ell,s}\\
A_{\ell,V}
\end{bmatrix},
\]

得到唯一 LoRA；总 rank 要如实记为两部分之和。这不增加部署 adapter。

MT 初始化不是理论必需条件，也不是对旧公共 prior/P/I 失败的豁免。它只是这次有限比较的合理起点。全部旧训练任务的真实风险必须保留，不能为训练新关系而挤掉旧任务。

**这些安排仍不保证闭环保持。**条件项即使不改变公共权重，也能破坏原成功。保持必须由完整 R/G/L 和合法换视频结果裁决，不能由“底座冻结”宣布。

### 5. 为什么它值得比旧候选先试？

它改变了一条此前未直接改变的学习条件：

> 旧风险主要要求“教学 i 对任务 i 有用”；新风险要求“教学中表达的同一个关系，在多个真实自身情境中有用”。

这可以压低视频中的绝对布局、轨迹外观或整任务身份作为控制规则的作用，给可复用的目标解释更直接的功能信用。

但它仍只是一个**中等偏低置信度的优势来源假说**。它可能只改善通用目标条件控制，最后被 L 或 MT 完全吸收。出现这种结果，就应接受它没有兑现 EMBER 的视频增量。

### 6. 对实际行为的预测应收窄

我预期它若有效，首先应表现为：

- 保住 task3、task11 已有的视频收益；
- 减少合法换视频时的损失与成功交换；
- 在原先损伤的对象—受体、相对位置任务上出现更一致的完整新增；
- 收益开始超出原来两个高贡献任务。

我不会预测它凭书—caddy 的跨情境数据就自动解决 task23/39。

对抽屉，真正有意义的改善是：开口出现后，保持可进入状态并完成搬运、入内。对微波炉，是实际进入炉腔并完成目标。更多 Open、更高举杯、更低 gripper MSE 都不能替代这些行为。

若它只改善前述简单关系，仍应把结论限制在这个范围；不能宣布已经学会普遍的阶段连接或接收状态反馈。

## 八、它相对最近似历史方案，究竟改变了什么？

| 历史近邻 | 已经建立的部分 | 仍未建立的部分 | 此候选真正新增的部分 |
|---|---|---|---|
| 完整 P/Q、task clone | 输出空间及某些 task-local 解可达 | 合法教学的共享映射和 held 迁移 | 同一条件直接承担跨情境真实功能风险 |
| Horizon、SemanticPath | 时序/语义解释、完整因子生成、真实 FM 都做过 | 有用内部表示没有稳定转成 held 优势 | 改变 support/query 的任务关系，而不是再加时序模块 |
| GOMQ/SEOD、教学自身信用 | 成功占据域和真实功能信用有过收益 | 成功路径上的知识怎样跨任务调用 | 不把成功占据域本身当作跨任务迁移约束 |
| learner-state、真实纠正 | 部分自身状态上的修正有用 | 教师在新接收状态的成功域和跨任务迁移 | 首版使用真实目标情境的动作，避开未经认证的动作搬运 |
| P/I 对应 | 同 task 更紧的参考—query 对应已经试过 | 参考细节是否提供有用增量，未稳定成立 | 直接跨 context 监督同一关系，而非追逐每条参考的路线细节 |
| 关系支持、36→95 | 有真实新任务和关系覆盖 | 隐式共享不保证学出关系运算；短窗不足以裁决充分学习 | 增加显式的跨任务功能配对，而非仅增加池大小 |

这些历史负结果使我不愿再把“自由因子”“更懂动作”“成功教师”“扩大支持”中的任何一个单独列为主线。

**成功续行认证主要让标签取得资格。**如果认证后的样本没有增加可区分的视频—任务关系，它仍可能主要改善 MT。这是上一轮候选最需要修正的地方。

## 九、首项工作：一次有界的完整视频增量判别

我建议首项只回答一个问题：

> **在同一强控制起点、相同真实训练资料和目标下，跨情境功能训练能否让视频产生语言生成器和 MT 没有的完整增量？**

不先造新纠正教师，不做 rank、memory、decoder 的矩阵搜索。

### 1. 最小数据与学习范围

一个具体起点是：

- 原 36-task 训练范围全部保留；
- 加入上述书—caddy 九格，形成 45-task 范围；
- 先核实际 canonical 任务身份、使用的教学终态与 query 数据，确保交叉的是同一目标关系；
- 九格中的每个教学事件，用**同一生成 LoRA**同时接受本情境与另外情境的真实 query 信用。

例如，一次 28-query 事件可固定为：

- 14 条来自教学所在情境；
- 其余两个同目标情境各 7 条。

这使跨情境约束进入同一次真实功能损失。所有动作仍来自各自 query 的实际 episode。对称安排 teacher/query 次数，避免新增任务或某个 scene 被额外加权。

这九格已经属于 source 的知识范围，所以它们是学习编译关系的训练材料。**主泛化裁决仍是当前正式 held8/400。**

### 2. 三个不可删的学习臂

| 臂 | 内容 |
|---|---|
| **M** | 忠实的强 MT，获得相同新增 query、动作、任务权重和合理优化机会 |
| **L** | 充分的 exact-language 生成器，与 V 使用相同完整参数生成后端，初始函数也精确等于 MT |
| **V** | 相同后端，加合法有序视频和上述跨情境功能配对 |

L 不能用“把视频置零的 V”代替。M 不能被剥夺新增数据，也不能为了形式上的相同 macro 数使用明显不合适的优化配方。

V 不得额外获得更多 query 曝光而将收益归因于配对机制。若使用额外训练侧语义标签，其训练信息也应给相应参照。

三臂足以判断这个完整候选有没有视频增量。**它们不足以证明 cross loss 是唯一原因。**若要作这个因果归因，需要第四个同结构、同数据、同曝光但仅 within-task 配对的 V。首项可以暂不作这个更强主张，不能删 M/L 来换取一个更容易解释的架构对照。

### 3. 固定窗口与学习充分性的边界

可用一个明确的中等窗口作为预算起点：每个任务约 24 个教学事件。45 项共 1,080 个条件，以 4 条件/宏步计为 270 宏步，每臂约 **30,240 个真实 FM query**。

这个数字是建议的有限窗口，不是收敛保证。

需要预先检查：

- 普通条件下的训练功能是否已经获得；
- L 是否真正学会使用语言条件，而非仍处于新头启动阶段；
- M/L 的 non-held 学习曲线是否仍快速改善；
- 跨情境条件是否只是改善平均误差，还是在相关完整训练行为上也成立。

如果到预算终点参照仍明显没有学够，不能宣布 V 已超过充分训练的 M/L。也不能把这次阴性推广为所有跨情境学习不可能。应报告“这条实现尚未在有界预算内建立资格”，停止自动续训。

### 4. 完整读出

固定终点做：

- M：400；
- L：400；
- V：canonical 合法视频 400；
- 同一个 V：另一套预登记合法视频 400。

共 **1,600 条完整闭环**。原 MT153 和 T161 保留为历史强参照，不取视频成功并集作为成绩，不按结果选更好的教学。

主要比较应关注：

\[
\Delta_{\rm robust}
=
\min\{S(V_1),S(V_2)\}
-
\max\{S(M_{\rm old}),S(M_{\rm new}),S(L)\}.
\]

同时报告逐任务 R/G/L、两视频共同新增、共同损失，以及收益是否仍集中于 task3/11。这个标量不能替代逐行结构。

我建议事先采用一个明确的投资门槛：**两条合法视频都至少比最强参照多 20/400，且收益扩展到原两个主要贡献任务之外。**这是我对“值得继续投入”的实用门槛，不是统计显著性的定义，也不证明稳定突破。

达到门槛后，读取预登记的相邻节点，检查优势是否保持；随后才值得做独立训练重复。相邻点、两个视频都不能替代独立训练重复。

### 5. 阳性与阴性怎样改变决定

| 结果 | 后续取舍 |
|---|---|
| V 两条合法视频都有完整净优势、覆盖扩大、相邻点保持 | 这条候选取得继续优先研究的资格；再补独立重复及机制归因 |
| M/L/V 都提高，V 无额外优势 | 保留通用数据与监督收益；降低视频编译主线，不继续包装为视频突破 |
| V 训练内跨情境功能成立，held 或另一合法视频失败 | 降低“这类关系监督足以产生可迁移视频适配”的主假说，不自动换槽、加层、扩到 95 |
| V 内部误差改善，完整行为没有改善 | 继承 A64/居中的负证据；停止用内部拟合给完整训练续期 |
| L 稳定追平或超过 V | 视频专属 encoder/算子建设降级；不能削弱语言来制造优势 |
| 三臂基本学习都未成立 | 本次未裁决迁移，但候选的预算可行性未建立；不自动无限延长 |

这里最重要的是第三行：阴性必须改变对**整个学习原则**的投入，而不只是停用一个版本名。

### 6. 成本估计

已有费用尺度包括：

- C fresh450 整批约 **19.27 GPUh**；
- C450→900 继续批次约 **12.46 GPUh**；
- support diversity 短窗整批约 **8.48 GPUh**；
- 最新 90 条较短接手续行实际约 **0.21978 GPUh**，不能据此直接估算完整初态 400 的费用。[训练与费用记录](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/docs/analyses/conditional_support_diversity_evidence_20261002.json)；[接手费用与原件索引](https://github.com/LinFyM/EMBER/blob/f8a3dc1f/findings.md)

据此，我会把首批规划在 **约 20–30 GPUh** 的量级，包含三个学习臂、条件编码、1,600 条完整读出及必要余量。已有后端可复用时，工程与审计按数个工作日估计。

这不是已测吞吐承诺。应以一个真实可用训练宏步和真实读出吞吐修正预测。若新 encoder/decoder 工程使成本明显超出这个范围，就不再属于这项最小工作；不能为了压成本删掉 L、不给 M 新标签，或把 400 缩成 32 后仍作同样主张。

## 十、哪些资料仍缺，哪些结论必须靠新实验建立

| 类别 | 最小对象 | 能改变什么判断 |
|---|---|---|
| **已有但本次未上传** | 90 条首计划的原七通道数组，至少区分平移、旋转、gripper | 判定文本作用较大主要体现在哪些动作分量；不能单独裁定新方法 |
| **已有数据中可继续核查** | 首项实际使用教学的终态/成功字段、canonical region 身份、对应 query 的动作和状态记录 | 确认跨情境监督语义成立，避免把文件名相同当成物理任务等价 |
| **尚未测量** | 少量明确 non-held 条件之间的完整功能更新转移，而非裸特征余弦 | 可区分某个更新只在源条件有效，还是能帮助另一真实情境；目前不能宣称已测梯度冲突或控制子空间 |
| **需要新实验** | 同新增数据、同强起点的 M/L/V 完整学习比较 | 决定视频是否有额外迁移价值 |
| **需要新实验** | 独立训练重复 | 决定优势是否稳定 |
| **需要新实验** | 多类真实接收状态上的成功续行 | 决定某教师是否具备广泛纠正资格 |

我不把完整 teacher/query 大张量或跨任务 Jacobian 普查列为首项前置条件。它们可以帮助解释具体失败，却不能替代缺失的强语言参照和同数据 MT。

## 十一、研究推进应作的实质取舍

过去几个月最严重的问题，不是实验不够多，而是**不同层级的正例反复被当成了下一层成立的理由**：

- 标签有用，被推进为合法视频应当能预测它；
- 输出空间可达，被推进为共享生成应该能学会；
- 读取或动作误差改善，被推进为控制功能已取得；
- donor 正常初态成功，被推进为可接手教师；
- 局部面板改善，被推进为值得完整训练；
- 完整结果失效后，又回到另一个中间表示寻找局部阳性。

这些箭头并不自动成立。新增证据恰好又切断了其中几条。

我建议保留的基础是：冻结 source 与规范化、合法输入合同、完整 38-target 部署、真实跨 episode FM、已有强 MT、逐行获得与损失审计，以及那些确实取得过视频增量的历史结果。

我建议停止默认投入的母假说是：

- 原生 feature 经同 A 寻址就具有可迁移控制含义；
- 自身调用更强、角色更准或动作读出更低误差就足以进入完整训练；
- 自由因子或更多参数本身会解决共享学习；
- 一个正常初态成功的条件可以直接成为另一接收状态的教师；
- 只要增加更多同池任务，关系复用就会自然出现。

目前也没有足够证据把冻结 prefix、一次编译或单套 LoRA 指认为不可克服的主要障碍。完整 P/Q 的局部可达与当前 T 的真实能力，说明这套部署形式仍有空间；现有在线视频控制结果又没有建立一个明显更强、可供编译逼近的上界。因此，我不建议现在以放宽这些边界作为主线逃生口。

**下一笔投入应购买一个会改变主线判断的答案：在真实跨情境监督和共同强控制基础下，视频是否仍能带来可重复的完整增量。**

如果答案是肯定的，就围绕这个已经成立的增量建设完整方法；如果答案是否定的，就应降低视频专属架构建设的优先级。继续用 public-only、局部损失、可解码性或单次最高点替代这个问题，任何新的 Writer 都很容易回到目前的困境。
