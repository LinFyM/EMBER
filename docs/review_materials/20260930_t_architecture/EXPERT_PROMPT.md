# EMBER 专家审阅请求：公共基座是否必要，以及它应怎样学出来

仓库：[LinFyM/EMBER](https://github.com/LinFyM/EMBER)。
入口：[README](https://github.com/LinFyM/EMBER/blob/main/docs/review_materials/20260930_t_architecture/README.md)。

证据：[EVIDENCE](https://github.com/LinFyM/EMBER/blob/main/docs/review_materials/20260930_t_architecture/EVIDENCE.md)。

请作为独立研究专家，整体审阅模型与训练机制。核心不是替现有设计辩护，而是判断：
**A₀/B₀作为共通基座、S/M作为视频适配的设想是否合理；如果合理，能否让这种分工通过更自然的学习机制形成？**

我们讨论过直接public FM、随机划分查询、条件作用正则、复用native输出监督，以及把条件适配吸收到公共参数。
Owner仍有根本疑虑：为了让基座有能力而额外优化它，是否只是人为规定职责，
没有解释这种分解为何有利于完整任务，以及共通知识怎样从多任务经验中形成。
我们不要求无任何归纳偏置，也不把“少一个loss”“公式漂亮”本身视为优点。
请不要只用“所有学习都需要人为目标”结束分析；需要判断哪些约束来自任务，哪些是在维护未证实的分解。

先读整合与证据，再按入口核对实际源码和最近似历史。报告实际读取的commit，
若转交方提供commit快照，全部材料与代码固定到该commit，不随main后续更新。
区分当前研究代码、各实验训练来源与未实现的候选。远程仓库不含checkpoint、原始native大张量或完整RGB；
可以核公式、源码和导出的行/统计，不能声称重新执行了模型。

EMBER目标是：从冻结generic π0.5-derived source出发，将exact language和action-hidden正确教学视频，
在rollout前一次编译成一套完整task LoRA，从新初始化闭环执行，绝对能力超过强MT-BC，且视频提供有益增量。
teacher action/state/reward/task ID不能进入Writer条件；自身执行可用合法观测和state。
训练可用授权non-held动作，held数据不产生梯度；部署没有环境试错、逐任务优化或第二套expert adapter。
公共A₀/B₀是否需要存在或独立有效，正是本次可质疑的假说，不是必须维护的前提。

请先重建两条链，不要把它们混成已经验证的一个方法：

```text
已执行原T：公共beta读取X/H → 局部变化Value与实际A地址 → M
           → 唯一(A, B0+M) → 自身hidden/动作 → 完整FM共同学习。

讨论候选：公共beta读取X/H → 因果动态解释 → 结合X与A0X生成S
           → A(V)=A0+S → 依同一A(V)生成M
           → 唯一(A0+S, B0+M) → 自身执行 → 完整/公共功能监督。
```

重点回答以下相互联系的问题：

1. **公共分解是否成立且值得追求？** 区分跨task共享参数、共同控制能力、视频解释所需表征与独立无视频执行能力。
   哪些必须绑定，哪些不必？公共policy仍读语言和自身状态，不等于平均动作；BA因子不是天然可辨识的技能坐标。
   证据支持保留、修改还是放弃这一设想？允许公共表征有用但独立public能力不必成为额外目标这一可能性。
2. **共同训练缺少什么？** 原T只有完整FM仍学出公共能力；直接公共监督提高部分公共成绩，却未自动改善完整成绩。
   分析信用分配、共同补偿、表示兼容性和有限任务泛化，区分可推出机制与未定位假说。
   不把分解不唯一、理论反例或参数范数直接当成实际主要根因。
3. **有没有更自然的学习机制？** 给出最支持的一条完整方案，与最强替代方案比较，写明假设。
   解释怎样从多任务经验区分可复用作用和视频特定作用，真实输入、特征、算子和梯度怎样实现。
   若仍认为直接公共FM最合理，请独立论证必要性、收益条件与代价，不能以“希望基座有能力”循环论证。
   若认为不应强行分解，也给出完整替代，不只建议删除loss或模块。
4. **怎样承接完整架构？** S是否应感知A₀当前作用，A变化如何传到M和执行，native应提供什么信息？
   区分因果视频编码与片尾编译、视频时间与flow time、合法推理状态与含真实动作的FM输入。
   保留或撤换模块均可，但要说明计算、信息墙、同episode辅助、成本与学习条件。
5. **怎样可能被证伪？** 保留T的有益条件作用、强MT参照、成熟/fresh public反例及Context/self_read结果。
   核对最近似历史，说明建议改变了哪条失败预测。给出最小有区分力的证据，不铺大矩阵或用继续训练回避判断。

区分严格性质、假设下推论、仓库实证和待验证假说，最终形成自己的排序与取舍。
参数量不设上限，不默认先训练MT再冻结，不要求保留delta-rule、固定probe、共享A或特定decoder。
若建议改变现行fresh共同训练等合同，指出改变及必要性，不当作已获执行授权。
未来慢速巩固/吸收经验只是动机，不要求现在实现在线记忆或merge。

请先给出对公共基座设想的结论，再用连贯推导和关键正反证据支持，最后给出首选完整机制、适用条件与最小反证。
不要只复述材料、列方法名或罗列优缺点。主动指出局部解释之间的矛盾，明确未知。
