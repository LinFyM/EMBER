**最终我选择：辅助头保留完整真实 FM 目标，撤回“只能读取时间中心化 Value、执行 query 只能改变选择权重”的限制，改为轻量的状态条件化视频残差头；蒸馏只在 Compiler/native D 上与真实 FM 做归一化混合，视频编码器始终以系数1接收真实 LoRA FM。**

这样解决的是两处设计一致性问题，不是用结构宣告视频依赖已经成立。

## 一、辅助头：让参数化与它实际承担的目标一致

### 1. 上一版确实存在张力，而且可能鼓励我们不希望的解

辅助预测写成

$$
T(x,V)=u_0(x)+\delta_R(x,V),
$$

其真实 FM 损失就是

$$
\mathcal L_R
=
\mathbb E\left\|
\delta_R(x,V)-\bigl(y(x)-u_0(x)\bigr)
\right\|^2.
$$

因此，辅助头的目标是 **source 的全部动作预测残差**。其中可能同时包含对象识别、静态关系、一般操作、过程推进和随机动作目标带来的误差。完整 LoRA 在另一条路径上学习共同能力，并不会改变这里的目标。

若同时要求 \(\delta_R\) 只能使用时间中心化内容，就存在不必要的张力：监督要求它解释全部残差，参数化却有意抑制其中一部分合理信息。网络可能因此把跨视频共有的运动、时间模式甚至非关键变化组织成通用动作特征，再由执行 query 选择。**“迫使预测经过变化通路”不等于“监督已经只剩过程误差”。**

我也不采用 \(y-\operatorname{sg}(S)\) 作为所谓“纯过程目标”。学生当前的残差仍可能混有各种错误，而且随学生变化；它不是被识别出来的视频动态标签。

所以，最终保留可靠的完整真实动作目标，修改辅助头的表达形式，不再强行把它命名为“动态专用纠错器”。

### 2. 仅改变选择权重，并非一定不能控制，但不是合适的首版限制

对固定视频，上一版单头读出可以写成

$$
\delta_R(x,V)=\sum_n\alpha_n(x,V)\,w_n(V),
\qquad
\alpha_n\geq0,\quad \sum_n\alpha_n=1.
$$

其中 \(w_n(V)\) 是视频 Value 经共享线性投影得到的动作向量。因此，新增修正在该视频对应的固定动作原型凸包内；多头情形是相应固定集合的组合。

这**不是不可能性证明**：原型足够丰富时，权重变化也能覆盖不同方向和幅度，而且 source 本身已经承担很多状态依赖控制。

问题是，这种参数化要求教学内容同时充当“操作关系证据”和“不同执行初始化下的动作向量原型”。例如，同一个“抓住目标后运向篮子”的关系，在机器人位于篮子左侧与右侧时需要不同平移方向。让执行状态直接参与关系到动作的转换，比要求视频 Value 提前容纳所有这些动作方向更自然。

### 3. 最终辅助头的形式

保留已经选定的完整时间×任务 token 表示：

$$
E=E_\phi(g,V).
$$

它包含任务相关静态内容和有序变化；**辅助 Value 不再强制做时间中心化**。此前的局部变化建模、完整 H 读取和语义轴保留不需要撤销，只撤销辅助出口对可用信息的硬限制。

对每个执行 action-horizon 位置 \(h\)，使用未安装生成 LoRA 的冻结 source 特征 \(q^0_h(x)\)：

$$
r_h
=
\operatorname{Attn}_\eta
\left(
q^0_h(x),E,E
\right),
$$

$$
\boxed{
T_h(x,V)
=
u^0_h(x)
+
W_o
\left[
\operatorname{GELU}\!\left(U_q\,\operatorname{LN}(q^0_h(x))\right)
\odot
U_r r_h
\right].
}
$$

这是一个小型状态条件化残差头：视频读出提供控制上下文，执行特征负责将它转成当前状态下的动作修正。保留一个无偏置、零初始化的 \(W_o\)，其余读取与投影采用非零初始化；不另加独立的 query-only 残差网络。

这个形式允许状态不仅改变“读哪段视频”，还改变读到内容的作用方向和幅度。以固定 \(r_h\) 为例，新增项已经是关于 \(q^0_h(x)\) 的非线性函数，不再只是对该视频一组固定动作向量做凸组合。当然，它没有自动获得平移、旋转等变性，也不能恢复冻结执行特征中不存在的信息。

**这是对上轮限制的明确撤回，而不是新增贡献。**当前候选的实质仍是执行状态条件化的直接功能信用，以及它与同一份完整 LoRA 编译的共同学习。

### 4. 常量读出捷径仍然存在，但不再用不匹配的限制去堵它

若 \(r_h\approx c\)，则上式会退化为

$$
T_h-u^0_h
\approx
W_o\operatorname{diag}(U_rc)
\operatorname{GELU}\!\left(U_q\operatorname{LN}(q^0_h)\right),
$$

即一个主要依赖执行状态的修正器。这一点必须承认。

最终选择接受它作为可行解，而不继续叠加中心化、差额扣除或错误条件惩罚，理由是：

**完整 FM 本来就包含共同能力误差。**允许辅助头使用静态语义和状态条件变换，比迫使它借助无关运动编码这些误差更一致。共同能力的学习不是违规，也不是失败；只有把这种改善宣称为视频动态收益，才是结论错误。

相应的代价是，辅助头可能主要学习共同修正，蒸馏也可能传递这些共同修正。没有哪条结构规则保证视频条件解会战胜它。保留时间×任务 token 和直接功能信用，只是在提供一条有希望学到教学—执行对应关系的路径，而不是把这种对应关系预先写成结论。

因此，辅助头的最终职责应表述为：

> **学习一个完整的视频条件化动作函数，为共享视频表示提供直接功能信用；其中是否形成有益的教学内容与顺序增量，仍需由行为证据裁决。**

## 二、损失与梯度：归一化只作用于编译参数，不能顺带削弱编码器的真实 FM

你指出的问题成立。若直接使用

$$
(1-\rho)\mathcal L_C+\mu\mathcal L_R+\rho\mathcal L_D
$$

并阻断 \(\mathcal L_D\) 到编码器的梯度，那么编码器确实只收到

$$
(1-\rho)\nabla_\phi\mathcal L_C
+\mu\nabla_\phi\mathcal L_R.
$$

这会随着蒸馏增强，系统性改变两条真实监督对表示的相对权重。它与“真实 LoRA FM 持续约束表示的可编译性”的设计理由不一致。

**最终不用这一条全模型统一加权规则，而采用明确的分参数组路由。**

### 1. 参数组及预测定义

将可训练参数划成不重叠的三组：

| 参数组      | 包含内容                             |
| -------- | -------------------------------- |
| \(\phi\) | 视频编码器、共享语义/过程表示、读取侧 Action Meta  |
| \(\eta\) | 辅助执行查询、attention及动作残差读出          |
| \(\psi\) | Compiler、codes到完整A/B的映射、native D |

source 基础参数始终冻结。辅助 query \(q^0(x)\) 来自冻结 source，不受学生 LoRA 改变。

定义

$$
E=E_\phi(g,V),\qquad
S_\psi(E,x)=\pi_{\theta_0+G_\psi(E)}(x),\qquad
T_\eta(E,x)=\text{上述辅助预测}.
$$

这里 \(G_\psi(E)\) 一次生成完整 LoRA，仍对同一条件的全部执行 queries 复用。

### 2. 最终总训练代理损失

使用两份**数值相同、梯度路径不同**的真实 LoRA FM：

$$
\mathcal L_C^{E}
=
\ell\!\left(
S_{\operatorname{sg}(\psi)}(E_\phi,x),y
\right),
$$

$$
\mathcal L_C^{G}
=
\ell\!\left(
S_\psi(\operatorname{sg}(E_\phi),x),y
\right).
$$

其中，第一项只向编码器传回编译路径的真实信用；第二项只训练 Compiler/native D。两者在同一参数版本、query、flow time和noise下具有相同预测值。

另定义

$$
\mathcal L_R
=
\ell\!\left(T_\eta(E_\phi,x),y\right),
$$

$$
\mathcal L_D^{G}
=
\ell\!\left(
S_\psi(\operatorname{sg}(E_\phi),x),
\operatorname{sg}\!\left[T_\eta(E_\phi,x)\right]
\right).
$$

最终采用：

$$
\boxed{
\mathcal L_{\rm route}
=
\mathcal L_C^{E}
+\mu\mathcal L_R
+(1-\rho)\mathcal L_C^{G}
+\rho\mathcal L_D^{G}.
}
$$

这里的 \(\ell\) 均采用相同任务权重、有效 horizon/action mask及动作维度归一化。

**这是实现分组梯度的代理损失，不应把它的标量值当作一个新的统一性能指标。**两份 \(\mathcal L_C\) 没有对同一参数组重复加权；统计时仍分别报告原始 \(\mathcal L_C,\mathcal L_R,\mathcal L_D\)。

另一个重要实现细节是：\(S_{\operatorname{sg}(\psi)}(E_\phi,x)\) 只停止对 \(\psi\) 求导，不能对整个 Compiler执行 `no_grad()`，否则也会错误切断到 \(E_\phi\) 的真实 FM 信用。

### 3. 每组实际收到的梯度

上述代理损失产生：

$$
\boxed{
g_\phi
=
\nabla_\phi\mathcal L_C
+\mu\nabla_\phi\mathcal L_R
}
$$

$$
\boxed{
g_\eta
=
\mu\nabla_\eta\mathcal L_R
}
$$

$$
\boxed{
g_\psi
=
(1-\rho)\nabla_\psi\mathcal L_C
+\rho\nabla_\psi\mathcal L_D
}
$$

其中 \(\nabla_\psi\mathcal L_D\) 把视频表示和教师输出都当作本步固定值。

| 参数组                        | 真实 LoRA FM |    辅助真实 FM |       蒸馏 |
| -------------------------- | ---------: | ---------: | -------: |
| 视频编码器／Action Meta，\(\phi\) |   **1，固定** | \(\mu\)，固定 |        0 |
| 辅助读出，\(\eta\)              |          0 | \(\mu\)，固定 |        0 |
| Compiler／native D，\(\psi\) | \(1-\rho\) |          0 | \(\rho\) |
| 冻结 source 基础参数             |          0 |          0 |        0 |

所以，蒸馏渐增时：

**编码器的两条真实监督系数完全不变。**它不会因为 \(\rho\) 上升而被人为推向“更适合辅助检索、较少接受真实编译约束”的训练目标。

**Compiler/native D 的目标才逐步混入教师函数。**它们在原始动作目标和辅助函数目标之间做归一化组合，系数和保持1。

**辅助头只接受真实动作监督。**它不会通过追随学生来降低蒸馏损失；蒸馏也不会直接推动共享表示迁就教师自身产生的目标。

要注意，固定的是监督**系数**，不是实际梯度范数或训练效果。随着表示、Compiler和误差变化，梯度大小、夹角以及 AdamW 的预条件响应仍会改变。这套路由消除了你指出的显式权重失衡，却不保证两条真实监督永远协调。

### 4. 权重与预热也固定成一个版本

为了不留下多个平行选项，首版采用：

$$
\mu=1,\qquad 0\leq\rho\leq\frac14.
$$

读出预热期间 \(\rho=0\)，但编码器、辅助头、Compiler和native D都参与各自允许的真实 FM 学习；随后按预登记的固定日程渐增至 \(\rho=1/4\)，不再继续提高。

这使最终权重为：

$$
g_\phi=\nabla_\phi\mathcal L_C+\nabla_\phi\mathcal L_R,
$$

$$
g_\eta=\nabla_\eta\mathcal L_R,
$$

$$
g_\psi=\tfrac34\nabla_\psi\mathcal L_C
+\tfrac14\nabla_\psi\mathcal L_D.
$$

选择 \(1/4\) 是让尚未经验证的辅助教师处于次要地位的**保守工程默认值**，不是历史证据推出的最优比例。它也不等于错误教师不可能伤害学生；这里只是不让蒸馏在首版直接取代真实动作监督。

### 5. 路由可以利用现有VJP结构，不要求复制两次完整policy计算

当前 `supervised.py` 已经把真实policy的 LoRA cotangent、Writer重放和observer VJP分开执行。这为分组路由提供了实现基础，但当前代码只有原FM信用，新增蒸馏与分组处理尚未实现。

记生成的A/B张量集合为 \(\Delta\)，分别取得

$$
v_C=\frac{\partial\mathcal L_C}{\partial\Delta},
\qquad
v_D=\frac{\partial\mathcal L_D}{\partial\Delta}.
$$

然后：

* 向编码器传递 \(J_{G,E}^{\top}v_C\)，再加辅助真实FM信用；
* 向Compiler/native D传递

  $$
  J_{G,\psi}^{\top}\bigl[(1-\rho)v_C+\rho v_D\bigr].
  $$

不能先把两份cotangent混合，再把混合后的结果一路传回视频编码器。所有分支在同一参数版本完成反传，最后才统一optimizer step。

合法identity初始化也继续保留：当前native D的A/B输出映射为零，A从模板 \(A_0\) 起步、B为零。这里保留编码器真实FM的系数1，并不意味着identity的第一步它就必然有非零编译梯度；零初始化造成的初始梯度结构仍然存在。

## 三、收敛后的版本及结论边界

最终版本是：**完整时间×任务 token 表示，同时服务于小型状态条件化功能教师和唯一完整LoRA Compiler；两条真实FM共同训练表示，只有Compiler/native D接受归一化蒸馏。**

现在已经解决的设计一致性问题是：辅助头不再被迫用“动态专用通路”解释全部source残差；执行状态能够参与动作方向与幅度转换；蒸馏渐增不再削弱编码器的真实LoRA FM系数。

留给实验的则是科学问题：完整辅助头是否真正利用教学内容，而不是主要学习共同修正；这种教学收益是否能被Compiler学进固定LoRA；共享表示的两条真实信用是否能稳定协调。**辅助头失败仍不能直接证明表示无信息，辅助头强而LoRA弱仍不能直接证明rank16容量不足。**

这版不再试图靠不断增加通路限制来保证视频特异性，而是让每个模块有足以承担其监督目标的表达能力，同时明确约束信用流向。是否产生并保留了有益的视频依赖，仍由结果裁决。
