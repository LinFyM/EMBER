# EMBER：停滞原因与完整方法的重新审视

2026-10-07。供只能访问 Git 远程仓库的专家使用；这是与 Owner 讨论审阅问题的材料，尚未定稿为委托提示词。
没有要求专家维护现有架构，也没有预先选定后继实验。

## 现在真正需要解释的事

EMBER 希望将 **exact language + 正确、action-hidden 教学视频**，在 rollout 前一次编译成完整 task-conditioned LoRA，
使冻结的 π0.5-LIBERO source 在未见初始化完成任务。目标是初次生成就有效，并在强 MT 参照之上获得稳定、广泛的实际能力；
部署后逐任务优化不是当前目标的替代。

目前最强原 T 的单 checkpoint Validation8 为 **161/400**，强 MT300 为 **153/400**；相邻较晚 T 点为
147、154、160、154、159，尚无稳定显著的优势。另一方面，selected T 的 correct / same-task-other / public-only /
cross-suite-wrong 为 **161 / 150 / 103 / 65**：教学条件确有功能作用，不能把它简单判为完全忽略视频。
但这些差额也不能自动证明学到了可迁移的操作规则，或把所有条件收益归为新操作知识。

上次专家建议共同学习条件读取与写入；实际条件读写 C 将两侧参数、时序解释器与真实 FM 共同训练，
seen 从 **91→115/144**，held 从 **137→140/400**。后续动作校准、动作/效果信用、关系监督、共享 RL、
特权示范动作参照及在线视频控制诊断，也没有给出比强参照更可靠的完整方法。
这些实验分别约束了不同假说，**并未共同证明唯一根因，更没有证明目标原则上不可行**。

主讨论需要承担的缺口是：积累了大量局部事实，却未将它们收敛成能解释正反结果、预测下一完整方法的认识。
这次审阅应允许质疑我们的问题分解、数据与学习设定、架构基础和决策方式。

## 建议专家回答的核心问题

**在当前输入与监督下，怎样才能把教学中的操作证据学成能在新任务自身状态上调用的控制规则；
现有方法究竟在哪些联系上缺乏支持，什么完整原理最值得保留、撤换或重建？**

建议围绕四个相互关联的问题展开，而非列出一张模块改进清单：

1. **给出能同时解释阳性与阴性的机制判断。** 从实际 RGB/语言/native 特征、读写算子、最终 LoRA、
   自身执行 hidden 与动作逐段说明：T 的条件作用可能来自什么，为什么 seen 学习可以增长而 held 不随之改善。
   区分有原件支持的事实、结构推导、特征语义假设与尚未区分的竞争解释。请不要先指定“表示”“寻址”或“FM”一个词作根因。
2. **判断当前学习问题是否足以教会所需迁移。** 同 task 跨 episode FM 已存在，source 与 meta-task 数不同，
   95-task 干预也只是固定预算的短窗口。请分析现有变化范围、标签、梯度消费者与完整策略风险，
   哪些关系可由监督辨识，哪些捷径同样能减小训练误差；支持什么数据/学习取舍，什么仍未知。
   不接受由一个小探针失败推出“视频无信息”，也不由非零梯度推出“迁移关系已学会”。
3. **提出有取舍的完整方法原理。** 可保留、撤换甚至放弃目前的 native probe、A 绑定、delta memory、
   rank、公共基底或解码器。解释新原则为何改变最近似历史方案的失败预测；明确输入、特征、算子、
   标签、训练与部署的因果链。优先给出一个有理由的主判断及必要备选，而不是多个未排序架构。
   若现证据不足以选方法，请指出最小的、会改变选择的证据与可失败预测；不要求先证明必然成功。
4. **审视研究决策本身。** 我们是否反复在局部代理问题上获得答案，却绕开了控制获取与跨任务迁移？
   哪些假说应降低优先级，哪些正证据被低估，哪些比较不足以支持转向？如何停止补丁循环和换架构循环，
   又保留渐进验证的效率？请直接批评主讨论的推断和投入选择。

这些是主讨论建议的审阅重点，尚待与 Owner 对齐。专家可反驳本文判断；无需为某版设计背书。

## 材料的边界

- 所有正式数字均指固定 Validation8 的单 checkpoint 400 行；seen144、局部32与新增训练留出16是不同诊断，不能混排。
- 本次只导出已经存在的数据并重算统计，没有新模型 forward、环境步、标签或 checkpoint 选择。
- 远程可审源码、配置、数学关系及导出成败；原始权重、RGB、连续状态、X/H/余切大张量未上传。
  CSV 是原始结果的字段投影，并非物理轨迹的完整独立复现。功能 JSON 是既有原件读回的摘要，不能声称专家重跑了它。
- 历史记录中的服务器绝对路径只标注来源；本目录新增 provenance 使用 run-relative 标识。
  可直接访问的证据在 Git 内给出，不要求专家访问服务器。
- **Test 和 shuffled/reversed 封存结果排除在本次方法审阅之外**，即使历史可见也不得反哺设计。
- 只保持最终部署与信息墙：合法教学视频/语言、冻结 source、rollout 前一次产生完整单套 LoRA、
  视频动态证据有必要增量。具体 memory、rank、A/B 分工、层对应和 decoder 都可质疑。
