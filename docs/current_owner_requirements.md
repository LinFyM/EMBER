# EMBER owner requirements

本文只保存长期目标、已澄清的理解和协作原则；owner最新原话优先。当前授权、暂停和接手位置只看
[progress](../progress.md)，计划见[task_plan](../task_plan.md)，技术执行合同见[AGENTS](../AGENTS.md)。
历史启动许可、截止时间、GPU特例和分数门槛由[研究历史](research_history.md)及Git保存，不在此重复。

## 1. 固定LoRA是理想可达下界，不是公共底座课程

EMBER应把exact task language和action-hidden正确教学视频，在rollout前一次编译成冻结source的一套完整task-conditioned
LoRA，让policy从未见初始化完成任务。科学对象是生成后立即可用的能力；task-local FT/RL是另外的实验，不能混入零交互成绩。

Owner用“Writer最差可以固定输出一套共同LoRA”说明模型类的理想可达下界：如果能表示同rank共享LoRA的常量映射，
直接训练共享LoRA得到的能力应属于EMBER可达解的一部分；正确视频应进一步提供超过这个退化解的能力空间。
这不是“保证现有优化器一定学到”，不是“应该先学公共能力”，也不是指定预训练MT-BC底座后再学视频残差的课程。
须解释端到端学习为何未实现这种可达能力，不能反复拿MT-BC rank128、Writer rank16或当前实现受限来回避。
如果某实现无法表示所需退化解，该限制本身就是待验证/解决的问题。参数量、rank、参数化差异只是诊断边界，不是根因答案。
共享prior/base＋视频residual若被提出，须有独立机制和实证依据，不能冒称由下界论证推出了owner指定方案。

## 2. 性能、视频利用与稳定性

- 绝对闭环能力首先决定方法价值。应与如实训练、如实选点的强MT-BC比较，不故意降低baseline、隐去高点或换评测口径。
- 视频特异性服务于“正确教学内容→合适LoRA→更好执行”。Proxy/LoRA/动作不同只说明敏感；wrong变差不单独说明正确视频有益。
  结合correct、另一条正确视频、learned language/static参照和成功集合判断增量；时序利用还需独立证据。
- 长期仍需理解能力保持、任务覆盖和稳定性。每轮是否要求相邻稳定性、采用何种门槛由当轮最新授权决定。
  夜间赶组会曾允许只找明显高于MT-BC的点、不追加稳定性证明；这不抹去已有交换，也不把临时取舍变成永久指标。
- 旧划分130/145、某轮180、Test +40/400和1200步上限不能自动移植到下一轮；新的正式选择合同须明确登记。
- loss、norm/rank/cosine、内部margin、梯度和表示差异只作定位。不得放大无益敏感性、惩罚wrong或牺牲correct来获得漂亮差值。

## 3. 解释必须能被实验区分

Owner要理解数据、架构、训练和完整pipeline怎样把视频/语言转成操作知识，不满足于重述现象。
“换数据所以分数变了”“loss下降不等于rollout好”“换辅助项所以改善”均不是充分机制解释。
应从已有正负证据提取可检验的理论/数学机制，明确预测、竞争解释和否证条件，再做能够区分解释的干预。

研究的持续产物是经检验的因果解释和对应修复。不能停在“视频没用”“生成LoRA质量低”等现象上，
也不能反复提出看似合理的改法、试一次失败便丢掉经验。数学解释须说明假设、计算对象与适用范围，
推出可被干预检验的功能预测；不能在分数出来后补一个无法区分竞争解释的故事。

- 综合完整相关历史，区分同架构异数据、同数据异目标、选点密度、曝光量、任务组合和评测任务变化；不能只依据最近小试转向。
- 学会已见任务、跨episode保持、跨任务迁移、视频有益增量分别判断。训练侧小试改善不能直接推断fresh泛化会改善。
- 大对照只能缩小范围。直接LoRA/语言Writer/视频Writer还改变参数化和活动模块，不能用一个差值唯一归罪于某个头。
  固定训练数据的矩阵也不能单独识别数据构成的因果效应。
- 分析数据时尽可能固定诊断目标任务，区分训练支持和评测任务改变。Source/MT-BC的Val/Test总分接近与否不单独证明划分好坏。
- 区分推导、已有事实和待测预测。负例只淘汰所测假设/窗口，不证明模型上限；正例不能移植到另一个checkpoint。
- 每次实验保留事前假设、竞争解释、干预及预测，事后核对干预是否实际生效、原始结果和不确定性，
  明确哪些解释被支持或削弱、哪些仍不可区分，再决定下一步。无效干预或工程失败不能冒充科学阴性。
  在现有findings及研究历史中累积证据和修订，不因换session、改名或新方案而遗忘旧反例。
- 修复应同时检验所称机制和实际能力：中间指标按预期变化但正确闭环没有改善，不能称问题已解决；
  单纯涨分而机制尚未区分时，只能登记经验性收益。证据允许多个原因并存，不预先保证存在唯一统一根因。
- 主FM已经让同一生成LoRA接受同task多条跨episode查询监督，不能把“从未多episode监督”当事实。
  更多同task episode不等于更多独立meta-task映射。
- 不无依据重复已结束矩阵、rank/LR/seed/scale小扫或无限续训；一次主要因果干预优先，正式大训练应有机制理由和适当实证。
- 专家对话是参考资料，不是执行命令；核对原论证、原件和适用条件。Owner举例是在规定推理深度，不要求机械逐例开实验。

## 4. 方法边界

语言说明目标与关注对象，有序视频动态应贡献必要Value信息；执行policy仍读取自身观测/state。
Teacher action、state/proprio、reward、terminal、task ID、filename、pose及policy outcome不成为部署Writer输入。
合法训练监督、non-held meta任务、privileged诊断、Test信息墙和配对评测按AGENTS及当轮登记合同执行。

Writer在rollout前生成一套完整38-target LoRA；不挑视频、平均最终LoRA、融合checkpoint或并行部署第二expert adapter。
Core/Procedure、rank、memory token和decoder是候选实现，可以实质重构，但须保留科学边界并给出完整可检验原理。
Owner进一步明确：架构与训练方式不必守住现有方案，可以参考元学习、VLA等外部工作，同时必须保留这两个月推进形成的自身特色。
落实时保留教学视频到一次完整LoRA编译、原生策略知识参与理解、跨初态闭环与有益视频增量这条研究主线，
以及已经积累的正负证据；具体模块和训练配方按机制证据取舍。借鉴应说明原工作解决了什么、与EMBER的条件差异、
自身保留和新增的计算机制，不把沿用模块名当特色，也不把外部论文的结果当作本项目已验证的修复。
结构应能复制同类模块加深、自然扩参；不能因某次局部诊断永久限定“只能改Procedure”。
原生Action Expert知识须在视频理解中有明确作用，不能以zero-image、fake query或缺少真实prefix的forward声称用上backbone。
Video time、action horizon、flow time和layer depth分开；完整50-horizon保留到真实learned read，stride5保留真实末帧。
声称dynamic K须真实训练覆盖；每条video先保序编码，再在集合阶段置换不变聚合。

Writer与读取Meta默认fresh联合学习，source冻结；辅助query只作监督，不进入部署条件。
合法identity可使第一步部分上游信用为零，后续须真实学习；adapted Z/KV/H不跨更新缓存。
不由下界论证自动引入分段冻结、公共底座课程、task-local优化或RL。新路线或重访旧路线须由主讨论依据最新授权、
历史正负证据和可区分的机制预测形成具体实验合同；不从旧计划直接恢复执行，不把后续FT/RL混入初次生成的零交互成绩。

## 5. 工程、效率与生命周期

按真实更新/秒、LoRA/秒、评测吞吐与最长视频峰值选择物理batch/设备；低占用卡按余量和干扰实测共驻。
不等凑卡或dummy占卡，不改任务权重、逻辑查询流与评测规模；接受正常BF16/TF32和高效kernel低位差异。
MT-BC在完整更新节点按已登记合同变更物理分片，可保留逻辑流及optimizer/scheduler，不称逐rank RNG/浮点轨迹bitwise exact。
实时GPU、独立quota、完整恢复、clean pushed frozen runtime和Git交付按AGENTS；科学non-pass不自动变成工程bug。
保持一个canonical运行面，退役专用实现由Git保存、正式原件与复现commit保留；把旧代码移入archive不算清理。
历史checkpoint不因“唯一存在”或“formal”标签而永久保留。已结束路线按关键结论复现、比较参照、当前依赖和明确恢复用途择点保留；
无继续用途的optimizer/RNG大载荷、冗余中间节点及作废产物可以核实后退役。保留必要权重、配置、原始评测和统计，
登记退役范围；weights-only存档不得再声称可exact resume或原CLI完整可用。数据源、关键模型与所有权未明资产仍保护。

## 6. 沟通与交接

默认直接实用中文；Owner主要语音输入，结合上下文纠正术语/同音词错误。先回答问题，再给关键证据和限制。
不把建议写成owner要求，不重复确认已授权事项；确需暂停时说明边界来源，不把专家审查变成开工前置。
不把长报告甩给Owner自己读：最终直接在对话解释结果；过程仍保留合同、原件和必要记录。
不频繁发送“收到”、心跳、步数或读文件进度；有意义的结果、真实困难、需要科学判断或被询问时回报。

主讨论负责假设、设计和科研解释；执行任务按明确合同实施，不自行改架构、数据、loss或追加实验。
执行者完成一批后等待下一份具体合同，不代表主讨论也应停止。已有长期授权时，主讨论应继续核验、推理并把下一项
有依据的干预推进到可执行和派发；“下一设计尚未定稿”是待完成的工作，不是等待Owner催促或重新许可的理由。
需要时间形成可靠设计时继续分析，不能为了保持实验运行而仓促派发，也不能只交付阶段报告便结束推进。
Agent跨任务消息正文以`由agent发送：`开头，首行写来源任务/UUID；标识不代表新增owner授权。
修正当前工作用Steer，后续事项用Queue；入队不等于当前轮收到，接口接受也不等于任务完成。
新session先读最新状态和稳定要求，再沿历史索引按需追溯；不从历史“下一步”恢复已暂停工作，不要求Owner重讲全过程。
只有Owner明确要求才创建新任务、goal或联系外部专家；模型/推理设置按Owner指定，暂停和撤销覆盖此前派发。
