# 专家第五轮回复：教学引导行为发现，再训练进固定 LoRA

> 来源：2026-10-08 旧专家对话在信息边界放宽后的完整回复。Owner 基本接受其方向，并要求下一轮先给出具体完整架构。文中的模块、首批规模和同预算语言对照均为专家提议，不是已实施结果或已冻结合同。尤其“第一阶段先明显超过强 MT”的最新优先级见 [讨论衔接](DISCUSSION_BRIEF.md)。以下保留原文；旧会话引文标记若不可解析，请沿正文 Git/论文链接及历史证据入口核对。

**明确：对一次给定教学的适应过程，最终只形成一套完整、固定的 LoRA；这套 LoRA 用于该教学条件下所有新的评测初态。** 教学读取、环境实践、候选搜索、价值学习和参数修订都发生在评测前。最终成绩只来自固定 LoRA 的独立闭环执行。

在这个准确的信息边界下，**我建议撤下“共享 Writer 必须从教学和少量经验中前向预测正确参数更新”这一核心组织方式，转向“教学引导的任务内行为发现与策略迭代”，直接把实践中获得的控制能力训练进最终那套 LoRA。**

这次我会实质修改第四轮推荐：

- 保留“教学要求什么、当前控制实际做到了什么”这一区分。
- 自身状态、接触和奖励既然可以直接获得，就不再把视觉效果估计、独立逆动作模型、前向元更新器设为必经环节。
- 充分使用 action expert 在**真实自身状态下**提出有控制先验的动作。
- 让教学影响值得尝试的操作与候选排序，让环境确认实际后果。
- 直接更新最终完整 LoRA，使它逐步吸收这些行为；持续检查撤下搜索后是否仍然成立。

**首版我更推荐“搜索发现改进，真实行为监督提取策略”，而不是立即让大模型沿未经校准的 critic 动作梯度做完整 flow 反传。** 下面解释这一取舍的依据、完整计算过程，以及它最可能失败在哪里。

## 一、这次真正改变的是：新任务的修订方向可以由该任务自己的证据建立

首先纠正一个容易延续的混淆：**EMBER 的训练侧一直有真实动作信用，也实际做过奖励学习。** 现在改变方法排序的，是 validation 任务上的自身交互反馈可以用于学习和修订。不能把这次变化描述成“终于允许使用动作监督或 RL”。

我采用如下组织：

| 环节 | 信息来源 | 学习什么 |
|---|---|---|
| 共享训练 | 训练任务的示范、动作、物理状态、关系、奖励和自行交互 | 控制初始化、教学读取、目标条件的动作评价 |
| 当前任务适应 | 指定教学 RGB、exact language，以及模型自己交互获得的动作、观测、状态、接触、奖励 | 当前任务的动作评价与同一套完整 LoRA |
| 最终评测 | 新初态下的自身观测与既定语言 | 参数固定，独立闭环执行 |

首版我选择让最终 actor 继续使用现有自身 RGB/proprio 与语言接口。完整物理状态主要用于适应期的评价和监督。**这是我为保留现有执行模型而作的设计选择，不是再替 Owner 添加一条信息禁令。**

这使“编译”的含义发生了实质变化。它不再必须是神经网络的一次前向：

\[
\lambda=G_\phi(V,L),
\]

而可以是一个具有真实反馈的优化过程：

\[
\lambda_{\mathrm{final}}
=
\mathcal A\!\left(
V,L,\lambda_0,\mathcal B_{\mathrm{self}}
\right),
\]

其中 \(\mathcal B_{\mathrm{self}}\) 只包含该模型合法自行交互得到的经验，\(\mathcal A\) 可以交替进行尝试、评价和梯度更新。**输出仍然只有一套 LoRA。**

### 为什么现在值得改变这一层，而不只是继续改 Writer？

已有证据支持三个有限但重要的判断。

**第一，当前 source 与完整 LoRA 家族并没有被证明缺乏可学空间。** 最新四任务独立教师从初态达到 12/16，接手达到 9/16，救回一些 T 的失败；同时接手丢失原成功，task29 仍然 0/4。它证明存在控制增量，也证明成功示范拟合不能自动产生覆盖学生状态的可靠教师。[教师结果与逐行边界](https://github.com/LinFyM/EMBER/blob/cc4786dd08c536e10f7edd1466bbd47cac417bd8/docs/analyses/aligned_teacher_recovery_20261008.json)

**第二，只改变共享学习中的配对关系，没有显示所需修复。** Within/Product 的 147/152 与另一视频的 148/151，使我进一步降低“保持 T 的主要计算形式，只靠更合适配对就能兑现能力”的优先级。它没有否定未实施的新入口、自由输出等完整组合，但那些组合也没有因此获得正证据。[跨情境配对结果](https://github.com/LinFyM/EMBER/blob/cc4786dd08c536e10f7edd1466bbd47cac417bd8/docs/analyses/cross_context_pairing_20261008.json)

**第三，旧负结果已经禁止我们把“真实奖励接通”本身当成新原理。** 10 月 6 日实际做过完整共享 Writer 的 72 次更新、1,152 条交互，真实 score 信用并非没有进入参数，最终也没有提高原 T。其优势主要来自整 episode success 的组内比较，尚不是当前任务上的目标条件动作评价与局部策略迭代。10 月 8 日状态基线分析则没有参数更新和新闭环，不能被登记为 actor-critic 训练失败。[历史 RL 消费者核对，findings §395](https://github.com/LinFyM/EMBER/blob/cc4786dd08c536e10f7edd1466bbd47cac417bd8/findings.md#395-main消费当前专家可学控制的正例不能扩成可靠恢复标签2026-10-08)；[状态信用分析](https://github.com/LinFyM/EMBER/blob/cc4786dd08c536e10f7edd1466bbd47cac417bd8/docs/analyses/state_baseline_full_writer_credit_20261008.json)

这些证据**不能确认共享生成器就是长期失败的唯一主因**。但它们足以支持一个方法取舍：现在既然允许在当前任务中实际发现修订，就不必继续要求有限的跨任务训练先学会预测所有修订。

旧方法需要同时完成：

1. 从教学推断所需控制；
2. 从其它任务学会这种推断如何跨任务成立；
3. 把推断变成一整套有效参数。

新方法仍需迁移已有知识，但当前任务中“这个退出动作有没有用”“这个新控制能否连接后续阶段”，可以直接交给实际经验回答。**自由 A/B 只是移除一道限制；当前任务自己的控制证据才是新增学习条件。**

## 二、我建议的完整分工：教学给出操作目标，action expert 提供行为先验，实践产生可学习的控制证据

### 1. 教学表示应保留什么？

我不再推荐把固定 probe 下的原生 hidden 差分作为教学的主要表达。首版采用：

- 冻结 source 的空间视觉 token 和语言条件前缀特征；
- 保留相机标记、帧内位置和视频顺序；
- 读取对象及操作部件的候选区域；
- 从前后片段中形成**候选目标关系及其变化**，保留对应视频片段供适应时重读。

输出不必是一张完整、精确的世界状态图。更有价值的是一组可检验的操作条件，例如：

- 某个容器入口已经可用；
- 手已离开操作部件，同时入口仍保持可用；
- 指定物体已被拿起；
- 物体相对目标容器的位置进入可放置区域。

这些目标应包含“需要改变什么”和“改变时仍要保持什么”。“抽屉打开过”与“机器人退出时抽屉仍可用”，是不同目标。后者才有机会连接后续放碗。

在训练任务上，读取器可以用对应帧的真实状态、关节和关系监督。到 validation 时，它只接收合法 RGB 与语言，输出的是**推断及置信度**。教师接触、关节、位姿没有因为模型预测了一个数值就变成已知真值。

### 2. 如何避免把教师坐标搬到自身场景？

目标应优先描述对象角色与对象局部关系。例如，将物体 \(i\) 相对对象 \(j\) 的关系写成：

\[
\rho(S;i,j)=
\left[
R_j^\top(p_i-p_j),\
R_j^\top R_i,\
q_j,\
c_{\mathrm{hand},j}
\right],
\]

分别表示局部相对位置、相对朝向、相关关节状态和手与部件的接触关系。

这里有一个精确性质：共同刚体变换不会改变前两项。因此，教学和自身场景只是整体位置、朝向不同时，不必重新学习一套绝对轨迹。

但这**不解决所有情境差异**。障碍、把手形状、接触方式、容器开口和可达方向可能不同；教师从左侧离开的路径在自身场景可能不可行。目标读取还可能认错物体或姿态。因此，教学提供的是值得尝试的关系约束，实际自身状态仍然要决定怎样实现它。

这也是我对上一轮“跨情境关系编译”的修订：不再要求共享 Writer 仅凭这种规范化就产生正确执行函数。规范化后的关系要进入**真实动作评价与实践**，接受当前场景的检验。

### 3. action expert 应承担什么？

它最有价值的身份是**已有的条件动作分布**。

现有 π0.5 的正常执行是在自身图像、语言和 proprio 条件下生成完整动作块，再执行其中一段。代码中，proprio 被量化后进入前缀；完整生成从噪声开始，经过多步 flow 更新得到 action horizon。旧 native 教学读取则缺少教师 proprio，采用固定噪声和固定 flow 时点，其输入条件与正常自身执行不同。[EMBER 输入处理](https://github.com/LinFyM/EMBER/blob/cc4786dd08c536e10f7edd1466bbd47cac417bd8/src/ember/pi05_processing.py)；[native 读取](https://github.com/LinFyM/EMBER/blob/cc4786dd08c536e10f7edd1466bbd47cac417bd8/src/ember/operator_writer/native.py)；[固定版本 π0.5 实现](https://github.com/huggingface/lerobot/blob/30da8e687a6dfc617fcd94afc367ac7071c376ce/src/lerobot/policies/pi05/modeling_pi05.py)

这里需要分清三个轴：

| 轴 | 含义 | 可以提供什么 |
|---|---|---|
| 教学时间 | 实际操作过程的演变 | 顺序、关系变化、阶段连接 |
| action-horizon 位置 | 当前状态下提出的未来命令序列 | 多步动作之间的协调先验 |
| flow 时间 | 从噪声生成该动作序列的计算过程 | 条件动作生成的内部计算 |

它们不能按相同序号直接对应。完整 horizon 也不是未来环境状态预测：source 没有因此预言抽屉会不会被重新带回、是否接触到边缘或是否完成任务。

我的首选用法是：

> **在真实自身状态下，让当前 LoRA 和已有 MT 先验提出完整动作候选；让实际执行前缀及其真实后果，为这些候选建立可调用的评价。**

在现有设置中，可以先保留完整 50 步生成、执行前 5 步的组织。完整 horizon 负责保持候选动作的协调性，环境信用只属于真正执行的动作。

教学侧做完整 action-expert forward 在信息上可以合法，但缺少真实教师 proprio 时，其物理条件仍然不完整。若要先恢复一个教师 proprio 分布才能解释该 forward，就增加了另一项需要验证的推断。我不会把它设成首版必需。历史 source-action 1NN 的失败也提醒我们：模型在教师画面上提出动作，不等于它已经构成可迁移控制教师。[特权动作与 source 动作 1NN 对照](https://github.com/LinFyM/EMBER/blob/cc4786dd08c536e10f7edd1466bbd47cac417bd8/docs/analyses/privileged_action_memory_control_20261007.json)

## 三、在稀疏完整奖励出现之前，需要一个具体可学的动作评价

只把视频拼进一个整任务 \(Q(S,a,V,L)\)，然后等待 success 标签，仍然很容易重复旧问题：全零回报时没有排序方向，条件分支也可以被忽略。

我建议首版只建立一个核心评价函数：

\[
Q_\psi(S,u,g,H),
\]

含义是：

> 在真实状态 \(S\) 执行动作前缀 \(u\)，之后继续采用当前候选控制机制，在剩余预算 \(H\) 内建立目标关系 \(g\) 的可能性或折扣可达性。

它接收真正获得的物理状态、物体关系、机器人状态，以及准备执行的动作前缀。它不需要先生成未来图像，也不需要先反演教师动作。

### 1. 训练标签从哪里来？

从训练任务已有的真实轨迹中，取某个未来状态，将其中实际达到的关系作为目标 \(g\)。对同一条实际转移，可以询问：

- 这次动作是否有助于保持抽屉打开？
- 是否有助于离开把手？
- 是否有助于使物体进入容器？

同一个 \((S,u)\)，因为目标不同，可以得到不同标签。这比“同 task 的动作都应该拟合”增加了一项明确约束：

**动作的用途必须随具体目标变化，不能只由任务常量决定。**

这属于 hindsight goal learning 的基本思想：失败轨迹依然可以说明某些实际达到的目标如何实现。它不意味着这些替代目标就是原任务，也不意味着所有未达到目标都不可达。HER 的原始方法正是通过改变经验对应的目标来增加稀疏奖励下的学习信息。:chatgpt-content-reference{index="0"}

可以用有限时域的目标条件 Bellman 更新：

\[
y_g
=
r^g_{t:t+h}
+
\gamma^h(1-d_g)
\max_{u'\in\mathcal C(S')}
Q_{\bar\psi}(S',u',g,H-h).
\]

其中：

- \(r^g\) 根据实际状态是否建立指定关系计算；
- \(d_g\) 包含目标达到、环境终止或预算用尽；
- \(\mathcal C(S')\) 来自真实自身输入下的 action expert 候选；
- bootstrap 是模型推断，实际首次达到关系的记录才是环境证据。

未执行的候选没有实际成功或失败标签。某条 continuation 没有达到目标，只能说明这次执行没有达到，不能被扩成不可能性结论。

### 2. 视频接口怎样获得功能训练？

不能训练时永远给 \(Q\) 完美目标状态，适应时突然换成有误差的视频预测。

共享训练应同时包含两种输入：

- 由训练轨迹真实状态定义的目标；
- 由训练视频读取器实际预测出的目标表示。

后者的监督结果仍由真实状态关系决定，目标标签不能随读取器输出一起漂移。这样，视频读取器既接受对象与关系监督，也接受其表示进入动作评价后的功能监督。

这仍然不保证视觉目标能可靠迁移。但它比“辅助关系预测很准，最终策略应该也会用”多了一条实际联系：**视频所表达的目标必须改变对具体动作的评价。**

### 3. 为什么不在首版再加一个整任务 critic？

我暂时不把它设为必需。完整奖励很稀疏时，再加一个整任务 \(Q\) 不会凭空增加可靠标签，却会增加一次外推和策略提取问题。

首版可以这样分工：

- 目标条件 \(Q\)：帮助选择值得尝试的动作；
- 实际 task reward/success：判断这些尝试最终是否形成完整能力；
- 真实行为监督：把有效控制训练进 LoRA。

后续若已有足够完整成功与失败，再增加整任务价值学习，可以有明确的数据依据。现在不必先把系统堆成多套评价器。

## 四、适应应是主动的行为发现过程，而且必须能改变提案分布

### 第一步：从强控制初始化开始，直接持有完整 LoRA

首版使用已有强 MT 的完整 LoRA 作为 \(\lambda_0\)，保留冻结 source 与原生前缀。随后直接更新全部 38 targets 的 A/B。

我保留这个初始化，是因为它提供已有接近、抓取、运输等功能，且比较容易建立公平参照。**MT 在这里是初始化和行为先验，它的 LoRA 可以被修订。**

当前共同 A、逐层教学寻址、公共/条件矩阵分工不再是编译器的约束。也不需要将多个独立 adapter 的矩阵平均成一个结果。

### 第二步：教学决定当前值得追求的候选关系

根据教学、语言和当前自身状态，选择尚未满足的操作条件。过程位置依据真实状态重新判断，不按照视频时间播放一个固定阶段表。

尤其不能在所有目标中简单选择 \(Q\) 最大的那个。最容易、已经完成的目标通常会胜出，最后就会变成重复打开、重复接近等循环。

目标是否达到，要检查实际状态与关系，不用 \(Q\) 自己的高分认证。必要条件重新丢失，可以恢复它，但不能因此不断获得“任务成功奖金”。

### 第三步：让 action expert 提案，同时留出产生新动作的空间

候选可以来自：

- 当前 LoRA 的不同 flow 噪声；
- 保留的 MT 先验；
- 在动作范围内、经过训练侧校准的平滑变化，例如退出方向或夹爪切换时机。

从教学推断出的阶段子语言，也可以用于调用 action expert 提案。例如“松开把手”“离开把手区域”。这些是模型推断，来源合法。但 source 是否真正会执行这些子指令仍需检验；语言参照也必须拥有同样的分解和调用能力。

**只对几乎相同的噪声样本做重排是不够的。** 如果当前 actor 从不提出正确退出方式，任何价值网络都无法在候选里选出它。提案支持不足是本方案的主要风险之一。

### 第四步：实际执行，再修订评价与行为

每次只执行选定前缀，记录：

- 当时自身输入；
- 完整候选与实际执行前缀；
- 状态、接触、物体和关节变化；
- 实际 reward、success、终止；
- 所用参数版本。

只有实际执行过的分支产生环境证据。我不假设可以免费从同一 snapshot 尝试所有候选；若使用状态复现或重试，其资源应计入适应成本。

实践可以推翻原来的阶段判断。例如模型以为已经离开把手，真实接触与关节变化却表明仍然牵连；系统应重新处理这个条件，必要时回看相关教学片段。这里不需要把一次失败解释成唯一的物理原因。

### 第五步：在发现完整成功之前，也允许有限的局部能力获得

若必须等第一条完整成功才更新 actor，task23/39 这类需要多个阶段同时修订的任务可能一直没有学习机会。

因此，我允许：

> 经真实联合子目标验证的短片段，获得有限局部更新资格；完整成功轨迹，获得完整功能学习的高可信资格。

例如“抽屉仍保持可用，而且手已退出”可以支持学习这段退出动作。“曾经打开过”则不足以支持把随后整条失败轨迹都当作好行为。

这让已经发现的局部控制进入当前 LoRA，改善后续提案分布，而不必每轮都靠随机探索重新发现它。

## 五、怎样把这些经验真正训练进最终 LoRA？

这是整套方案的关键。我推荐直接训练最终 actor 的动作生成函数。

### 1. 完整成功轨迹：使用真实动作窗口做 FM

从实际执行轨迹构造：

\[
A_t^{\mathrm{real}}
=
(a_t,\ldots,a_{t+49}).
\]

这个窗口可以跨越多次重规划，因为其中的动作都真实发生过。它与某次候选中从未执行的尾部是两类来源。

按当前 π0.5 的时间方向：

\[
x_\tau=\tau\epsilon+(1-\tau)A_t^{\mathrm{real}},
\]

\[
\mathcal L_{\mathrm{full}}
=
\mathbb E
\left[
w_t
\left\|
v_{\Theta,\lambda}
(o_t,p_t,L,x_\tau,\tau)
-
(\epsilon-A_t^{\mathrm{real}})
\right\|^2
\right].
\]

这里的 velocity 目标方向与实际代码一致；采样时从噪声端向动作端积分。[π0.5 的训练与采样实现](https://github.com/huggingface/lerobot/blob/30da8e687a6dfc617fcd94afc367ac7071c376ce/src/lerobot/policies/pi05/modeling_pi05.py)

梯度直接进入最终 38-target A/B。视频读取器和搜索器没有替代这个消费者。完整成功轨迹应有稳定的正权重，不能让一个不成熟 critic 决定它是否有资格进入训练。

这是一种策略提取，不是精确 policy gradient，也不具有无条件单调改进保证。

### 2. 局部成功片段：必须承认 50 步接口的困难

假设某次只执行、验证了前 \(n\leq5\) 步，就不能给后 45 步授予成功信用。

首版可使用一个明确的有界近似：

\[
\widetilde A
=
\left[
a_{1:n}^{\mathrm{executed}},
\operatorname{stopgrad}
A_{n+1:50}^{\mathrm{proposal}}
\right].
\]

它用于构造 flow 输入，但：

- 局部正向监督只覆盖真正执行且得到验证的前缀；
- 后缀只是模型完成先验，不能称为环境确认的好动作；
- 其余部分使用旧策略的功能保持约束；
- 片段后面的等待、关回、错误抓取不能继承局部正权重。

**这是局部策略改进的近似，不是原完整动作分布的精确边缘训练。** horizon 位置存在注意力耦合、共享参数，mask 不保证其它动作不受影响。

我把这个限制写出来，是因为它确实可能成为实现瓶颈。若实际发现这种近似产生明显生成偏差，更严格的替代是对完整采样过程输出的已执行前缀做监督回归。那会更贵，但它依然是对已知动作的监督，不需要相信 \(Q\) 的动作导数。应在观察到具体问题后作这项替换，而不是首版同时混入多种 actor 更新机制。

### 3. 为什么首版不直接做 full-flow Q-gradient？

在当前证据下，我们尚未建立可靠的候选排序，更没有建立可用的局部动作价值导数。沿 \(\nabla_a Q\) 反传完整 flow，容易让 actor 利用 critic 的局部误差。

FQL 原文也直接讨论了这种 full-flow BPTT 的成本和不稳定；其解决方式是训练并部署另一个 one-step actor，不能直接视为当前 π0.5 单 LoRA 的现成答案。另一方面，单纯加权 BC 也有策略提取效率不足的反证。:chatgpt-content-reference{index="1"}

我的取舍不是认为 FM 天生优越，而是明确分工：

- **新行为由主动实践产生；**
- **FM 负责把实际获得的行为学入现有执行模型。**

如果搜索已经稳定找到真实完整改进，而覆盖当前 actor 状态的 FM 仍然无法吸收，那么才有理由把更直接的策略优化提高优先级。

### 4. 一个局部动作怎样变成多个状态下的功能？

最终每层仍然是：

\[
W_\ell^{\mathrm{eff}}
=
W_\ell^0+B_\ell A_\ell.
\]

参数固定，但输入 hidden 随自身图像、proprio 和当前 noisy action 变化。因此 LoRA 可以学习“在这种自身状态下释放、在另一种状态下接近”的反馈函数，而不只是存放一个时间表。

不过，一个状态上的更新会怎样影响其它状态，只能局部写成：

\[
\delta a(q)\approx J_\lambda a(q)\,\Delta\lambda.
\]

这个式子说明跨状态推广与干扰都可能发生；它没有证明当前 Jacobian 具有我们希望的结构。

因此，能力保持不能只靠参数范数或局部 loss。需要：

- 多个适应初态；
- 接近、操作、退出、运输等阶段共同回放；
- 对此前实际有用行为的功能保持；
- 更新后由**不带搜索的当前 actor**重新采集；
- 最后在未参与适应的新初态完整评估。

保留项应约束动作功能，不能把 A/B 数值接近当成功能接近，也不能对所有失败状态盲目保持旧动作。

## 六、以抽屉退出为例：这条链路怎样获得新控制？

以你指出的“打开后退出，又把抽屉带回去”为例。

### 1. 教学提供的是过程约束

教学可能显示：入口保持可用，手离开把手，随后转向碗并放入。模型可以提出联合目标：

> 手已经脱离把手区域，同时抽屉入口仍然可用。

这是从合法教学中推断的约束，不是教师动作标签。

### 2. 实践直接提供物理证据

自身交互可以直接观察：

- 抽屉开度何时开始下降；
- 哪个部件仍接触；
- 夹爪状态如何变化；
- 手的运动与关节变化是否同步。

这些信息使上一轮一些间接效果估计不再必要。

但一次观测仍不能唯一判断是未松手、退出方向、碰撞还是其它因素。它只能缩小需要检验的候选。

### 3. action expert 提出具有已有控制结构的尝试

在该真实状态下，候选可能改变：

- 先释放还是先移动；
- 离开把手的方向；
- 抬升与后退的组合；
- 转向抓碗的时机。

完整 action expert 提供动作尺度与多步协调先验；goal-Q 根据训练知识和已积累的当前任务经验排序。未执行前，这些仍是候选。

### 4. 实际建立联合关系，才给局部更新资格

若某次执行保持了入口并完成脱离，可以训练这段真实退出控制。若只有“打开过”和“离开过”分别成立，中间入口已经关闭，就没有建立联合目标。

这一步与旧局部纠正的区别不在于“现在有真实动作信用”——旧路线已有。区别在于**当前任务、当前 actor 实际到达的状态可以持续提供新标签和真实验证**。

### 5. 后续阶段仍然要取得自己的证据

更好的退出未必使机器人拿起碗，更不必然完成放入。搜索可以在一条 episode 中连续修订多个阶段，找到完整成功轨迹，再让同一 LoRA 联合学习这些改变。

这里有一个重要的策略迭代问题：

> 如果当前纯 actor 的完整成功一直为零，要求每个局部改动都先满足“交还当前 actor 就能成功”，会阻止需要多个阶段同时改变的学习。

因此允许适应期多次干预是必要的。但这种轨迹的回报属于搜索行为，不能冒称原纯 actor 的 \(Q^\pi\) 标签。

最终必须撤下搜索，让新 LoRA 自己证明：它能够接近、打开、退出、抓碗、运输、放入，而不依赖外部阶段切换。

### 6. 为什么可能跨初态成立？

因为训练输入是每次真实自身观测，监督是这些状态下应采取的动作；教学相对关系负责引导发现，最终控制由自身图像和 proprio 调用。

但这只给出学习机会，不能保证跨初态。如果成功只来自少量相似接触状态，换位置或换抓取姿态仍可能失败。微波炉的入口对准、杯子姿态与门体接触也可能需要不同控制支持，不能从抽屉退出成功推出它们已经解决。

## 七、为什么这条路线可能有强 MT、充分语言适应之外的收益？

需要把两个问题分开。

### 1. 为什么完整绝对能力有机会提高？

因为现在能够针对当前任务实际出现的不足，获得合法的新动作与后果数据，并直接更新最终控制函数。

这是强于静态 MT 的资源。独立教师正例说明当前 source/LoRA 族存在部分可学增量；历史接手失败又说明必须在当前 actor 的实际占据状态中学习。这条路线正面利用了两条证据。

因此，**静态 MT153 不再是足够的主比较对象**。它只能作为零适应预算起点。

### 2. 视频额外价值来自哪里？

我对视频的优先预期是：**减少寻找有效操作过程的成本，提高有限适应预算内获得完整行为的概率。**

具体可能来自：

- 语言指定对象名称，视频进一步给出目标实例和操作部件；
- 语言指定最终关系，视频显示哪些中间条件必须先建立并保持；
- source 知道多种可行控制，视频帮助缩小优先尝试的方向、顺序或几何实现。

这不是视频在信息论上不可替代的论证。充分语言模型、source 先验和自身环境反馈，也可能推断出这些过程。

目标条件训练所增加的，是一个有限学习优势的可能来源：同样的自身动作，对于不同视觉关系目标具有不同用途；模型已经在训练侧学过这种目标条件的控制评价。新视频于是可以调用它，而不必重新从稀疏完整回报中识别整个过程。

但这里仍有两道未知：

1. 现有视频能否可靠提供**语言与自身状态尚未足够提供**的关系约束；
2. 这些约束是否能使当前 action prior 更快发现可固化的完整行为。

随着环境反馈开放，视频的不可替代性实际上更难主张。**如果同资源的语言适应取得全部收益，就应承认主进展是任务内控制学习，而不是视频编译突破。** 这不会使绝对能力改进失去价值，但会改变 EMBER 的研究主张和投入排序。

## 八、相对最近似旧路线，新增的究竟是什么？

| 最近似历史 | 已经存在的能力 | 本方案真正改变的条件 |
|---|---|---|
| 完整 P/Q、自由 A/B、task clone | 输出自由度和部分 task-local 可达性 | 当前任务只靠自身交互产生合法控制标签，直接更新最终 LoRA |
| GOMQ、SEOD、LocalField、真实纠正信用 | 同一执行函数上的真实功能监督 | 查询状态随当前 actor 改变，标签在其真实占据域中重新发现 |
| 条件读取、对应学习、关系预测 | 条件能影响表示、参数和部分行为 | 关系目标直接改变实际动作评价，并由真实转移校准 |
| 共享 Writer RL | 真实 reward 与完整参数信用 | 当前任务内适应；目标条件评价帮助探索；行为监督直接提取到 task LoRA |
| 在线读取、NN 接力、donor 接手 | 外部条件有时影响执行 | 外部辅助只用于适应；最终必须撤下并证明单 LoRA 能力 |

所以，新方法不能被描述成“第一次有自身调用”“第一次有真实监督”或“第一次能更新完整参数”。

它的新增内容是一个闭合的学习循环：

> 教学提出值得建立的关系 → 已有控制分布产生动作 → 当前任务实际验证 → 新行为改变同一 LoRA → 更新后的 LoRA 产生新的自身状态 → 再学习 → 固定参数独立评测。

我会停止把固定 probe 差分、共同 A、逐层地址、共享更新器或者某种 decoder 视为主线必须保留的基础。它们将来可以用于加速，但应在“什么实践确实有用、最终策略能吸收什么”已经建立之后再做摊销。

## 九、最小验证应该直接检验“发现—固化”是否成立

我建议首项不是训练一整套新的元编译器，而是实现一个有界的完整循环，做**同资源的语言适应与视频适应对照**。

### 对照怎样保持充分？

两臂使用相同的：

- 强 MT 完整 LoRA 初始化；
- 训练侧数据和目标条件评价器基础；
- 自身状态、接触、奖励与终止信息；
- 候选数量、动作变化范围、交互预算；
- LoRA 更新方法与更新预算。

语言臂也可以分解 exact language、形成操作目标，并用自身图像和状态进行绑定。不能让视频臂拥有 goal-Q、主动探索、更多候选，语言臂却只跑普通 MT。

核心差别只有：适应时是否使用指定教学视频。

### 首批范围

我倾向于先用两个互补任务：

- **task23**：检验共同失败上的阶段连接和绝对能力获得；
- **task11**：检验已有视频增益相关的任务中，视频能否继续帮助适应，同时观察能力保持。

这不是把目标收缩为守住 task11。task23 承担新能力的压力，task11 提供另一种机制和较强起点，减少两臂全零时的解释歧义。

一个可以讨论的首批上限是：每任务、每臂做两次独立适应，每次最多 64 条完整适应 episode，再用 20 个未参与适应的初态评估固定 LoRA。共 512 条适应 episode、160 条最终评测。数字是研究预算建议，不能被理解为 Owner 规定或所有方法的充分训练上限。

适应初态应独立于现行正式 paired400 初态。若目前没有这样的适应池，建立它是必须补齐的评测条件，不能拿正式初态适应后仍称原协议的新初态成绩。

### 最重要的读数

必须同时记录：

1. 适应期带搜索的完整成功；
2. 撤下搜索后固定 LoRA 的完整成功；
3. 到首次完整成功所消耗的交互；
4. 新初态上的收益、损失与覆盖；
5. 两次独立适应的稳定性。

后续真正支持完整方法时，仍需同预算语言参照下的单 checkpoint paired400、任务覆盖、能力得失和合法换视频。Test 与 shuffled/reversed 不进入本轮设计反馈。

### 不同结果怎样改变判断？

| 结果 | 应作出的取舍 |
|---|---|
| 视频使完整成功更早出现，固定 LoRA 也保留增量 | 支持视频帮助行为发现，并可被参数化吸收 |
| 搜索明显更强，固定 LoRA 没有提高 | 优先处理策略提取、自身状态覆盖或最终 actor 可观测性；不继续默认改视频入口 |
| 语言与视频都显著提高，二者接近 | 保留任务内控制路线，降低视频额外收益主张 |
| 只有局部关系改善，完整任务持续不变 | 联合目标或阶段连接假说没有通过，不能以更多局部成功晋级 |
| goal-Q 分数提高，实际关系建立率没有提高 | 动作评价未建立，不应继续放大 actor 更新 |
| 适应初态提高，新初态持续失败 | 学到的是过窄的控制或轨迹，固定 LoRA 的目标未兑现 |

这组阴性只约束所实现的关系接口、动作支持和学习预算；它不能证明所有交互适应都不可能。但如果在真实状态已经清楚、目标读取基本可靠、有限提案变化已经执行的条件下，仍反复只能获得孤立局部改进，那么应降低**这条目标分解与局部策略迭代主假说**，而不是换一个版本名继续。

### 成本与还缺的证据

现有记录可作为部分成本锚点：四独立教师训练约 4.55 GPU 小时；Within/Product 两臂训练约 7.35 GPU 小时。它们说明直接 LoRA 微调可以做成有界工作，但不能据此准确估计新 goal-Q、候选批量生成与交互循环的总成本。[教师资源记录](https://github.com/LinFyM/EMBER/blob/cc4786dd08c536e10f7edd1466bbd47cac417bd8/docs/analyses/aligned_teacher_recovery_20261008.json)；[配对实验资源记录](https://github.com/LinFyM/EMBER/blob/cc4786dd08c536e10f7edd1466bbd47cac417bd8/docs/analyses/cross_context_pairing_20261008.json)

首批应先测候选批量采样与一次完整更新的真实吞吐，再锁定总 GPU 和交互上限。我不建议先支付大规模世界模型、逆模型或元更新器工程。

目前缺口也应分清：

- **已有但覆盖情况需要核实：**训练 RGB 与物理状态、关节、接触之间的可恢复对应，哪些可以直接生成目标条件监督。
- **尚未测量：**当前任务中，目标条件评价能否可靠选择实际有效的动作；固定 LoRA 能否吸收多阶段干预所得行为。
- **必须新实验才能建立：**同环境资源的语言/视频适应比较，以及最终固定 LoRA 的新初态稳定收益。

补传权重或更多旧日志不能替代后两项结论。

## 最终取舍

**我仍然认为 EMBER 值得继续，但主线应从“让一个共享生成器猜出新任务控制”转为“利用教学和已有控制先验，在新任务中发现、验证并固化控制”。**

我的信心分为三层：

- 对撤下前向 Writer 必要性、允许真实任务内优化这一组织变化，信心较高。
- 对“目标条件行为搜索＋真实行为监督提取完整 LoRA”作为首批完整方向，信心中等。
- 对视频能在充分语言、状态和奖励参照之外形成稳定增量，尚无足够证据，必须由公平对照裁决。

值得支付首批成本的理由，是这条路线把过去最难验证的几项联系放进了同一个可检验过程：教学是否改变有效尝试，尝试是否产生真实控制增量，这些增量是否进入最终参数，以及参数是否在新初态继续起作用。

**最终验收对象始终是那一套固定 LoRA。** 如果能力只能存在于适应期的搜索器、阶段选择器或特权评价器中，EMBER 的这次重设计就还没有成功。
