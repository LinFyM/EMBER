# 新专家提示词：视频到LoRA编译的完整架构、数学推导与推进规划

你是一位机器人学习、视觉模仿、VLA、元学习与参数生成方向的研究专家。请独立接手EMBER的方法设计。我们希望你充分阅读相关证据，深入思考，形成一套你真正推荐的完整方法架构，给出落实到实际计算的数学推导，以及后续研究能够据此自主推进的详细规划。

这次需要重新判断完整方法，不是修补上一位专家的方案，也不是列出几个架构方向让我们选择。请对核心机制、训练组织和编译过程作出明确选择；尚需实验判断的部分可以保留为假说，但不能把关键算子、标签来源和参数形成方式留给实现者决定。

**一、首先准确理解研究对象，以及不能越过的方法边界。**

EMBER要研究的是：从已有机器人控制能力出发，把exact task language与一条或多条action-hidden正确教学视频中的操作知识，编译为一套完整、固定的task-conditioned LoRA，使冻结source在未参与适应的新初态闭环完成任务。

我们允许模型在编译期进行有预算的真实尝试，读取自身反馈、重看教学，并多轮修订LoRA。整个过程可以是包含共享模型和明确计算过程的Writer，不要求单网络、一次前向或全程可微。但这些开放条件不能改变下面的排除条件。

Owner最新明确要求：

> 只要最终环节是通过一系列手段准备好轨迹数据，然后通过微调给出最终LoRA的，我都不接受。只要是这种形式，就是和EMBER背离的。因为这种方法本质是在合成数据，而不是将视频编译为LoRA。

因此，下面这整类路线都不接受：

`视频 → 恢复／合成／搜索／采集动作轨迹 → 用这些轨迹微调策略 → 最终LoRA`。

无论轨迹来自模型还是自身真实交互，无论数据准备器是否经过共享学习，无论采集与微调是否交错、是否先生成初始LoRA再末端微调，都不改变这一判定。即使视频确有贡献、性能很好，也不能据此把这条路线作为EMBER。把流程改称Writer、蒸馏、经验吸收或学到的优化器，也不能绕过实际计算的判定。

请严格区分两件事：**训练共享Writer时，用合法动作和功能监督教会它如何从教学形成LoRA，是允许的；面对一个新教学条件，先准备动作训练数据，再拟合该条件的最终LoRA，是排除的。** 自身实践的记录可以成为理解与编译的证据，不能转成后一条路线。若方案使用梯度运算，请明确优化变量、目标与信息来源，并说明它在编译中的实际作用；不以“有梯度／无梯度”代替上述判断。

上一位专家最终提出了物理轨迹读取、短步动力学、候选动作搜索和经验认证，再用完整成功轨迹的FM与局部动作前缀回归直接训练LoRA。**这套完整方案尚未实施，现因方法形式被否决。** 我们不需要你继续补齐它，也不要求保留其中任何模块。旧材料中的“基本接受”“任务内优化可以替代生成”等表述，只代表当时时点，不能覆盖最新边界。

**二、现有资产、信息边界和最终目标。**

- source从generic `lerobot/pi05_base`出发，使用经任务等价审计的LIBERO-90中71 tasks×50成功episodes建立；不是读过目标40动作的`pi05_libero`。source基础权重和原生图文prefix冻结，normalization沿用冻结source统计。
- 目标是LIBERO四suite共40任务，当前显式24 train／8 validation／8 test。主要既有Writer训练使用train24＋12个已审计support tasks，共36个条件映射、每task50条示范。source见过71任务不等于Writer已经学过71个映射。其它non-held meta tasks须按现有合同审计、明确allowlist；不能静默扩大数据。
- 共享训练可用合法训练任务的动作、状态、关系、奖励等监督。主功能监督使用同task跨episode的教学与执行query，具体辅助标签须有来源与消费者，不能把动作标签混入教学输入。
- 新任务离线教学只包含指定视频与exact language；不能读该示范episode的action、proprio/state、物体真值、reward等配套标签，也不能另调该held任务的离线训练资料。task ID、文件名或专家字典不得成为路由。
- 自身实际交互所得动作、RGB/proprio、环境状态、物体位姿、接触、reward/success/terminal可以用于编译期理解和修订。这个许可按信息来源定义，不取消第一节的方法边界。模型预测、未执行候选和真实环境后果须分开。
- 观看与实践可多轮进行，当前LoRA可以参与后续理解。适应结束后，同一教学condition只形成一套完整38-target LoRA，供未参与该condition适应的新初态使用；Writer、教学读取、搜索与外部阶段选择退出，最终不更新参数、不看教学，也不读取特权状态。Test默认封存，最终评测反馈不得反哺方法或适应。
- 教学内部有序，frame stride5；每条视频独立保序编码，多视频只在集合阶段置换不变聚合，不平均原始帧或最终LoRA。one-shot、few-shot及是否支持动态K由真实性能与方法选择；声称动态K就须训练覆盖相应cardinality。
- 原生执行使用双相机render256/model224、双图180度rotate、8维proprio与7维action；10步flow产生50步action horizon，每次执行前5步后重规划。完整LoRA覆盖18层Q/V及action_in/out共38处。具体张量尺寸、padding/mask和消费者以现有实现为准。

强MT是有价值的控制起点，怎样利用其LoRA由方法决定；不要求维护旧Writer的参数化、memory token、rank、层对应或训练课程，也不要求此阶段匹配Writer与MT的参数预算。不能为了使用action expert，构造没有合法原生输入的假forward。

当前首先追求**完整固定LoRA的实际任务能力明显超过强MT**，同时逐步建立稳定性、任务覆盖与有益视频增量。视频确实提供操作知识是方法核心。无需在开工前完成全部消融或先胜过充分的同预算语言适应，但超过静态MT本身不证明视频贡献，输入敏感性也不等于理解。早期证据应服务完整方法判断。

**三、请继承实际历史，而不是从空白假设出发。**

旧方法已经有完整A/B、真实自身状态调用、跨episode FM与视频模块的功能梯度，不能用“给视频接上动作信用”重新描述已做过的工作。当前协议下，强T单点161/400，强MT153/400；T对MT保留117、新增44、丢失36，邻近较晚点为147/154/160/154/159。T的correct／同task另一视频／public-only／wrong为161/150/103/65：存在教学条件作用，但未建立明显、稳定、广泛的优势，public-only也不是独立训练的强语言baseline。

条件读写C改善了seen学习，held仍没有可靠突破；改变跨情境配对只产生有限差额。自由参数、关系监督、在线读视频、纠正教师、共享Writer RL、参数回读等各有具体正反证据。旧self-read没有真正进入环境，所以不能用其阴性否定所有实践后重读；状态信用分析没有策略更新，也不能当作新训练失败。没有实施的组合不得被合并成“已经试过”。

**四、请先形成完整方法架构，再展开关键数学推导。**

请先用总图或表格贯通共享训练、一个新教学条件的编译／实践、最终固定策略执行三个阶段。明确每个模块的真实输入、特征来源、计算、输出、消费者，以及共享参数、任务内状态、被生成LoRA和冻结参数各自的归属。说明哪些现有能力直接复用，哪些确需新训练。物理轨迹估计等已有能力可以作为工具，但不能替代视频到LoRA的核心贡献。

请重点推导以下完整联系，而不是仅写一个 `LoRA = G(video, experience)` 就跳过其中的学习问题：

1. **视频中什么信息能成为可迁移控制知识。** 实际表示从哪些图像／语言／原生特征算出，怎样处理时间、视角、对象与动作过程；相同目标下视频相对语言和静态图像增加什么。若使用物理量、阶段、接触或必要条件，分别说明哪些有标签、哪些可计算、哪些只能推断。单条成功路径不自动提供因果必要性标签，可解码也不等于可控制。
2. **教学内容怎样形成每层LoRA。** 给出具体编码、选择、汇聚、归一化、调制与参数输出／修订算子，关键张量维度及依赖。写清最终各目标层A/B如何计算，怎样作用于机器人自身执行时的hidden，例如相应的低秩算子怎样改变投影与后续动作。解释教学中的过程为什么可能在不同初态、不同自身状态及flow阶段被正确调用，而不是只复制一个时间表或记住训练task。
3. **实践反馈怎样修正编译。** 定义一次合法交互记录怎样被编码，它提供什么视频单独无法判定的新信息，怎样改变重读、当前编译状态或下一套LoRA。给出实际更新公式、初始化和终止规则；说明什么经过共享训练学成，什么只是算法规定。禁止用“筛出正确动作后再微调”填补这一环节，也不能只把失败轨迹拼进token后假定模型会用。
4. **训练为什么可能教会上述联系。** 写出完整目标、采样关系、标签来源、梯度消费者、必要的stop-gradient与冻结位置；功能信用怎样经过生成LoRA与真实policy回到教学和反馈读取模块。说明跨任务共享训练如何覆盖编译时的经验分布、多轮修订及最终新初态使用方式。若包含RL、辅助目标或分阶段训练，解释各自解决哪项具体缺口，不能用辅助loss下降替代真实控制学习。
5. **新能力与原有能力如何共同保留在一套参数中。** 明确机制依据、可能的干扰与限制；参数相加、残差较小或分阶段更新都不是不遗忘证明。说明怎样处理视频歧义、实际失败、长任务衔接和新初态迁移，而不另留运行时teacher、并行adapter或外部控制器。

数学推导须服务实际机制判断：对关键公式说明变量来源、计算可行性、性质成立的条件及限制。**可表示、能从现有监督学到、能迁移是三个不同问题。** 一般链式法则、注意力权重、Jacobian非零、低秩可达性或复杂符号本身不能证明视频理解。我们不要求事前证明必定成功，但需要你提出有依据、可以失败的预测。

请用一个现有操作任务贯穿全部计算：看到什么教学证据，当前策略缺什么，实践带来什么新认识，哪些具体特征与算子因此改变，怎样生成／修订同一套LoRA，最后为何有机会在新初态独立完成任务。例子不能手工给模型正确程序；阶段条件与官方完整成功条件须区分。给共享训练和新condition编译的伪代码，使参数与数据流能够被实现者复核。

然后将推荐机制与最近似历史方法比较：哪些功能原来已经存在，你真正改变了哪项学习联系或归纳偏置，为什么有机会改变过去的失败预测，新增成本与风险是什么。若认为旧基础应撤换，请给完整替代原理；若保留，也请给理由。不要为了与旧方案不同而增加模块。

**五、基于这套架构，给出详细而渐进的推进规划。**

首批应当是**小而完整的视频到LoRA学习与闭环循环**，能改变对主假说的判断。不要先排列一串只有局部指标的模块验收，再把局部通过自动拼成端到端资格。也不要一开始铺大矩阵或先要求证明唯一根因。

请按实际依赖给出每批的目标、前置资产、工作内容、数据与参数更新范围、产物、判断依据、预计wall-clock／GPU小时／存储峰值、扩大条件和停止条件。区分已有测量依据与待profile估计，首批应先测会影响总成本的关键吞吐。方法参数应作出选择，物理microbatch等执行参数可留给实测，不用猜出的精确数值冒充证据。

规划需要贯通：必要实现和数据准备、共享Writer的真实学习、有信息量的闭环节点、适应后新初态能力、相邻稳定性、正式评估与视频因果证据。训练共享Writer的数据准备允许；第一节排除的是以准备新任务动作数据来微调出最终LoRA。

比较要能改变判断，保留强参照与不利结果。早期请选择少量与机制直接相关、公平的证据判断教学是否提供有用知识；不机械前置全部语言适应与视频controls。最终选点只认预注册的single-checkpoint strict paired400，报告per-task／suite、覆盖、retained／gained／lost、churn及相邻成功集合。K1一轮每task50条合法teacher各用一次，跨checkpoint固定映射；同task换视频按合同检查。shuffled／reversed只在选点冻结后用于时序特异性，不进入训练或选点。

**请特别核算“一个教学条件一次编译／适应”的成本。** 正式400行对应400个不同task–video条件；若每个条件需要实践或内部学习，就要核算400次独立适应，不能按8个task各适应一次估价。小批可用一套LoRA在多个新初态检验迁移，但不能据此冒充正式400资格。分别列共享训练一次性成本、每condition成本和最终执行成本，说明哪些缓存可合法复用、哪些不能。

现有常规资源为两节点A40，合计最多8张；空闲总量不超过10张时合计上限6张，单节点至多6张，实际启动前还须现场准入。不要假定无限并行、无限环境重置或免费额外模型。若某项设计的成本明显不适合迭代，请在完整方法层面调整，并说明代价，不只把预算表写长。

**六、给出支持后续自主推进的判断原则。**

请选择本架构最关键的几个失败分支，说明竞争解释、优先核对的真实证据、能改变判断的最小干预，以及应继续训练、修订哪条联系或停止哪项假说。特别关注：视频内容可读但没有参数效用；实践改变了表示却没有有效修订；训练任务学会而held没有增益；局部阶段改善但完整能力或相邻保持变差；适应初态有效但新初态失败。

区分工程合同违约、学习尚未充分与有效科学阴性。负结果必须降低相应主假说的支持度，不能通过无限续训、rank/LR/seed小扫、添加辅助头或不断换架构维持同一个弱假说。与此同时，不把一次低分外推成整个目标不可能。后续主讨论负责科学分析、机制判断与接续，实验session负责实现、测试和运行；计划应让双方知道每批结果会改变什么决定，而不是等待owner逐步指定下一项实验。
