## 1. 当前真正需要审阅的问题

Owner希望A₀/B₀表达多任务可复用的公共基础，S/M从新视频形成具体适配，生成后立即有效。
公共policy仍读取exact language、自身图像和state；公共不等于所有任务输出相同动作。
未来可研究吸收可复用经验、保留旧能力及merge回source；这是长期动机，不是当前实施任务。

原T的full-only训练已经产生公共能力。Owner认为，所需可能只是避免条件通路重复承载共通作用，
而不是另造一套需要单独教会的底座。主讨论此前过于强调“无法普遍保证公共能力”，未充分展开软偏好。
后来提出的条件作用正则也未被Owner接受。Owner可以接受每批划分部分query直接训练公共A₀/B₀，
但仍担心：**这样是否只是强行让公共模型符合我们的设想，而不是共通能力自然形成？**

本次请审阅这个前提本身。共享参数、能读视频的公共表征、独立无视频控制能力不是同一个概念；
是否必须由同一A₀/B₀同时承担，尚未得到确认。完整闭环和新视频带来的能力是最终标准。
“更自然”须落实为数据和目标怎样决定分工、梯度怎样学习以及为何有望迁移；不以loss数量或公式简洁代替。

## 3. 实际基础与新候选的完整链路

source为冻结generic π0.5-derived LIBERO policy。T在38处使用LoRA：18层action-expert Q/V及action_in/out，
各层有自己的A₀/B₀。rank128是实现选择，不是所有task共用该子空间足够或整体参数预算受限的证明。
教学为exact language、有序双相机RGB、stride5，无teacher action/state/reward/task ID等privileged条件。
自身执行可用合法自身观测/state；训练动作只在授权监督侧出现。每condition只生成一套完整LoRA。

原T有：

```text
beta={A0,B0}; W_public,l = W_source,l + B0,l A0,l
native_beta(video,L) -> X_l[t,d_in,50], H[t,1024,50]
K_l,t = normalize(A0,l X_l,t)
V_l,t = O_l {GELU(P_l K_l,t + C_l Hbar_t) * D_l DeltaHbar_t}
M_(t+1) = M_t + (V_t - M_t K_t) K_t^T / 50
W_full,l = W_source,l + (B0,l+M_l) A0,l.
```

50是每帧内部的动作horizon槽，不是50帧，也不是已执行的50个动作。H是公共策略的动作计算响应，
不能直接命名为物理技能或正确teacher动作。教学key单位化，执行Aq不单位化；公共native与完整策略hidden也不同。
当前读取固定noise probe、tau=1、无state；noise/time可以改变，不是方法原则。

最近完整候选为：

```text
合法video+language -> 公共beta一次native X/H
 -> 时间×horizon上的c/d解释器
 -> 输入侧头读取真实X、当前A0 X及动态内容，生成S
 -> A(V)=A0+S
 -> 用A(V)X重新形成key，Value同时读取S X，生成M
 -> 唯一(A(V),B0+M) -> 自身状态下10步flow及闭环执行。
```

解释器讨论过4个独立、宽1024的Transformer block，不先平均50槽，也不要求为省参数循环共享层。
c承载上下文，d由真实跨帧变化产生并经零保持运算；语言/static负责选择，不能独立填充动态Value。
动态证据可从出现位置传到后来适用的写入地址，输出头不再乘回本地原始Delta H。
该结构仍可能学成模板开关，尚未证明操作语义或迁移能力。

Owner要求前序编码看不到后帧。§90相应采用H[t]-H[t-1]、帧块因果mask和不回灌未来的归一化/上下文；同帧50槽可互看。
转移(t-1,t)在t产生，§90起点寻址实例把它与X[t-1]配对，不能称t-1时已可见。
具体转移/写入索引尚未冻结；不能混用§88原双向版本和§90因果版本。
最终A在片尾形成，再据此重放特征编译M，故整个Writer不是逐帧在线因果；rollout前一次编译允许使用完整视频。

S不是左乘A₀换基，而是从高维X关联生成r×d_in矩阵。令Xi为归一化X、Delta U为动态生成的读取响应改变量：

```text
S_next = S + (Delta U - S Xi) Xi^T / 50
A_V = A0 + S
z0 = A0 X; delta_z = S X; zV = z0 + delta_z
K = normalize(zV); V_B = learned_head(K, c, d, delta_z)
M_next = M + (V_B - M K) K^T / 50.
```

S无需先求A₀的SVD才能相加，但有用调整取决于当前A₀作用；显式A₀X是让联系更清楚的候选接口。
S受本视频X张成空间限制。只做A_V=R_V A₀不扩展固定层输入行空间，但可能改变归一化寻址，不能简单称无效。
M须据生成后的同一A构造；A接收执行直接信用与经M返回的信用，不detach这条链。
以上只有小矩阵代数核验，没有真实模型训练或性能证据。

## 4. 已讨论的训练办法及未解决处

q含自身图像/state/语言及真实FM的x_tau、tau，y=epsilon-a。b(q)为公共policy输出，g(q,V)为完整输出。
d=g-b是整套非线性policy的输出差，不是各层M作用的简单相加。

| 办法 | 已找到的依据 | 未解决或不采纳的原因 |
| --- | --- | --- |
| 只有完整FM | 原T已由同一误差共同学习公共与条件模块 | 完整正确不单独确定公共能力，分工可以共同补偿 |
| full＋public FM | 条件已补偿公共错误时，公共误差仍受监督 | 有真实负例；可能限制视频表征或降低使用视频的需要 |
| 随机分query | 同期望双目标的计算折中，所有task覆盖两支 | 不创造信息，固定总量下完整监督减少、方差/Adam轨迹变化 |
| 复用public native输出监督 | action_out已算出却丢弃，可提供直接公共动作信用 | 原读取无state且单端点；改读取须重算信息墙、监督和成本 |
| 吸收S/M后混合训练 | 当前条件完整策略可成为新的公共策略 | 单task解不是公共知识；读取随beta变化，没有自动保留或幂等性 |
| 条件作用成本 | 相同完整能力下偏好公共承担可复用作用 | 也收缩必要适配；Owner未采纳 |

双目标是E||g-y||²+lambda E||b-y||²。完整信用回全部相关模块；公共信用只直接回A₀/B₀，
但其后beta变化会影响native、地址与条件目标。共同训练从合法identity和fresh optimizer开始，没有先训MT再冻结。
公共控制变好与视频语义被教会不是同一个结论。

随机分配在同task/teacher的query内部进行，不固定一些task或episode永久只训底座。
public概率p时，为保留双目标，完整样本权重1/(1-p)、公共样本lambda/p，或分别对子集求均值再加权。
p分配计算/精度，lambda决定目标权重。公共分支须同时关S/M；只关M仍有B₀S，不是原公共函数。
两个分支本已共享冻结prefix，省掉的是另一action-expert suffix及反向，不是整个模型2倍加速。

Owner明确纠正固定noise与tau=1不是必须。可以从随机噪声按公共策略逐步去噪，合法读取各tau的hidden；
主要输入差异是缺少teacher state，但需要多步suffix并重新明确监督和梯度。
标准FM的x_tau=tau*epsilon+(1-tau)*a在tau<1含真实动作；该hidden进入Writer就泄漏标签，detach不能解决。
独立训练分支可用正常FM，其含动作hidden不能复用为Writer条件；两条路线不能混为免费等价。

因子吸收也有具体问题：(B₀+M)(A₀+S)=B₀A₀+B₀S+MA₀+MS。
E[S]=E[M]=0不推出平均条件作用为0；分别平均因子不等于平均功能。一个适配不能直接当作公共风险梯度。
未来可用混合任务行为决定保留什么，但本轮不实施在线巩固、反复merge或任务内优化。

未采纳的软约束是L_full+lambda E||[(B₀+M)(A₀+S)-B₀A₀]sg(h_query)||²，约束层内实际改动而非raw因子范数。
它避免部分因子换尺度歧义，但也压缩必要的视频适配；尚未验证或被Owner采纳。

## 5. 数学支持尚未解决的实质问题

公共FM可纠正被条件代偿遮蔽的错误；线性化平方风险新增J_public^T J_public，约束部分full-only不可见方向。
这不是深网收敛或泛化保证，也未确定全部LoRA换基。双平方风险可写成加权输出中心误差加full/public输出差代价，
必须同时理解两项，部署不平均两条policy。

任意独立函数空间中b*=E[y|q]、g*=E[y|q,V]可同时最优；实际共享参数/native反馈不满足独立任意表达假设。
若exact language已确定task且teacher/query条件独立，理想训练总体的视频甚至可能不增加Bayes信息。
有限任务、未知映射与held任务的视频迁移是另一个问题；强公共目标可能学得更好的语言/任务路径，而非视频学习机制。
专家应审视数据支持、归纳偏置和优化怎样共同促成可迁移视频知识，不能只在公共/条件参数命名中寻找答案。

共通作用还可能是全体task共享、某些task共享，或依自身状态才体现的规则。
一个公共低rank因子对是否合理，应由完整机制判断，不能预设所有能力能线性平均进A₀/B₀。
如果当前分解制造不必要的学习问题，可以提出完整替代，同时保留冻结source、合法输入、唯一部署LoRA等真正合同。
