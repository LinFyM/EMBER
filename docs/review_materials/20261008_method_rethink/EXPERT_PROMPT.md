# 接续讨论：综述启发与新的方法空间

接着前几轮讨论，请结合这次综述和下面的新想法，彻底思考EMBER需要怎样的实质性方法更新。
[远程仓库](https://github.com/LinFyM/EMBER)已更新；请沿用你已经建立的项目与历史理解，只补看最新发生变化的部分。

目前长期没有突破，我担心继续围绕现有方法做局部修正仍然不够。希望你重新审视其基础假设和学习方式，
形成自己的完整方法判断。本次不预置主讨论的具体方案，也不要求你维护此前的建议。

**综述打开的几个思考方向**

- [HOST](https://arxiv.org/html/2607.20033v4)、[XSkill](https://arxiv.org/html/2307.09955v2)
  提醒我们重新考虑：教学中的操作进程，怎样对应到机器人自己的状态和当下需要的控制？
  这是否应改变视频理解、执行知识形成与参数编译之间的分工？
- [Doc-to-LoRA](https://proceedings.mlr.press/v306/charakorn26a.html)
  让我们关注：把上下文编译进参数，需要先具备怎样的功能理解和学习条件？
  这对EMBER现有的视频到LoRA学习有什么实质启发？
- [WAM-TTT](https://arxiv.org/html/2607.06988v2)
  提供了另一个视角：适应过程本身可以是被学习的对象。我们是否应该重新考虑“如何从视频获得适配”的整个过程？
- [ICRT](https://arxiv.org/html/2408.15980v2)、[Zero-WAM](https://arxiv.org/html/2608.26103v2)
  提醒我们区分：训练模型记住一组任务，与训练它真正利用新示范获得能力，究竟需要怎样不同的学习条件？

这些只是启发，不是让你拼装论文模块。各工作的训练资源、基础模型是否可训练、是否持续读取教学等条件与EMBER不同，
请从原理及适用条件判断，也可以提出综述之外更合适的认识。

**我新开放的一项边界**

不必坚持看完视频立刻一次生成LoRA、随后只能评估。生成过程中，允许source或安装阶段性LoRA的模型
在环境中实际动作，并利用自己的RGB、proprioception、所执行动作和可观察后果，继续理解教学或形成适配。

这里明确允许的是**无奖励的真实试做**：不给环境成功/奖励、目标物体真值或教师动作/state。
真实交互会带来新的环境反馈，其成本应单独计算；最终仍固定一套LoRA，在未参与适应的新初态评估。

请认真判断，这会怎样改变原来的学习问题：什么信息现在能够获得，什么仍然不可辨识？
没有正确动作和奖励反馈时，怎样才有依据形成有益的修正，而不是强化自己的错误？

**另一个关于阶段性理解和生成的直觉**

能否从基础模型开始，理解一段教学、形成阶段性LoRA，再让已经适配的模型参与下一段的理解和后续适配？
希望已有理解和控制功能能够积累，使最终模型在任务进行到不同状态时，都有合适的功能对应，
而不是新学一段就破坏此前学到的东西。

我提到去噪或SSM，只是在表达逐步形成、修订和保持的直觉，形式并不重要。
这不是要求固定视频分段、逐段叠加adapter或冻结旧参数；请判断这个动机怎样才有合理的数学与学习含义，
也可以指出它哪里不成立。尤其希望你认真思考“让LoRA参与理解过程”究竟可以增加什么。

**这次请你独立解决的问题**

请结合以上启发和新空间，重新判断：现在最值得撤换的基础假设或学习组织方式是什么？
怎样作较大的方法更新，才有理由预期解决长期未能突破的问题？

我希望得到一套由你推导出来的完整办法：视频与source已有知识怎样成为可用的中间特征，
这些特征怎样形成有效LoRA、作用于自己的控制，以及训练究竟怎样教会并保持这条联系。
请把训练期与新任务阶段分别讲清楚，落实到实际信息、算子、监督和梯度，不能只停在模块名字和一般公式上。

这两个想法可以采用、修正或否定，也不必同时使用。请继承你已了解的正反证据，
明确新方法相对最近似旧路线究竟改变了什么、为什么应当改变原来的失败预测。
如果某个关键前提仍然未知，请指出最有判断价值的检验，以及不同结果应怎样改变方法选择。

请优先形成你最看好的完整方向及其理由，而不是泛泛列出多种可能或给当前架构继续加补丁。
既不要求先证明必然成功，也不希望再靠一次次换名称、换模块来延续同一个没有进展的假设。
原有未变的科学边界继续保持；若你认为必须改变某项前提，请明确说明原因和代价。
