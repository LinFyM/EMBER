## 一、v5.2 的两种配方，首先指向“学习过程选择了不同的解”

**我现在最支持的解释是：EMBER 同时存在较容易学到的共同策略修正，以及更难建立、也更容易被后续学习改变的视频条件化修正。架构、初始化和更新组织共同决定两者怎样形成。**目前的证据不足以把全部问题归给某个模块，但已经足以排除“补齐信息、接通梯度，视频能力就会自然出现”的推论，也不足以支持“先训练语言基座，再增加视频残差”成为主线。

### 1. 两次 v5.2 的差异，比“batch 变大”具体得多

两次运行的 `src/ember/writer/model.py` 返回了相同的 Git blob：`58aa7bae…`。它们使用相同的 `CompleteLoRAWriter` 和零初始化末投影的 `FactorHead`。运行合同则明确改变了以下训练因素。

| 项目                       |        v5.2 old，step900 | v5.2 task-complete，macro400 |
| ------------------------ | ----------------------: | --------------------------: |
| 每次 optimizer update 的任务数 |        4，轮转覆盖完整 train24 |                   24，每次全部覆盖 |
| 每个视频条件的动作 queries        |                      21 |                          20 |
| 每次更新动作 queries           |                      84 |                         480 |
| 累计 optimizer updates     |                     900 |                         400 |
| 累计动作 queries             |                  75,600 |                     192,000 |
| 累计视频条件调用                 |                   3,600 |                       9,600 |
| 峰值学习率                    |      \(3\times10^{-4}\) |          \(3\times10^{-4}\) |
| warmup / cosine decay 时标 |            100 / 12,000 |                    17 / 400 |
| 终点日志中的实际学习率              | \(2.9600\times10^{-4}\) |    \(1.00045\times10^{-5}\) |

最后一行不是根据配置猜测：我补读了 old 的 `metrics.part005.jsonl` 第107条，即 step900，以及 task-complete 的 `metrics.part009.jsonl` 第40条，即 macro400。两者同时记录了累计 queries、条件调用和实际学习率。

这意味着，task-complete 获得了更多监督样本，但经历了更少的参数共同适应步骤，而且学习率在这些步骤内迅速衰减。**“看过更多数据”与“让多级条件化映射得到更充分的优化”在这里并不等价。**

行为变化也很有辨别力：

$$
132/138/74/82/83
\quad\longrightarrow\quad
120/109/107/111/124
$$

顺序为 correct、other、wrong、shuffled、reversed，各400。正确条件下降12，但三个破坏条件分别上升33、29、41。虽然跨配方变化不能当成单因素因果效应，这种形态仍然约束了解释：它不是简单的“整个网络训练坏了”，更符合**条件化响应减弱，同时一部分不依赖正确过程的能力增强**。它也可能包含对分布外输入更稳健的成分，因此不能把破坏条件变好本身视为坏事。

### 2. 最有根据的学习机制：逐级共同适应，而非立即获得过程监督

v5.2 的实际过程通路是：

$$
\text{Procedure}
\rightarrow \text{Core 条件化读取}
\rightarrow (\gamma,\beta)
\rightarrow \text{融合 slots}
\rightarrow \text{FactorHeads}
\rightarrow A/B
\rightarrow \text{执行 FM}.
$$

其中，`SlotNormalizedCoreProcedureCompiler` 的 `modulation.weight` 初始化为零，融合为

$$
c=(1+\gamma)\odot \operatorname{Norm}(c_{\rm core})+\beta;
$$

`FactorHead` 的末投影也初始化为零。零初始化维持了部署 LoRA 的 identity 起点，但同时决定了过程表示的监督要经过下游映射逐步建立之后才能充分传回。

这不是说“前两步没有梯度，所以400步不够”。那样解释过于粗糙。更实质的问题是：在一个简化的局部近似中，过程贡献包含类似

$$
\Delta u_{\rm process}\approx D\,M\,p(V,g)
$$

的乘性协作。编码器收到的有用信用依赖 \(D\) 和 \(M\) 已经学到什么；反过来，二者也依赖 \(p\) 是否能区分相关条件。**更新次数、学习率时标和任务混合方式，会改变这套协作形成的顺序。**

由此，我把以下解释排在较高位置：

**第一，task-complete 压缩了条件化通路的有效学习窗口。**这个解释直接受到初始化结构和实际学习率日志支持；但还没有模块级历史轨迹证明，过程通路确实因此错过了学习窗口，故不能提升为已确定根因。

**第二，多任务平均改变了早期条件化方向的生长方式。**理想采样下，两种配方可以估计同一个任务等权期望目标，但有限步 AdamW 的轨迹不会相同。每次覆盖24任务，更容易保留跨任务一致的修正；尚未形成共同坐标的任务相关过程梯度，则可能在汇总时弱化。这里说的是跨任务、跨模块的共同适应，不是已经被当前诊断否定的“共享 reader 两分支强烈互相抵消”。

**第三，视频路径是否形成，与它是否随后被保持是两个问题。**old 的 correct 从900步132，之后曾降至1200步92；v6-fast 的143也没有随着继续训练而稳定增长。因此，即使给过程通路更长学习窗口，也不能推出越训越好。

### 3. 哪些解释受到反证约束

我不会据此建议简单恢复小 batch、高学习率或旧训练长度。

v6-fast 在 task-complete 制度下达到143，说明全任务更新不构成普遍能力障碍；它的五臂143/135/125/128/129又说明绝对能力与强顺序依赖可以分离。当前 off 仍用四任务更新，却未恢复正确动态优势，进一步反对“每次只混四任务就能解决问题”。

同样，v5.2 的成功不能主要归功于某个精巧的自适应 frame selection。v6 设计记录，v5.2 的 frame-attention gate 在900—1800步仍约为0.0490—0.0504，接近其初始混合比例。这个历史记录更支持：**稳定的逐 token 视觉语义与后续过程调制可以共同产生视频依赖，不必先获得复杂的帧选择机制。**

最后，两次旧 v5.2 都使用同一50-episode池的独立 teacher/action 日程；当前则实施互斥分池。这个差异影响旧新整体比较，却不能解释两次 v5.2 自身的反差，也不能未经进一步检查就被称为数据泄漏。

## 二、后继为什么没有整体超过它：被改善的，经常不是同一个瓶颈

### 1. “后继保留更多信息”并不是严格的函数类包含关系

旧 v5.2 有三个观察侧 Meta：Text、VL、Action；语义 Core 保留任务 token 轴并读真实 patch。当前 `native.py` 冻结 vision/Gemma prefix，只训练 Action Meta，并保留最终完整50个 horizon hidden。这是在**不同轴上增加和减少了可学习性**，不能概括成旧输入是新输入的严格子集。

当前 Horizon 的过程路径又经历了：

$$
[T,50,1024]
\rightarrow[T,50,d]
\rightarrow\text{局部对应、视觉核实、递推与回写}
\rightarrow P_4[T,d].
$$

`contextual_language()` 将每帧任务 token 读成一个条件向量；`horizon_read` 再将每帧完整 H 读成一个过程 token。C 的 `VisualSemanticEncoder` 确实保留了语言 token 轴，但该分支在帧集合上聚合、不承担视频顺序；过程分支仍输出每帧一个向量。

因此，后继改善了 H 轴的信息完整性，却没有自动解决：**哪个对象、哪种关系、哪个过程变化，在后续参数生成中持续保持可区分。**这是我认为目前比“再增加过程模块”更值得重视的表示问题。

不过，冻结 Gemma 是否已经造成不可恢复的语义损失，仍未被单独识别。我不会把恢复 VL Meta 当成无需验证的答案。

### 2. 历史正负证据支持的是一条有断点的链，而非全面无效

| 证据组             | 应保留的正证据                                          | 它实际限制了什么解释                                  |
| --------------- | ------------------------------------------------ | ------------------------------------------- |
| v6、GOMQ         | v6-fast143；GOMQ151，且其五臂151/139/131/127/115仍有视频差额 | 后继并非全无视频特异性；单点能力和差额没有形成稳定整体胜出               |
| 多视频、LPCP        | 同任务参数变化显著降低；LPCP曾143                             | 降低参数变化不等于改善执行；BA cosine极高仍可伴随大量 gained/lost |
| G1、G2           | 限制输出方向的投影有真实行为代价；有序响应在具体动态监督下可读                  | 不能说原生响应没信息，也不能说任意低维输出都足够                    |
| G3、primal 等     | task-local、fixed-chart、free-summary有局部通过         | 有效 code 可被给定或优化，不等于共享 Writer 能从自然视频预测它      |
| P/Q、完整输出、clone  | 完整输出有获取收益；匹配任务曝光的 whole-Writer clone明显更强         | 共享获取问题真实存在，不能把所有弱结果归给未见任务迁移                 |
| Horizon off、D绑定 | 删除额外 Compiler query 有跨初始化净收益；D绑定改善训练获取           | 改善查询或共享方式会改变行为，但没有统一解决视频价值与迁移               |
| C、无变化参照         | 训练动作拟合和部分训练执行改善；静态伪时间响应被大幅削弱                     | 数学上的过程“干净”没有自动变成正确视频净收益                     |

这些数值和边界分别由历史地图、G1/G2及G3账本、clone对照、Horizon干预和最新结果支持。尤其 GOMQ 的151、v5.2的强差额和其他模型的稳定性，不能拼成一个不存在的模型。

其中有三组结果，对新设计尤其重要。

#### 完整输出有价值，但“更多 decoder 参数”不是答案

当前 `NativeFactorLoRADecoder` 使用

$$
A=A_0+D_A\operatorname{GELU}(U_Ac),\qquad
B=D_B\operatorname{GELU}(U_Bc),
$$

且 \(D\) 按 target、rank、side 独立。这提供了很直接的因子学习通道，但也允许 decoder 在缺乏充分分化的 code 上学出不少共同修正。

然而，直接把 \(D\) 跨 rank 绑定也失败了：训练获取改善，validation却115→82。实际 code 的 Gram 矩阵高度集中于共同方向，使绑定后的局部更新核混合了 rank 梯度。这支持**输出参数共享必须与输入 code 的几何共同分析**，反对“参数太多，所以绑起来就会泛化”的单因素解释。

#### 共享获取差距，不只是“某个任务还没见够数据”

whole-Writer clone 对照中，两项任务各匹配了128次任务执行、1024条 action rows；合同明确说明，clone和shared18的任务权重有意不同。因此，它不是纯粹的容量隔离实验，但确实排除了“clone只是多看了这些动作样本”的解释。结合14/20对共享3或4/20，以及共享过程没有先强后弱，更支持**任务相关更新在共享学习中未能充分形成**，而不仅是已有能力被遗忘。

#### 当前过程通路的弱净价值，已经有功能证据，不只是 attention 图像

C200的独立动作表中：

* source→correct 的 FM 改善为 **0.040365**，24/24任务改善；
* correct相对static的平均优势为 **0.000414**；
* correct相对shuffle的优势为 **0.000410**，该任务 bootstrap 区间略高于零；
* 固定语义后，把正确过程换成static过程，只增加约 **0.0000438** 的 FM。

这意味着不能说“完全没有顺序信息”；但从平均误差量级看，过程条件差异远小于共同适配收益。这个比例不是梯度比例，也不是行为归因百分比。

闭环进一步说明，小幅离线优势尚未兑现：C200固定机制面板 correct42、static49、S51、source15，各96；固定语义后的correct/static过程均15/32。无变化参照削弱静态时间响应后，训练侧差额仍不确定，validation为34/400，且只观察到200步。

**所以当前不能只补“过程表示含有运动”这一条件。真正缺的是让过程表示在与执行相关的位置获得足够明确的功能意义，并把这种意义保留进完整 LoRA。**

## 三、我选择的机制理论：动作功能信用在长链条中被稀释，并伴随共同适应的漂移

这里需要区分事实与推导。

**已有事实**包括：当前 VJP 链真实接通；Meta有梯度且没有陈旧响应缓存；若干完整学习臂没有触发梯度裁剪；共享 reader 两分支没有发现强稳定抵消。与此同时，四次真实其他任务更新已经造成一个预选成功任务失效；模块替换显示 P 的变化，或 C与D的组合变化，都可能造成不同失败。

**我据此提出的推导**是：

当前视频编码器主要通过下列复合 Jacobian 学习：

$$
\nabla_{\phi}\mathcal L
=
J_{\text{video},\phi}^{\top}
J_{\text{compiler}}^{\top}
J_{\text{factor}}^{\top}
J_{\text{policy},\Delta}^{\top}
\nabla_u\mathcal L.
$$

这个链条有梯度，并不意味着它给出了容易学习、跨任务一致的“应该从视频读什么”的信用。

同一个正确视频生成的 LoRA，要解释另一 episode 的许多不同执行状态。最终聚合到 A/B 的 cotangent，混合了目标选择、接近、抓取、运输、释放等需求。编码器必须同时发现视频中的操作结构、找到跨 episode 的对应关系，并适应正在变化的 Compiler/D。共同任务语义比较容易在这条链上获得一致信用；细粒度过程信用则更依赖整条链已经协调。

这能同时容纳以下现象：

* v5.2较短的参数化与特定优化轨迹，曾经自然形成有效条件化；
* 同图改变更新组织后，条件化强度发生显著变化；
* 扩充 H 和过程模块后，表示更丰富，但功能信用没有相应变得更可学习；
* 独立任务学习较强，任务平均之后获取不足；
* decoder本身学到有用变化，但编码器与Compiler继续变化后，一部分收益被改变或抵消。

这不是唯一解释。尤其不能把所有损害都叫“信用稀释”：BBQ和橙汁实例有实际目标选择改变，另一些组合则围绕正确对象但执行失败。已有轨迹要求我们保留语义选择、操作实现和模块交互三种不同失效。

**我给这项理论的优先级高于“再增加时间信息”，原因是前者能解释已有信息为何没有形成有益更新；后者只补充已有多次正控已经证明存在的东西。**

## 四、据此选择的完整方案：用训练期执行查询，直接教会共享视频表示怎样服务控制

我建议的主线是：

> **保留完整标准 LoRA 出口，重建保留任务语义轴的有序视频表示，并增加一个仅在训练期使用的“执行观测查询视频”的动作功能读出，与完整 LoRA 编译路径共同学习。**

不建立独立冻结语言基座，不恢复固定 carrier，不部署第二个控制器，不先把 Program 训练完冻结后再开始编译。

### 1. 原始输入到逐帧证据：保留已经验证的原生读取

仍从准确语言和K=1真实视频开始，stride5、合法相机处理与固定数据角色保持。

每帧使用当前真实 prefix 路径，得到：

$$
Z_t^{\rm patch},\qquad Z_{t,i}^{\rm task},\qquad
R_{t,h},\ h=1,\dots,50.
$$

其中 \(i\) 是准确任务语言的 token 位置，\(h\) 是 Action Expert 的相对动作 horizon。Action Meta继续属于共享视频读取模块；执行侧 source基础权重冻结，执行时不安装读取侧Meta。完整50-H在第一次真实任务条件、跨帧联合读取之前保留。当前 `NativeVideoObserver.capture()` 已提供这一合法原生接口，不需要新造一个视觉 backbone。

这里我暂保留冻结 vision/Gemma，而不是直接恢复旧三组Meta：当前证据还没有证明必须修改它，且它允许可靠复用prefix。这个选择不等于认定其表征永远足够。

### 2. 过程表示：保留“任务 token × 视频时间”，不立即压成每帧一个过程向量

先形成每帧逐任务 token 的真实视觉 grounding：

$$
z_{t,i}
=
\operatorname{Ground}\bigl(Z_{t,i}^{\rm task},Z_t^{\rm patch}\bigr).
$$

然后用相邻两帧的任务语义共同提出查询，读取两端完整H及视觉证据：

$$
e_{t,i}
=
\Psi\!\left(
z_{t-1,i},z_{t,i},
\operatorname{Read}_{i}(R_{t-1,1:50},R_{t,1:50}),
\text{两端 patch 内容}
\right).
$$

关键是，**第一次 H 压缩已经同时看到了任务条件和两个真实时间端点；压缩之后仍保留 \(i\) 轴。**

接着用少量交替的标准 attention blocks，在每个时间点组合语言 token，并沿视频时间做过去定向处理，得到

$$
E=\{E_{t,i}\}\in\mathbb R^{T\times L\times d}.
$$

这种表示不硬编码“第几个 event就是抓取”，不做单调DP分段，也不将教师帧编号当机器人执行阶段。它为“哪个对象的哪种关系正在变化”保留可分辨的位置。

这一步相对历史的实质差异是：

* v5.2 的语言 token 轴主要保留在无序Core；
* v6虽然构造 \(D_f[L,d]\)，随后被单个Action probe query读成每帧一个向量；
* 当前Horizon/C的有序主干仍归约到 \(P_4[T,d]\)；
* **这里让任务语义轴一直进入长程有序表示与后续功能读取。**

我会删去当前四组“对应—H-query—双端视觉核实—逐H GRU—长程回写”的反复循环，改为一次局部任务条件读取加简洁有序组织。这是明确的架构替换，不保留四帧窗口和四组回写作为永久要求。

理由不只是降低复杂度。`relation.py` 在对应偏置中同时使用视频 gap与H索引差；但 \(R_{t,h}\) 是固定probe、flow time=1下的隐状态，并非正确采样完成的未来轨迹。让网络有机会利用H结构是合理的，把大量学习能力押在这种对应结构上，则仍缺乏行为证据。新读法保留H信息，却不先要求它解释成物理时间对齐。

### 3. 一次生成完整 LoRA：保留自由输出，避免重开已失败的参数化链

部署路径从整个 \(E\) 读取target/rank codes：

$$
c_{j,r}=\operatorname{Compile}_{j,r}(E),
$$

再生成全部38个目标的完整A/B：

$$
A_{j,r}=A^0_{j,r}+D^A_{j,r}\operatorname{GELU}(U_Ac_{j,r}),
$$

$$
B_{j,:,r}=D^B_{j,r}\operatorname{GELU}(U_Bc_{j,r}).
$$

首个候选可以继续使用当前独立native D。这不是把它视为最优decoder，而是已有D绑定反证不足以支持现在同时更换输出共享方式。也不重新引入X/Y signed span、固定A或raw-factor重建目标。G1与后来的完整输出结果，都要求谨慎保留有行为价值的方向自由度。

Compiler保留target/rank身份，但不增加已经有负面学习证据的额外静态语言仿射query。准确语言已经进入逐token视觉和有序表示。**这里的主要改动是它读取的内容以及这些内容得到的监督，不是再发明一种query几何修补。**

### 4. 新增的关键训练接口：机器人当前观测查询同一份 \(E\)

对于另一episode的合法执行query，用不带编译LoRA的冻结source得到：

$$
q_{x,h}=Q_{\theta_0}(o_{\rm robot},g,a_\tau,\tau)_h,
$$

其中 \(a_\tau,\tau\) 是正常FM训练使用的噪声动作和flow time，绝不进入视频编码器或Compiler。

一个小型训练期读出头让每个执行query读取同一份视频表示：

$$
r_{x,h}
=
\operatorname{Attn}\bigl(Q(q_{x,h}),K(E),V(E)\bigr),
$$

$$
\tilde u_{x,h}
=
u_{0,x,h}
+
W_o\!\left[
W_q q_{x,h}\odot W_r r_{x,h}
\right].
$$

读出头的新增修正必须使用视频读出值，不设置独立的可训练query-only动作残差；source本身仍可使用准确语言和自身观测。这个限制不能从数学上保证动态必要性，但避免辅助头仅凭自身容量成为另一个普通动作模型。

它所学习的问题十分具体：

> 机器人现在处在这个合法自身观测中，教学视频中的哪些对象关系和有序变化，对当前动作预测有帮助？

这个头与Compiler共享同一个视频编码器和同一个 \(E\)，不另建一个只服务辅助loss的表示。它只在训练和明确标记的诊断中存在。

**部署时删除该读出头和视频表示。**保留的只有一次编译所得完整LoRA；机器人每次重规划仍只读取自己的输入。

## 五、训练如何改变学习动态，而不只增加一个好看的辅助任务

### 1. 三项功能目标，各自承担明确作用

设 \(u_C\) 是挂载编译LoRA的真实source动作预测，\(\tilde u\) 是训练期视频读出头的预测，\(u^\star\) 是合法动作示范对应的FM目标：

$$
\mathcal L_C=\|u_C-u^\star\|^2,
$$

$$
\mathcal L_R=\|\tilde u-u^\star\|^2,
$$

$$
\mathcal L_D=\|u_C-\operatorname{sg}(\tilde u)\|^2.
$$

训练使用

$$
\mathcal L=\mathcal L_C+\lambda_R\mathcal L_R+\lambda_D\mathcal L_D.
$$

所有项按真实有效动作维度与任务权重归一；不让padding维度贡献虚假改善。当前 `pi05_mean_flow_loss()` 已明确截取实际action width，这一处理应沿用。

三项作用不同：

**\(\mathcal L_C\)** 保证完整LoRA始终直接接受真实动作监督，不能用辅助头成绩替代它。

**\(\mathcal L_R\)** 给视频表示增加一条较短、由当前执行状态明确条件化的功能信用路径。它不必先等待大规模D、Compiler和视频编码器彼此协调，才知道哪段教学内容与动作有关。

**\(\mathcal L_D\)** 要求固定LoRA在相同自身观测、flow time和noise上实现辅助读出得到的功能。目标端stop-gradient，辅助头由真实动作监督锚定，不以“和学生一致”作为自己的学习目标。

蒸馏项不应从初始化就强压学生追随尚未学会的头。采用一个预注册、短暂的读出预热和蒸馏权重渐增即可；不恢复“G2通过后冻结Program，再长期训练G3”的分段制度。全部共享视频模块从头共同学习，完整LoRA的真实FM从第一步就存在。

### 2. 为什么这不是旧方案已有的同一句话

旧G2已经有动作与progress监督，`stage0_objective.py` 也已经有frame/event动作重建和一致性损失。不能把“增加动作辅助loss”当成新思想。其合同主要监督local next-10-phase动作摘要、event后验与其他Program量；旧G3则冻结Program，再学习共享native-factor选择。

这里改变的是**监督的条件变量与进入位置**：

* 不是从教学帧单独预测教师动作摘要；
* 不是给一个privileged task code再拟合decoder；
* 不是把事件表示冻结后要求另一模块理解它；
* 而是在另一episode的真实执行观测上，直接读取同一视频表示预测动作函数，并要求唯一LoRA同时实现该函数。

因此，监督直接连接“教学中的操作证据”和“机器人自身状态下的控制需求”。这正是当前长梯度链需要自行发现、却尚未可靠学到的对应关系。

它也不是新增部署输入：动作标签只在loss端，query观测只进入训练读出头与执行policy；**Compiler仍只接收视频和语言，且同一生成LoRA复用于整组query。**

### 3. 它没有消除监督识别边界

这里必须保留一个重要限制：准确语言可能已经充分标识任务，同任务跨episode动作监督在统计上未必要求使用视频。新增读出头没有创造额外任务信息，也不构成视频必要性的数学证明。

我选择它，是为了改变**有限数据、有限优化下的学习条件**：让操作证据先以更直接的形式获得功能意义，再由真实policy损失约束其可编译性。

它的可证伪主张是：

> 如果当前主要困难包含功能信用过长与教学—执行对应难学，那么增加这个短功能路径，应当提高正确视频的可用收益，并有一部分收益能够进入同一份固定LoRA。

辅助头只变强、LoRA不变强，不算成功；辅助头只增强静态任务能力，也不算恢复过程特异性。

### 4. 训练配方选择：先不同时改变数据支持与优化时钟

首个对照应沿用off的四suite任务等权、每任务一个K1条件与64个action queries，保持既定video/action/diagnostic角色，不把R的两个K1×32queries当成已证明更优的分配，也不同时扩大到95-task。R相对off的同query预算结果已经约束了“更多条件自然更好”的说法。

同样，不把旧v5.2的 \(3\times10^{-4}\) 直接搬到当前大规模native D。先保持一个明确的共同优化合同，以裁决新信息组织和功能信用路径。v5.2的学习时标证据说明要认真记录优化过程，不足以指定一个跨架构通用学习率。

训练读出复用同一批合法query，不增加独立动作数据，但会增加source query特征计算与监督运算。必须分别报告独立样本、条件调用、optimizer updates和实际source forward次数，不能把这些成本全部藏进“相同query预算”。

当前按条件缓存冻结prefix、在同一参数版本重放Meta VJP的机制可以沿用；读出loss和编译loss对视频表示的cotangent汇总之后，再回传观察侧，不能因为新增监督就缓存跨optimizer step的旧响应。

## 六、一次固定 LoRA 怎样实现这种控制，以及它可能失败在哪里

在执行侧，LoRA作用于机器人当前激活：

$$
q'=W_qh+\frac{\alpha}{r}B_qA_qh,\qquad
v'=W_vh+\frac{\alpha}{r}B_vA_vh.
$$

因此，视频编译的参数可以改变当前动作token如何读取**机器人自己的**图像和任务上下文，也可以改变后续动作表示与输入输出投影。参数固定，不等于修正恒定；修正随 \(h\) 改变。

训练期的执行查询读出，恰好提供了一个更直接的目标：“在这些自身状态下，应使用这部分教学信息”。学生必须将这种条件选择折叠进q/v及输入输出投影的固定参数，而不能在rollout中继续查询视频。

已有Q投影干预支持这些挂载点具有实际目标选择作用：BBQ动作分叉主要经Q相关交互传递，但直接删除Q又不能恢复正确行为，因为有用适配也被删掉了。它支持挂载位置具有控制意义，不证明新读出一定能被rank16编译。

本方案主要有四种明确失败条件。

**第一，视频表示仍然没有可利用的细粒度信息。**辅助读出在独立执行query和真实闭环中也没有正确动态优势。此时不能再把问题推给Compiler；冻结视觉前端或过程表征不足的解释会升高。

**第二，辅助读出学到了视频控制，但固定rank16 LoRA无法实现它。**训练期按观测读视频比一次参数编译更自由。task-local专家250/400并不证明这类视频条件函数全部属于可编译函数类。若出现持久的辅助头—LoRA功能与闭环差距，本方案的核心编译假设失败，不能把辅助头偷偷部署。

**第三，联合训练仍主要学成任务识别。**正常视频、错误视频和无序集合带来的共同提升相近。此时较短梯度路径改善了拟合，但没有改善需要的机制。

**第四，视频收益形成后仍发生共享漂移。**实际跨任务损害证据说明，功能读出只能改善信用，不能保证保留。必须检查相邻checkpoint的正收益和成功集合；不能再次用单个峰值宣告解决。

我因此不会承诺这套方案整体超过所有历史版本。它的优势在于：每种失败都对应一个可区分的接口，而不是继续用“更复杂的过程模型应该会理解视频”解释一切。

## 七、哪些保留，哪些替换，哪些才是实质改动

| 机制                           | 历史或当前已经存在                          | 本次判断                       |
| ---------------------------- | ---------------------------------- | -------------------------- |
| 准确语言、真实patch、Action Expert响应 | v5.2/v6及当前均有                       | 保留；不当作新增贡献                 |
| 跨episode动作监督、真实VJP           | 早期和当前均有，分池合同有差别                    | 保留当前严格信息墙；不再将其当成尚待补上的机制    |

这张表的重点是：**我并不把一个新的attention模块、一条差分通路或一个“过程”名称当成新机制。**值得投入的变化，是把同一份教学表示放到机器人自身控制问题中直接接受监督，同时仍要求完整LoRA在训练期间共同实现它。

## 八、用少量实验裁决，而不是再开启一串版本

### 实验一：一个有限的2×2，区分表示改变与信用路径改变

只比较两个因素：

|                  | 当前完整LoRA FM训练 | 加入执行查询功能读出与蒸馏     |
| ---------------- | ------------- | ----------------- |
| 当前off过程表示        | 基准            | 检验短功能信用能否直接改善现有表示 |
| 保留时间×任务token的新表示 | 检验表示本身是否足够    | 完整方案              |

四臂使用相同source、分池、独立D、任务与query日程、预注册节点。新增监督成本单独报告，不声称等计算量。先在Train内合法留出query和冻结开发机制面板判断；选定方案后再用固定validation8检验迁移，Test不开放。

这不是四条平行研究路线，而是对一个机制理论的最小交互检验。

* **当前表示＋新信用就改善正确视频收益**：支持信用瓶颈，削弱“必须重建表示”的判断。
* **新表示＋纯FM就恢复收益**：支持表示组织是主要限制，削弱辅助读出的必要性。
* **仅完整组合有效**：支持表示与信用需要共同改变。
* **四臂都主要增加共同能力，没有正确动态净收益**：否定本轮主线足以恢复特异性的判断；不通过增seed、改margin或无限续训挽救。

### 实验二：将辅助读出与可部署LoRA分开裁决

在同一正确视频、相同自身观测及配对随机性下，比较训练期读出和唯一LoRA的功能及闭环表现。辅助读出成绩明确标记为诊断，不计入EMBER部署成绩。

关键预测是：正确视频的收益先在直接功能读出中变得可辨认，随后在LoRA中出现，而不是只形成更大的latent差异。

若读出有稳定有益特异性，LoRA始终无法承接，便直接否定“该表示可以通过当前完整rank16出口可靠编译”的假设。此时不回到free-code恢复链，也不把部署约束改成在线读视频。

### 实验三：顺序破坏与非语义时间扰动应产生不同结果

只在冻结模型上做预注册开发诊断：保持真实内容的时间重参数化，与破坏操作先后的真实帧干预分开。前者保持操作含义，后者改变它；不能都用一个“shuffle”名称概括。

理论预测是：收益应对不改变操作含义的时长变化相对稳定，对必要先后关系的破坏更敏感，并且这种差异在完整LoRA中成立。若所有时序扰动都同样有害，更像输入脆弱性；若只在辅助头中成立，仍然是编译失败。

---

**最终选择上，我会把“保留语义角色的有序表示＋执行查询条件化的联合功能学习”放在最高优先级。**它保留v5.2证明过的普通监督可学性、G1证明过的输出方向价值、G2证明过的动态可读性，同时正面处理G3、clone和当前C揭示的共享获取与功能落地缺口。

v5.2两种配方的唯一归因仍缺少历史过程通路的学习轨迹；这会影响如何安排优化时标，但不阻塞上述设计选择。当前证据已经足够支持一个更具体的判断：**EMBER下一次最值得改变的，是视频内容如何在学习中获得“对机器人当前控制有用”的含义，而非继续累加过程计算，或用错误条件退化来证明视频被使用。**
