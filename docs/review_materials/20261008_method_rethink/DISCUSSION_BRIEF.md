# 讨论衔接：EMBER从教学与实践获得固定LoRA能力

截至2026-10-08。本文供无法读取旧专家对话的新专家使用。它综合仓库已存证据、第四/第五轮回复和owner最新修正。
“专家建议”“主讨论判断”“已执行结果”分别标明；没有新实验、已选定的完整架构或active design。

## 1. 现在要完成什么

EMBER研究能否从已有π0.5控制能力出发，根据exact task language和一条或多条action-hidden正确教学视频，
理解任务怎样完成，结合自身实践获得相应能力，最终把能力落实到**一套完整、固定的task-conditioned LoRA**。
同一个教学条件形成的这套LoRA用于该条件下所有新的评测初态，不能每个评测初态重新适应、选一套参数或继续搜索。

最初主线曾要求零交互地前向生成。Owner后来先允许无奖励试做，继而明确允许使用模型自行交互得到的完整环境反馈。
因此，“编译”现在可以包含任务内学习与多轮修订，并不要求必须由一个共享神经Writer前向猜出全部参数。
最终source基础权重与原生图文prefix仍冻结；MT是有价值的控制起点，MT的LoRA如何初始化、保留或更新由完整方法选择。

**当前第一阶段目标是最终source＋唯一固定LoRA的完整任务表现明显超过强MT。**
不要求先击败同预算、充分训练的语言适应方法，也不把补齐全部视频因果对照当作开始工作的前置条件。
这不把研究改成与视频无关的task-local RL：方法仍须具体说明从视频学到了什么“怎样做”的知识，怎样改变实践与最终能力。
以后声称视频有额外价值时，仍要在公平资源条件下建立证据；超过静态MT本身不证明收益来自视频。

Owner基本接受第五轮“教学引导实践→发现有效行为→训练进最终LoRA”的方向。
**这次先要具体完整架构，然后才是推进规划和困难处理原则。** 不能只交候选菜单、模块名称、局部探针或下一批实验清单。

## 2. 最新信息边界：按来源区分

| 阶段/来源 | 可以用什么 | 必须区分的边界 |
| --- | --- | --- |
| 共享训练 | 合法训练任务的动作、状态、关系、奖励及其它已授权监督 | 训练监督从未被限制为只有视频；不扩充现有外部数据规模，不把held离线标签混入共享训练 |
| validation离线教学 | 指定action-hidden视频及既定exact language | 不读取该示范episode的动作、proprio/state、奖励或配套标签；不另取该task的训练数据帮助适应 |
| validation自身交互 | 自己实际执行的动作、RGB/proprio、环境状态、物体位姿、接触、reward/success/terminal等 | 可用于理解、评价、探索、学习和策略修订；这与读取教师数据集标签不同 |
| 模型内部计算 | 既有模型特征、完整action horizon、hidden、候选动作与预测 | 可以充分利用，但模型推断、未执行候选和真实环境后果分别标明；不虚构teacher proprio填补输入 |
| 最终评测 | 固定source＋同一套完整LoRA；原政策合法的自身观测与语言 | 采用未参与适应的新初态；不继续更新、看教学、运行候选搜索或外部阶段选择器；Test仍默认封存 |

允许多轮观看—实践—重读—更新，没有只能看一遍、两遍或只能试做一次的限制。轮数、环境步数、重置和停止规则须在具体实验中登记、计费；
允许使用success并不等于免费无限重置。适应与最终评测的初态、反馈用途和参数状态必须分开，不能把交互成绩记成zero-interaction。
任务内更新的参数副本、共享预训练参数和最终部署参数要在设计中明确；不能含混地把不同任务的held适应经验混成共享训练。

Owner的乒乓球类比是：身体基础对应source/MT；看发球视频对应action-hidden教学；自己练习与结果对应自身交互反馈；
根据差距反复观看、调整和练习对应教学理解与LoRA修订；练后稳定发球对应固定LoRA在新初态独立完成任务。
“假设由教练手把手给正确动作”只类比**新任务额外提供正确动作标签**，是另一种信息来源；当前方案不存在一个先在场、后撤下的教练模块。
训练任务的合法动作监督、自己发现的有效动作做FM，都不因此被禁止。自己采取过的动作也不能全部自动视作正确标签。

## 3. 已有系统与基准，避免重新发明已经做过的工作

Source由generic `lerobot/pi05_base`在经过specification审计的LIBERO-90中71 tasks×50成功episodes建立，随后冻结；
不是读过目标40动作的`pi05_libero`。目标40含Spatial/Object/Goal/Long四suite，当前显式24 train/8 validation/8 test。
T/C主要在train24＋12个审计过的support tasks学习，共36个视频→适配映射；source见过71个任务不等于Writer学过71个条件映射。
后续曾有support71支线，实际曝光与完成边界见原件，不把“更多同task视频”等同更多独立规则。

教学保留视频内部顺序，stride5及末帧。最终策略双相机render256/model224、双图180度rotate，8维state与7维action，
10步flow生成50-action horizon，每次执行前5步再观测，settling10，suite horizon为220/280/300/520。
完整38-target LoRA覆盖18层Q/V及action_in/out；当前T/C rank128。共享Writer总参数、输出rank、共同子空间是不同概念，
owner没有要求当前阶段匹配MT参数量，也没有要求rank扫描。

原T的实际学习链并非“视频表示没有收到动作信用”：

1. 双RGB和exact language走真实冻结图文prefix，teacher prompt省略State段；公共LoRA参与native读取。
   固定50×32 Gaussian probe、flow time=1得到每帧完整H与各层实际projection输入X。
2. 各层 `K=normalize(A X)`，Value由K、H及相邻H变化构成；顺序delta写入从0累积M。
   最终为完整 `(A, B0+M)`，实际执行时M作用于机器人自己的、随状态与flow变化的hidden。
3. 同task、不同episode的真实RGB/state/action query通过同一生成LoRA做完整FM；同一参数版本重放编译与native信用。
   常用每macro4tasks×28queries=112，真实梯度到达公共参数与视频读写模块。

C进一步用4层因果解释器处理完整时序/horizon，视频修订A得到A0+S，再用最终A编译B0+M；真实FM共同训练。
这些方法已经包含完整A/B、时序、真实自身状态调用和功能信用。新的方法不能只靠重新命名这些性质证明进步。
同时，H是模型计算响应，固定probe下的H差分不是teacher动作或已经理解的接触效果。
详细算子与实际代码身份见[MECHANISM](../20261007_research_reassessment/MECHANISM.md)。

## 5. 五轮专家意见怎样演进

1. **第一轮**重建历史：条件控制确实存在，但局部有用功能未变成新任务上可靠的自身调用；
   降低继续为T/C堆局部头的优先级，提出更自由完整输出及有效自身状态监督的候选。
2. **第二轮**修正：自由A/B与更近标签并未解释共享教学如何跨任务学会；重点转为跨情境的功能学习关系，
   提出新教学编码/完整编译等组合，但只愿支持有界检验。
3. **第三轮**进一步收窄：撤回把完整组合直接推荐为长期主线，只保留同T的Within/Product学习比较。
   该比较已执行且未修复总体能力；新encoder＋自由A/B＋MT起点的完整组合没有实施。
   之后独立教师与状态信用分析由主讨论自行选择，不能统称专家方案连续失败。
4. **第四轮**在“无奖励真实试做”的前提下提出效果元编译器：教学给所需效果、自身经验给动作后果，
   共享更新器由当前参数与经验生成修订，训练用跨episode功能信用及辅助效果学习。

## 6. 第五轮究竟推荐了什么，哪些仍是候选

第五轮全文见[原回复](EXPERT_RESPONSE_ROUND5.md)。其主组织是：

```text
合法训练数据 → 共享控制起点、教学读取和目标条件动作评价
教学视频＋语言 → 操作对象、关系变化、阶段条件与候选目标
当前实际状态＋当前LoRA/action expert → 多个真实可执行的动作提案
教学目标＋状态＋提案 → 评价并选择前5步 → 真正执行、记录后果
实际完整成功/有效局部片段/失败经验 → 评价学习、重读教学、LoRA学习
重复观看与实践 → 最终冻结一套完整LoRA → 新初态独立闭环
```

- 教学读取建议使用保序空间/时间特征与对象局部关系，同时保留原片段供重读；目标不仅是“抽屉开”，
  而可能是“手退出且抽屉仍开”。当前真实物理状态用于判断后果；教学关系仍须从RGB推断，不能读取教师真值。
- action expert在真实自身RGB/state/language条件下生成完整50步候选，改变noise或适度动作扰动，
  对实际将执行的前5步评价。完整horizon是控制先验，不是已发生的世界未来。
- 候选动作评价用有限预算目标条件Q，输入真实自身状态、动作前缀、教学目标与剩余时限。
  合法训练轨迹和自身交互可用未来已实现目标重标记、Bellman学习；首版不另堆整任务critic。
  高Q候选、bootstrap目标与实际达成必须分开。
- 行为发现不必等到首次完整成功才允许学习。完整成功轨迹的真实动作窗口用于原生FM；
  有限局部成功片段可尝试前缀监督，失败经验主要进入评价与探索，而非全部正向模仿。
- 第五轮承认局部5步与50步FM接口未自然解决：用实际前缀加旧proposal尾部构造输入、只给前缀正向损失，
  不是精确的marginal FM；全局attention/共享参数也意味着mask不能保证无干扰。替代方式须按实际问题选择。
- 适应期可以搜索、选阶段、读特权自身状态；这些辅助最终退出。最终LoRA应把行为吸收为自身RGB/proprio/语言下的控制，
  并用多初态、完整过程回放及实际纯policy行为检验能力保持。

这些模块不是owner逐项指定的答案。新专家可以改动或省去，但必须选择并论证一条完整主设计。
第五轮建议过两task、两臂、每臂两次适应、64episode等首批范围，**未获冻结或执行**；
owner随后明确同预算语言适应对照不构成第一阶段前置门槛，不能照搬其矩阵自动开工。

## 7. 主讨论的认可与尚未建立的连接

主讨论认可：新任务可用真实动作后果建立修订方向，直接任务内学习有机会减轻纯共享前向映射的负担；
新机制不同于旧零交互self-read，也不同于只在train任务上更新共享Writer的旧RL。
但这仍是合理候选，尚未有新闭环证据。主讨论尤其要求把以下联系设计到实际计算，而非只给模块名：

1. **视频怎样教“怎么做”。** 对象绑定、接近/退出方向、过程中的保持条件如何由视频产生，
   怎样改变动作分布、评价或参数更新？手写“手退出且柜门开”的例子不等于自动教学读取已经实现。
2. **自己的经验怎样改变下一次理解。** 发现退出时把抽屉关回，哪些观测构成新证据，怎样查询相关片段、
   改变原目标/动作解释，并形成更有针对性的尝试？不能只把失败轨迹拼到token后说模型会理解。
3. **怎样发现真正有效的新动作。** 更多flow seeds可能仍落在同一错误行为族；目标Q还依赖定义好的目标空间、
   达成判据与足够覆盖。未来目标重标记不会自动创造从未发现的有效行为，critic高分也可能误导。
4. **怎样把带辅助的成功变成固定LoRA能力。** 搜索器、特权状态与外部阶段记录拥有最终actor没有的输入。
   真实行为数据有价值，但不保证最终策略可观测、可表示、学得进并保持；局部改善不能拼接成全任务保证。

这些是待补的设计连接及竞争解释，不是让专家逐条新增探针或建立永久审批关卡。
Owner已经强调第一阶段重完整能力；不应再以“必须先证明视频胜过所有充分适应基线”拖延方法建设。

## 8. 最新委托与长期接续方式

完整原话见[最后一轮请求](OWNER_FOLLOWUP_REQUESTS.md#3-最新完整请求先设计完整架构再形成推进规划)。

训练目标、标签来源及梯度去向；再从架构推导第一批完整学习循环、扩大证据、停止条件和困难处理原则。
用一个具体操作任务贯通“教学→尝试→反馈→重读→同一LoRA更新→完整能力→固定后新初态执行”，允许循环多轮。
