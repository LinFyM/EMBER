# 一、我推荐的主设计

**我建议把 EMBER 的首批主线定为：从教学视频读出带不确定性的物理变化轨迹，用原生策略、短步动力学预测和真实实践把它变成有效操作，再把经过真实后续行为认证的经验直接训练进同一套完整 LoRA。**

整个条件适应过程是一套算法，包含读取、尝试、反馈、重读和参数更新。最终产物只有从强 MT 初始化、持续直接优化的一套 38-target LoRA。读取器、物理状态、搜索器、过程管理和任务内优化器在最终执行时全部退出。

我作出以下关键选择：

1. **教学表示采用“对象与部件的物理关系轨迹＋可观察变化点”，不训练缺少可靠标签的因果操作程序。**
2. **评价器采用五个真实控制步范围内的动力学预测，不以跨任务长程 \(Q\) 作为核心。** 长期是否有效，交给真实连续实践判断。
3. **完整任务目标由同一个环境成功标准固定。** 视频中的路径、退出方式和持续关系提供操作线索，不能因容易达到而被提升为完整任务目标。
4. **局部经验用完整采样器上的新噪声前缀回归；真实完整成功轨迹用原生 FM。** 首批撤下双采样 energy score。
5. **最终策略从自身实际到达的状态学习。** 适应中安排 actor 先行、原地接管，以及更新后的纯 actor 审计，检验辅助系统找到的行为是否真正进入 LoRA。
6. **首批只做三个 Validation 任务、每任务两个教学条件，并配一个预算匹配的“语言＋初末帧＋时长”适应参照。** 从完整循环开始判断视频贡献，不铺开全部消融。

## 1.1 三个阶段如何贯通

| 模块 | 实际输入与计算 | 输出及消费者 | 参数归属 |
|---|---|---|---|
| 冻结的 Source 与原生策略 | 原生 RGB、proprio、exact language；按现有流程生成完整 50 步 action horizon | 当前 LoRA 和 MT 各提供一个原生候选；最终只运行当前 LoRA | Source、原生图文 prefix 权重、normalizer 冻结 |
| 视频物理读取器 \(R_\phi\) | 冻结的空间图像 token、语言特征、相机与时间位置；预测对象、部件、夹爪轨迹及不确定性 | 物理变化轨迹、候选对象绑定、轨迹模式；供过程管理和动作编辑使用 | 合法 Train 上共享训练，held 适应时主体冻结 |
| 条件内视觉校准 | 自身 RGB 与实际物理状态配对；校准坐标尺度、偏置、夹爪开度，并维护场景外观对应 | 重新解读同一教学视频 | 每个 condition 独立，小参数更新 |
| 短步动力学模型 \(f_{\psi_c}\) | 自身物理状态、控制器内部目标、接触、实际命令；预测一个控制步，滚动五步 | 比较同一局部目标下的候选实际后果 | 共享初始化；条件内用真实交互更新 |
| 过程管理与动作编辑 \(E\) | 教学轨迹、当前真实状态、原生 action block、候选操作参数 | 一次确定实际执行的前五条命令 | 显式算法；模式与经验统计为条件内状态 |
| 经验认证与 LoRA 学习 | 真实动作及后果、连续后续行为、完整成功；只把最终可用的观测作为 actor 输入 | 更新同一套完整 A/B 参数 | \(\lambda_c\) 从 MT300 初始化，38 个 target 全部可训练 |
| 最终执行 | 新初态的 RGB、proprio、exact language | 原生 10-step flow、50-step horizon、执行前 5 步后重观测 | 只保留固定 \(\lambda_c\)，不使用以上辅助模块 |

这条路线的核心假说是：**教学中可恢复的物理变化与时序信息，足以改变真实行为发现；发现的行为又能在最终 actor 可观察的状态上被学习。** 两条联系都需要实验，不能由读出结果、attention 差异或参数变化替代。

# 二、这项选择承接了什么，又没有重复什么

本轮以仓库快照 [`77c7bb2`](https://github.com/LinFyM/EMBER/tree/77c7bb269d25f891e0156190bf07d7b24615ad1d) 为依据，读取了入口、最新架构审阅、第六轮正文、owner 后续澄清与实际问题、讨论衔接、长期要求和概念，并沿索引核对了与本方案最接近的机制、结果和控制／学习代码。第六轮是待实施设计，不能作为已验证能力引用。[入口](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/docs/review_materials/20261008_method_rethink/README.md) · [最新审阅](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/docs/review_materials/20261008_method_rethink/ARCHITECTURE_REVIEW.md) · [owner 后续要求](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/docs/review_materials/20261008_method_rethink/OWNER_FOLLOWUP_REQUESTS.md)

有三组历史事实直接影响我的选择。

**第一，旧 T/C 已经具有真实功能信用。** 当前 MT 为 153/400，T 为 161/400，保留 117、新增 44、丢失 36；后续节点没有形成明显稳定优势。旧系统已有跨 episode 的真实 FM、完整 A/B 梯度、时序与自身状态调用。因此，新设计的解释不能是“终于让动作损失传到参数”。[机制记录](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/docs/review_materials/20261007_research_reassessment/MECHANISM.md) · [证据记录](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/docs/review_materials/20261007_research_reassessment/EVIDENCE.md)

**第二，P/I 已经做过对象相对轨迹、实际控制和真实经验学习。** 其 privileged Train 转移执行达到 367/416，但随后视频到 LoRA 的路线没有转化为所需能力，P、I 的节点结果最终仍明显弱于目标。这排除了“只要对象坐标转移成功，再加 FM 就自然成立”的论证。新路线必须分别检验 held 视频读取、条件内行为发现和最终策略吸收。[P/I 设计与执行记录](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/docs/designs/demonstration_transfer_learning_design.md)

**第三，最近的直接专家恢复说明部分行为能够补上，但尚不存在可靠免费教师。** 归档中的四任务直接专家，在不同起点和 handoff 下表现不一致；它支持尝试直接学习有效经验，不支持预设辅助策略总能提供正确标签。[直接专家恢复记录](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/docs/analyses/aligned_teacher_recovery_20261008.json)

因此，我保留第六轮的主方向：

> 教学中的操作信息 → 目标固定的行为发现 → 真实有效经验 → 直接训练同一 LoRA。

但撤掉四个尚无可靠连接的部分：**强语义操作标签、作为中心的长程目标 \(Q\)、让目标随操作假说竞争、少量经验上的双采样 energy score。**

本轮核对的是仓库文件、代码和归档结果，没有在实验节点复跑原始 HDF5、教学像素和新模型。下面对视觉可读性、动力学可学性和新增吞吐的判断均明确保留为待测项；归档成绩也不写成本轮复现结果。

# 三、教学究竟提供什么信息，怎样从现有数据学出来

## 3.1 先缩小表示，避免把缺失监督藏进符号

我不让读取器直接输出“必须抓住”“必须保持打开直到完成”“下一步的必要前置条件”。

它输出以下内容：

- 哪些对象、部件和夹爪在图像中可见，分别对应哪条轨迹；
- 夹爪控制点、物体和部件的位姿或可辨认部分；
- 夹爪可见开度；
- 物体、部件与夹爪之间的相对运动；
- 这些量的观测不确定性；
- 由轨迹计算的变化点、局部路径和后续持续关系。

这里的“保持”只表示：

> 视频中某个量已经发生变化，随后在一段可观察时间内保持在某一区间。

它不表示该行为具有因果必要性。一个成功视频也不能证明“换一种方法必定失败”。

## 3.2 原始数据中已有的和需要新增导出的

现有合法共享数据是 **36 个任务、共 1,800 条示范**。原始数据包含动作、双相机 RGB、机器人状态、末端与夹爪相关量、完整 simulator states、reward/done 等；它并没有现成的“对象绑定—退出条件—保持条件—必要前置条件”语义表。[数据转换代码](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/src/ember/libero_data.py) · [训练范围合同](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/configs/libero_24_8_8_coverage_v1/manifest.json)

新增一个**仅处理合法 Train 数据**的物理标签导出器：

1. 使用已有 `model_file`、simulator states 和通用 body/joint/geom 注册表恢复状态。
2. 通过 FK 得到物体、关节部件和实际 OSC 控制点的位姿。
3. 通过相机投影与分割得到可见性、实例对应及二维监督。
4. 把物理轨迹与正确时刻的 RGB 配对。

这里有一个必须修正的真实数据细节：原始 HDF5 中，`states[k]` 对应 `actions[k]` 之前，而 `obs[k]` 是动作之后。不能把同一个下标的 RGB 与 simulator state 直接当成同步标签。应使用相应的后状态；缺失末端后状态的样本要屏蔽或实际恢复，不能猜补。旧 HDF5 的 FM 对齐与新交互日志也要分开：**新日志明确记录 \(T\) 条动作和 \(T+1\) 个状态，query 使用动作前观测。**[数据代码](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/src/ember/libero_data.py) · [Writer 数据代码](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/src/ember/writer/data.py)

## 3.3 每类字段的获取路径

| 字段 | 首批构造方式 | 能说明什么 | 不能说明什么 |
|---|---|---|---|
| 对象与部件绑定 | Train 的实例投影／分割监督，按整条轨迹匹配；held 结合自身场景中的 RGB—物理位置对应 | 哪个可见实例发生了什么变化 | 自动知道哪个对象在因果上必要 |
| 夹爪与物体路径 | Train FK 位姿监督；held 从双视图空间特征预测 | 可观察的接近、移动、退出走廊 | 教师实际控制命令、施力方式 |
| 关节或抽屉变化 | 部件相对静止父体的位移／转动 | 部件实际打开了多少 | 必须达到某个未观察过的最佳开度 |
| 事件顺序 | 对平滑轨迹计算开度变化、运动起止、接近／离开等变化点 | 可见事件的先后关系 | 未观测接触和隐藏操作 |
| 持续关系 | 对已经改变的相关量，计算之后稳定的时间区间 | “视频中随后保持如此” | “不这样保持就必然失败” |
| 下一段衔接 | 后一段开始时实际观察到的物理关系 | 一个可尝试的衔接状态 | 完备、必要的前置条件集合 |
| 教师接触、抓稳与否 | **不生成 held 教师真值标签** | 可保留视觉假说 | 不能冒充真实接触 |
| 完整任务成功 | 自身交互返回的环境 success | 该次实际执行是否完成官方任务 | 所有局部动作分别是否必要 |

变化点阈值从 Train 的标签噪声和校准集误差固定下来，例如要求变化超过噪声尺度并持续至少两个采样时刻。遮挡或对称物体不可识别的旋转分量不强行监督。

持续关系只关注**已发生变化、与操作相关的对象或部件**，不把整个静态背景都变成保持约束。后续视频如果显示该量应再次变化，相应保持窗口随之结束。

## 3.4 明确 \(g^*\)：本方案不假装已有“真实操作目标”标签

完整目标可以记为未知的成功状态集合：

\[
\mathcal G_c^*=\{S:\operatorname{success}_c(S)=1\}.
\]

算法通过自己的真实交互获得这个集合上的采样结果；它没有直接获得 held 任务的正确操作程序。

读取器学习的是另一种量：

\[
g^{\mathrm{obs}}_k=\rho(S_{\tau_k}),
\]

即 Train 成功轨迹在某个未来锚点上的**实际物理关系**。在 held 视频中，它变成预测的、带不确定性的 \(g^V_k\)。

二者必须分开：

- \(g^V_k\) 是视频提供的操作线索；
- \(\mathcal G_c^*\) 决定完整任务成功；
- 达到若干 \(g^V_k\) 不能自动记为完整成功。

这也是我选择短步动力学而不是长程目标 \(Q\) 的原因：无需先虚构大量正确的目标、事件和保持标签，便可以训练“这五条命令实际会造成什么变化”。

## 3.5 读取器的首批实现

我选择复用原生冻结图像编码得到的 **双视图空间 token**，保留空间位置，加入相机、时间和 exact language 特征；不把旧 fixed-probe hidden 默认当成三维几何。现有代码已有相应空间特征获取路径。[原生特征代码](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/src/ember/operator_writer/native.py)

新增读取器采用：

- 256 维对象／部件 token；
- 图像到实例的交叉注意力；
- 四层时序处理；
- 四个**整段一致的轨迹模式**；
- 位姿、可见性、开度和不确定性输出。

四个模式用于表达路径、绑定或遮挡下的多解。训练时按整段轨迹计算模式责任，不能逐帧挑选最接近标签的模式，也不能把左右两条绕行路径平均成穿过障碍物的路径。

共享训练按每任务固定 40/10 条划分训练和校准，共 1,440/360 条。损失来自上述真实物理标签、投影与可见性，并对不确定性做校准。**50% 训练输入只保留初末帧和明确共享的时长元数据**，训练同一个模型从这些输入预测操作轨迹先验。这会直接形成首批参照臂，而不是临时把一个只学过完整视频的模型输入清零。

held 条件内只更新小型输出校准器：坐标相似变换、尺度／偏置、夹爪开度校准及场景外观对应。其监督是自己的 RGB—状态对，不是教师配套 state。读取器主体保持冻结。

这条联系仍有明确风险：**现有 frozen spatial features 加合法 Train 几何监督，是否能把 held 教学中的关键关系恢复到足以指导控制的精度，尚未验证。**

# 四、从视频路径到前五条真实命令

## 4.1 把三个不同的量分开

必须区分：

1. 视频预测的夹爪路径；
2. 希望当前机器人达到的 OSC 目标；
3. 实际增量命令执行后的物理结果。

在所核对的 OSC 实现中，平移 raw action 经尺度映射为目标位置偏移，旋转经轴角增量设置目标；这不是实际末端立即移动同样距离。平移尺度为 \(0.05\)，旋转尺度为 \(0.5\)。夹爪正负命令也通过内部控制累积作用，不能视为瞬时开度设置。[OSC 实现](https://github.com/ARISE-Initiative/robosuite/blob/v1.4.0/robosuite/controllers/osc.py) · [夹爪实现](https://github.com/ARISE-Initiative/robosuite/blob/v1.4.0/robosuite/models/grippers/panda_gripper.py)

本方案统一以 **OSC 实际控制的 `gripper0_grip_site`** 为末端坐标。不能直接把 policy proprio 中名字近似的末端 frame、机器人末端 body frame 和视觉夹爪 frame 当成同一个旋转坐标系；固定变换必须在导出与读取接口中显式处理。

## 4.2 教学轨迹如何移到自身场景

对一个局部段，先在段入口固定教师参考系：

\[
r_j=
\left(T_{\mathrm{ref,teacher}}^{\mathrm{entry}}\right)^{-1}
T_{\mathrm{eef,teacher}}(j).
\]

然后在自身段入口绑定对应参考系：

\[
T^V_j=T_{\mathrm{ref,self}}^{\mathrm{entry}}r_j.
\]

**两边的参考系都固定在段入口。** 如果教师端每帧都用正在移动的把手作参考，手和把手共同移动时，相对轨迹近乎不变，拉开抽屉的信息反而被消掉。

参考系选择使用通用规则：

- 关节部件操作优先采用其静止父体；
- 接近局部物体时保留入口物体参考；
- 搬运到另一个目标时采用目标物体／容器参考；
- 不确定时保留少量完整绑定模式。

不把整个场景假设为同一个刚体变换。源物体和目标容器可以独立移动。这些绑定规则适用于通用对象与关节关系，不为 task23 人工写“先拉抽屉，再放碗”的程序。

## 4.3 短步动力学的输入必须足够真实

我选择三个成员的轻量物理图模型。输入包括：

- 机器人与物体的广义位置、速度；
- 关节类型和局部相对几何；
- 当前 OSC 目标；
- 夹爪内部命令状态；
- 自身真实接触；
- 本步 raw action。

输出下一控制步的广义状态变化与接触预测，再通过 FK 得到末端和物体位姿。已知控制器目标更新和夹爪命令累积采用解析实现，实际物理响应由模型学习。

夹爪累积必须按实际 simulator substep 的调用次数计算，不能把每次内部调用的变化量错当成每个 20Hz 控制步的变化量。[环境步进](https://github.com/ARISE-Initiative/robosuite/blob/v1.4.0/robosuite/environments/base.py) · [机器人控制调用](https://github.com/ARISE-Initiative/robosuite/blob/v1.4.0/robosuite/robots/single_arm.py)

原始示范未必记录了足够的控制器内部状态，因此首批动力学训练以**新采集的合法 Train 真实交互**为主。模型同时训练一步预测和真实五命令开环滚动，不能只看 teacher-forced 一步误差。

模型集成分歧用作不确定性惩罚和诊断，不声称它就是可靠失败概率。

## 4.4 一次 replan 的具体计算

每次边界只做以下工作：

1. 当前 \(\lambda_c\) 和冻结 MT 各生成一个完整 50 步原生 action horizon。
2. 经冻结 normalizer 的逆变换得到 raw command。
3. 构造八个候选：两个原生候选、三个视频轨迹编辑候选、三个通用编辑／探索候选。
4. 每个候选一次生成五条固定命令。
5. 三个动力学成员评价**同一组固定命令**。
6. 选择并真实执行这五条命令；下一次 replan 才使用新的反馈。

编辑变量包含：视频路径与原生目标的混合比例、局部位置／旋转偏移、阶段速度、夹爪开启或闭合的时机，以及 1、2、4 个 action block 的停留选项。首批不训练额外的大型动作编辑网络。

对第 \(j\) 步，根据预测状态把原生命令转为原生 OSC 目标，再与重定位后的 \(T^V_j\) 做位置与旋转插值，得到目标 \(T_j^d\)。非零旋转分支下，逆算为：

\[
u^{xyz}_j=
\operatorname{clip}
\left(\frac{p^d_j-p^{\mathrm{pred}}_j}{0.05},-1,1\right),
\]

\[
u^{rot}_j=
\operatorname{clip}
\left(\frac{\log(R^d_j(R^{\mathrm{pred}}_j)^\top)}{0.5},-1,1\right).
\]

随后必须重新经过真实控制器的限幅和分支规则，评价**实际设置成功的 goal**。

一个容易遗漏的分支是：零旋转命令会保留旧 `goal_ori`，未必设置为当前姿态。本方案的 hold 候选固定入口位置，并保留当前 controller 的方向目标；对于其他逆算后不符合预期目标的候选，按真实分支评价或排除，不私下调用环境接口修改姿态目标。

生成五条命令时，后续状态由名义模型预测。生成结束后，各 ensemble 成员都从真实 \(S_t\) 出发评价这五条相同命令。不能让每个成员在自己的预测世界里重新闭环编辑，否则会低估开环误差。

**适应也不增加外部 20Hz 视觉／状态伺服。** 数值状态可以每步记录，但外部编辑器只在每五步的边界决策；环境内部原有 OSC 控制照常运行。

## 4.5 候选为什么会受到视频影响

同一阶段的候选比较固定以下对象：

- 同一个下一物理锚点；
- 同一条观察到的持续关系；
- 同一个后续衔接要求。

候选代价使用经过 Train 固定物理尺度归一化的：

\[
J =
d_{\mathrm{next}}
+d_{\mathrm{corridor}}
+d_{\mathrm{persist}}
+\alpha\,U
+\gamma\,C_{\mathrm{action}}.
\]

这里的距离包含**物体与部件的实际预测变化**，不能只有夹爪是否贴近视频路径。否则空手沿路径挥动也可能得到高分。

路径及持续关系采用软代价，使原生策略和通用候选仍有机会找到视频路径之外的完整成功。四分之一的 guided 实践 episode 保留预注册的探索机会，用于覆盖开／闭、停留和运动偏移，防止模型错误把所有未试行为排除。探索消耗真实预算，结果不自动成为 actor 正例。

视频对动作的实际作用可以直接检查：例如预测目标偏移修正了 5mm，对应 raw 平移目标约 0.1 的变化；但是否产生正确物体运动，仍要由实际后果确认。这比“某个 latent 改变了”多了一条可检验的物理连接。

# 五、反馈怎样修订理解，又怎样防止目标变弱

## 5.1 固定完整目标，分开两种修订

我撤掉第六轮中让 \(g(h)\) 随操作假说一起参与

\[
p_{\mathrm{vis}}(h)\exp\{\beta Q(\cdot,g(h))\}
\]

排序的做法。

替换为两层：

- **视频解释层**：依据图像、共享监督和自身视觉校准，判断视频可能呈现了什么。
- **操作有效性层**：在固定完整成功标准及固定局部比较目标下，判断某种操作方式对自己是否有效。

一种方式更容易做到，不能反过来证明视频显示的就是它。

阶段目标和读取版本在一个 episode 内固定。重读主要发生在 episode 结束、校准或动力学更新之后。执行中若发现持续关系回退，过程管理可以回到较早阶段，但不能把失败改记为“另一个目标已经完成”。

## 5.2 什么证据允许修改什么

| 新证据 | 允许修改 | 不允许据此修改 |
|---|---|---|
| 自身 RGB—真实状态配对显示尺度或绑定错误 | 坐标校准、对象对应、同一视频的物理读数 | 完整任务成功定义 |
| 重读获得更可靠的可见开度／时序证据 | 可见事件的时间区间和不确定性 | 虚构教师接触或施力 |
| 实际释放后仍有接触，退出导致部件回退 | 自身动力学、释放停留、退出方向／速度的有效性判断 | 宣称教师必定用了同样控制 |
| 某条路线在相同完整目标上真实成功 | 提高该操作路线的使用权重 | 用一个更容易的局部目标替代完整任务 |
| 视频模板要求某种关系，但实际完整成功不需要它 | 降低该模板作为必要要求的地位 | 否认已经观察到的视频事实 |

在尚无完整成功时，不同整体操作模式保留探索份额；不能用各自不同的局部完成率评出“最正确的完整解释”。局部反馈可以优化**同一个局部目标**下的控制方式，整体路线优先级的成功证据则使用同一个环境完整成功标准。

## 5.3 task23 的一个必要纠正

仓库对 task23 的实际 BDDL／状态审计表明，官方成功目标是**碗位于上层抽屉目标区域内**。`Open` 阈值、手退出、最终仍保持打开，不是其额外官方成功条件。[task23 状态审计](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/docs/designs/task23_drawer_state_replay_20261006.md)

因此，“释放后退出且抽屉仍保持打开”在本方案中是一个可能帮助后续放碗的操作关系。它可以认证局部行为，也可能被实践修订；不能被加成最终评测的新门槛。

如果实际完整成功发生了，而某项视频模板没有满足，应接受完整成功，并修订模板的地位。如果只做到打开、退出，却未把碗放入，仍然是完整任务未完成。

# 六、真实经验怎样进入最终固定 LoRA

## 6.1 正例必须带有真实后续证据

我采用三级经验资格。

**一级：单初态局部认证。** 必须同时满足：

1. 实际到达固定物理锚点；
2. 相关持续关系在之后至少 20 个真实控制步中得到观察；
3. 同一条连续 episode 实际进入下一段的锚点或运动走廊。

20 步是最低后续观察量，不是每个阶段都要求机器人停在原地一秒。如果下一段要更久才能进入，认证延迟到真的进入。最后一段没有后继时，只能由完整环境成功认证。

**二级：跨适应初态复现。** 同一种局部方式至少在两个不同适应初态通过以上检查。

**三级：完整成功。** 实际环境 success，整个连续轨迹可成为完整任务行为数据。

只打开后等一会儿、没有后续衔接，不足以把该段全部加入 actor 正例。失败中也可以包含可靠局部行为，但必须逐段通过上述规则。

## 6.2 不同经验分别训练什么

| 数据 | 训练消费者 | 标签来源 |
|---|---|---|
| 所有真实状态转移，包括失败 | 条件动力学、视觉校准、操作方式统计 | 自身实际状态、接触、动作、后果 |
| 经过认证的短局部行为 | 同一 LoRA 的最终采样前缀 | 实际执行且通过后续认证的命令 |
| 完整成功中的真实 50 步窗口 | 同一 LoRA 的原生 FM | 同一 episode 连续真实动作 |
| 不足 50 步的成功尾部 | 前缀损失 | 实际存在的短前缀 |
| 预测候选、未执行尾部、模拟推断 | 搜索或诊断 | **不作为真实动作标签** |
| 未认证失败段 | 动力学与诊断 | 不自动反向成“正确动作”，不做普通 BC 正例 |

完整成功轨迹不能拼接不同 episode 的动作；原生候选的第 6—50 步也不能冒充已经执行过的经验。

## 6.3 我选择新噪声前缀回归，撤下 energy score

令最终合法输入为

\[
q_t=(I^{front}_t,I^{wrist}_t,p_t,L),
\]

令 \(F_{\Theta,\lambda}(q_t,\epsilon)\) 是完整原生 10 步 flow 采样器。对长度 \(h\le5\) 的认证实际动作，采用：

\[
\mathcal L_{\mathrm{pre}}
=
\mathbb E_{\epsilon\sim\mathcal N(0,I_{50\times32})}
\frac{1}{7h}
\left\|
P_{h,7}F_{\Theta,\lambda}(q_t,\epsilon)
-
N(a^{\mathrm{real}}_{t:t+h-1})
\right\|^2.
\]

实现要求：

- 每次更新使用新的普通高斯噪声；
- 完整保留 50×32 的采样与内部耦合；
- 跑完原生 10 个 flow 步后，才选取真实动作维度及前缀；
- 不使用发现成功时的同一噪声作为唯一训练噪声；
- 不用任意填充的尾部参与所谓完整 FM。

为什么选它？对固定成功动作 \(u^+\)，平方损失满足：

\[
\mathbb E\|U-u^+\|^2
=
\|\mathbb E U-u^+\|^2+\operatorname{tr}\operatorname{Cov}(U).
\]

因此它同时推动普通噪声下的平均动作接近已验证动作，并压低该状态上的动作分散程度。**这是一项有意选择：首批优先让一种已验证方式稳定出现。**

代价是它可能压缩多模态行为。为避免互相冲突的标签，回放要保留整段路线身份；对于观测相近但动作互斥的路线，优先学习在完整成功上得到更多真实支持的一条，而不是把所有成功分支平均。

双采样 energy score 的分布性质不能提供少量经验下的成功保证；它还增加第二条完整采样反向路径。首批暂不为这项复杂度付费。即使采用这里更简单的损失，完整采样反向仍明显贵于一次 FM，并且有限噪声样本上的拟合仍不保证闭环成功。

现有 `mean_velocity_loss(prefix_steps=5)` 是对**速度输出**做前缀损失，不等于以上最终采样前缀训练。原生 `sample_actions` 入口带 `no_grad`，需要增加一个复用同一 `denoise_step`、时间序列和 Euler 更新的可微入口，并验证其无梯度数值结果与原生采样一致。[现有功能信用代码](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/src/ember/writer/function_credit.py) · [固定版本 pi05 实现](https://github.com/huggingface/lerobot/blob/30da8e687a6dfc617fcd94afc367ac7071c376ce/src/lerobot/policies/pi05/modeling_pi05.py)

## 6.4 完整成功窗口继续使用 FM

对真实连续的 50 步动作 \(A^{real}\)：

\[
x_\tau=\tau\epsilon+(1-\tau)N(A^{real}),\qquad
v^*=\epsilon-N(A^{real}).
\]

沿用原生噪声／时间采样和真实 7 维动作的 FM 损失。它提供较便宜的长 horizon 行为训练，并让完整任务各阶段共同进入同一 LoRA。

所有环境后果、认证规则、候选选择、视频解释和目标都 stop-gradient。**actor 梯度只进入 38 个 target 的全部 76 个 A/B 矩阵**；不通过环境或认证程序求导。[LoRA 实现](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/src/ember/pi05_lora.py)

## 6.5 回放、更新次数和干扰控制

首批固定如下：

- 有足够真实完整窗口时，样本预算按 **50% FM、50% 前缀**分配；不足部分转为合格前缀。
- 前缀回放兼顾旧阶段和新增阶段，先按阶段再按 episode／初态抽样。
- 长等待段不因时长而占据多数样本。
- 每个独立 query 每轮最多复用八次；没有足够数据就少更新。
- AdamW：学习率 \(3\times10^{-5}\)，betas \((0.9,0.95)\)，weight decay 0，梯度范数裁剪 1；首批不扫学习率或 rank。
- 单初态局部、跨初态局部、完整成功的相对回放权重为 0.25、0.5、1。

**0.25 的 loss 权重并不能在 Adam 下保证更新幅度变小。** 因此还规定每轮实际更新上限：

| 当前经验资格 | 每轮 LoRA 更新上限 |
|---|---:|
| 无认证正例 | 0 |
| 只有单初态局部认证 | 16 |
| 有跨初态局部认证、无完整成功 | 32 |
| 有真实完整成功 | 64 |

有效 batch 为 16，四轮最多 256 次更新、4,096 个 query。这样，低认证经验受到的是实际优化预算限制，不能靠一个看似保守的权重无限续训。

我不在首批增加全局“保持 MT 输出”的额外损失。保留能力主要依赖全阶段真实回放、有限更新和 MT 在适应时继续提供候选。若出现学会后段却破坏前段，要从实际 gained/lost、阶段回放和自身状态覆盖定位问题。

## 6.6 特权辅助何时能被普通 actor 吸收

训练 actor 时，从来不给它物体真值状态、接触、过程编号或改写后的阶段语言。相同动作标签必须通过最终可用的 RGB、proprio、exact language 学会。

为此，实践中安排一部分 **actor 先行、在其实际到达状态原地接管**的 episode。新的成功行为由这些状态出发，形成真实修正标签。这个动机与在策略自身访问分布上聚合数据一致，但这里没有可靠免费专家，不能直接套用 DAgger 的保证。[proceedings.mlr.press](https://proceedings.mlr.press/v15/ross11a.html?utm_source=chatgpt.com)

还应主动形成可辨认的衔接状态：可见地张开夹爪、离开遮挡、稳定物体后再继续。这些动作可以使后续决定依赖可观察结果。

存在不能靠多训练解决的情况：两个实际状态在最终全部观测中不可区分，却要求立即执行互斥动作，而且没有安全的共同探测动作。此时无记忆 actor 无法知道隐藏条件；增加 LoRA 参数或更换分布损失都不补足信息。只有在确认“最终观测中确实不可辨认”，而非当前特征没学好时，才应下这个结论。

# 七、完整条件适应算法

```text
共享准备：
  冻结 Source、prefix、normalizer 和 MT300 参考。
  用合法 Train 导出物理标签，训练完整/端点两种输入模式的读取器 R。
  采集计入预算的 Train 真实交互，训练五步动力学 ensemble。
  完成 Train 上的小型完整循环与接口验证，冻结共享版本。

对每个独立 condition c：
  λc ← 完整 MT300 A/B
  ψc ← 共享动力学；视觉校准置零
  清空本 condition 的经验、模式统计和过程状态
  锁定视频、exact language、适应初态、审计初态、预算与随机种子

  for round = 1..4：
    guided/hybrid 实践，最多 6H 控制步、14 次重置：
      从预列适应初态启动；读取当前视频解释版本
      episode 内固定整体解释/目标版本
      每次 replan：
        获取自身当前观测与状态
        生成当前 λc、MT 的原生完整 horizon
        构造并评价八个候选
        确定五条实际命令，执行并记录真实后果
        按实际关系推进或回退阶段；环境 success 才记完整成功
      episode 结束：
        用真实转移更新小模型与视觉校准
        对相关片段重读，必要时整段重读
        认证有真实后续支持的局部段；更新真实成功经验

    按资格上限与全阶段回放直接更新同一个 λc
    运行两条纯 actor 适应期审计，最多 2H：
      不读取视频，不搜索，不接管
      数据只供下一轮使用；不当作最终评测

  末轮审计后不再更新任何适应状态、不选回旧 checkpoint
  固定 λc，退出读取、搜索、特权状态、过程选择和更新
  在预先封存的新初态上执行最终评测，反馈不进入学习
```

条件内小模型也有预算：每轮动力学最多 200 个更新步、视觉校准最多 50 个更新步，分摊在已完成 episode 后；动力学回放固定混合自身真实转移和合法 Train 物理转移。三个 ensemble 成员分别计数，不能把它们当一个免费模型。

# 八、用 task23 走完同一条链

下面是一条**拟实施时可能出现的轨迹**，用于说明算法；其中读取结果、失败原因和改善均是假设，不能当作本轮已经观察到的新事实。

### 1. 已有训练资料

读取器从合法 Train 中学习抽屉部件运动、夹爪开度、碗与容器关系。已有支持任务包含开抽屉、往抽屉放物体、关抽屉等相关变化；这些用于共享监督，不由人把几个任务拼成 task23 的正确程序。[任务划分与支持范围](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/configs/libero_24_8_8_coverage_v1/manifest.json)

### 2. 读取教学

假设模型从该条视频读出：

- 上层抽屉前部相对柜体向外移动；
- 随后夹爪开度增加，手离开；
- 抽屉在手离开后仍保持在相近位置；
- 再之后碗向抽屉区域移动。

这些先由预测轨迹和变化点产生。模型没有得到“教师接触已解除”的真值，也没有人指定释放时长。

### 3. 第一次实践

MT 提供接近与拉动候选；视频给出向外运动的物理方向和后续退出走廊。

假设系统拉开了一部分抽屉，但退出时抽屉回退。真实日志显示：退出命令开始后，手和把手仍有接触，抽屉受到带回的运动。

这一次不能只因末端跟上了视频路径就记为有效。

### 4. 反馈带来的两种不同认识

**校准变化：** 自身 RGB—状态对可能表明读取器把视觉深度或开度估得过大，因而修正坐标和开度解读。

**操作变化：** 动力学数据表明，在当前夹爪状态下，“发出打开命令后立即退出”仍会带动抽屉。于是 hold＋继续打开候选在下次比较中更有利。

前者是视觉坐标校准，后者才是学到了对自己更有效的操作方式。二者分别记录。

### 5. 重读与再次实践

校准后的重读可能让“夹爪先张开、手后退出”的时间区间更清楚。但即使视频仍看不清接触，系统也可以根据实际后果尝试多一个 block 的释放停留。

实际前五步由 hold 位置、旧方向目标和打开命令构成；下一次 replan 再查看真实开度、接触与抽屉位置。确认相应后果后，继续执行退出候选。

### 6. 有效经验

只有在退出后抽屉关系持续、而且同一 episode 真正进入取碗或放碗的后续段时，前面的局部行为才通过认证。

如果后续仍无法放碗，局部数据可受限地训练 LoRA，但该 episode 仍不算完整成功。若后来碗实际进入目标区域，则整条成功轨迹提供真实 FM 窗口。

### 7. 同一 LoRA 更新与完整能力

早期学习把“在这类自身视觉状态下稳定释放并离开”变成普通噪声下更常见的前缀动作；后续完整成功回放继续学习取碗、移动、放入与各段衔接。

纯 actor 审计可能暴露它过早切换或在遮挡下误判。下一轮在 actor 实际到达的状态原地接管，补充可执行修正；不把过程编号塞进 actor 输入。

### 8. 固定后新初态

最终 LoRA 在新的物体位置和机器人初态上，仅凭自身图像、proprio 和语言运行。如果它能在多个新初态把碗放入，才说明全过程能力进入了固定策略。

如果辅助系统反复完成，而裸 actor 仍只能拉开抽屉，结论就是**发现链成立，吸收链尚未成立**。不能用辅助成功替代 EMBER 的最终成绩。

# 九、首批完整学习方案

## 9.1 共享准备：新增多少数据与训练

复用资产包括 Source、MT300、38-target LoRA 路径、normalizer、原生 prefix 与 flow、现有环境包装、K1 视频映射、数据合同和回放设施。

新增五项实现：

1. Train 物理标签导出与时间／坐标对齐。
2. 完整／端点共用的物理读取器。
3. 五步动力学模型及 OSC 动作编辑。
4. 条件内经验、重读、认证、搜索与预算管理。
5. 完整采样前缀训练入口及最终隔离评测。

共享动力学新增 **36×8＝288 条合法 Train 交互 episode**：

- 每任务前四条：两条纯 MT、两条通用编辑覆盖；
- 训练第一版动力学；
- 后四条：两条完整视频引导、两条端点先验引导。

这样初始物理学习不依赖一个尚未训练好的评价器，也不会只有成功原生行为。读取器与动力学各最多 20 个训练 epoch，物理 batch、worker、microbatch 留给执行时测量。

另做三个合法 Train condition 的完整学习闭环，例如 global20、37、43，各一条固定视频：

- 每 condition 最多 \(16H\) 交互、32 次重置；
- 最多 128 次 LoRA 更新；
- 固定后八个独立 Train 初态评测。

这些循环包含真正的新实践、LoRA 更新和固定执行，不能用离线回放 288 条日志冒充。它们的条件 LoRA 不作为 held 初始化；held 仍统一从 MT300 开始。

## 9.2 首批 held 范围

| Validation 任务 | 选择理由 | 归档 MT 成功 |
|---|---|---:|
| task16：butter 放入 basket | 较短的获取与放置，检验基本行为学习 | 10/50 |
| task23：打开上层抽屉并放入 bowl | 关节操作、释放与后续衔接 | 0/50 |
| task31：cream cheese 与 butter 都放入 basket | 完整性、顺序与已完成部分的保持 | 24/50 |

这些基线来自现有同协议记录，不是本轮新评测。[证据记录](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/docs/review_materials/20261007_research_reassessment/EVIDENCE.md)

每任务取两条教学：按现有 K1 scheduler 的原始 row `init0`、`init25` 映射选定视频，**在观察实验结果前冻结文件与映射**。后续跨初态评测不能重新调用 scheduler 换教学。[教学调度代码](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/src/ember/expert_manifold/video_schedule.py)

由此得到六个 teaching condition，每个运行两臂，共十二次独立适应。

## 9.3 唯一主比较

**Full：** 完整 action-hidden 视频＋exact language。

**Endpoint：** 同一视频的初末帧、相同的时长元数据＋exact language；使用共享训练中真正学过此输入模式的读取器和操作先验。

两臂相同：

- MT 初始化、共享读取器和动力学初始化；
- 自身状态、接触、reward、success 的使用权；
- 候选数、编辑器和探索规则；
- 适应初态、随机性规则、控制步及重置上限；
- 小模型与 LoRA 更新规则；
- 固定策略评测初态。

中段画面必须在任何中段特征、事件、轨迹统计计算之前遮蔽。总时长作为明确共享元数据；实际控制时序换算仍使用原始帧索引—控制步映射，不能把重编码播放器时长直接当作物理时间。

这个比较能排除“Full 只是多用了任务内训练预算”的解释。它比较的是**中段操作画面相对于端点、语言和已学操作先验的增量**。

它仍不能单独区分：收益来自更准确的中间几何、操作顺序、释放时机，还是这些信息的组合；也不证明优于最充分的语言适应。首批不为这些进一步拆分铺设完整矩阵。

主要跨臂证据统一使用：

1. 首次真实完整成功前的累计交互；
2. 不同适应初态上的完整成功复现；
3. 更新后纯 actor 的完整成功；
4. 固定后新初态完整能力。

各臂自己定义的局部认证率只作内部诊断，不能拿来互相宣布“理解更好”。

## 9.4 适应与最终评测隔离

每个 condition：

- guided/hybrid 初态池：官方 `0…11`；
- 纯 actor 适应审计池：`12…15`；
- 最终封存评测池：`16…31`。

适应分四轮，每轮最多 \(8H\)：

- guided/hybrid：最多 \(6H\)、14 次重置；
- 更新 LoRA；
- 两条纯 actor 审计：最多 \(2H\)、两次重置。

每轮提前成功节省的审计步数不回补。总上限是 **\(32H\)、64 次重置、256 次 LoRA 更新**。末轮审计后不再修改 LoRA、小模型、模板或模式权重，也不据此选回旧 checkpoint。

最终：

- 六个 condition ×16 初态＝每臂 96 条；
- 两臂共 192 条；
- MT 在三任务同一 16 初态上另跑 48 条；
- 总计 **240 条最终 rollout**。

MT 的动作噪声由 task/init/replan 等共同规则决定，不依赖视频，因此这 48 条可以作为两个视频条件的共同参照。但统计时要承认：只有六个独立教学条件、三个任务，不能把 192 行当成 192 次独立适应。

# 十、记录什么，以及结果怎样改变方法判断

每个实际动作块必须能追溯：

- 教学与解释版本、当前阶段、轨迹模式；
- 原生候选、编辑参数、实际选中命令；
- 预测后果与真实后果；
- 真实接触、物体变化、success 和终止原因；
- 局部认证的后续证据；
- 被哪些 LoRA 更新消费、使用何种损失及噪声；
- 对应的纯 actor 与最终完整结果。

所有发现耗步包含之前的失败、guided、hybrid 和纯 actor 审计。未发现完整成功的条件报告为“在预算内未发现”，不能从平均发现成本中删去。

## 10.1 结果分支

| 观察到的结果 | 方法判断 | 下一步 |
|---|---|---|
| 视频关键几何持续错误，实际命令被引向错误对象／尺度 | 读取链未成立 | 修正标签、坐标与可见性学习；暂不归因于 LoRA |
| 读取合理，但五步预测经常漏掉接触／夹爪滞后，候选排序失真 | 物理预测与控制发现链薄弱 | 在合法 Train 增加对应动作覆盖或修正状态输入 |
| 找到可靠局部行为，始终没有连续完整成功 | 局部目标不足以支持任务完成 | 检查衔接、回退和长期探索；不能继续只刷局部损失 |
| manager 在多初态完整成功，裸 actor 始终失败 | 吸收链未成立 | 区分新噪声拟合、actor 到达状态覆盖和观测缺失 |
| 前缀拟合很好，自身到达状态也有修正数据，仍需不可见特权条件 | 当前最终观测不足 | 停止保护“只靠当前观测即可吸收”的假说 |
| Full 与 Endpoint 都显著超过 MT，发现效率和最终能力也相近 | 条件内学习有用，视频中段主张未获支持 | 不直接扩大视频机制的宣传或正式规模 |
| Full 更早发现完整行为，并更早学成裸 actor；最终两臂接近 | 支持视频提高学习效率 | 保留该主张，不能声称提高最终上限 |
| Full 的发现、跨初态复现与固定 actor 同时改善 | 支持整条机制 | 扩大教学条件，再扩大任务范围 |

我建议预先采用一个**投资门槛，而非显著性结论**：Full 在 96 个最终条件—初态行上相对 MT 净增至少 10 个成功，至少两个任务有正净增，并至少两个 condition 在不止一个新初态获得新增成功。所有 gained/lost 仍完整报告，尤其看 task31 是否丢失已完成部分。

视频贡献不要求首批必须达到一个任意固定的百分点差；但至少要有与共同完整 success 相连的发现／学习效率证据，不能只有表示或命令变化。

首批完成后，最多允许一次针对最早失效联系的有界修订。它应先在合法 Train 或下一批预注册条件上检验；不根据最终评测结果继续优化同一批已评测 LoRA。若同一联系在数据覆盖明确增加后仍失败，应停止保护相应主假说。学习率、rank、seed 的小扫不作为默认续命方式。

# 十一、工作量、资源上限与正式 paired400 成本

## 11.1 有依据的吞吐参考

最近直接专家记录中，1,920 次更新、215,040 个训练 query 使用约 4.55 A40 GPU 小时，折合约 **13.1 个 FM query／GPU 秒**。80 条评测共 25,406 个控制步，其包含失败加载的评测 GPU 时间约 0.326 小时，约为 **21.6 控制步／GPU 秒**的历史量级。它们不是新搜索器和新前缀反向的实测吞吐。[资源原始记录](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/docs/analyses/aligned_teacher_recovery_20261008.json)

完整采样前缀反向先按一次 FM 的 **10—20 倍 query 成本**规划，实际要测：

- 冻结图像编码与读取器吞吐；
- 两个原生候选及八候选五步评价；
- 可微十步 sampler 的速度、峰值显存与 checkpoint 开销；
- reset、render、日志与缓存 I/O；
- 一个完整 condition 四轮的真实用时。

## 11.2 首批预算

task16、23、31 的 \(H\) 分别为 280、300、520。[评测配置](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/configs/libero_24_8_8_coverage_v1/evaluation.json)

| 项目 | 上限或规划量 |
|---|---:|
| 十二次 held 适应 | 140,800 个控制步；最多 768 次 reset |
| held 适应 settling | 另计最多 7,680 步 |
| 240 条最终评测 | 最多 88,000 控制步；另计 2,400 settling |
| 共享 288 条 Train 交互 | 最多 101,760 控制步；另计 2,880 settling |
| 三个 Train 完整循环 | 另计各自 \(16H\)、更新和八初态固定评测 |
| held LoRA query | 最多 49,152 个 |
| 总 GPU 规划 | **50—90 A40 GPU 小时；硬上限 120** |
| 新增存储 | **硬上限 192 GiB** |
| 工程工作量 | 约 **5—8 个工作日**，完整首批约一至两周 |

以历史 FM 吞吐换算，49,152 个 query 若全部 FM 约 1.04 GPU 小时；若半数是十倍成本前缀约 5.7 小时；若全是二十倍成本前缀约 20.8 小时。总预算还包含共享读取、物理模型、真实实践、完整循环、验证和失败余量。

192 GiB 需要明确的存储策略：现有数据 stride5 加末帧约 59,114 个双相机时刻，512×2048 的 BF16 特征约 115.5 GiB；真实 RGB 只在 replan 和终止保存，全控制频率保留数值状态／动作／接触。不能同时复制全量 HDF5、缓存多份空间 token、再保存每个 20Hz 时刻的原始 RGB。

资源调度遵守仓库现有 A40 规则：全局卡数、单机卡数和低空闲时收缩；新输出写入既定可写位置，原始数据保持只读。[资源与执行约束](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/AGENTS.md)

若 Train profiling 表明完整双臂计划超过硬上限，应在 held 启动前报告并修订合同，不能运行到一半削弱参照臂或只留下表现好的 condition。

## 11.3 正式 K1 paired400 必须按 400 次适应计算

正式规模意味着：

- 400 个不同 task-video condition；
- 400 套独立的适应经验、优化器、校准和动力学状态；
- 每个 condition 都从相同共享初始化开始；
- 400 套最终完整 LoRA。

每个 condition 的正式评测初态必须排除在自己的适应池外；跨初态额外评测也要事先留出。不同 condition 之间不能共享同一 held 任务的实践缓存或已适应参数。

按本方案 \(32H\) 上限，400 条件约为：

- **422.4 万真实控制步**；
- 最多 **25,600 次 reset**，另计 25.6 万 settling；
- 最多 **163.84 万 LoRA query**。

仅 LoRA 学习部分，半数十倍成本前缀约 191 GPU 小时；全部二十倍成本前缀约 693 GPU 小时。加实践、读取、小模型更新和评测，一条主适应臂先按 **350—1,100 A40 GPU 小时**规划。按 6—8 卡和实际可用率，约 **4—15 天**是合理的运行量级估计；必须用首批实测改写，不能视为报价保证。

当前完整 rank128 LoRA 约 1,030 万参数，FP32 权重约 39.3 MiB；400 套最终权重本身约 15.3 GiB。但真实交互 RGB、数值日志、恢复状态和阶段 checkpoint 会把正式存储推到数百 GiB，不能沿用首批 192 GiB 上限。[LoRA 结构](https://github.com/LinFyM/EMBER/blob/77c7bb269d25f891e0156190bf07d7b24615ad1d/src/ember/pi05_lora.py)

正式 paired400 的每套 LoRA 只测一行，还不足以证明同一 condition 的跨初态能力。应另预注册一小部分 condition 的多初态面板，例如 16 条件各 16 个新初态，并单独计费、报告。**训练八套 LoRA 后各复用五十行，不属于这个实验。**

| **初态与交互** | guided/hybrid 使用 0…11；适应期纯 actor 审计 12…15；最终评测 16…31；每 condition 最多 \(32H\)、64 reset |
| **固定评测** | 每套最终 LoRA 独立运行 16 初态；双臂 192 条＋MT48 条；末轮审计后无更新、无 checkpoint 选择、无最终反馈回流 |
| **核心证据** | 同一环境完整成功的发现耗步与跨初态复现；manager—纯 actor 差距；真实经验消费记录；固定新初态 gained/lost；Full—Endpoint 的完整能力或学习效率差异 |
| **资源边界** | 首批目标 50—90 A40 GPU 小时，硬上限 120；新增存储 192 GiB；先在 Train 测实际吞吐，保证双臂完整预算 |
| **继续条件** | 固定 actor 对 MT 有实质净增，并在多个任务／condition／新初态成立；视频增量至少连接到真实发现或学成效率 |
| **修订或停止** | 按读取、控制发现、经验认证、策略吸收中最早失效的联系处理；只允许一次有界针对性修订，不以无限续训或小扫维持假说 |
| **待测主假说** | frozen features 能支持足够准确的物理读取；短步模型与有限探索能发现连续有效行为；认证经验能被合法观测 actor 吸收；中段视频在匹配预算下提供实际学习价值 |

**这份合同已作出会影响方法本身的选择。** 实验 session 可以据此实现数据接口、读取器、五步控制搜索、经验认证与采样前缀学习，先完成计费的 Train 闭环，再冻结共享版本启动十二次 held 适应。首批需要回答的是一条完整问题：教学是否改变了真实行为发现，以及这些变化是否最终成为同一套固定 LoRA 在新初态上的完整任务能力。
