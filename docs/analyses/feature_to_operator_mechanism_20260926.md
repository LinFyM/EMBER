# 从教学特征到执行算子：计算审计与下一方法假设

2026-09-26。Owner要求开始推进完整机制分析后的工作产物。本文是**方法假设与实验取舍**，不是已验证根因、
新方法成绩或GPU运行合同。当前S0合同保持；执行状态以[progress](../../progress.md)为准。

## 1. 本轮作出的判断

不能继续把问题概括成“没读到视频”“缺时序模块”或“只差LoRA出口”。当前C0完整400的正确/另一正确/语言
为120/132/121，旧大幅落后语言的现象没有稳定复现；冻结后续内容干预27对20/80又表明存在有限有益作用。
另一方面，几轮保留联合特征、原生续算和功能辅助的学习均没有获得足够能力。这些事实要求解释**知识怎样被学成
执行条件下可用的作用**，而非再次用张量完整、非零梯度或更大结构作充分理由。

本轮优先形成的候选是：**以执行状态查询教学内容的原生功能读出，建立可实测的条件控制函数，再检验它能否被
唯一完整LoRA承接。** 它包含一个必须允许失败的前提：合法视频读出本身要有真实闭环能力和有益教学贡献。
没有这个前提，不开始蒸馏，不把弱动作头重新称为功能教师。

这不是认定“固定LoRA不能按状态选择动作”。它本来可以。所比较的是两种条件作用的参数化与学习接口，
不把单层线性与整网非线性混为一谈，也不以放宽后的读出模型成绩冒充EMBER部署结果。

## 2. 现有代码实际上处理了什么

核对对象是当前`writer/{video_program,procedure,temporal,model,supervised,function_credit}.py`；
原科学模型C0的实现来源为dca1b550，最近S0开关不改变下面完整内容路径的定义。
记语言为L，教学帧为I_t，机器人执行查询为x=(o,s,a_tau,tau)，四个轴t/h/tau/native depth分别解释。

| 接口 | 实际计算 | 可以说什么；不能说什么 |
| --- | --- | --- |
| q_j | exact task token经原生text-only路径、Text Meta及2048→256投影 | 语言位置地址；不是已标注实体 |
| E_tj | 同帧原生图文task token投影，加q_j查询512个真实双相机patch的读出 | 同时含文字、视觉与任务条件内容；不是纯动态量，也不保证同j是稳定物体轨迹 |
| H_th | 真实图文prefix下，公开固定noise、tau=1的完整50×1024 Action Expert响应 | source动作计算表征；不是teacher正确动作或观察到的未来 |
| P_t | 初始mean_h(H)投影；每层重新读完整H、前后E，随后因果时间attention | 有学习过程关系的输入和算子；没有显式标注的抓取/放置阶段 |
| C_j | 每语言位置跨帧读取E，再沿语言轴处理 | 全视频语义内容；该读取自身对帧集合置换不变 |
| 参数slot | Core读取→Core条件的中心化P读取→AdaLN→slot交互 | 条件化的参数内容；slot/rank不是已知技能或物体 |
| A_l,B_l | 共享家族head从slot生成两侧完整因子，加合法identity模板 | 决定实际policy层的条件作用；参数相近不保证行为相近 |

具体地，FrameRead满足

```text
r_j = W_o sum_t [(1-lambda)/T + lambda alpha_tj] W_v E_tj.
```

在固定E时，这个读出本身不保留顺序；顺序还可经P传递。原件中中心内容选择较小只能描述这个接口，
不能推出内容选择没有功能价值；BF16权重和误差不能计为学习出的选择（findings§155）。

Procedure到slot的Value为

```text
p_r = W_o sum_t beta_rt W_v(P_t - mean_t P_t).
u_r = (1 + gamma(p_r)) * RMS(c_r) + beta(p_r).
```

中心化去掉了Value均值，但P仍进入Key，不能宣称整条函数对P公共平移不变。时间编码、内容相关权重和后续非线性
也使“S0广播首帧”不等同于给P输入常量。上述性质没有单独证明某个实际有用特征被丢弃，更不自动支持取消中心化。

部署第l个target上的更新则是

```text
delta y_l(x;V,L) = B_l(V,L) A_l(V,L) h_l(x)
                 = sum_r b_lr(V,L) <a_lr(V,L), h_l(x)>.
```

h_l由机器人自己的当前图像/state、动作latent、flow time及前层适配共同决定。
A定义对当前激活的作用方向，B定义输出方向；整个深层policy仍可形成复杂的状态条件行为。
A/B有基变换不唯一性，因此不能把某个rank坐标直接解释为“拿起”“再放下”。

## 3. 现有监督并未缺少跨episode信用

一个teacher生成同一LoRA，训练query来自同task其它episode。现实现先累积完整LoRA cotangent，再同版本重放Writer：

```text
g_w(V,L) = sum_q omega_q d loss_FM(F_source+w(x_q), y_q) / d w,
g_phi = [d G_phi(V,L)/d phi]^T g_w(V,L).
```

这是链式求导，不是截断掉动作信用；对query求和也不是新增的工程错误。
难点假设是：每个query需要的条件作用，必须经过一个共享参数生成Jacobian，才能给教学特征信用。
公式只给出这个依赖，不证明梯度必然冲突、必须改FM、或某个辅助loss一定更好。

在理想teacher/query条件独立的已知task分布下，同task固定LoRA可以最小化该task期望风险；有限池排除teacher
会有采样依赖，不能把理想独立性无条件套到真实sampler。即使语言唯一标识task，有限模型仍可能借视频学会
未见任务的操作规律。两点应同时保留：**不能用视频差异大小定义教学成功，也不能用训练有静态解证明视频无用。**
完整推导与限制见[信息可识别性分析](video_information_identifiability.md#3-为什么跨episode-fm允许视频无关解却不证明视频无用)。

## 4. 下一假设要改变的具体联系

当前Compiler先将教学内容变成一套A/B，再由未知的执行状态使用。候选功能读出则显式学习：
**对于当前执行特征，教学中哪些内容应改变该层输出。** 对一个可微cross-attention读出，记

```text
q_l(x) = Q_l h_l(x),
k_i = K_l m_i(V,L),  v_i = V_l m_i(V,L),
alpha_i(x,V) = softmax_i(q_l(x)^T k_i / sqrt(d)),
R_l(x,V) = U_l sum_i alpha_i(x,V) v_i.
```

m_i须来自真实q/E/H及有序处理，Value不能由task ID、动作标签或执行query构造。
执行query来自当前policy，且只在这个训练/诊断读出中使用；最终Writer仍只能读取L,V。
语言解释关注对象和目标；时间内容提供观察到的状态与变化；query决定这些内容何时对自己的计算有用。
这是拟学习的角色，不把注意力权重本身当成已理解操作的证据。

若g为下游动作损失对R输出的梯度，局部精确导数为

```text
d loss / d v_i = alpha_i U_l^T g,
d loss / d k_i = alpha_i [g^T U_l(v_i - v_bar)] q_l / sqrt(d).
```

它显示同一真实执行query怎样同时训练“读哪个内容”和“该内容产生什么作用”。与当前路径相比，候选把这段
query—教学内容的交互显式放在原生动作计算里，不先要求所有作用经自由参数生成间接建立。
这提供一个具体学习假设，而不是有用知识必然学成的定理。表示欠缺、有限任务支持或学习预算仍可能使它失败。

为防止再次混淆层次：固定LoRA单target是线性算子，R通常是非线性函数，但整个LoRA policy不是线性的。
不能由此证明rank16不够，不能将读出优胜唯一归因于softmax，更不能将它作为逃避MT-BC下界的借口。

## 5. 最终怎样接回唯一LoRA

这里的R是候选功能教师/诊断参照，不是增加一套部署控制器。只有它在独立episode和合法视频上取得行为证据后，
才值得检验如下完整方法：

```text
L,V → 共享原生图文/Action特征 → 有序教学表示
    → G_phi一次输出全部38-target A/B
    → 冻结source依自身状态执行。

训练监督：跨episode真实LoRA FM继续端到端学习G_phi；
合法训练task上的功能读出R只提供同坐标的附加监督，不进入部署。
```

候选监督对象是**在真实执行特征上的作用**，例如`BA h`对`R(h,V)`，不是任意专家A/B的欧氏坐标。
若用于学习，R须在学生自己的h上取值，不能用另一个运行路径的h冒充同一点；辅助项中的h可stop-gradient，
避免学生仅通过移动查询特征降低局部匹配误差，而主FM仍保留完整反传。
教师标签来源、R是否冻结、权重及学习节点必须在后继合同明确；本分析不隐含批准一个额外蒸馏loss。
准备稿将R作用于第10层q/v两个真实LoRA target，避免hidden输入纠正与投影输出纠正坐标不一致。
最终Writer仍输出全部38-target；只在有对应R输出的target定义局部标签。
即便在学生自己的h上查询R，也不能假设这些h都在教师已学会的分布内；这种传递覆盖仍需实测，不能被同坐标形式消除。

一般平方误差只给出三角界

```text
||S-y||_2 <= ||T-y||_2 + ||S-T||_2,
```

不保证蒸馏优于真实标签，更不是闭环成功界。必须分别观察教师能力、传递误差和学生闭环。
不能把弱教师准确复制称为改进，也不能为降低传递误差保留其错误。

另有一个可以精确定义的局部判别。固定授权训练查询，收集同target的实际输入X及R输出Y，
令`X=U Sigma V^T`为薄SVD、rank(X)=s，考察`min_rank(M)<=r ||Y-MX||_F^2`。
在非零奇异子空间上，最优残差是

```text
||Y(I - VV^T)||_F^2 + sum_(j>r) sigma_j(YV)^2.
```

第一项是该有限查询上单个线性算子不能复现的部分，第二项是指定rank的额外代价。
这比仅检查LoRA参数范数明确，但依然只属于固定局部接口：深层各target共同改变h，训练/部署状态也不同，
因此它不是全模型不可表示性证明，更不能单凭这个数增加rank或认定Compiler已失败。
若一个condition的查询数不超过输入维度且X列满秩，第一项可机械地等于零，不能据此称非线性作用已经可迁移编译。
不同video有不同目标LoRA，不能将其查询混为同一个固定M来制造残差。真正使用此判别时需明确样本量、有效秩和独立查询。
与旧Native Correction不同，Y应来自已具行为证据的合法教学读出；它不是privileged cotangent标签或任意专家参数。

## 6. 历史反例怎样约束这个候选

| 已有事实 | 本候选必须承担的限制 |

| Semantic-Path、统一中层Writer保留联合轴/原生续算仍未成功 | 不以保留T×L、fullH或进入native为充分理由；若功能读出仍无收益，显著下调本候选，不再通过加深读头续命 |
| 真G有闭环收益，RGB Native Correction/Local Field/Pullback未取得相称获取 | 不回到预测特定cotangent、固定source span或固定Jacobian像作为唯一出口；保留自由完整A/B和主FM |
| Cplus可表示语言路径却未改善 | 不靠函数包含或多一条残差宣称优化保证；不自动引入公共底座课程 |
| C0与语言近似持平，但冻结后续内容有有限正效应 | R必须同时看绝对能力和正确教学贡献；不能把任意输入敏感称为新知识 |
| 旧目标支持、task-slot、lookahead/回报更新均未给出统一修复 | 不预设只是任务冲突或通用动作loss问题；本候选改变的是视频知识与执行条件的接口 |

外部方法只帮助界定问题，不提供本项目成功证明：

- [Vid2Robot](https://arxiv.org/html/2403.12943v1)用执行状态与演示内容的交互产生动作；
  其在线条件接口不是EMBER的单次LoRA部署，不能直接移植分数。
- [Doc-to-LoRA](https://arxiv.org/html/2602.15902v1)把有上下文教师的行为传给生成adapter；
  本项目尚未拥有相同意义上的强视频功能教师，不能跳过此前提。
- [WIZARD](https://arxiv.org/html/2606.07217v1)以任务专家adapter监督权重生成；
  它的监督、输出覆盖、划分与本项目不同，不用其参数重建结果推翻本项目的功能/几何反例。

## 7. 实验应裁决什么，而不是默认打开哪些阶段

当前首选待辨解释为H_read：有益操作信息与执行条件的联系难以通过当前参数生成链共同学成；
替代解释H_repr：给定数据与学习预算，原生教学表示本身尚未取得可迁移知识。
二者可能同时成立；读出与Compiler都改变时，不能由总分唯一定位某一个tensor。

第一项值得准备的是**fresh联合学习的原生条件读出比较**，而非立即重训一套带KD的Writer。
最低有解释力的参照应包含同接口的language条件读出，以区分视频收益与单纯新增执行容量；
已有C0/B及S0用于明确预算/输入边界，不能把B当MT-BC。只做固定弱E读头不满足这项比较。
Reader本身执行时使用教学memory，必须标注为训练/诊断模型，不能进EMBER零交互部署成绩表。

| 观察 | 会改变的判断与行动 |
| --- | --- |
| Reader正确闭环与匹配language读出均无优势 | 下调本query—内容接口，不启动蒸馏；不从单个小面板断言所有视频表示不可能 |
| Reader强于当前Writer，却不强于同接口language | 可能改善执行参数化，但未建立视频教学价值；不把它作为视频知识教师继续整条投入 |
| Reader从正确/另一正确视频获得一致额外闭环能力，且能力丢失可接受 | 获得合法功能教师的前提证据；才值得登记同坐标作用传递、真实LoRA主FM及固定部署验收 |
| 教师成立，学生局部作用匹配改善但闭环没有改善 | 编译/分布传递尚未成立，不称修复；不因局部loss漂亮无限续训 |
| 唯一LoRA同时保留教师有益贡献并取得绝对提升 | 再按固定完整400和强MT-BC比较，检验保持与覆盖；screen不选正式模型 |

这些是候选的明确证伪方向，不是所有方法必须经过的普遍审批链。可直接由一项更有依据的结构学习干预替代，
但须解释替代依据。S0完成后只修订相关支持度，不自动把输/赢映射为“删动态/加动态”。

## 8. 强MT-BC的真实比较边界

coverage协议强MT-BC selected300为155/400；同协议Writer selected600为142/400。
对应配置是`configs/libero_24_8_8_coverage_v1/{protocol,mtbc,writer_task_diversity,evaluation}.json`，
原件沿[夜间结果索引](../review_materials/20260923/overnight_results/README.md)及研究历史定位。
本轮只核定非Test的比较口径，不利用Test结果修订方案。

当前fit28的diagnostic-held8与coverage Validation8不是同一集合，旧MT-BC训练用过当前diagnostic-held任务。
因此不能把当前C0的120/400直接从155相减来估算“还差35”。四臂A是本诊断数据下匹配direct-rank16参照，
不是充分搜索过的强MT-BC；B是language Writer。这个缺口不自动要求现在重训baseline。
当候选取得值得扩验的能力时，需要在明确共同协议上保留强MT-BC的真实选点和完整配对结果。
